# Normal captured-file Upload and Cancel

Feature 11 remains capability-closed. The normal Upload owner is a source
component over the separately committed passive collector.
It does not establish an authenticated backend result, rendered review, main
process/SDK retirement, independent witness or the complete Snapshot journey.

The owner reopens the original completed capture without recapturing. It uses
the actual filename-owned export row and existing ordinary Qt input transport.
Its closed input journal persists responsibility before dispatch; an uncertain
issued input can only recover its original native reception, never resend.
Capture, Upload and input/packet namespaces remain separate.

The first new native upload must follow the actual delivered input. Its opened
body file is bound to the original capture's native revision, byte count and
private filename. A new inner source version 2 retains the original mode and
UID needed by the native ten-field revision grammar. Literal source version 1
and the outer version-1 transport remain readable. Same-byte replacement is
insufficient: device, inode, mode, links and original modification/change times
all remain part of that exact revision.

The component's terminal boundary requires an actual native decision, returned
Script upload callback, actual dead QObject/stack markers and body descriptor
absence in three independently acquired native/host quiet groups. A reused
numeric descriptor, weak death alone or input ACK cannot qualify. Cancel still
requires an independent backend original because the server may already have
received bytes. Transport resource and process proof remain outstanding.

The host composition declares Qt, native clocks and HTTP as boundary models;
its body reads, original capture file, descriptors and weak lifetimes are real
host resources. It opens the original same capture inode without copying the
body into a replacement producer. Native source edits are uncompiled and the
actual native observer exception boundary is not exercised by those models.

Focused host verification:

- One connected normal Capture→Upload positive passed in 7.897 seconds. The
  received bytes are the original PNG and pure historical replay uses no
  transport query.
- Five normal Cancel/error/recovery cases passed in 31.096 seconds: a body
  already read before Cancel, lost normal input return without resend, held FD
  despite dead QObjects followed by actual FD closure, same-byte replacement
  refusal, and a persisted child reservation before the parent CAS.
- Two revision/namespace cases passed in 0.013 seconds: actual ten-field stat
  grammar, literal-1/source-2 reading, exact inode distinction, separate old/new
  namespaces, profile substitution, in-process source-version pinning and
  primary-role restriction.
- Twenty-three existing Upload, input owner, original source packet and
  Pending→PNG/two-prefix cleanup cases passed in 18.676 seconds. A separate
  Assets read-only diagnostic overlapped briefly; these timings are functional
  test evidence, not a performance qualification.
- A final six-case owner selection passed in 40.241 seconds after strict
  parent replay began checking the ordered original native-clock chain and
  phase ownership explicitly. Erased phase and rewound native-tail originals
  are refused by the pure decoder.
- Normal Upload and Cancel then passed together in 15.308 seconds after the
  fixture reflected the actual QML hidden Cancel and disabled active Upload
  controls. Production input handling was unchanged.

Logs are retained privately under `.ios-host-tmp/` as
`snapshot-upload-owner-resume-20261027-{04,negative05,compat06,small07,final09,ui10}.log`.
The first normal-flow admission exposed incorrect absent-file metadata in the
new fixture; the second exposed that its inner IO handler had bypassed the
existing queued file-job publication wrapper. Both fixture-only issues were
corrected without weakening production admission.

Next is the authenticated backend original and body readback/cleanup tied to
these same ordinary inputs and original request tickets, followed by actual
review/status and the outer same-main/Actor/process/witness composition.
