# Avatar acquisition and historical publication owner

`IOSAvatarObserver` owns complete independent acquisition for the primary or
actor observation role. Each role retains separate source/peer archives for
both actual SDKs and its own Vulkan image owner. It prepares the normal People
surface, brackets primary peer identity before primary source facts, brackets
actor source facts between actor receiver reads, then captures the observing
SDK's actual self or remote-primary image. Actual provider reads and every
native/host acquisition remain separate originals.

Only `IOSAvatarFacts` derives normalized facts. Each immutable observation
record binds its proof to the exact references, provider response and image
returned during its durable acquisition prefix. Source and peer recovery
ledgers are consumed historically, including every earlier abandoned source
prefix. Public callbacks reopen original files and validate history without
an SDK request, live provider read or live process guard.

The observer retains partial passive acquisitions and opened writer inodes.
Recovery adopts an already saved original locally; otherwise it retains the
old owner, partial bytes and component snapshots in an immutable abandonment
record before taking distinct future reads. Abandoned records cannot become a
public observation. Original files are never overwritten or deleted to clear
an unknown outcome.

The actor publishes through the shared `PhaseWitnessPublisher`. An issued POST
with unknown delivery is resolved by reading the original bound journal; it
is never sent again. Publication proves receipt of independently validated
facts and does not establish product cleanup.

`checkpoint()` permits the same original nine-fact acquisition under the actual
cleanup ticket, after an admitted active baseline. Its sequence continues the
existing observation history. The checkpoint deliberately retains its live
panel, script, entity and file resources. It can establish bilateral contact
absence before account logout; it cannot establish scene retirement or complete
cleanup. The ordinary `observe()` entrypoint still refuses cleanup tickets.

Host coverage includes a complete acquisition, reconstruction and historical
callback; distinct actor-owned reads of the primary SDK and its own remote
PNG; actual journal commit followed by synthetic delivery loss and no second
POST; lost peer return, saved-file adoption, partial empty-file preservation
and inode replacement; and proof substitution counterexamples. Native Qt,
AvatarMixer, renderer and observer-surface producers are explicit synthetic
seams. The actual ordinary Surface transport and real loopback publication
authorization are independently covered by their component suites. Native
compilation and device qualification remain unverified.

The contracts `ios-avatar-observer` and `ios-avatar-observation-record`
write version 2 and read versions 1 and 2. Frozen version-1 files retain their
original bytes and grammar. Version 2 stores every acquisition component and
the completed staged record in separate immutable private originals. The
fixed journal retains planned/opened/saved inode descriptors, rather than
nesting growing native histories inside its 64 KiB packed payload. Record-2
parts bind every component descriptor to its actual retained bytes; interrupted
opened parts remain owned even if they contain no complete JSON. Recovery
adopts a completed staged file without another native query or writer resend.
The private carrier namespaces `avatar-observation-part` and
`avatar-observation-staged` have independent version-1 storage envelopes; they
add no product evidence. Historical publication also replaces the live
OriginalFrameStore guard with an explicitly read-only guard, so candidate
continuity cannot cause an SDK call during pure validation. This is the observation coordinator, not an advertised
whole-feature capability. Whole feature preparation, recipe coordination,
input-outcome recovery and complete paired cleanup remain separate work.

Within one observer instance, `AvatarRecordCache` reuses a fully typed original
record only after two byte-based reads agree across independent actual file
signature inventories. Each use checks the exact dependency files again for
original device/inode, ownership, mode, link count, length, mtime and ctime, and
records their actual read membership. Planned-but-uncreated paths remain
separate absence dependencies: every use checks `lstat`-equivalent existence,
including dangling symlinks, without inventing a successful original read.
Private parent ownership and 0700 mode are checked again on reuse.
Any changed dependency fails that cache
closed, even if bytes and mtime are later restored. A cold reader still performs
full original decoding. This avoids repeatedly decompressing every historical
record at each pending-journal transition; it adds no product fact or timestamp.
