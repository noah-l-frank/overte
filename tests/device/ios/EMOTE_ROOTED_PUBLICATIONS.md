# Original Actor publication joins for rooted Emote cuts

`emote_rooted_publications.select` reopens the actual typed Actor cleanup
snapshot under both original source locks. It builds the existing rooted
observation decoder from the original Source/Peer envelopes, without a runtime,
SDK, native reader or fixture client. The unchanged `PhaseWitnessPublisher`
archive reader then checks all original observations, input-phase originals,
HTTP journals and committed publication receipts.

Each requested Actor entry must match exactly one actual published receipt.
The result retains the immutable publisher reference, original observation
reference, original acquisition and exact received server entry. It also opens
the actual private observation payload for the
[terminal-window join](EMOTE_TERMINAL_WINDOW.md), which compares it to the
Actor retirement original. This private payload is never a public result. It cannot
infer publication from an ACK, copy Primary state into the Actor, renew an
epoch or accept a projection-only match. Duplicate selections and unresolved
publisher responsibility fail closed. The existing run/role/process/candidate,
phase instance, fixture URL and private path checks remain mandatory.

The existing [scoped original round](EMOTE_ARCHIVE_ROUND.md) bounds repeated
pure validation to the unchanged complete artifact/SDK inventories. No new
wire grammar or publisher protocol is introduced. This helper reads literal
rooted component versions and publisher version one; it does not publish.

An actual retained Actor graph from the interrupted multi-cut host attempt
passes the exact committed-receipt join in 3.730 seconds. A selected entry with
its received epoch changed by one millisecond is rejected in 3.737 seconds.
Both tests reopen the actual source, independent UDP peer, PNG and HTTP receipt
originals; all 855 retained files remain untouched. Native/Qt/GPU/SDK and
acquisition clocks are declared models. This component does not qualify the
complete three-pair window, terminal seal or process/SDK end. Builds and
devices remain untested and complete Emote capability admission remains closed.
