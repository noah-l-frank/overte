# iOS normal login UI and private input

Current physical binding: [installed-code binding v1](../INSTALLED_CODE_BINDING.md) guards these
components with actual installed bundle/PID measurements. Legacy simulator and
cleanup-only modes still refuse component access. Historical blanket-refusal
statements below do not describe the new physical path. Complete feature-area
capabilities and device qualification remain absent.

The E2E-only Qt/UIKit source recognizes common login-control metadata v2. It reads
actual generic QML component/root IDs, visible error/spinner/server state and
owner-thread AccountManager context. Original native root generations/control
tokens bind normal UIKit pointer inputs back to the actual Qt window/control.
Native C++/Objective-C++ is uncompiled and unexecuted on devices.

NativeInput validates the optional loginControlsVersion:2/generation extension,
exact rows and original geometry. IOSLoginIO selects those actual rows, rejects
source-time regression and supplies original tokens for normal UIKit clicks.
The supported server field uses ordinary IME and focus-loss preference handling
with a closed, non-secret HTTPS origin. Unsupported/credential-bearing origins
are rejected before public transport. Full owners must retain/restore measured
original private configuration and must not redirect an existing real account.

## Dedicated private credential path

`_login_controls(selector,intent,run,origin)` now composes the shared recipe and
private input lease v2 with the original native UI component session. The caller
must separately stage/verify the owned native account-origin fixture and actual
trusted product endpoint. The factory neither changes native origin nor installs
trust. Missing preparation fails before secret GUI input. No full Authentication
feature triple is advertised by this component.

The public NativeInput edit API still refuses username/password before any
fixture request. Credentials never enter its readable HTTP/probe/CommonJS
command channel. IOSPrivateLoginTransport uses the same bound private Appium
session's AFC push/pull over the native-created 0600 original. It sends only lease
metadata through FeatureObservation; no text, base64 data or secret digest enters
public commands, status or durable journals. The transport module has a distinct
name so the existing legacy utility import path cannot shadow the shared owner.

The [private lease v2 contract](../../native/PRIVATE_LOGIN_INPUT.md) requires
in-place transfer, original byte readback and actual descriptor/file retirement.
A driver that replaces the reserved inode is unsupported. The bound private
driver must await writes and serialize the subsequent read RPC: after uncertain
upload this actual read is the completion fence. transferPending is persisted
before upload. A failed fence prevents native retirement and retains the journal,
so a delayed write cannot silently recreate data after cleanup. The actual
AFC/driver semantics remain to be qualified; no unsupported mode is bypassed.

Test.iosPrivateLoginInput accepts only closed metadata and dispatches its lease
on the real GUI owner. The native file reader validates the exclusive original,
run/nonce/body and separately owned origin, consumes the attempt and removes/
truncates original backing data before GUI input. Raw/parsed credential bytes
never return to the script engine. The GUI callback resolves only the original
username/password control and validates native UI instance/token/sequence/focus,
five-second source age, actual account/submission endpoint, visible current hit
point and active/key UIKit window. It then uses existing NativeFieldInput's real
IME route and actual editor readback. It cannot invoke a QML login function,
assign a property, change authority or bypass native TLS. Submit uses the
separately token-bound normal Login button, never an AccountManager call.

A delivery receipt remains input metadata, never login success. The full journey
still needs fresh independent protected profile/backend/UI effects, actual
persisted login and source-bound restart/logout. Native/UI epochs remain original;
no requested principal or desired result is returned as a measurement.

## Ownership and cleanup

The mandatory caller callback records actual UI/control intent before each
input without credentials. The inner private-input owner uses the existing
private state store, additionally pinning actual native private source identity
and persisted transfer state. Every attempted transfer retires its original
nonce/file/descriptor or retains the journal. An uncertain GUI effect is never
replayed. File cleanup does not undo an input or clear product authority.

Adapter-wide cleanup drains a pending private input before native probes,
account origin, Script ownership and original base teardown. A failed private
scope still reaches original process/session teardown but keeps its journal and
refuses green. A replaced process/session cannot adopt old scopes. Intentional
restart must close this lease first. The outer full Authentication owner still
needs owned view close, anonymous protected profile, fixture revocation/handler
quietness and all product/data cleanup before removing its own run journal.

Twelve private wrapper/factory cases execute original Python/fixture metadata
paths against synthetic Qt/AFC boundaries with real local original files/FDs.
They cover ignored transfer/field input, foreign copied inode, missing results,
false cleanup ACK, actual base teardown, pending close/reopen, failed/drained
uncertain transfers and explicit canonical rejection. Eight earlier UI/privacy
cases remain. These prove test/adapter logic only, not native UI/AFC behavior.

The canonical iOS installed-code association stays unavailable and both new
private factories explicitly reject there. No full-area or device acceptance is
inferred. Full startup/restart/logout/run ownership, trusted native setup and
independently measuring complete account/UI/backend actors remain required.
