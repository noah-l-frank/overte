# iOS login observation and normal controls

The E2E-only Qt/UIKit source recognizes the common login-control metadata v2.
It reads actual generic QML component/root IDs, visible error/spinner/server
state and owner-thread AccountManager context. Its real root/tablet visibility
changes advance a native generation nonce; original source/element tokens bind
normal UIKit pointer inputs back to the actual Qt window/control. The source
is uncompiled and unexecuted on iOS.

NativeInput validates the optional loginControlsVersion:2/generation extension
and exact original login rows/geometry. IOSLoginIO selects only those actual rows,
rejects source-time regression and supplies original tokens to normal UIKit
clicks. The ordinary server field can be edited through the existing normal
IME channel with a closed, non-secret HTTPS origin. Host and native reject
unsupported/credential-bearing origins. It is a preference/configuration input,
not a desired login result. Full owners must restore their measured original
private configuration and cannot redirect an existing real account.

Username/password are **refused** by both IOSLoginIO and the existing public
NativeInput edit API. The shared fixture command endpoint is readable and must
never carry these credentials, even if a server is TLS protected. A dedicated
private input lease/transport, with actual file cleanup and nonce retirement,
remains to be implemented. No ordinary login success is claimed by these
observations or pointer/server input. Source metadata, ACKs or a declared field
cannot stand in for native protected profile/backend/UI witnesses.

Eight new device-free checks cover original synthetic view/element state,
ignored pointer/server input, missing/foreign/legacy metadata, source context/
process changes, clock regression and refusal of private credentials before any
public transport access. They prove parser/input/privacy logic only. Existing
normal component checks are separate from installed-code qualification.

The canonical iOS installed-code association remains unavailable and no full
Authentication feature triple is advertised. Actual startup/restart/logout,
durable run ownership, trusted native fixture setup and independent account/UI/
backend witnesses are still required. Full cleanup must close only owned views,
retire private input, release native probe/origin resources, separately revoke
fixture authority and verify all owned data absent before discarding ownership.
