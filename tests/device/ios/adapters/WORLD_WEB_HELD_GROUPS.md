World Web held lifetime labels
=============================

The full 19-step host journey exposed 134 measured native lifetime groups. The
common terminal/public contract permits at most 64 labels. That bound remains
unchanged.

`world_web_held_groups.project` is a private projection over an already decoded
original set. Sets of at most 64 retain their exact existing form. Larger sets
use one label per native kind, keeping every complete member original, binding,
run, source instance, context/owner identity, descriptor and counter. The label
contains a prefix of the full group digest. New, changed or removed members
therefore change the label even when their kind and pending total stay equal.

`expand` validates exact canonical groups and recovers every original member.
`verify` additionally joins to a separately decoded complete member set. Neither
function establishes native liveness, callback drainage, source freshness or
process death. Native consumers must rederive members through their typed source
and lease decoders; a hash or standalone group is never a cleanup fact.

The existing World collector calls this projection only after its normal source
qualification. Six bounded projection cases passed, including repaired-hash
membership loss, source/context/counter changes, aliases and literal small sets.
Two previous held-resource composition cases also passed. Actual retained
19-step originals passed all Source/lease/GPU/pixel/public validators with 134
exact members in four labels (130.792 s, 1,445 files unchanged, zero queries).
Four further mutations against that actual member set were refused (52.659 s).
SDK/native/OS producers and clocks in those host runs are declared models; no
physical run or real-CPU freshness qualification is claimed. The later retained
full nineteen-step end passed with 1,919 unchanged original file identities;
central integration, current-source recovery/inventory checks and real
operation bounds remain required before advertising the full capability.
