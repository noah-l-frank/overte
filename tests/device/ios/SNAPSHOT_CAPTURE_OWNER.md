# Partial normal still/PNG capture composition

`IOSSnapshotCaptureRuntime.capture_owner` uses the existing installed candidate,
SDK, native source and real Script source lock. This internal packet requires
the actual SNAP review page already open in still/PNG mode, with no pending
capture, foreign title or existing images. It does not open system UI or alter
Photos authorization. The original empty/owned title is measured and retained.

`capture(ticket)` accepts only the actual active still/PNG fixture capture.
It retains the actual configured default Script root and loaded Snapshot Script
source pins, empty native file baseline, Script/capture originals and ordinary
token input intent before delivery. Existing `SnapshotInputOwner` handles lost
input returns using original reception histories without another capture.
Read-only source queries retain their own immutable nonce and original bytes;
an uncertain query is not resent. New independent polling queries preserve
original source prefixes rather than retiming a previously held callback.

The existing manifest/chunk/artifact owners acquire actual native capture
bytes. `snapshot_completion.decoded` joins the normal input, original Script
closures/timers, actual native terminal capture and decoded nonuniform PNG.
Native completion and an ACK cannot replace missing, stale or corrupt bytes.
The result keeps scene fidelity, destination and independent witness required.

`cleanup` requires actual Script/capture/export drainage before exact native
file removal. Each removal uses the existing durable native ID/revision owner,
passive ACK and independently observed worker return/finally/weak expiry.
It never retries an uncertain unlink. Three fresh file-channel groups must
span at least three seconds on the original host and native clocks. Original
UI restoration is measured under a separate native clock bracket. The host
artifact and all original evidence remain retained for later paired cleanup.
This packet does not claim complete product quiet or process/SDK retirement.

Pure `archive` reconstruction reopens actual local child journals/originals
without SDK or native getters. Lost child metadata, orphan original carriers,
changed source/candidate and missing files cannot be silently adopted.
Every declared typed child is decoded even when its parent digest update was
lost. A saved child frame or complete issued raw response remains reachable
through its original inode-bound files. The live child can adopt its own saved
proof without another input/query or file rewrite; finishing an acquisition
whose final clock was not retained may still need a new independent clock
observation. Partial bytes never become a completed capture or fresh result.
The partial owner uses a 25-second host API budget; the existing per-source
1.5-second joins and three-second file quiet requirement remain unchanged.

The connected host fixture uses real private files, actual normal-input and
HTTP/AFC codecs, immutable child journals, image decoding, host unlink and
weak host jobs. SDK, native capture/Script/Photos facts and clocks are explicit
models. It does not compile native sources or qualify a device or real timing.
Whole Snapshot completion still needs scene fidelity, paired witness/final
quiet, permission/system UI, Photos/Share companion installed-code admission
and original destinations, authenticated upload, background recovery, other
output modes and normal page restoration. No capability is advertised here.

Ten focused owner/recovery host cases pass in 24.695 seconds. Recovery cases
pin original bytes, inodes and stat identities, and check actual modeled input/
source query counts. This validates host logic, not physical capture or timing.
