# Frozen role ownership joined to its original terminal seal

`IOSEmoteRootedOwnership` consumes the exact paired role metadata copies and
the Primary's original terminal-journal copy. The existing role reader first
reopens every required WAL/source/recovery/scene/GPU/publication owner. The
terminal reader then reopens the actual inode-bound proof file, validates its
sealed journal and rederives the complete three-pair proof from original
Source/Peer/PNG/Actor HTTP data.

The copied role live journals must exactly match the sealed proof's journals.
The copied Actor publisher must exactly match its original publisher snapshot.
Every publisher record is reopened through the explicitly supplied frozen
store boundary. A missing copy cannot fall back to current SDK metadata.
Changed or later journals cannot borrow an older seal.

Both artifact and SDK inventories remain unchanged throughout the combined
read. Only the existing bounded pure validation scope is shared. No SDK,
native/UI/image query, input, clock renewal or process operation exists.

`IOSEmoteTerminalJournal.archive` reads the same literal version-one metadata
through a read-only store. Inspect, seal, save, intent and recovery writes are
all refused by this historical owner. The normal journal factory retains its
existing persistence behavior. Ordinary publication selection retains the
default actual-file record factory; frozen selection requires explicit copies.

Thirty targeted no-build host tests pass in 1.145 seconds, covering actual
private proof files/CAS, journal write refusal, changed live/publisher metadata,
missing copies, replaced/missing originals and the existing controller/inventory
regressions. Paired measurements and complete role decoding are explicit models
in these fast cases.

The normal-cleanup connected scenario reached all three actual Primary/Actor
pairs, all window counterexamples and the persisted inspect/seal proof, then
failed after 1998.300 seconds at the paired inventory barrier. Its fixture
returned preloaded component objects without all direct current-metadata reads.
All 2707 captured sources were unchanged. The corrected scenario now uses the
actual production `IOSEmoteTerminal.local_window` reader on the live fixture
owners. The complete changed scenario has not yet been rerun.

Independent replay over those actual retained originals passes in 603.292
seconds. The typed current-file/recovery/scene/GPU readers account for all 1436
scoped carriers; the frozen role/three-pair proof then requalifies with every
current metadata path forbidden. All 1465 original files retain their exact
identities, lengths and hashes. SDK/candidate guards are models. An initial
diagnostic incorrectly passed an archived Scope to the live snapshot API and
was rejected; no historical guard was changed to make it current.

The failed connected case stopped before the real fixture DELETE and retired
phase read. No inactive phase or final host-copy transaction exists for this
corpus. Fixture shutdown is not retirement evidence; neither is reconstructed.
These durations do not qualify the unchanged thirty-second operation budget.

This is pre-process-end ownership. Once-only Stop, fresh source/native/phase
fencing, independent OS absence, separate SDK deletion/404, canonical/generic
cleanup, worker recovery and complete runtime/common journey remain required.
Finish and complete capability admission remain closed. Native sources are
uncompiled and devices are untested.
