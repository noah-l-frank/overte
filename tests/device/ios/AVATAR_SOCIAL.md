# Avatar social evidence

`ios-avatar-social` version 1 derives invitation, connection and absence from
originals belonging to two distinct SDK sessions of the same candidate. The
native account principal and endpoint hashes must match the actual allocated
role. Each source stays in its own original process clock bracket.

An invitation requires the actual outgoing and incoming Pal prompts to name
the other actual avatar session and the same original request UUID. Actual
running protocol workers must have evaluated the independently pinned Pal and
PeopleConnection source bytes. No service GET or pending response supplies
the other person's consent.

A connection requires actual independently authenticated POSTs from both
roles, actual successful confirmation responses and actual completed Pal
tables on both SDKs. Exact provider request/response bytes and original reply
IDs join the real request.js DONE callback's responseText read. The actual
worker membership, top-level submitted code and compiled caller modules join
the same original XHR. Each complete table must equal the latest consumed PSF
page, including profile and place fields. A finished reply alone does not
prove that table exists.

Absence requires fresh consumed empty PSF pages and actual completed empty
tables on both SDKs, idle prompts and destroyed protocol timers. When removal
was performed, the original successful primary DELETE must target only the
allocated peer and precede its fresh table response. Whole VM timer, native
XHR, GPU, peer and authority drainage remain separate cleanup obligations.

The additive `consumed_responses()` parser returns all matching originals in
their original order without changing source packets. Existing
`consumed_response()` keeps its latest-response API and rejects an empty set.
No wire source version changes.

Host tests exercise real controlled OAuth/provider state and exact stored
response bytes at explicitly synthetic native/QML/SDK boundaries. They cover
missing peer POST/read, mismatched materialized rows and candidate code,
foreign principal, outstanding parse callbacks, stale model time, request
UUID mismatch and missing original DELETE. They are not device qualification.
The complete feature owner must still perform ordinary actor input, retain
all original ownership and integrate GPU observations and quiet cleanup.
