# Original Create work and lifetime sources

Feature 4/14 remains gated until its complete normal-input, two-actor,
rendered-image, export and restoration owner is integrated and verified.
These are source-level prerequisites; native code has not been compiled or run
on an iOS device in this task.

`feature-ios-create-work` accepts only `schemaVersion`, `commandId`, `action`
and `runId`. Work version 1 retains original native main-thread clock brackets,
PID, read-channel birth/sequence, four actual Create closure roles, their native
VM caller membership and submitted-code hashes, actual callback entry/returned/
finally events and pending state. Repeated VM heartbeats refresh their real
capture time without replacing the retained transition history. The native
ledger cannot be reset. More than 512 retained events per role, an invalid
nesting/identity transition, stale code, missing role or overflow fails closed.

The helper is required only after the dedicated gated Test method is present.
Ordinary production paths load no additional helper module, connect no additional
signal and advance no observer counter. The source-pins manifest is version 1;
its hashes cover the exact UTF-16 code units actually submitted at main/include/
require evaluation. Reading a file later is not an execution original.

The separate lifetime profile is version 1. Every actual EntityTree read records
weak references to the real entity and every real renderer Model observed for
it. Native destruction is observed from weak-reference expiry, with original
birth and destruction-observed clocks. Model records are never removed or
reassigned. Source version 3 adds actual `sourceUrl`, `userData` and
`collisionless` properties to Create entities; readers still accept versions 1
and 2. Neither map absence nor a hidden panel alone establishes retirement.
The owner must additionally join the original manager-thread queued Script work
barrier, callback/timer drainage and retained image/GPU/file retirement.

Host verification uses synthetic SDK boundaries and real durable temporary
files, actual fixture/probe/HTTP/AFC dispatch, the real instrumented JavaScript
helper and existing normal Create bridge. Tests cover source/pin/clock/birth
changes, pending callbacks/timers, missing original resource birth, destruction
revival, missing Test/Script.require, original return/throw/finally behavior and
one-dispatch-per-nonce preservation. No DomainServer, device or build is started.

The ordinary action layer now connects all 21 shared journey steps to actual
Create controls, exact pre-delivery command UUIDs, original Qt field tokens,
model/texture and filled PolyVox actions, native world pointer input, document
import/export and the owned domain permission control. It journals a newly
returned entity before naming or editing it. Uncertain inputs remain owned;
their original recipes cannot be repeated. Cleanup has its own durable stage
reservations and requires fresh observed postconditions before continuing.

The rez client uses only its explicitly configured authenticated loopback
control. Its recovery operation reads the exact original command's outcome;
the server's matching branch never repeats a settings POST. PID/start/exe and
domain identity changes refuse continuation. Permission settings remain input
authority; actual native permission and creation/denial sources decide effects.

Each `CreateSources` role retains complete original Create/domain/closure/VM
read groups and their own native and host brackets in immutable private records.
A phase crossing remains historical. Peer joins require independently acquired
entities from a different candidate-qualified app/target on the same actual
domain/mixer, actual creator identity, model/texture readiness and voxel bytes.
UI fields still come from independently read primary UI, which does not replicate.

Marker files carry only a bounded local Web marker. A prepared marker lease
validates its original assigned Script manager, evaluated UTF-16 code, actual
entity and preserved body/view; it does not stand in for setup or cleanup.
World measurements join original Vulkan pixels, recorded camera, actual marker
and subject geometry, capture ordering and positive GPU storage retirement.
The drain validator independently checks entity/model weak expiry, manager-thread
callback/timer barriers and original editor settings. Existing product timers
remain actual product resources; natural timer countdown is not reset.

The self-contained packet passed 74 explicit no-build host tests, including
ignored/lost inputs, unowned edits, import/export bytes, real loopback control
recovery, late/wrong peer effects, image/geometry failures and incomplete native
retirement. SDK and native events remain modeled. Whole observer/publication,
marker acquisition recovery, paired quiet cleanup and final dispatch remain
unfinished, so Feature 4/14 is still partial and no complete capability is enabled.
