# Snapshot Share conditional run retirement

Feature 11/14 now connects the ordinary Share transfer to conditional retirement
of its exact App Group and archive Documents run roots. This is a component
result; the complete Snapshot capability stays closed.

At successful native import, the archive pins the initial identities and actual
bytes of exactly six private files: the group's `original.bytes` and
`share-original.json`, and the archive's `original.bytes`,
`original-extension.json`, `import-intent.json` and `import-original.json`.
The original metadata identity is sampled before its first import read. The
copied artifact's initial revision, both created run roots and both parents are
retained. Subsequent same-byte replacement cannot establish that first file.

The ordinary Retire button accepts only a fresh nonce. It records an exclusive
durable intent before removing anything. Native code opens no-follow private
directory/file descriptors, checks exact censuses, hashes and initial file
revisions, and closes every original reader before the first unlink. Each
conditional named unlink and empty-directory removal records its actual result
and native clock. It does not recursively remove a directory or adopt an
unexpected child. Failure, close/fsync uncertainty or partial deletion keeps an
incomplete responsibility; the input never repeats.

A separate ordinary inspection button writes fresh native observations of the
two original parent-anchored run names. Only an actual `ENOENT` qualifies as
absence. Permission, descriptor, parent identity or other errors remain unknown.
Each observation includes the unchanged original retirement record, fresh
native clocks and its own nonce. The archive AFC reader admits only this closed
observation path and the additional original import-intent path.

`IOSSnapshotShareOwner.cleanup` retains the original import-intent JSON, exact
receiver/import JSON and every returned observation as immutable host originals.
Before issuing Delete it requires three independently qualified original
extension PID/bundle absence queries, spanning at least three seconds in both
the actual Node clock and the separately sampled owner host clock. The latest
query must remain fresh through the normal input guards. If an unissued window
expires, the owner appends a new group and preserves all earlier clocks and
original files. It cannot replace or re-anchor the first actual receiver PID.

After retirement, three further rounds independently join actual extension
absence and actual native run absence. Both the Node/host and native-file/host
windows must span three seconds. A lost Retire or Inspect return cannot issue
the same button again. An issued late inspection is retained before a new
passive nonce is allowed; it stays historical and cannot be given new clocks.
The existing main process then returns to the foreground, with a fresh drained
native Share operation. The capture PNG remains available for the later upload.
