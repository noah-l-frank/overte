# Callback history row reuse

The explicit Callback Live2 path can reuse an immutable historical row within
one original feature flow. A cold row is decoded twice with matching literal
results, actual original-file membership and physical signatures. A warm row
checks the same complete physical identities and absence duties before
restoring the verified row and its read membership. Current native facts,
clocks, image capture and resource retirement are never obtained from this
cache. The existing complete inventory, ordering and pending/orphan checks
remain outside it. Literal Live1 and unselected defaults retain their behavior.

The closed policy binds the actual project decoders, original-store context,
code objects, aliases, defaults and supported constants, plus the actual JSON
and PNG reader dependencies. A changed parser, policy, owner, codec or original
identity falls back to the literal decoder or refuses. Unsupported objects do
not become cached success. Inert annotation metadata is not evaluated.

All 27 distinct mechanism cases pass across scoped runs: 19 historical results,
three subsequent results and five final selected cases. Two test-only mistakes
were corrected in later selections. Their original failed aggregate runs remain
failed, with the missing first aggregate census recorded explicitly; completed
per-case cleanup and later aggregate censuses are retained. No passed prefix
or smoke test was repeated merely to replace those reports.

A fresh postboot production capture/append created 235 original files. Both
original Node processes and the actual host owner closed normally. Its first
measurement failed when Python profiling and process observation selected the
same monitoring slot. A separate read-only run subsequently decoded the same
physical originals, without regeneration, input, native query, SDK or network.
Every body, device/inode and complete inventory remained unchanged.

For that one stored row, the measured archive-read intervals were 21.456 seconds
with an empty row cache and 1.292 seconds on reuse. Actual decoder reopen counts
were two and zero, with the same 215-file read membership. The literal owner and
reference metadata and ordinary PNG parser registration were prepared outside
both intervals; no historical row or image was decoded to warm the cache.
These are scoped archive measurements, not whole-journey or API latency claims.

Callback Window and final-archive construction must select the original flow's
cache explicitly. Their whole-flow integration and the complete Emote journey
require separate qualification. Native producers remain models, native code is
uncompiled, devices are untested and whole-feature admission remains closed.
