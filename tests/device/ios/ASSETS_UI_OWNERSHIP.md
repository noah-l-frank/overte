# Assets UI original ownership

The Assets UI screen inventory reopens the original native-source, screenshot,
segment and sample files under independently supplied run, binding, state and
artifact roots. Both roots require the existing private-directory ownership
boundary before any file exists, and their device/inode/owner/mode identities
remain stable across the inventory. The selected source checkpoint, current
image action ticket and screen policy are external authority. Upload ticket and
original marker birth do not supply the later image ticket.

Historical inspection performs no SDK, native, clock, screenshot or input
acquisition, retry, recovery, cleanup or file write. Unknown UI namespaces,
foreign inodes or context, changed root ownership, and incomplete membership
fail closed. Actual stale, blank or interrupted images retain their originals
and outstanding responsibilities; they cannot establish a current screenshot.
Recording and frozen metadata views still require actual original-file reads.

`asset-ui-ownership` version 1 is an inventory report. Its
`wholeEndEligible` and `currentNativeFactsProduced` fields remain false. The
component does not qualify current whole Assets behavior, native capture,
installed code, devices, process/SDK retirement or completion of all 29 actions.
Literal Tablet screenshot defaults retain their existing namespaces and DTOs.
