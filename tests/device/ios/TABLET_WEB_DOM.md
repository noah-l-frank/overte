# Original UIKit Tablet DOM and presentation acquisition

This prerequisite is source-level work for feature 7/14. Native Qt/WK/UIKit
code remains uncompiled and unexecuted here. Host tests run the actual passive
observer and unchanged reference handler with modeled DOM/native SDKs.

`ios-tablet-web-dom` version 1 has action `feature-ios-tablet-web-dom`, original
file `feature-ios-tablet-web-dom.json`, and a 2 MiB native envelope bound. Its
separate original DOM body is at most 1 MiB. It is not a World DOM DTO.

The actual native provider selects exactly one foreground Tablet policy/view
whose immutable source stamp belongs to the requested fixture. It requires the
actual key main-screen window, foreground scene, presented controller and
current WK descendant; another sheet, hidden or transitioning presentation,
wrong window or recycled native view fails closed. The native WK/window/view
and original document identity are checked again after the JavaScript callback.
Before/after presentation records must match exactly within this acquisition.
They include actual UIKit coordinate spaces, frame/bounds/safe insets, screen
scale/orientation, scroll offset/size/zoom and current responder/recognizer
state. Querying does not load a controller view.

The DOM source is installed only on a genuine owned Tablet policy grant. The
existing World script bytes and World getters remain unchanged; World observer
installation is limited to its actual World surface. The Tablet source reads
controlled, type-checked text/foreign fields and optional HTTP controls, actual
visual viewport/scroll/element rectangles, original trusted/untrusted pointer,
focus/input/composition events and the unchanged reference handler's displayed
Tablet echoes. It never clicks, edits, focuses, scrolls, sends a bridge packet,
reads arbitrary/password values, or reads key/data/inputType event text.
Composition history contains only actual target birth and active state.

Actual native finished/verified document identity, nonce and original HTTP
response header/status are joined to the returned DOM. An inline acquisition
instead requires the actual current native carrier and exact synthetic inline
response URL, null HTTP metadata, and independent original decoded-source /
carrier / binding provenance. It does not fetch HTML or label HTTP bytes as an
inline document.

Native requests retain all original query nonces, at most 4096 entries / 64 MiB
of immutable cached packet bytes. Each nonce issues at most one actual DOM
JavaScript evaluation. Pending polling keeps the original acquisition start;
terminal reads return identical original packets/clocks. A timeout or callback
body return does not imply the actual WK block was released. A separate weak
capture token lives only on the initiating stack and actual native block. A
new query cannot replace an outstanding same-owner capture while that weak
token remains alive, including after terminal timeout. Source-level checks and
an actual host weak-closure counterexample cover this boundary; they do not
execute native C++.

The Python reader separately validates the native envelope, closed DOM grammar,
source joins and current presentation. Valid pending packets are retained as
native birth/counter/acquisition-start floors; a later valid-looking source
reset, lower counter or rewritten terminal timestamp cannot pass. Current
recognizer inactivity is explicitly not a UIKit touch-lifetime receipt.

Remaining whole-feature obligations include the separate passive real
UIApplication/UIEvent/UITouch source, actual native inline callback hold/replay,
independent Tablet native closure source, ordinary WDA inputs/fixture buttons,
actual PNG/page challenge joins, all 26 actions, independent witness,
interruptions/recovery, repeated full retirement and final API integration.
No full feature capability is advertised by these prerequisites.
