# Snapshot ordinary pending capture and cancellation

`IOSSnapshotPendingRuntime.pending_owner` connects the unchanged
`capture-cancel(animated,png)` phase to ordinary Qt controls on the existing
admitted input session. It holds the actual source lock and forbids session
recreation. The main installed-candidate byte/process guard remains active
before every source and input boundary. No setting or desired effect is sent
through a test setter.

The owner starts from an actually idle still/PNG page with no images. It retains
the original controlled title, root and QML source, sets its own animated title
through the normal input owner, and opens the actual mode popup. A separate
closed original reception profile admits only the existing animated/still
RadioDelegates. Readonly E2E QML references expose the actual delegate's combo
and root; native metadata independently checks the root's feature/QML gate,
delegate context, current popup content ancestry, same window, enabled combo,
actual checked mode, native blocking and owned input point. A retained combo
identity prevents a replacement popup owner from extending an old choice.
Actual QML `var` references are unwrapped from `QJSValue` when necessary before
the same QObject/root/popup checks; no requested root is supplied.

The existing `press` path remains the only input dispatch. The new native
`SnapshotPending` journal records the original command, actual popup metadata
and original positive/negative return; it cannot change a mode or capture.
The Test getter, probe, fixture and AFC reader expose only the closed
`feature-ios-snapshot-pending-inputs` command/file. Missing native support stays
unavailable. Existing Snapshot reception literal 1 does not admit these option
commands and keeps its original grammar and namespace.

Capture and Cancel each have a durable one-send intent. The owner retains the
actual pending script work before ordinary Cancel, then composes the existing
strict pending-cancellation codec: independently pinned script code, two actual
350/60000 ms single-shot timers with no fired dispatch, the original capture
ID, `cancelNativeCapture` entry/returned/finally, original normal input receipts,
no matching native capture begin, and before/after original file absence.
An ACK, empty UI flag or a callback return cannot replace these facts. A real
timer still owned after Cancel blocks completion; a later fresh passive query
can observe its actual destruction without resending Cancel or changing an
earlier original.

Ordinary still-mode and title restoration follow the cancellation proof.
Three distinct source groups then require empty animated-prefix manifests,
quiet script timers, drained native captures and drained native exports over
at least three seconds of both original native and independently sampled host
time. Native clock birth, sequence and process binding are replayed across
every saved source and the restoration packet. `archive` reopens only retained
local originals after SDK loss; it cannot issue native commands.

All Pending packet/input/manifest/segmented-byte namespaces are separate from
Capture, Photos and Share. The manifest's new protected `_store_prefix` hook
defaults to its original literal path. Existing Capture runtime factories keep
their original behavior. Saved originals before a parent CAS retain their
actual device/inode/bytes and do not cause a query or input to repeat. Partial
opened originals remain owned and cannot be overwritten.

modeled. Timer destruction follows real Python weak lifetimes; host UTC and

clocks and Qt timer dispatch are declared model boundaries.
