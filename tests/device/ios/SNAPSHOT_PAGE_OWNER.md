# Internal normal Snapshot page ownership

`IOSSnapshotPageRuntime.page_owner` uses the existing installed candidate and
W3C session. It does not admit a public feature, recreate a session, discover a
device, install an app or promote the Snapshot capability. The caller supplies
the active still/PNG Snapshot fixture ticket.

The owner starts with an actually closed tablet. A normal UIKit open input
reveals the existing route. A launcher is paginated through ordinary source
token controls until the actual SNAP entry appears, bounded by its observed
page count (at most 32), 72 owned navigation actions and 384 original frames.
An already loaded SNAP page can be revealed without replacing it. A foreign
editor is never replaced by Home; only its unchanged visible controls may be
hidden again to restore the original visibility.

## Actual selected-page interface

`TabletHome.qml` exposes read-only `featureLauncherCurrentIndex` and
`featureLauncherCount` from the real `SwipeView`. They return unavailable
values unless the existing `Snapshot.featureObservationEnabled()` build and
test-script gate is active. The shared QML path is also used by Phone/Pico;
there is no setter, new handler, delay, product navigation or destination
behavior in this extension.

`IOSTabletLauncherControls.h` accepts only the actual `TabletHome.qml` ancestor,
its expected source URL and enabled gate. It adds an observational root UUID,
current zero-based page index, count, control index and actual point ownership
to visible SNAP/page controls. `tabletLauncherControlsVersion=1` is an optional
extension of the existing native DTO. Legacy observations remain decodable;
the new owner requires the real extension and a coherent complete indicator
set. Every relevant property participates in the control's source token.
`NormalUiInput::press` rechecks the same native metadata before ordinary mouse
delivery and cannot fall back to unbound input if the original gated root
disappears.

UIKit generic proxy buttons expose the actual token as accessibility value.
The primary Open/Close toolbar instead recreates its UIKit object on token or
window replacement and captures that original token in its normal handler.
The owner retains the exact resolved WDA element, checks generic values, and
independently re-reads the actual native row before its only click. It does not
call QML handlers, set the page index, use coordinate guesses or use a native
activate fallback for the SNAP entry.

## Durable originals and recovery

The same actual Script source OS lock, full candidate/process/session binding
and CAS state guard every operation. `ios-snapshot-page-owner.json` owns a
separate immutable original namespace, avoiding the private capture owner's
child census. Original frames retain the UI DTO and complete actual Snapshot
Script/native timer work under independent native before/after clock packets.
The configured default Script root and exact loaded Snapshot source pins are
validated; a request result or ACK cannot establish the current route.

The internal runtime, owner and archive accept an explicit `combined=True`
choice for the ordinary default-script manager that includes Snapshot.
The owner and observation markers are then version 2. The same coordinator
path refuses an opposite-profile envelope before observation or input; stored
bytes never choose a profile. Combined uses only the fixed
`feature-ios-snapshot-combined-work` reader, its four submitted-source pins
and original V8 caller/timer histories. It uses the separate
`ios-snapshot-combined-page` namespace with distinct version-1 frame/original
keys, retaining the unchanged byte, inode, five-second storage and size limits.
Undeclared files from either main Page namespace prevent new ownership.
Default Separate1 frame keys, paths, query grammar and archive remain literal;
the existing Share-return subclass retains its own Separate1 namespace.

Actual native/work/UI query nonces are saved before transport. Unknown
GET-style observations can be abandoned only with their whole owned nonce
prefix retained; a new observation has entirely new nonces. An opened/saved
original frame is recovered through its exact inode/digest, without replacing
its bytes. Interrupted partial original writes remain unresolved. Unknown
files in the page namespace block reconstruction.

Each navigation intent stores its reference original and exact WDA object
before delivery. Once issued, it is never sent again, even when the ordinary
SDK return was lost or input was ignored. A later independent observation can
establish the resulting route/selection; unknown SDK delivery stays explicit
in the result. This does not turn an observed route into an independent causal
witness of that input. An ignored input retains its unresolved responsibility
and cannot produce page success.

Restoration uses normal Home/page/Close input and independently observes the
original selected index/count and closed tablet. Home may create a new real
launcher root: both original UUIDs are preserved, without claiming that the
old root's weak lifetime ended. A changed page count or foreign route blocks
restoration. Repeat calls acquire a new actual closed observation and never
replay Close. Repeat opening also observes the actual current SNAP root.

`capture()` composes the existing private still/PNG owner under the same held
lock, transferring original native source floors without resetting a live
reader. It keeps the capture packet unchanged. The child still owns its files,
original bytes, callbacks and cleanup; navigating Home is not child cleanup.
An explicit Combined Page constructs the same Capture coordinator with its
explicit Combined2 profile, preserving its actual manager/work prefix.

The outer API retains the shared 25-second monotonic operation budget. The
native acquisition bracket remains below 1.5 seconds and every original
carrier remains below 1 MiB. Pagination does not extend these deadlines.

## Verification and remaining obligations

`SnapshotPageOwnerTests` models the real UIKit/native boundary, preserving
ordinary W3C requests and actual normal HTTP/AFC source codecs. It uses real
immutable files, CAS and OS locking. Cases cover actual pagination/restoration,
lost entry/Close returns and reconstruction without resend, ignored selection,
stale source token, foreign editor preservation, initially loaded SNAP,
changed page count, native timer dispatch retention and saved-original CAS
loss with inode/bytes/query pins. A connected case runs normal launcher opening,
the existing private capture owner, actual PNG bytes, child file cleanup and
normal restoration in one real held lock. Home recreates the modeled native
launcher root; both normal and lost Home/page-return cases restore its actual
selection across the new UUID. A replaced launcher root between WDA resolution
and delivery blocks the old token. `TabletLauncherControlTests` checks coherent
typed selection. Passive native/QML gating requires source review. These are host tests, not
device, UIKit, scene-image or hardware results.

This packet owns navigation and visibility only. It does not prove capture
scene fidelity, destination identity, Photos or Share outcome, permission or
system UIKit retirement, old launcher weak death, host-original retirement,
independent witness, paired cleanup or whole Feature 11 completion. All remain
explicit obligations; no capability or installed-adapter configuration changes
are included.

The final explicit selection passes 32 host cases in 60.244 seconds: 13 page
owner cases, one launcher codec case, eight existing normal-input cases and
ten existing capture/recovery cases. It includes normal open, actual existing
capture ownership, original decoded PNG bytes, child file cleanup, Home root
recreation, restored observed page index and closed visibility. Lost Home/page
returns keep once-only input responsibility. Native compilation, device and
real whole-call timing remain unqualified.

Shared reconciliation includes the passive properties in
`interface/resources/qml/hifi/tablet/TabletHome.qml`, the iOS normal-control
sampler/token/press recheck, and the optional Python launcher codec. The QML
uses the existing `Snapshot.featureObservationEnabled()` build/runtime gate;
no product route or setter changes. Reconcile the six existing page/launcher
registry entries alongside the other platform union, including the explicit
Page owner/observation version-2 choice and retained version-1 reads. The two
separate Combined frame/original entries remain version 1.

The separate Combined Page component is described in
[the combined work handoff](SNAPSHOT_COMBINED_WORK.md). It retains the same
ordinary launcher/input and restoration paths and does not imply a matching
Photos2/Share2 return archive or frontend Combined HTTP consumer. Its closed
versioned joins must be reconciled separately; no feature capability is enabled.
