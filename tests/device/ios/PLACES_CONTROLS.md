# Original iOS Places controls, version 2

This is a component of the pending Worlds/navigation adapter. It does not
advertise a feature capability or prove arrival, saved bookmarks, directory
consumption, process replacement or quiet cleanup. Scripts, Authentication and
Graphics remain the three complete source-level areas.

The actual iOS selector profile retains the shared touch startup. Its selected
`scripts/+android_phoneInterface/defaultScripts.js` includes `places.js` in the
same engine and sets the presentation flag that selects `PicoPlaces.qml`.
PlatformInfo's `has3DHTML` alone is not an iOS selector. The native survey checks
the actual `places.home` semantic screen, QML root/context and canonical source
suffix. On iOS, file sources must lie inside the running app directory; qrc
sources are accepted. A similarly named HTTP page cannot supply these controls.

`NormalPlacesControls.h` only reads actual QML items. Original delegate
`placeId`/address and bookmark name/address determine opaque row identities.
Each live root has a weakly held UUID; root destruction or row replacement cannot
recycle an earlier field token. The anonymous bookmark Cancel uses its actual
original dialog footer and attached `RejectRole` enum. No translated label,
synthetic object name, requested bookmark or inferred row index selects it.
The dialog and typed fields must be known before the source is admitted.

The iOS survey writes `placesControlsVersion: 2` and an actual monotonically
advancing `placesSourceSequence`. The existing input sequence remains separate.
Python preserves the original native epoch and elapsed time; historical packets
do not become new observations through a wrapper. Original native geometry is
validated by the existing input reader before projection.

`IOSPlacesIO` supplies normal pointer activation and replacement of an already
focused search/bookmark/server field. It uses the existing iOS HTTP/AFC/Qt event seam.
Every input retains the caller's original root, process, field token and input
sequence. A fresh source read must advance the observation sequence without
replacing that reference. C++ checks the original item token and its live source
again before ordinary pointer/IME delivery. Ignored input ACKs remain ACKs; actual
text is read separately. No lookup, bookmark, setting or model setter is added.
The legacy Back/Forward aliases on another page remain component controls and
cannot borrow the new Places profile.

Version 2 uses `qt-places-qml-v2` and adds actual server URL/add inputs, original
Fetch/Pin checkboxes and actual maturity-filter popup checkboxes. Server row IDs
hash the actual original URL; the actual model index is retained separately,
never guessed from its current position. Checkbox state, original popup scope,
root, field text/focus and actual geometry enter the native source digest used
for the input token. The Qt input store consistently retains that digest as a
QString; JSON metadata is separately projected. This also corrects the previous
uncompiled Places-only JSON/QString type mismatch. Native compilation remains
unverified, so this source review is not a compile result.

Only the actual foreground bookmark or rating popup can admit its corresponding
controls. Unknown/multiple popups fail source discovery; background controls
cannot borrow their eligibility. Checkbox ACKs remain separate from fresh
observed checked values and [loaded preferences](PLACES_PREFERENCES.md). Server
text replacement accepts only a bounded credential-free origin or an empty
field; arbitrary paths, queries and credentials fail before delivery. Existing
ordinary Qt pointer/IME events perform every accepted input. No setter, QML
handler call, synthetic desired checkbox value or popup-close shortcut is added.

The reader still accepts original v1 snapshots and their v1 profile. It rejects
mixed profiles, new controls under v1 and old references replaced by v2 rows.
The control envelope/input-sequence contract is unchanged. Reconcile the
`ios-places-controls` registry writer 2/readers 1,2 with the shared branch union.

Host counterexamples cover changed rows/roots/tokens, modal background controls,
foreign QML sources, stale/retimed packets, another accepted input, changed focus,
ignored ACKs and root replacement at delivery. Native code is uncompiled and
devices are untested. These simulations qualify component logic only.

The passive [bookmark source](LOCATION_BOOKMARKS.md) now supplies independent
loaded entries and original persistence bytes. The [model source](PLACES_MODEL.md)
separately reads the actual lists, typed loaded preferences and retained QML queues.
The [XHR source](PLACES_HTTP.md) separately joins actual response consumption and
materialization. The full area still needs their whole-journey owner, actual arrival/pose/images,
an independent publisher, restart and retained-callback/quiet retirement. The
existing named-lookup error reply reader and server delivery receipts cannot
substitute for those sources. No full Worlds operation is admitted by this work.
