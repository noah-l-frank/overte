# Snapshot Share original history

`IOSSnapshotShareOwner.history` reopens the existing Share owner and its exact
original transfer and retirement packets without constructing an SDK, native
source, fixture client or foreground context. Its two actual source locks must
remain held. The caller supplies the original bindings, run, fixture URL,
configured system selectors, primary bundle ID and selected Archive IPA.
These are admission inputs, not inferred from the requested result.

The reader preserves the existing literal owner envelope and source profiles.
It independently reopens the Archive admission and original extension-query
journals, validates the selected IPA forest, and joins the retained action,
receiver, capture, import, bounded chunk and conditional run-retirement
originals through the same strict readers used by the live owner. Original
file bytes, private inode identities and original sample clocks remain intact.
An unexpected source file, substituted binding/run/selector/bundle or same-byte
inode replacement is rejected. Replay still checks both held locks, the owner
compare-and-swap value and the original admission and query journal.

Read-only instances reject normal open/cancel/select/cleanup entrypoints and
source acquisition or state-writing helpers before live use. Retained proof
methods remain available. This makes the existing transfer and two-run
retirement evidence readable after the live processes end; it does not itself
terminate a process or discharge native source-journal responsibility.

The complete Snapshot capability remains closed, and the source-complete count
remains 5/14. The actual Archive admission singleton still owns its retained
bundle descriptor, and six global chunk/admission/retirement output files remain
outside the already retired run roots. Their first identities, actual close
results, once-only conditional deletion and independent absence windows are
the next source-retirement integration work. Upload/Actor and complete outer
journey requirements also remain open. Native companion source is uncompiled
and the repository process plugin is uninstalled.

## Host validation

The final negative selection passed one case in 5.450 seconds
(`share-history-resume-20261026-02.log`), including wrong run, primary bundle,
both process bindings and configured selector, undeclared source census and
same-byte original inode replacement. Failed reads preserve every original
byte, inode and sample clock. The existing reader also rejects the replaced
file on its next proof read.

The completed transfer and two-run retirement replay case passed in 13.162
seconds (`share-history-resume-20261026-03.log`). Once its originals existed,
all SDK, Node, context construction and private journal writes were forbidden;
both original proofs still matched, and all seven normal mutation entrypoints
were refused without modifying state or files. The transfer/quiet fixtures use
real host files and Node clocks with explicitly modeled native/OS producers.

Three existing ordinary cancellation/recovery cases and all three installed
factory cases passed in 17.462 seconds
(`share-history-resume-20261026-04.log`). The source packet changes neither the
literal envelope nor any registry version. No build, compiler, device,
installation, laboratory, service or remote operation was used.
