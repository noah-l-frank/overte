# Emote image slot ownership

Active Emote samples now use the same original slot-authority predicate as the
original restoration-frame owner. A native capture's first inspection must have
proved that this request's slot was empty. A preexisting occupied or unknown
slot grants no authority to capture, release, drain or recover that resource.

The guard applies to capture's failure cleanup, explicit sample drainage,
interrupted sample recovery, retained partial PNG validation and historical
successful sample validation. An unqualified slot remains unresolved with its
actual private metadata and inode responsibility. It is never turned into an
abandoned-success receipt by releasing someone else's resource.

The transport/owner/sample DTOs and versions remain unchanged. The original
protocol already required the proven-empty initial inspection before writing a
read intent. Reservations that have not created a native owner retain their
existing once-release tombstone and unknown-release inspection rules.

Twenty-nine host checks cover active samples, sample recovery and original
restoration ownership. The new occupied-slot counterexample observes only the
initial inspection: no native read or release occurs through capture failure,
explicit drain or attempted recovery, and the foreign request, pixels and
resource state remain unchanged. Native compilation and device execution remain
unperformed.

## Explicit callback-pending sample profile

The separate `IOSEmoteCallbackSamples` profile writes Sample/Image version 3.
It can return an original completed PNG after once-only release when a fresh
inspection shows that only the original callback ticket remains. Its receipt
retains that responsibility; it does not prove resource absence. Every new
capture first inspects the preceding owner, and a retained callback blocks a
new slot or nonce. Quiet and end still require actual callback drainage.
Default Sample/Image readers keep their literal version-one/two grammar and
cannot adopt version-three journals.

Six pending-release owner cases, nine shared Frame/Trace/Window context cases
and six connected sample cases pass, alongside the twelve original owner and
twelve original sample/image cases. The connected sample selection retains 32
files in six roots and 102 original producer returns. Its host producers select
the actual shared callback context before capture; native, GPU and SDK behavior
remain modeled. Observer/recovery integration, public activation and complete
Emote retirement remain open.

## Explicit callback-aware consumer and lost-read recovery

The private Feature4 consumer selects Sample3, Image3, Observer3 and Recovery2
explicitly. The normal consumers keep their literal versions. An actual pending
callback is exposed through the existing `connection:emote-native-callbacks`
resource grammar. A historical pending original keeps that fact even after its
real token later drains; only a new independent image and fresh owner inspection
can establish an empty current resource list. Rewriting an old receipt cannot.

Lost passive reads retain the original outer Sample3 and existing abandonment
frame. Recovery reopens that same owner without another PNG, input or source
acquisition. Typed pending exceptions unwind the existing source locks before
the readiness wait, including failures during preparation and abandonment.
No-image or retired observations remain closed until separate typed drainage
originals can support their absence claim. Canonical configuration does not
select this prospective consumer.

Eight connected host cases pass in 14.462 seconds, retaining 239 files and 75
original raw returns. Twenty-two existing selected regressions and the five
restored-peer cases also pass. Original process/thread/stream checks pass and

used two different clock origins; its failure remains retained. The corrected
producer selects one domain epoch before its first capture and rewrites no
original. Native, SDK, Rig, renderer and device execution remain unqualified.

## Immutable callback-drain originals

Explicit Observer4 can record a retired observation without an image only
after fresh owner inspection and the actual marker-scope quiet cut. It stores
the unchanged Samples3 envelope, scope snapshot and current released-owner
transcripts in immutable OriginalFrameStore carriers. The existing Observer
pending WAL owns every planned/opened/saved write. Compact references retain
the complete known prefix; no second owner journal is introduced. The original
pending Sample3 facts keep their historical callback duty.

Each drain must preserve the sample's actual capture and transcript prefix,
follow the original scope quiet cut and precede its same-process observation.
Original host spans retain the existing 1.5-second bound. Historical reads
reopen actual carriers and original PNGs, preserving byte/inode checks and
read membership. Unknown carriers, changed owner files, missing originals and
foreign or future cuts cannot clear resources. Partial opened writes remain
explicit unresolved responsibility; this slice does not adopt or erase them.

Nine connected host cases pass in 51.900 seconds, retaining 702 files and 100

to original restoration pixels, current key/IME facts and the existing scene

an empty callback list does not establish process or SDK retirement.

same original; an opened empty file, changed inode, unknown prefix or missing
