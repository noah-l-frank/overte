# Paired iOS Graphics finalization, 2026-10-22

`IOSGraphicsFinalization` composes original world/image restoration, one normal
final Stop, two independent process quiet windows and recoverable ownership
retirement. It runs **after** the shared journey's observable cleanup and actual
fixture retirement. It is separate from `feature.graphics.cleanup`, which must
remain observable and repeatable while the controlled scene and process exist.
The finalizer does not mark the journey successful or advertise a capability.
Graphics remains partial until its worker, private configuration and canonical
dispatch are integrated and verified with the full shared journey.

## Operation and original evidence

`step()` performs one primary or actor contribution under the existing stable
source lock and existing SDK session. It returns `False` while another role or
a quiet window is required and `True` after exact metadata retirement. A step
has a 60-second ceiling; nested source acquisition retains its original 1500 ms
bounds. No session, target, installation, simulator or laboratory is started.

| Phase | Ordinary input / independently acquired originals | Required boundary |
| --- | --- | --- |
| Restoring | Existing preference cleanup and normal world/camera restoration | Measured original settings, world/avatar/camera and closed owned UI |
| Restored | Each role releases its current sampler, retires uncertain POST responsibility, observes original Web/scene lifetime and captures its own original restored-world Vulkan PNG | Both role snapshots, source floors, actual recorded view and original resource counts |
| Stop issued | A final native/subject/load/UI clock fence and actual installed-code/process admission precede one canonical `app.stop` | Durable intent before delivery; no retry after unknown delivery/result |
| Stopped | Each role reads its own new original numeric-PID/OS observations | At least three observations and three seconds on all four original clocks |
| Retiring | Exact frozen original metadata, original file bytes and both fresh process windows | CAS removal of known files only, with immutable recovery originals |
| Receipt | Pure validation of original records and retained PNGs after removal | Historical completion only; no new current product fact or timestamp |

Both roles must contribute before Stop. Primary values, expected absence,
requested settings and input ACKs cannot fill an actor contribution. An old
active provider floor cannot revive the actually retired fixture. A merely
inactive resource provider is insufficient: the original phase journal must
also prove its authority retired, with the same complete ticket history.

The final live fence brackets newly acquired actual subject, committed scene
loads, generic Graphics controls and original tablet inventory with independent
native clocks. It requires the original world/camera/settings and absent owned
UI. The runtime Stop boundary revalidates the original per-role images and
lifetimes, candidate/session/process/source binding and this fence before normal
termination. It receives the exact already-held source-lock object; it does not
replace the lock or bypass canonical installed-code admission.

## Unknown input and actual resource retirement

The parent persists `stop-issued` before calling canonical Stop. After a lost
return it only obtains original OS observations. It never sends another
terminate or launches a process. Canonical retiring-state recovery can finish
only after actual absence. An ignored Stop or an ACK while the numeric PID
remains present leaves responsibility owned and cannot complete cleanup.

Pre-exit lifetime groups retain their actual `held` or `released` values. A
cached software image can therefore remain nonzero in the final archive. No
native query, zero resource inventory or foreground reconstruction is performed
after process exit. Native/GPU source factories are forbidden in the host
counterexamples after Stop; only the existing OS source and pure archives remain.
Stage 1 preserves the original world's old PID, the strict restart/old-PID-death
receipt, old role samples/lifetimes and current-process images separately.

An acquisition whose owner intent failed before any native capture remains an
explicit abandoned sample. Its retained original must have no capture or native
release and its artifact must actually be absent. It earns no image/observation
sequence and no invented GPU absence receipt. Allocated owners instead require
their own original release transcripts and later source sequences. Actual image
captures and POSTs are never replayed to replace missing outcomes.

## Original archives and exact metadata removal

Before Stop, all static role/stage samples, PNG/chunk owners, observer histories,
calibration, scene/preferences, background/restart and publication records are
validated and retained as exact immutable originals. Existing child validators
gain pure archive entrypoints where required; their wire contracts are unchanged.
Original file integrity includes private mode, owner, inode, size and SHA-256.
Partial files remain partial diagnostics; a hash does not turn them into images.

Original JSON files remain separate, hash-referenced artifacts. Manifest pages
contain at most 64 references; the parent's bounded payload contains page
references rather than nesting all compressed histories. The existing 48 KiB
packed-state and 64 KiB private-file limits remain unchanged. A 130-original
counterexample exercises multiple pages and a small parent reference payload.

Both process owners must finish their independent fresh windows. Metadata
serialization/file validation cannot make an old pair current. If the pair has
aged before the first removal, no metadata is removed: the parent returns to
the stopped phase and both roles acquire new originals. Once exact removal has
started, an interrupted CAS resumes from the same immutable verified cutoff;
the original quiet-window clocks and counts are not rewritten. The retired
candidate/session/source scope must still be admitted during recovery.

Only owner-declared runtime paths may be retired. A directory scan rejects
additional responsibility; it never supplies a broad deletion list. Every
present file must still equal its retained original. The main feature owner is
removed last, followed by the retirement plan after the immutable receipt is
committed. Native PNGs and diagnostic originals remain private and unchanged.
Unknown metadata, changed scope, foreign roles even with recomputed hashes and
modified image bytes fail closed. The separate canonical installed-code binding
is preserved for ordinary session teardown and OS-source admission.

A completed receipt is a historical ownership result, not a fresh native/OS
sample. Pure revalidation after metadata removal uses original copies and
actual retained files, with an explicitly unusable HTTP client and no SDK/source
factory. It cannot mint a new image, current absence or input outcome.

## Verification and remaining integration

Host cases use real private files, loopback fixture requests and the actual
coordinator/runtime/parser implementations with synthetic native, GPU, UIKit,
driver and OS boundaries. They cover both roles, source-clock separation,
retained cache holders, lost/ignored Stop, ACK without absence, changed
candidate/role/PNG, never-allocated capture cancellation, stale pre-removal
evidence, partial metadata-removal recovery, manifest bounds and strict stage-1
provenance. Native code remains uncompiled and devices remain untested.

The final combined selection passes **63 no-build host cases** in 311.048
seconds across finalization (16), whole-operation coordination (8), calibration
(15), restart (15) and background/lifecycle (9). The separate sampler, retired
sample and owned-archive selection passes 31 cases in 35.338 seconds. All five
selected repository suites, the contract registry and whitespace checks pass.
These selections remain distinct from the earlier broad aggregate; they do not
claim device qualification or a new unrestricted aggregate pass.

The new registry entries are `ios-graphics-finalization`,
`ios-graphics-final-role`, `ios-graphics-final-original-reference`,
`ios-graphics-final-manifest`, `ios-graphics-final-receipt`,
`ios-graphics-final-file` and `ios-graphics-final-fence`, each version 1. Shared
journeys remain version 16. These iOS-specific additions require a registry
union during later Phone/Pico reconciliation; no parallel worktree is modified.

The worker must remain alive after fixture/retirement intent, contribute its own
restored image and process window, and exit only after the actual final receipt.
The existing Script/Authentication worker's early-exit behavior cannot substitute
for this protocol. Worker/configuration/canonical dispatch and a complete
fifteen-step journey followed by this finalization are the next required
integration packet. No complete Graphics capability is enabled by this file.
