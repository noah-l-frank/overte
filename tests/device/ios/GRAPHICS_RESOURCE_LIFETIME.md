# Durable original iOS Graphics resource lifetime

`graphics_lifetime.py` owns separate primary/actor and stage-0/stage-1 original
resource histories. The canonical runtime factory reuses its existing candidate,
session, process and source lock. It supplies no normal input, fixture mutation,
public feature state, resource reset or complete feature capability.

## Actual marker admission

The owner joins newly acquired original subject v3, scene-load and Web lifetime
v5 packets to an independent original native-clock acquisition. Fixture clocks
remain host clocks; original iOS epochs are unchanged. An entire group,
including source validation and persistence, has a 1500 ms ceiling. Native and
subject sequences belong to separate counters; they are never compared with
each other. Their actual source births, original clocks and per-source floors
are validated independently.

The actual marker entity must have the owned UUID, expected scene geometry and
an actual visible Web type. Its real `web-entity:<UUID>` native identity SHA-256
and original source URL select the lifetime contexts. The URL belongs to the
original scene ticket: the real page polls `/current` for later phase challenge
pixels. A current phase ticket is not substituted into that original URL.
Native view/grant/bitmap, actual Qt node/offscreen/upload, CPU/Vulkan, delegate
and snapshot-object ownership must have originally occurred. Required active
holders remain actually live. No fixture GET or requested setting supplies a
resource count or rendered effect. Independent original PNGs remain the
sampler/observer's responsibility.

## Retained originals and interruption

Version-1 private state stores per-source accepted floors, reference hashes,
active admissions and quiet windows. Each original group has its own immutable
version-1 record, with full candidate/process/run/role/stage/provider ownership.
A durable acquisition intent precedes the read. Source floors persist as they
are accepted, including incomplete acquisitions. Account, animation and recorded
voice histories retain their existing authoritative prefix checks during live
reconstruction and pure archive validation.

A record written before a lost owner update is adopted by its exact original
hash. This is historical ownership, never a fresh product sample. A lost passive
read without a record becomes an explicit abandoned record retaining its
accepted original floors. A later query uses a new nonce. No ordinary input or
resource-creating capture is replayed. Unknown/corrupted original files, foreign
roles/PIDs, changing source births or rewritten prefixes fail closed.

Historical validation has no live SDK or source factory. It can read the
original private records or receive an exact ordinal-to-original mapping from a
parent's immutable evidence archives. The latter permits validation after
metadata files retire; missing/extra/changed originals cannot fill a reference.
The owner does not itself delete metadata or declare the feature finalized.

## Original world and complete quiet

Release requires actual fixture retirement, the original restored world/avatar/
camera, no owned subject entities and committed scene work. Fixture retirement
or entity disappearance alone cannot retire held native resources. Every traced
callback and native/software/GPU holder must actually drain, including contexts
created after the original admission.

Every invocation starts a new complete three-second quiet window under the
existing 20-second/81-read bound. It begins after the first complete original
absence acquisition. The last acquisition must begin at least three seconds
later according to original native epochs, host UTC and monotonic time. Initial
observation latency is excluded. Any new resource/callback creation/retirement,
scene-load activity or actual lifecycle counter change resets the window, even
if it happens entirely between two zero-pending samples. Interrupted windows
and their originals remain durable; their elapsed time cannot be reused by a
later invocation. Immutable record intents bind each group to its actual window.

After restart, the original world retains its original PID and source birth.
Stage 1 requires the strict existing candidate/session/target-preserving restart
receipt, original lifecycle increments, actual old-PID `ESRCH` and exact owner
file scope. The old lifetime archive retains its original pending counts and
cannot be relabelled as a new-process zero inventory. The parent still needs to
compose both role/stage archives and their independent process-death evidence.

## Validation and remaining composition

Targeted no-build cases use actual private files, normal iOS HTTP/AFC input
framing and loopback scene/provider responses. Native, Qt, GPU, OS and kernel
sources are synthetic. Counterexamples cover held resources, missing/foreign
marker sources, source replacement, lost request/record/state returns, partial
floor recovery, metadata intent failure, corrupted archives, current PID
replacement, old-window reuse, background activity, slow initial acquisition,
interrupted quiet polling and strict restart provenance. No builds, compilers,
devices or native functionality have been exercised.

The complete Graphics owner, actor worker lifecycle and publication recovery,
cleanup before a successful initial admission, final fresh resource/native
verification, paired archive/metadata retirement and the unchanged fifteen-step
shared journey remain to be composed. The three-second proof is retained
history; the parent must obtain fresh original absence again before final
metadata removal. This component does not advertise a full Graphics capability.

The image carriers also now compare actual image metadata before returning a
tracked wrapper. Device pixel ratio, DPI, offset, color space/table and absent
text metadata must remain identical. Unsupported metadata returns the original
image and invalidates source completeness, rather than changing product image
semantics or detaching away the original lifetime hook. Native code remains
uncompiled; physical timing and graphics behavior remain unqualified.

Validation for this packet: 68 selected no-build cases pass across lifetime,
original source-history and Web closure/resource parsing. The lifetime cases
include separate actor credentials/original queries, three coupled strict
restart cases, explicit abandoned passive requests, both lost-write outcomes,

The combined observer/effect/Vulkan-owner/sample/preference/scene/history/

## Partial-setup cancellation, owner and record version 2

`observe_aborted()` reads a complete original five-source ledger for a partial
or failed setup. It does not require the complete active marker, settled scene
or every GPU resource to have been created. Unknown passive reads preserve their
accepted floors and an explicit abandoned record; immutable committed records
can be adopted without another query. This audit is separate from `activeProofs`.
An already committed active admission cannot be reclassified after a lost return.
An audited cancellation cannot later become a positive active admission.

`wait_aborted(original, restart=...)` requires that actual audit, actual fixture
retirement, measured original world/avatar/camera restoration and all original
plus later Web/Qt/GPU callback/resource counts at zero. It uses the same newly
started three-second native/host/monotonic quiet window and activity-reset rules.
Version-5 native completeness and immutable context/history prefixes remain
mandatory even for an audit with no created contexts. A missing source, forgotten
context or retired fixture without original-world restoration cannot pass.
The normal `wait_released` still requires actual positive marker admission.
Neither API converts cancellation cleanup into feature success.

Owner/record v1 remains readable; no abort proof is invented during migration.
Original packets retain their actual PID, birth, nonce, clocks and contents.
Fourteen new no-build cancellation cases and the 26 existing resource cases pass,
including strict old-PID death and new-source evidence for failed stage-1 setup.
The full whole-owner failure/finalization composition remains in progress.
Native compilation and real devices remain unexecuted.

## Actual cached software-image boundary

Source inspection confirms that HTML Web entities return their surface to
`OffscreenQmlSurfaceCache`: `Application_Setup.cpp` pauses the surface, replaces
the Web loader URL with `about:blank` and returns the surface to the cache.
`OffscreenQmlSurfaceCache::release` retains that paused surface.
`SharedObject::pause` sets the pause flag; it does not clear the software image.
`RenderEventHandler` intentionally retains its paint allocation between renders.
The instrumentation conservatively preserves actual scope leases on that image.
Consequently, scene removal and a blank replacement must not be assumed to free
all retained software pixels. The synthetic SDK's immediate release model cannot
qualify this actual native cache behavior.

The full finalizer therefore still needs a process-retirement composition:
both roles observe actual original-world restoration before the owned stop,
then independently prove the old numeric PID absent and a fresh complete quiet
window before retiring its ownership. Original resource counters must retain
their pre-exit values; no fictional post-death zero packet is allowed. This is
adapter work, not authorization to change or clear product caches. The read-only DVT process source now has a v1 original numeric-PID observation
after stop (`process_plugin/README.md`); bundle absence alone remains
insufficient. Paired finalizer integration and fresh quiet-window ownership
remain unfinished.

The archived local RemoteXPC 5.15.3 API was read only as a source reference:
`Services.startDVTService` exposes `deviceInfo.isRunningPid`. No service, server,
device connection, installation or retired workstation laboratory was started.
Live Proxmox installation and device behavior remain unverified.


`observe_restored` now supplies one durable role-owned pre-stop group, preserving
actual retained cache holders. It never claims a completed native quiet window.
The separate [process-retirement owner](PROCESS_RETIREMENT.md) supplies new
numeric-PID/OS reads and independent four-clock quiet windows after stop. Their
whole-run finalizer and actor handoff remain pending; neither API advertises a
complete Graphics capability.
