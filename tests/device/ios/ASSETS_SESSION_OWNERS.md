# Assets successor ownership at installed session boundaries

`assets_session_owners` inspects private original ownership before canonical
installed `describe`, `invoke`, component teardown and session cleanup. The
inspection is historical and read-only: it creates no source lock, SDK session,
candidate query, native clock/read, input, fresh product fact or retirement.
Existing owner decoders validate the original file/picker/reply records and
immutable upload frames using transport-free codec contexts. Unknown ownership,
orphan originals, changed tokens, corrupt originals and incomplete phases fail
closed. No owner file is removed.

The successful-upload owner is an explicit successor to the original picker
preparation. Its file-owner token, page and picker identities must match. The
original picker remains in its truthful `primary-chosen` phase; the successor
owns the later input and actual root/client retirement proof. It is not
rewritten as the old unavailable-file workflow's `retired` phase.

The later [mapping-tree owner](ASSETS_MAPPING_TREE.md) has its own WAL referencing
the same original upload frames. Historical inspection validates that join and
keeps unfinished mapping actions owned. Confirmed mapping deletion plus client
root death still retains `server-retirement`; the tree WAL cannot qualify stored
blob, meta, worker or oven absence.

The separate [backend successor](ASSETS_BACKEND_RESTORATION.md) now records its
own immutable source segments. Historical inspection validates its exact same
run/role/binding, file-owner token, page and picker. Complete original backend
map/hidden/meta/blob restoration plus task/queue/weak drainage and independent
native/host quiet can release the same upload's server responsibility. The old
picker record is unchanged. Backend-only admission, partial originals, unknown
queries and a client-retired upload without that complete backend successor
still retain `server-retirement` and block installed/session effects or teardown.
Local file absence, closed read leases and callback expiry cannot discharge
server work. Fully decoded retired negative-picker or read-only ownership can
remain as historical evidence without blocking ordinary cleanup; neither owner
adopts or deletes pre-existing server data.

This guard precedes feature-specific teardown and preserves the existing rooted
Emote gate ahead of generic scans and SDK fallback. It enables no Assets area or
public capability. The explicit narrow runtime owners remain responsible for
recovering their own original resources; the guard cannot replace missing
server cleanup with process termination.
