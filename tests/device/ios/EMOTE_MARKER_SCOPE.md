# Owned Emote marker setup and retirement

`IOSEmoteMarkerScope` preserves the actual connected Domain and AvatarMixer.
Its ordinary Script manager/file picker loads an explicitly reserved private
bundle containing only a local Web marker and its companion module. Exact
submitted UTF-16 code, original assigned manager, actual returned entity UUID,
complete scene inventory, ordinary View controls and original native clocks
establish setup. A separate Web callback source establishes actual resource
creation. Setup never asserts an Emote, replicated motion or rendered pixels.

Each passive read retains its actually returned World, Script terminal, dialog,
Web, UI, work and clock originals in private immutable files. An interrupted
read keeps its original owner and opened file identity, including empty or
partial bytes. Recovery relinquishes only that passive acquisition; a distinct
future read must extend every returned prefix. It never replays input, completes
missing native facts or deletes these original records.

Normal input is journaled before delivery. Uncertain Stop, Home, file selection,
view restoration and native file release are resolved using their actual source
effects when available. They are not sent a second time. The owner closes only
its own picker/Script roots, restores the original camera view and body context,
then requires complete source/entity absence and original terminal receipts.
It checks every observed Web callback/resource lifetime and actual UI absence
in a fresh quiet window of at least three seconds before releasing owned input
files. The quiet interval excludes both boundary acquisitions and requires both
host monotonic time and the same original native World clock to exceed three
seconds. Repeated cleanup preserves original native histories and sends no input.

Partial setup is explicit. An ignored confirmation is cancelled through the
normal picker and needs the original returned Application dialog callback;
destroyed QML/listeners alone cannot prove a queued callback drained. Every
cleanup path requires both the actual returned callback and original listener
destruction; loaded callbacks must identify the actual admitted manager. A submitted
Script that never painted still owns its actual worker and scene effects. A
Script that ended before cleanup needs its original pre-load worker birth,
submitted bytes, shutdown-drained receipt and independent actual thread-finished
receipt. It receives no new Stop. Missing receipts leave ownership retained.

`archive(..., require_ready=True)` reads only immutable original files and the
retained owner envelope. It neither creates an SDK nor invokes a live guard.
`bind_image_world` joins each actual image's World geometry to the admitted
Script's exact marker and original body context. Historical admission remains
readable after native fixture-file retirement. Image pixels and the independent
peer remain separate requirements of the whole Emote observer.

The scope (`ios-emote-marker-scope`), partial execution
(`ios-emote-marker-partial`), read recovery (`ios-emote-marker-recovery`) and
abandoned read (`ios-emote-marker-abandoned-read`) contracts write/read version 1.

Host tests execute the actual staged JavaScript/companion bytes in an isolated
Node VM and use the real ordinary Script manager/file-picker recipes and private
file owners. Native UI, worker, Web, renderer and SDK responses are modeled.
Native C++ remains uncompiled; no device, simulator, lab or build was used.
The complete Emote act/observe/cleanup capability is not advertised by this
prerequisite and remains unfinished.
