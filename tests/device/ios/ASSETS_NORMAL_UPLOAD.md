# Ordinary Assets bundle upload and independent readback

This is a partial source vertical. The normal bundle review, primary choice and
destination confirmation now connect to the existing client-upload lifetime and
independent server-read owners. No native code was compiled or executed on iOS;
no actual AssetServer, oven, installed candidate or device was exercised. Whole
Assets admission remains closed.

`IOSAssetBundleControls` observes the actual canonical QML picker/page roots,
original `FileDialogHelper.documentBundle` values, real ComboBox selection and
the existing Dialog standard buttons. Guarded passive QML getters expose those
existing button/editor objects. They change no handler or product behavior.
Native input uses rendered pointer events, focused field replacement and
Home/Down/Return key events for the actual primary choice. No adapter invokes a
QML handler or `Assets.uploadBundle` as input. The original QML invokes its
normal service after the actual destination button is pressed.

The new control metadata is version 2; version 1 remains readable with its
literal grammar. The separate bundle inventory is version 1 and joins the
existing version 1 weak-root inventory. Tokens bind the actual manifest,
root/window/dialog identities, selected index and destination editor text.
Changing that text between reference and final capture invalidates acceptance
before delivery. The extension cannot replace the old weak-root source.

`OwnedAssetsUpload` is a separate durable successor to the existing picker
preparation. It retains that original file-owner token and page/picker IDs; it
does not relabel the old unavailable-file owner's phase. It chooses actual
companion and folder rows, checks the real complete review, selects the real
primary and enters only the owned destination. Each input command is written
before delivery. A receipt alone never resolves an input: a later original
source must show its exact effect. Unknown deliveries are observed without
another upload or repeated release. Ignored input can be abandoned only after
actual owned root death and verified client cleanup.

Full original native-clock DTOs, clock/UI queries, UI replies and independent
host acquisition brackets are retained in immutable private frames. Every
historical frame is reopened through its exact inode, bounded, hashed and read.
An identical already validated digest may reuse its semantic decode; a fresh or
restored digest receives complete grammar and native-history checks. Neither
live candidate/clock guards nor fresh nonce-bound reads are reused. Interrupted
frame capture remains owned; recovery can read an exact completed frame and
cannot resend its unknown query or silently replace a partial original.

Before acceptance, an independent GetAll reply must show the owned destination
empty. Completion requires original current page state plus new actual client
bundle/upload holders for the selected file paths. Their terminal callback
entry/return and weak expiry must drain. These client facts remain separate
from the existing GetAll/GetMapping/GetInfo/bounded GetAsset chain, which reads
actual independently serialized hashes and bytes. The returned bundle is
reconstructed from those original read proofs, including during owner restore.
It supplies no model, rendering or oven result.

`IOSAssetsRuntime._assets_upload_readback` composes existing file/picker owners,
the successor and the independent reply owner. Failure attempts ordinary
client cleanup and preserves the identical primary exception object; secondary
cleanup failure remains private in `runtime.cleanup_errors`. Exact unresolved
commands and resources remain in the WAL.

Client cleanup closes actual owned dialogs/pages, observes weak root death and
at least three contiguous seconds of quiet on both original native clocks and
independent host acquisition brackets. It retires read leases and releases only
the sealed original staged input files, observing actual private root absence.
Server mappings remain present. This is deliberately not namespace/blob/oven
cleanup or a whole Assets completion. Installed cleanup must retain this server
responsibility and the successor relationship until a later qualified owner
establishes full retirement.

## Host validation

The host fixture executes original QML JavaScript with real temporary input
files. Its declared Qt/native/clock/client/server boundaries are models. The
modeled upload service reads the selected actual files; independent binary
GetAll/GetInfo/GetAsset replies read a separately maintained publication store.
The adapter supplies neither returned rows nor returned bytes. Client holds
use actual Python weak references. No socket or compiler is used.

There are eighteen new cases: twelve upload-owner cases, three runtime
orchestration cases and three bundle-control grammar cases. Focused selections
cover success, ignored input, lost acceptance/release returns, pre-existing
destination rejection, external destination edits, actual weak holds, corrupted
or rehashed foreign originals, restore, live guard loss and fresh clock nonce
failure. They also check original-error preservation after successful cleanup
and after a secondary guard failure. The orchestration tests declare their
factory boundary; separate canonical factory tests retain the real existing
session, HTTP/AFC and candidate checks.

- The initial combined 26-case run passed 24 cases and exposed two identical
  constructor-restore failures; both were fixed without repeating input.
- The subsequent focused 17 cases passed in 54.133 seconds, including both
  repaired restores, history/guard counterexamples and ten factory regressions.
- Four runtime/fresh-clock cases passed in 62.965 seconds.
- After binding destination text into tokens, the final five-case selection
  passed in 49.682 seconds, including external-edit rejection and the complete
  ordinary runtime upload/readback/client-retirement path.
- The twelve existing picker and six original-QML cases passed in the combined
  selection. The earlier slow first attempt was interrupted after one passing
  case to remove measured duplicate historical decoding.

The private logs are under `.ios-host-tmp/`; they are not device results or
publication artifacts. Native acquisition and physical deadline qualification
remain outstanding. Further integration needs ordinary mapping-tree selection,
rename/delete/import, original server/blob/worker retirement, actual permission
ownership, independent Actor publication and loaded/rendered model sources.
