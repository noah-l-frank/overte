# Synchronous original Chat archive proof reuse

The symmetric Chat6/7 receipt dependency graph repeatedly validates the same
completed Send subgraphs while decoding one outer owner. An original read-only
profile of the retained33-file pair recorded871 frame reads in the peer archive.
The first full symmetric case timed out at180 seconds. The subsequent case

No20-second,1.5-second or180-second budget has been increased.

`chat_archive_round.py` reuses only fully validated historical decoder results
inside one synchronous outer decode. The normal literal decoders establish the
proof first. Each key includes the actual WAL path and complete candidate value,
current owner memory, role/profile, full frontier/ticket and actual bounded
sender/receipt context. Fresh wrapper identities are normalized only for their
own original bound receiver and literal archive guard code. Active keys are not
completed proofs; the original frontier recursion guard still runs before any
lookup. Returned trees are independent copies.

The round pins both original artifact directories and both actual lock/WAL
parents, with bounded inventories and every file's device, inode, mode, owner,
group, link count, size, mtime and ctime. Directory pins establish consistency,
never file membership. Actual typed original reads establish membership and are
propagated to the surrounding original-read scope on a proof hit. A dependency
outside those exact roots does not acquire membership through memoization; it
clears/disables the memo and retains the literal decoder for that entire round.
A dedicated real candidate-metadata-file counterexample proves this fallback.

Every hit preserves actual current candidate/bound callbacks, lock checks, WAL
reads, current memory and parser identities, including transitive imported
validator helpers. The exact existing bounded sender factory is required;
custom factories, owner/store/frame subclasses, instance-parser overrides or
substituted parser methods retain the literal path and disable any active
round's memo. Sanctioned temporary decoder `self.state` assignments
are tracked explicitly. Other in-memory changes invalidate the proof.

A query, save, input intent, evidence-storage intent or live capture cannot
cross an active round. The outer decoder always clears its memo in `finally`.
Only integer diagnostic hit/completion counts survive; no original, decoded
state or proof survives. No new wire version or result capability is created.
