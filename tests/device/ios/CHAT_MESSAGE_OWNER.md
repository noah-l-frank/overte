# Normal Chat Send and original local history

Feature 10 remains partial. The existing `IOSChatDraftOwner` and
`IOSChatDraftRuntime.draft_owner` continue the same input/observation journal;
no public operation, configuration or complete capability is enabled.
Owner/observation writers are version two with literal readers one and two.
Existing version-one journals remain version one and cannot admit new verbs.
The immutable frame/original carrier grammar stays version one.

Normal `select-channel` and `send` use the actual shared `TokenChatUI`/iOS
control path. Every primitive intent is durable before the native command.
The original native component generation, consumed input cursor, selected
channel and actual draft bind Send. An unchanged selected channel needs no
input. Lost or ignored delivery cannot invoke another click. No Return route,
peer send, setting write or history injection is added by this packet.

An empty editor or successful input acknowledgement cannot prove acceptance.
Fresh clock-bracketed normal controls and the separate native view must agree
on actual channel row counts, visible ListView rows and persisted
`ArmoredChat-Messages` events. No unowned row is admitted. Each append must join
exactly one actual owned Send with a consumed input, its original draft/channel,
the unchanged earlier event prefix and a genuine timestamp after the original
before-cut. Unexpected appends between operations, changed text, duplicates,
stale timestamps and model/storage disagreement remain unavailable. The
original configuration digest is preserved. UI model/history reads are local
acceptance; they carry no remote-delivery, sender or mixer claim.

Ordinary asynchronous acceptance may arrive after editor clearing. The owner
retains each original empty cut and waits using read-only acquisition under
the unchanged twenty-second operation budget and original 1.5-second source
brackets. It does not renew that budget or resend Send. A missing callback
leaves the action pending. Explicit failed-action cleanup retains failed
status and source responsibility.

Close/reopen preserves both measured channel histories and actual new page
generation. Close still needs three advancing quiet originals spanning three
seconds on host/native clocks. The retained messages are not called restored
or deleted. Initial admission still requires an absent page/editor/keyboard
and an empty private history; arbitrary prior private history is not adopted.
Normal history/settings restoration remains required for whole Chat cleanup.

`chat_session_owners` retains any partial, malformed, orphan or unknown
`ios-chat-` file before ordinary describe/invoke/cleanup/component cleanup.
The runtime writes the exact run/binding/artifact-root scope beside the session
before input or evidence acquisition, so external artifacts stay discoverable
after an operation-owner loss. Failed scope CAS cannot enter the input session.
There is no complete retirement permit yet; the marker is not automatically
removed after a local close. Historical ownership with both session marker and
operation metadata already missing is not globally reconstructed or scanned.
