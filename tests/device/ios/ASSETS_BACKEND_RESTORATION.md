# Ordinary mapping successor and backend restoration

This packet joins the ordinary Assets upload/tree successor to the separately
owned backend original source. Full Feature 13 stays closed, source count 5/14;
native instrumentation remains uncompiled and no device, server or oven ran.

`OwnedAssetsBackend` records the same run, installed candidate/session binding,
role, original file-owner token, page and picker as `OwnedAssetsUpload`. Its
private record contains a SHA of the narrow reader credential, never the raw
credential. Actual exported admission/query/observation/saved bytes are retained
through the closed `assets-backend-sources` segment profile. Individual original
frames retain the existing 1 MiB ceiling; the existing bounded segment protocol
preserves larger exports without re-encoding their native base64 bodies.

Each caller request has a saved owner intent before transport. Mutable owner
records and immutable original chunks share a directory fsync before the next
operation. Unknown Observe responses recover only through Poll of the same
native nonce. Completed originals retain their original acquisition bracket;
they do not become a fresh baseline after a busy sample. Busy baseline samples
remain retained while a new nonce acquires the next actual original. A partially
opened segment remains a visible unresolved owner; it is not overwritten,
resent, retimed or silently retired. Automatic completion of such partial
segment failures is not implemented by this packet.

An upload checkpoint reconciles actual backend server/domain UUIDs with the
independent binary readback target. Owned path/hash sets must agree exactly,
and retained backend original blobs must match the independently read upload
bytes and lengths. UI status, handler return and an upload receipt cannot
supply those facts. Backend clock stamps remain in their own native domain.

Restoration requires exact baseline mappings, hidden meta/baked entries and
foreign blob identities/bytes. All newly introduced unshared blobs must be gone;
baseline shared hashes survive unchanged. Unknown baseline bodies stay
unqualified. Both native work snapshots must report complete actual queues,
pools, task bodies, original shared owners and QObjects drained. Every task
needs an observed run entry and return; expired never-entered leases do not
establish an empty pool queue. Bake tasks additionally need an observed returned
original callback. Sticky `isBaking`, mapping absence or callback completion
alone cannot discharge a task.

Quiet proofs require at least three seconds independently in the backend native
monotonic clock and retained host read brackets. Job/event history must stay
identical across the quiet interval. Even a new job that has already returned
and died interrupts quiet. The predicates never delete or restore product data.

`IOSAssetsRuntime._assets_mapping_with_backend` acquires backend admission before
ordinary file staging/input, joins upload readback, executes the original normal
Browse/Rename/Delete route and retires its client roots/read leases/staged files.
Only then does it acquire independent backend restoration/quiet originals. The
original exception is preserved if failure cleanup also fails; secondary errors
remain private. The existing narrow mapping/upload APIs retain their scope.

Historical `assets_session_owners` recognizes the additional backend record and
all exact segment files without creating a live transport or native query.
Backend-only admission and partial originals retain `server-retirement`. Only
the same fully decoded upload successor plus complete restoration proof can
release that responsibility. The old picker record remains truthfully
`primary-chosen`; it is never relabeled retired by its successor.

The separate new-Bake predicate additionally requires a post-baseline actual
task/run/callback/weak chain, current successful original meta and readable
original and actual baked/redirect-target bytes. It does not establish model
loading, parsed geometry, textures, Add to World or independent rendering.
