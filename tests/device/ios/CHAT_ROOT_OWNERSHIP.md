# Original Chat QObject identity and weak lifetime

Feature 10 remains partial. The gated iOS `ChatViewObservation` writes native
view version three; other platform writers remain version two. Literal readers
one, two and three preserve their original fields. Native view three adds
`rootOwnership`, the private version-one Chat profile of the existing original
Qt-root ledger, and the visible UI's original `rootIdentity`.

The native complete walk observes actual Chat pages, editors, both aliased
QAbstractItemModels, the original ListView and its actual model. Current page
membership joins their observed identities, component source and actual
visibility. A visible view cannot select another hidden page; an absent view
cannot conceal a currently visible member. Component source identifies the
QML location, not loaded QML bytes. No model text or account/name data is added
by this source. The request still contains only its run and observation nonce.

The shared native ledger gains a Chat profile with QObject zeroing-weak
operands. Scripts and Login retain their exact version-one output, kind sets,
QQuickItem restriction and 16 KiB bound. Chat alone admits the actual model
QObjects and has a 64 KiB bound. All profiles retain at most 64 identities.
Both test startup flags and the original main thread remain required. There
are no destruction callbacks, strong QObject references, history purges,
setter calls or new product controls. The code is gated by
`OVERTE_E2E_FEATURE_TESTS && Q_OS_IOS` and remains uncompiled.

`firstObserved*` records observation time, not allocation. A page absent from
the current walk can remain alive in its original weak ledger. Hiding, closing,
detaching or rebuilding a page cannot erase its old identity or manufacture
weak expiry. A new object receives a new identity. Original weak-expiry
observation times are immutable; identity resurrection, changed source/PID,
reused sequence and forgotten prefixes fail. An unavailable or incomplete
walk cannot establish absence. Missing initial aliases mark that walk unready
rather than manufacturing model identities.

The existing native reader pins this root-source history as well as its parent
protocol/instance. The same Chat owner retains the complete original packet,
checks nested native acquisition times and restores that exact cursor on
reconstruction. Its unchanged owner/observation version three and frame/original
version one require no rewriting of earlier journals. Local null-history
restoration now accepts native view two or three with the same original
protocol and exact typed-value hash. Historical replay still queries nothing.

The connected normal Send, Erase, page rebuild and final-close case restores
the actual original modeled history while all cached page/editor/model/list
operands remain demonstrably alive. Its result therefore carries no native
resource-retirement authority; the session marker and original journals remain
owned. Only independently observed actual weak expiry can make
`weakly_absent` true for these observed objects. That predicate alone proves
no callback drainage, process/SDK end or completeness of the whole app heap.

Eight new source/reader/owner cases and the existing Chat, typed-value, Script
root and Login root cases pass together: 41 cases in 3.825 seconds. They use
real Python weak references, private files, locks, journals and decoders over
explicit Qt/native/keyboard/transport/clock models. They do not execute the C++
header, compile Qt/iOS or qualify a physical device. Loaded Script/QML byte
association, independent peer/mixer effects and full source/process/SDK
retirement remain required before complete Chat admission.
