# Rooted Emote component archive

`emote_rooted_archive.capture` selects the actual latest committed keyed
cleanup under both source locks. It retains the five current component
envelopes (native, restoration frames, rendered, keys and keyed), their actual
paths and the exact reference. It refuses pending or historical writers.
It does not copy a requested checkpoint or manufacture a public answer.

Archive version one selects the literal rooted version-two component readers.
Every referenced native, peer, Script, input, file and PNG original is decoded
again; no SDK, fixture, live guard or native transport is consulted. Role, run,
candidate/process bindings, roots, source locks, component paths and closed
schema tags remain mandatory. No legacy component is promoted to version two.

An explicit read-only historical mode accepts an exact retained prefix after
later cleanup records exist. Current writers retain their next-record orphan
checks. Historical owners cannot save, resolve, abandon or retain new records,
even if supplied with a writable metadata store. Neither mode changes an
original timestamp, reference, sequence or resource inventory.

models. This archive is a terminal integration component; the complete Emote
