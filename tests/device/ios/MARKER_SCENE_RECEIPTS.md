# Closed marker file and Qt original receipts

`OriginalMarkerFileReceipts` and `OriginalMarkerPointers` extract the existing
Emote v1 owners without changing Emote filenames, fields, raw native DTOs,
public facade methods or historical interpretation. Closed `avatar` and
`worldweb` profiles select their own namespaces and actual marker-byte factories.
World Web additionally validates its real pinned base-source identity. Profiles
cannot inject arbitrary validators, file factories or expected product state.

The file owner records actual four-file bytes or an independently observed
native absence packet. A release ACK cannot establish absence. The pointer owner
records actual Qt dispatch/contact/button/world-tap state. Its quiet predicate
requires actual startup, unchanged original dispatch history and a native plus
host interval around the independently sampled World window. An input release
ACK cannot establish callback drainage. All original and abandoned files remain
private, immutable and checked against their exact hashes.

New Avatar and World Web v1 profiles also durably admit every passive native
clock nonce before send and retain raw clock returns before interpretation.
Interrupted queries are abandoned without resend; their actual returned source
prefixes constrain later samples. Clock observations create no product input,
Script VM or GPU object. Emote v1 keeps its original wire: its old clock window
retained the completed native endpoints but could lose a passive intermediate
query prefix if interrupted before saving the window. This extraction neither
relabels that legacy envelope nor claims stronger legacy query ownership.

`avatar_scene_transports.owners` uses the actual unbound clock-source instance
for the clock window and the existing pointer factory. It makes a private copy
of the existing NativeScriptFiles transport with that same clock. The old
factory creates fresh hidden clock readers; wrapping only an outer bound native
reader would leave those extra queries outside the durable ledger. New profiles
therefore refuse outer bound native readers. Candidate/process guards and all
native file/pointer APIs remain unchanged.

Host coverage includes independent literal Emote v1 writers, actual private
0600 files, historical reads, legacy unknown-query and weak callback cases,
new Avatar/worldweb byte and namespace separation, passive clock ownership,
lost returns and actual runtime-factory clock sharing. Native/Qt production is
explicitly modeled; no native build or device result is claimed. These are scene
components. Account/provider retirement and full paired feature cleanup remain
separate obligations.

Avatar contracts write/read version 1: `ios-avatar-file-receipts`,
`ios-avatar-native-file-receipt`, `ios-avatar-abandoned-file-read`,
`ios-avatar-pointers`, `ios-avatar-pointer-receipt`,
`ios-avatar-pointer-original`, and `ios-avatar-pointer-abandoned`.
