# Retained model parser input and independent baked output

`AssetsParsedSources` and `OwnedAssetsParsedInput` add a closed observational
join after the existing normal rebake and actual Model adoption. They issue no
model input. Existing Model-source version 1 journals keep their literal
schemas, default read order and recovery behavior.

The separate source acquires original Create-before, Create-work, actual
Assets model-origin and Create-after frames inside the original native/host
clock join, then records the actual normal-UI frame. The whole trees must
agree; domain, process, session and actual adopted UUID remain bound to the
Model owner. The origin source supplies the accepted parser/Geometry lineage,
not a wanted entity or URL. Its own native history clock remains separate
from the outer read-channel and host clocks.

Every raw carrier is saved before parsing in the closed `assets-parsed-native`
profile. Exact logical frames use `assets-parsed-source`; the parent stores
only immutable references. Completed frames, interrupted attempts and original
queries retain the existing 32/8/24 bounds. No native body, packed-parent,
expanded-frame or raw-reference limit is enlarged. No legacy Model journal is
migrated into this profile.

The parent records the exact next source index before acquisition. A complete
saved source recovers across lost parent adoption without another getter. An
opened prefix remains exact owned bytes and blocks completion. A failed
read-only source attempt can be retained explicitly, then a new bracket uses
a fresh query nonce; the old attempt and raw observations are never retimed
or rebuilt. This does not repeat normal acceptance, baking or upload.
An interrupted child saved before a lost parent update is adopted only by its
exact original index. Dirty in-memory parent state and a prior orphan backend
slot are refused; neither can silently acquire a fresh meaning.

After saving the native source, the owner acquires a separate original backend
checkpoint. Its intent precedes dispatch; a lost return polls the same query.
The existing qualified rebake is revalidated from its original files. The
new checkpoint must retain the same actual owned server/domain, quiet work,
input mapping, current metadata and output mapping/hash. Actual readable output
bytes must equal the original native parser input byte for byte, with matching
SHA-256 and count. Current native domain and the normal acceptance's original
network admission must agree with that backend. Backend and app native clocks
are never equated.

The resulting `assetModelBakedInputProofVersion` records an observed parser
input on the actual created Model matching an independently read current
baked blob. It is not a rendered-pixel, actor, permission or acoustic verdict.
The private runtime factory creates no app/session, source query or feature
action. Pure inspection reopens original bytes/inodes, verifies exact frame
membership and performs no transport.

## Responsibility remains open

The original picker phase remains unchanged. Pending raw/logical work keeps
`parsed-source-write`; even a completed byte join keeps
`parsed-resource-retirement` and the existing model/server responsibilities.
The native origin source still reports `resourceRetirementAvailable=false`.
No resource/cache is cleared, worker behavior changed or weak lifetime inferred
from a loaded flag or file closure. Actual rendering, independent actor
consumption, model removal, complete cached texture/resource/decoder/GPU work
and quiet final restoration remain required. Full Assets capability stays
closed and source completion remains 5/14.

The cases use original QML normal controls and real private bytes/inodes,
immutable source files, export WALs and parent recovery. They reject foreign
parser bytes, unfinished native delivery, changed original inodes and incomplete
raw prefixes. Lost backend results retain the exact primary exception and poll
the same original; lost read-only origin returns preserve the old attempt
before a fresh query. Historical inspection adds no input or source query.

This component deliberately begins with a declared existing server FBX; it
does not claim a fresh upload. Server/oven, native parser, renderer and Model
tree are explicit boundary models. The modeled output is derived from the
original service input, not parsed by an actual FBX parser. The separate fresh
pinned FBX upload qualification remains documented in the reply-source packet.
No native compiler, device, server/oven/service, installation or remote write
executes here.
