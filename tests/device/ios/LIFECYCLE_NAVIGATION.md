# Original normal Lifecycle navigation

Feature 14 remains partial, with no complete capability advertised. This packet
adds ordinary navigation input ownership beside the existing field/Back owner,
editor history and world measurements. Native Qt additions are uncompiled and
no device or simulator execution is claimed.

The existing normal Qt survey carries a separate, version-one
`lifecycleNavigation` inventory for its actual HUD tablet button, Home, Close,
launcher page buttons, Create/Chat entries and Scripts entry/menu controls.
Existing feature rows keep their exact schemas. Each inventory row records the
actual control, window, containing HUD/tablet and nearest available QML context
through non-reused weak QObject identities, plus the original context URI and
current hit ownership. Dynamic HUD buttons use their actual inherited context;
no expected QML URI or caller locator is substituted. Unavailable context,
ambiguous controls and weak-identity capacity exhaustion close admission.

The native source token also tracks this context identity. Delivery rechecks
the current token, source and hit ownership, then sends one ordinary pointer
press/release through the existing `press` route. It never calls a QML handler
or sets tablet/editor state. The dedicated E2E path supports the normal HUD and
Close buttons alongside existing navigation. QObject key values are copied
before `press` refreshes its source map, avoiding references into that replaced
map. Outside the existing dedicated test gates, the added inventory/input path
is inactive.

A fourth closed passive normal-input profile, `lifecycle-navigation`, retains
the original reception and positive or negative return. Avatar, Snapshot and
field/Back Lifecycle profiles preserve their literal schemas. Shared event
validation has explicit profile-local query, command and root validators; it
cannot accept another profile's history. The probe consumes each query nonce
once and retains the native packet with the existing private atomic writer.

`LifecycleNavigationOwner` specializes the existing Snapshot one-send WAL and
immutable original proof store. It persists issued intent before HTTP, checks
the actual source again and refuses resending uncertain input. Recovery adopts
only its exact native reception/return, with unchanged clocks, commands and
source identities. The shared proof owner now explicitly binds the outer
packet's run and integer PID before recovery and historical replay as well as
checking the existing inner command/root/receipt. A positive inner receipt in
a foreign envelope cannot modify the retained WAL.

Canonical `_lifecycle_navigation_runtime` holds the existing installed Script
source lock and candidate/process gates. It opens no session or application.
Readers cannot escape that scope. The unbound adapter refuses it, and ordinary
session teardown also refuses orphan navigation proof files until full
Lifecycle cleanup exists.

The explicit compatibility selection passes 57 cases in 1.235 seconds, including
twelve navigation owner/runtime cases, existing Lifecycle input cases and
Snapshot, Chat, Launcher and original transport compatibility. Tests execute
the actual WAL, private files, HTTP/AFC codecs, canonical gates and probe JS in
Node; Qt source, OS and SDK boundaries are declared models. Counterexamples
cover lost or ignored input, foreign run/PID/profile, source replacement,
disabled/occluded controls and incomplete or mismatched membership. A positive
opening or Close receipt deliberately leaves modeled UI state unchanged; no
editor generation or navigation effect is inferred from delivery.
The additive inventory also accompanies the actual existing host Create and
Chat input flows without changing their row projections or independent effects.
