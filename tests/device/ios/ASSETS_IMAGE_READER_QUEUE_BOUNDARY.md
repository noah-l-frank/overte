# Optional ImageReader queue bridge source boundary

This separate native source bridge connects actual ImageReader Dispatch and
setImage entry observations to the optional exact-Qt6.11.1 MetaCall API. It is
uncompiled and unexecuted native source. It adds no external getter, Probe/AFC
route, host codec, registry tag or authority for a composed end check. Existing
ImageReader Source1, ModelOrigin History5 and their wires remain unchanged;
Source1 still reports queued attribution unavailable. Overall completion is
still5/14, with no promoted TextureRelease, native, device or whole result.

The required optional SDK artifact and private ABI constraints are described
in [the QtCore source boundary](ASSETS_QT_METACALL_BOUNDARY.md). An absent
CorePrivate target, unpatched header/marker, wrong Qt/API version or missing
actual runtime --testScript keeps the new source unavailable. The library only
links CorePrivate in the dedicated iOS feature-test configuration. No SDK is
modified or built by this packet.

The existing main-thread ImageReader construction path prepares observation
after Source1::created returns. Existing Source1 task/dispatch/receiver/resource
IDs and weak target are copied under Source1's mutex, which is released before
entering the bridge. Admission alone cannot produce a complete source record:
snapshot remains unavailable until an actual native Dispatch supplies its known
Source1 parent. New optional context-copy failures do not expand Source1
authority or change its wire. No new ID is invented to replace an original
Source1 parent. The actual Dispatch identity supplies the opaque Qt binding
words. Actual QObject method metadata must resolve the existing declared
setImage(gpu::TexturePointer,int,int); unknown metadata remains unavailable.

The actual indexed Qt invocation/event provides queued provenance. Its callback
validates event ID, actual invocation, weak receiver and method. A native
setImage entry can attach only its actual existing Source1 receiver ID to that
current actual event. FIFO order, a sole pending row, equal payload, URL/hash,
script-provided expected outcome or raw-pointer address never establishes the
association. No argument, payload, URL, content hash, GPU holder or texture
getter/operator is read. Registry references to product objects remain weak.

The bridge keeps original Qt UTC/steady-nanosecond phase clocks separate from
its native UTC/elapsed-millisecond clock. Queue delivery and argument-value
destruction may precede invokeMethod returning on its producer thread. It does
not invent a sequential order between those independent threads. Cancelled
events may have creation/destruction with no delivery or native receiver.
Normal return and exception unwind remain distinct. Nested unobserved events
gain no guessed association; duplicate receiver binding refuses.

There is no lock across product dispatch. Source1's mutex only copies context;
the bridge's separate mutex only updates bounded primitive/weak metadata.
Every Qt diagnostic API call occurs before or after these mutex scopes, and
the callback itself invokes no Qt diagnostic API, product code, event pumping,
queries or payload access. Entries are bounded to256; overflow and observer
failure latch process-long unavailability without reset or reuse of old good
receipts. A future strict reader must additionally join the actual complete
Source1 owner and preserved originals; this packet does not supply that reader.

The published diagnostic State uses an atomic shared_ptr slot. Each callback
and snapshot first obtains its own strong State pin before waiting for its
mutex. That State contains no strong Resource/GPU/task/receiver owner. The small
publication slot itself is retained for process lifetime so a late callback
cannot touch a destroyed global shared_ptr object. Actual State can be released.

Disarm first latches unavailable, atomically exchanges publication to null, then
calls Qt-disable without a Source1/bridge mutex or waiting drain. Running or
mutex-waiting callbacks retain their independent State pins until return;
later callbacks see null. The retired publication pin and callback/snapshot
pins release outside the mutex. State destruction occurs only after its last
pin. Snapshots recheck admission/API after copying, so disarm cannot publish an
older good complete prefix. Both actual application aboutToQuit and destroyed
signals install direct diagnostic disarm callbacks capturing no product owner.
Their native execution/ABI remains unverified.

The exact twelve host models passed: five Python thread/barrier/weak-State
lifetime and lock counterexamples plus seven bridge identity/gate/order/capacity
cases. All nine actual test/source inputs retained identical metadata and
SHA-256 before and after the selection. A separate read-only source projection
confirmed that removing the new dedicated-test blocks restores the previous
TextureCache.cpp bytes, preserves existing Source1 C++ tokens, and leaves only
the conditional CMake appendix. These checks do not compile or run the C++
bridge, Qt callback, or atomic shared_ptr ABI and establish no performance,
native, SDK, device, resource or whole-end result.

An actual Qt argument-values-destroyed phase concerns the original metatype
destruct/destroy loop and argument-buffer release only. Event/base allocation,
inline backing storage, independent byte copies, KTX, QRunnable/thread pools,
decoder, GPU and complete Resource retirement remain unavailable. Existing
Actor/backend/source/process/SDK end responsibilities remain open. Diagnostic
State pins establish safe observer storage lifetime, not product completion.
