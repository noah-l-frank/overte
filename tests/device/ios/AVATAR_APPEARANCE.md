# Historical Avatar appearance effects

`avatar_observation.source_history()` reads immutable SourceOwner2 originals and
its retained abandoned-source recovery journal without acquiring an SDK or
using a live guard. Every relevant abandoned source prefix and retired manager
remains authoritative. Individual appearance frames are rejoined to their
actual immutable manifest/file/inode rather than trusting a mutable Python
copy of native state.

`appearance()` derives seven fields: actual requested and loaded model identity,
loaded geometry/Rig, current original load failure, settled scale, genuine owned
wearable geometry/absence and the persisted owned bookmark. The original
baseline must be an actual loaded, visible, scale-one sample in the controlled
baseline phase. Controlled activation metadata only labels actually observed
native URLs as original/A/missing. An acknowledged A input cannot label a
foreign loaded resource as A. Missing model requires the actual failed immutable
resource assignment in the current native generation; fallback still requires
actual loaded default geometry, while unavailable requires actual mesh/scene
absence.

Owned wearable IDs come from this observer's independently read native
addEntity returns and independently reviewed submitted Avatar VM code. No
primary action acknowledgement, copied primary public state or claimed entity
ID supplies an effect. The complete Renderer inventory preserves unrelated
Avatar entities. Present owned wearables need actual loaded geometry and Hips
parenting; absence requires the complete actual Avatar entity map and tree.
The current unavailable-parent/Hips case must not reuse a vanished Rig as
current rendered geometry. Separate real peer reception remains mandatory.

The owned bookmark must match actual original persistence bytes and the
independently loaded map. Its first observed saved entry retains the actual
model URL/scale and remains unchanged until removal. Unrelated rows remain
unchanged. A genuinely missing initial persistence file can represent an empty
baseline; it is never silently described as an existing persisted empty file.
Whole cleanup still owns that original-file distinction.

`IOSAvatarActions.history()` separately validates exact retained recipe,
UIKit/Qt input receipt/reference and original returned UUID ownership. It runs
without a live SDK and cannot resume, acknowledge or replay an uncertain input.
The appearance decoder derives product fields independently of that recipe
reader. The new derived appearance contract `ios-avatar-appearance` writes and
reads version 1; SourceOwner2, native originals and input/action wire formats
remain unchanged.

Six new host tests exercise the eight full normal appearance recipes using
real owners, transports and immutable files with explicitly synthetic Qt/model/
VM/native producers. They cover current failure/fallback, actual wearable UUID,
bookmark restoring scale/removing wearable, full original restore/delete,
foreign loaded resource despite primary ACK, mismatched persisted bookmark,
changed native input reference, mutable in-memory results and abandoned source
birth reset. There was no native compilation, device, simulator or laboratory.

This is an appearance decoder prerequisite. Full nine-field social/peer/GPU
observation, ordinary observation surface ownership, publication and verified
whole cleanup remain unfinished. It advertises no complete feature capability.
