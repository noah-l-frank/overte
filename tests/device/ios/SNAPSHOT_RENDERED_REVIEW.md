# Original capture and visible Snapshot review

`IOSSnapshotReviewRuntime.rendered_review_owner` composes the existing combined
Page2 and completed Capture2 owners with a separate original WDA PNG owner.
This is an internal capture-stage component. It does not enable the complete
Snapshot capability or replace the existing normal operation path.

The dedicated native test inventory observes reachable `NativeSnapshotReview`
roots and their actual `QQuickImage` objects on the GUI thread. It records stable
weak identities, actual source/status/size, painted geometry, clipping,
transforms, window size and device pixel ratio. The local source must resolve to
the row's same canonical regular, non-symlink full file path. The private file
name is exposed only for the existing controlled Snapshot naming pattern. No
URL, object name or Ready status alone establishes rendered pixels. The new
QML object name is inactive without the existing feature observation gate;
native instrumentation requires all existing iOS E2E build gates.

The owner reopens the actual normal capture input, native completion, Script
callback/timer histories, manifests, chunk files and retained PNG artifact.
It takes two original Page observations around one independently stored WDA
screen PNG. All owners share the same held source lock, candidate/process/run,
fixture and actual SDK session. The capture must have completed before the
first UI sample. The same visible root, image object, source and unchanged
input cursor must occur on both sides. Actual screen native timestamps must
lie between those samples, within the unchanged 1500 ms limit.

The first profile accepts only opaque still PNGs, a full unoffset Qt window,
matching source dimensions/aspect and a preview of at least 128 physical pixels
per axis. It independently decodes both files and compares a fixed 128 by 128
sampling: maximum mean channel difference8 and at least95 percent of pixels
within24. Nonuniform source pixels are required. Other window mappings,
projections, animation, colour paths and platform rendering need separately
measured profiles; the caller cannot choose tolerances.

Before Page observations and screen acquisition, durable parent intents record
the exact existing child prefix. A lost parent CAS may adopt exactly one fully
saved, context-bound child tail after reopening its original files. Unknown
screen delivery leaves the planned/opened inode owned and cannot trigger
another screenshot. Unknown Page GETs follow only the existing Page recovery
policy. Final proof rereads original UI, capture and image bytes/inodes. No
screen, source, input or native clock is reissued by completed historical proof.
The component retains its host originals; it supplies no cleanup permission.

## Original OS resume and rendered review

`IOSSnapshotResumeRuntime.rendered_resume_owner` connects the existing completed
capture and capture-stage review to an original OS background/activation bridge,
new resumed Page observations and another independently retained WDA PNG. It
uses the existing installed candidate, SDK session and one held source lock.
It creates no session or launch. This is still an internal component; it does
not enable `feature.snapshots` or replace the existing normal operation route.

The explicit Resume Page3 has its own owner/frame namespace. Its prepare
operation requires the current `background-resume` ticket and cannot navigate,
capture or restore the original page. A separate segmented native-input owner
retains the complete original command/return history. The last actual command,
positive return, root and input instance must match the current UI cursor.
Older commands remain part of the same validated prefix; the cursor is not
incorrectly fixed to the earlier capture command before Save/Share/Upload.
The new profile does not widen the literal Page1/Page2 or input packet readers.
It retains the existing `iosSnapshotPageOwnerVersion` and observation field
names with value3. Its frame/original envelopes retain the combined Page
version-one wire fields under the distinct resumed file namespace; the registry
describes these separate profiles without inventing different wire keys.

The OS bridge reuses `LifecycleOSContext` and its actual process/source and
installed-code readers. Home and activation each have a durable intent before
their once-only send. Lost returns recover by original OS status, never another
Home, activation or launch. Background recovery constructs no native/UI source
and reads only OS continuity and saved originals. The same process and input
cursor must survive exactly one new native background/activation pair. A saved
complete Page original may finish its parent CAS under the current foreground
OS guard without another phase, UI, clock or WDA acquisition. Unknown or partial
original delivery remains unresolved.

After foreground admission, the rendered owner takes fresh Page observations
around a new WDA image and compares it with the same original captured PNG.
It preserves the capture review's fixed pixel/geometry/clock requirements and
also binds the new observations to the saved OS-after original. Another native
lifecycle transition between the OS bridge and rendered review is rejected.
The image profile uses a distinct `snapshot-resume-review` namespace and typed
owner; the capture-only historical reader cannot consume it. Completed proofs
reread original bytes and inode identities, and unknown screenshot delivery
cannot trigger another WDA request.

## Reopening the completed resume after live transport retirement

`SnapshotResumeBackground.archive` and
`SnapshotResumeRenderedReviewOwner.archive` reopen the completed original
OS/Page/input/image graph using its actual held source lock and an independently
admitted candidate bundle. They require completed journals and retain their
original process, run, fixture, clocks, file bytes and inode identities. Neither
reader constructs SDK/native/UI sources, acquires another observation, repeats
Home/activation nor writes ownership files. Historical mutation APIs refuse
before effects. Each proof checks its complete in-memory state against the saved
decoder, then derives its result again from the original child graph. This is
historical evidence; it provides no current foreground or freshness authority.

in14 actual temporary directories. They cover blocked live ports and writes,
