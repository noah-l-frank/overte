## Explicit runtime handoff after normal Return

`IOSSnapshotShareRuntime.page_return_owner` can now opt in to the existing
Photos End owner after normal page restoration. Its default `photos_end=None`
keeps the existing PageReturn behavior. The explicit request requires
`combined=True` and this exact profile:

```python
photos_end = {
    "profile": "combined-photos-return-v2",
    "photos": photos_descriptor,
    "domainPolicy": independently_selected_public_policy,
}
with runtime.page_return_owner(
    selector, run, client, archive_descriptor, system_ui,
    combined=True, photos_end=photos_end,
) as returned:
    restoration = returned.restore()
```

The Photos descriptor supplies the existing `client`, `sessionStore`, `target`,
`binding`, `artifactPath` and `admissionStore`. The Archive descriptor keeps
those same existing fields. No helper SDK, session, grant or source is created
by this handoff. Public domain policy must be independently selected before
the original journey; a result or owner header cannot supply that authority.
Only the profile is admitted before Return. The helper descriptors and policy
are validated after successful Return, before live End work.

The original input and two-lock Return scope finishes before the factory
acquires the three distinct existing Main/Photos/Archive locks in path order.
It reopens the complete literal Combined Result2 and closes its passive read
area before constructing `SnapshotPhotosEndOwner`. That existing owner keeps
its first-PID/source admission, exact SDK-slot identity, durable Stop/DELETE
intent, independent process quiet/GET404 and local pointer CAS requirements.
An exception in Return or its context exit propagates before automatic End.
A lost End return can be reopened through the same runtime's explicit
`photos_end_owner(..., profile="combined-photos-return-v2")`; an absent or
unknown direct-factory profile refuses before source/helper acquisition.
Missing-parent process responsibility remains a refusal, not an adoption.
