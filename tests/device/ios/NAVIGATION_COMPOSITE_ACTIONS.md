# Ordinary Places arrival and close

`NavigationCompositeActions` connects the existing normal Places recipe owner
and surface owner on the same candidate, run, lock and attached provider. It
handles actual `directory-select` and `bookmark-visit` calls. Bookmark visit
opens normally; both paths select the original observed row, acquire independent
native scene/pose and UI originals, then close the exact owned Places page.
The original public call/ticket/fixture phase remains unchanged throughout.

A recipe acknowledgment cannot authorize close. The native acquisition must
follow the actual selected input's original native clock/counter, preserve
process/source/lifecycle histories, show the committed controlled scene and
settled actual position, and retain the owned page root. Provider phase reads
bracket that acquisition. Close follows a newly acquired frame within its
original 1.5-second deadline and the composite's original 30-second deadline.
An ignored arrival retains the visible owned page and every original read.
`settle()` may acquire another frame; it never repeats the selection.

Every stage is journaled before child work. Uncertain opening, selection or close
blocks replay after reconstruction. `recover_arrival()` seals only a fully
retained lost read and sends no input; a later `settle()` still needs a new
original before close. `recover_close()` accepts only an existing retained child
close acknowledgment, with no additional reads or input. Partial acquisitions
remain owned. Duplicate delivered calls return only their old delivery result.
The original monotonic deadline survives reconstruction.

The candidate-qualified factory is
`IOSNavigationRuntime._navigation_composite_actions`. This coordinator leaves
its journal and child originals intact. The full Worlds owner still needs current
GPU/independent actor publication, missing-address closure, restart transfer,
static restoration, resource drainage and repeated quiet cleanup. No complete
Worlds capability is enabled here. Native compilation and devices remain
unverified.

Nine host coordinator tests cover original phase HTTP, actual private journals,
actual Python W3C surface inputs, and explicitly modeled Qt selection/world
sources. They cover ignored motion, old/foreign/lost sources, changed page/phase,
two consecutive composite journeys, original deadlines, and lost result
recovery. The existing original-token recipe tests remain separate. Fifty
combined coordinator/surface/missing/runtime/recipe tests pass; these establish
host adapter behavior only.
