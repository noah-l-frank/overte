# Original iOS missing-place dialog and lifetime, version 1

This is a component of Worlds/navigation, which remains partial. It provides
the actual native callback/modal/normal-OK/lifetime sources, but no whole owner,
arrival/images, independent publisher, restart or combined retirement. Native
code is uncompiled and devices are untested.

## Actual creation and original ownership

The existing AddressManager named-error observer retains the original current
request event with run extracted from its actual owned hidden-name URL, response
header ID, origin, status, network error, request generation and callback epoch.
Its new iOS-only `featureCurrentNavigationError` C++ getter returns that original
event only for the actual current active lookup generation. No requested run or
desired modal is supplied to this getter. The v1 named-reply packet is unchanged.

Under `OVERTE_E2E_FEATURE_TESTS`, `Q_OS_IOS` and `--testScript`, the existing
`AddressBarDialog::displayAddressNotFoundMessage` captures this context before
its unchanged normal `OffscreenUi::asyncCritical` call. It records the actual
returned ModalDialogListener, its actual dialog item and the original creator.
There is still exactly one normal creation call. No dialog, setting, navigation,
listener completion or cancellation setter is added. Unrelated errors receive
no ownership, and a second modal cannot borrow the same callback event.

One source lives in the UI library. Weak QPointers retain observed identities
without extending product lifetimes. The source records original creation,
actual response and independent dialog/listener/creator destruction signals.
It never schedules deletion or disconnects product callbacks. Bounds are 128
original creations, 512 events and 262,144 bytes; exhaustion, invalid clocks or
source ambiguity become unavailable rather than a successful empty history.

The source observes whichever real QML path normal creation selected:
`dialogs/MessageDialog.qml` or `dialogs/TabletMessageBox.qml`. File sources must
be inside the running application; qrc sources are accepted. Existing desktop/
tablet routing is unchanged. Failed creation remains an explicit original
creation record, including any live deferred listener. It cannot supply a
visible missing-place outcome.

## Observation, input and outcome

The existing private fixture/probe/Test/atomic JSON/AFC path accepts only
schemaVersion 1, an iOS nonce, action `feature-ios-navigation-dialogs` and run ID.
The fixed private filename is `feature-ios-navigation-dialogs.json`. Missing
hooks remain unavailable. The probe calls the hook once for the current nonce;
an uncertain query or input is never silently resent. Existing candidate/source
and SDK-session guards remain the whole owner's responsibility.

The packet preserves PID, source birth, advancing sample counter, immutable
native event history and original UTC/monotonic clocks. It includes current
original dialog text, QML source, visibility/window, buttons/icon/clicked button,
listener/creator liveness and creator visibility. Native Qt enum originals are
retained; Python does not guess the numeric OK button. Actual unrelated
registered modals are counted without exporting their contents or identities.
Separate nonce-bound native clock acquisitions bracket the read within 1.5
seconds; host monotonic time bounds transport only. Historical validation never
refreshes these originals or creates a source/session.

`owned_missing` requires an exact original current named-reply event, matching
native source instance/generation/PID/run/response ID, a genuine same-ticket
provider 404 receipt and the native-created visible matching modal. Native and
provider time barriers are separate. The original event must follow the native
barrier; the server receipt must follow its own server-clock barrier. Hidden,
missing, already-responded, old/foreign or ambiguous modals cannot pass. Server
delivery, a callback alone or a similarly worded popup is insufficient.

The normal input survey exposes only the original recorded dialog and its
actual original MessageDialogButton whose dialog pointer and button enum match
that native root. It does not use a translated OK label or a guessed role number.
It refuses a dialog with another registered unowned modal. After the actual
response signal, the dialog is no longer eligible even while deferred deletion
is pending. Root/callback/run/generation identity and original geometry/focus
enter the native source digest used for its token.

The host input join preserves the caller's original root/field token and native
input sequence. A new observation must advance its source counter within 1.5
native seconds; a changed modal or process cannot replace that reference. C++
resolves and checks it again before ordinary Qt pointer press/release through
the existing iOS input seam. No QML click handler, expected state or private
close method is invoked as automation input. An ACK is only input delivery.

`drained` requires explicit known owned dialog IDs and actual destruction of
both dialog and listener. A response or scheduled delete alone cannot pass.
For the normal dismiss checkpoint, `require_ok` additionally requires the
original actual OK response. Other destruction may retire known owned resources
during failed-run cleanup, but cannot prove the normal dismiss step. The creator
Go To dialog has separate normal closing and observation obligations. Historical
native error events are retained after dismissal; clearing the UI does not erase
or retime the request history.

The future whole adapter must additionally verify unchanged B arrival, absence
of owned Go To UI, three-second recovery/cleanup quiet windows and combined
QML/XHR/native/process/SDK retirement. No complete feature capability is admitted
by this component.

## Host checks and reconciliation

Twenty new tests execute the actual probe branch and existing Python HTTP/AFC
input/observation codecs, including a real loopback missing-name HTTP 404. Native
Qt creation/callbacks/SDK/process boundaries are modeled. Counterexamples cover
ignored and lost input results, replacement before/at delivery, missing/hidden/
foreign/retired same-text modals, stale or changed histories, failed creation,
retained dialog/listener, wrong response role and independently offset clocks.
These are source/test-logic checks, not native compilation or device acceptance.

Reconcile the new `ios-navigation-error-context`, `ios-navigation-dialogs`,
`ios-navigation-dialogs-acquisition` and `ios-navigation-dialog-controls` v1
registry entries, closed probe/fixture action and gated shared networking/UI
instrumentation with the Phone/Pico union. Existing named-error v1 and normal
input envelopes remain compatible. No protected or parallel branch is changed.
