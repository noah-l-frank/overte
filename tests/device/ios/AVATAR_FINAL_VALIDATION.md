# One historical Final traversal

`avatar_final.validation_round()` shares already decoded original components
only within one synchronous historical traversal. Live samplers keep their
existing full acquisition and durable query paths. No quiet verdict, public
state, source clock, publication or cleanup acknowledgement is cached.

Each key includes the complete original carrier and group bytes, bindings,
inputs, exact role/run/root/store, authority context and actual source-lock
objects. A cold group executes the full postlogout, Tail and pointer decoders.
Every reuse checks actual private file signatures and unchanged independent
directory inventories before and after returning its copied raw data. Typed
child owners must retain their original envelopes and exact context. A new
file, dangling symlink, changed bytes on the same inode, changed binding or
mutated child state fails closed. The successful traversal rechecks all entries
at exit. Nothing survives that traversal.

Original read membership is restored on every reuse. A distinct fresh collector
performs its own complete decode. Append-only component and native-prefix joins,
quiet derivation and final acquisition/API deadlines remain outside the reused
data. A slow durable save still fails the unchanged 1.5-second acquisition bound.
Legacy original formats and all serialized schemas remain unchanged.

The paired whole owner previously reconstructed the same final groups through
`archive.parse`, quiet checks, source joins and both Login lifetime traversals.
The controlled interrupted whole run spent its last stack in
`Final.group -> archives -> Tail.proof -> validate -> native clock queries`.
It is recorded as interrupted, never passed. The focused genuine-file case
measured the same three-row archive and two quiet derivations at 3.586 seconds
without reuse and 1.643 seconds within a checked traversal. Both use the exact
same original graph and issue no native queries. These host measurements do not
qualify a complete iOS journey, native compilation or real acquisition/API timing.
