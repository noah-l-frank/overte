# Owned Avatar marker setup and retirement

`IOSAvatarMarkerScope` loads an explicitly reserved private marker-only Script
bundle through the ordinary Script manager/file picker. The actual Domain and
AvatarMixer remain connected. Its exact submitted UTF-16 source, companion
module, actual assigned worker, newly observed local Web entity UUID and full scene
inventory establish ownership; ordinary View input supplies the camera. No
Avatar URL, scale, wearable, social result or rendered pixels are produced by
this helper. A fresh native Web resource inventory independently establishes
actual marker rendering resource creation.

The closed-profile `OriginalMarkerScope` and `OriginalMarkerRecovery` share only
input ownership, immutable original storage and cleanup mechanics. The Emote
facades preserve their original v1 envelopes, filenames, code bytes, native
World profile and public API. The Avatar facade uses its own namespaces,
`avatar-marker-v1` code/userData, strict AvatarWorld originals and widget source
generation. A caller cannot supply another component profile, expected entity
UUID, source result or target pose. These profiles cannot adopt each other's
original envelopes or staged files.

Every actually returned passive World, terminal, dialog, Web, widget, work and
native-clock packet is retained. An interrupted read keeps its original owner
and actual opened-file identity/bytes; a new passive acquisition must extend
all original prefixes. Normal input is journaled before delivery. Lost Stop,
Home, selection and native release are resolved only by actual source effects;
uncertain input is never sent again. Recovery does not invent a missing worker
birth or terminal receipt.

Cleanup restores the original camera/body, preserves the whole unowned scene,
closes owned Script/picker surfaces, and requires actual marker/worker absence.
Tree absence does not establish the original Entities.addEntity return or actual
entity weak-reference expiry. The whole-feature owner must additionally join
the separate original CreateEntities source (without relabeling its DTO) to
prove original returned UUID/birth and observed weak expiry.
It observes both shutdown-drained and independent thread-finished receipts,
the real returned Application dialog callback and listener destruction, plus
all traced Web resource/callback lifetime retirement. A window of at least
three seconds excludes both boundary acquisitions and independently spans
host monotonic time and the original native World clock. Only then are owned
native input files released. Partial setup retains submitted worker ownership;
an already ended worker receives no new Stop. Repeated cleanup sends no input.

`archive(..., require_ready=True)` and `bind_image_world` join the immutable
ready owner, exact original code/files and actual entity geometry without a
live SDK or guard, including after native files retire. This is marker-owned
UI/resource cleanup; the whole Avatar feature must separately restore model,
scale, owned wearables/bookmark/social state, actual hidden Avatar/People roots,
protocol timers/HTTP/VM callbacks, GPU and independent peer ownership.

Contracts `ios-avatar-marker-files`, `ios-avatar-marker-measurements`,
`ios-avatar-marker-partial`, `ios-avatar-marker-scope`,
`ios-avatar-marker-recovery` and `ios-avatar-marker-abandoned-read` write/read 1.
The generic extraction adds no wire version and preserves Emote v1 bytes.

Host tests execute the actual staged JS/companion bytes in an isolated Node VM
with real normal Script manager/file-picker ownership recipes and private
files. Native SDK/UI/renderer/worker packets remain synthetic. No build,
compiler, device, simulator or laboratory was used. The complete Avatar feature
capability remains unfinished and is not advertised by this component.
