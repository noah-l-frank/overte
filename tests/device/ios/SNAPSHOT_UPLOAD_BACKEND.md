# Original backend bytes for normal Snapshot Upload

Feature 11 remains capability-closed; five of fourteen areas are source-complete.
This component joins the existing normal captured-file Upload to actual
authenticated protocol requests and privately retained backend originals.
It does not qualify the complete Snapshot journey or real-device transport.

The optional `SnapshotUploadProvider` uses the existing trusted HTTPS fixture
listener and its exact `AccountAuthenticator`/`AccountProvider` authority.
The default is disabled. A reader-only preparation route binds an account that
already exists; it creates no account, grant or native login. Actual product
Bearer requests must resolve that principal. Adapter credentials cannot mutate
the fixture, POST an upload, publish peers or prepare accounts.

The provider parses one bounded native multipart PNG and the actual native
story JSON. Rows arise from those requests, with original filename/body hash,
server-generated upload/story IDs, actual serialized response hashes, observed
write callbacks and handler departure. Missing writes remain unresolved.
Credentials and raw authorization headers are absent from source journals.

`backend_context()` reopens the exact original main binding and sealed native
Upload owner. It performs only closed GETs through the existing private
`Client`, first checking the real adapter-only role and independent account
authority. The source's PID, instance, principal/account scope and HTTPS origin
are retained. Native upload/story response hashes select the actual backend
rows, including when another earlier upload used the same PNG bytes.

Each query intent precedes dispatch. The provider materializes original source
JSON bytes once per nonce and preserves their clock and cursor on retry. Actual
body reads use fixed 512 KiB chunks, original per-part hashes and real closed
`BytesIO` readers. The owner stores these original byte envelopes in ordinary
private `OriginalFrameStore` files with the unchanged 1 MiB ceiling, inode,
mode, hash and write-state checks. Its final comparison reads the original
captured host artifact and requires exact byte equality. Pure replay uses no
HTTP, native getter or input transport. An opened incomplete frame remains
owned and cannot be overwritten or converted into a new request.
The opt-in protocol currently bounds each PNG at 8 MiB; the existing native
capture/file limits are unchanged.

The source/body reader is separate from the operational upload rows. Its
cached export originals remain evidence responsibility; they do not establish
source-journal or service-process retirement. The result explicitly retains
those obligations, rendered review, fixture cleanup and the complete journey.

Normal story DELETE is recorded only when the product actually issues it.
In the current Script source, `maybeDeleteSnapshotStories()` runs when another
capture starts; ordinary Close does not imply deletion. Explicit fixture
retirement therefore remains distinct. It requires actual account authority
revocation, known handler/write responsibility, both independent backend quiet
clocks and exact selected owned rows. Native deletion and fixture retirement
have separate retained fields/events. An upload body cannot retire while an
active story still refers to it.

Host evidence:

- The connected normal Capture→Upload protocol selection passed 20 cases in
  6.989 seconds. Native callback hashes matched actual existing `Handler.send`
  bytes, and an independent modeled backend reader obtained the original PNG.
- The final durable owner selection passed six cases in 56.835 seconds:
  admission/body/pure replay, lost source return, saved frame before parent CAS,
  same-byte inode substitution, independently wrong account authority, and an
  actual 1.65-second late return followed by fresh same-process admission. Old
  original bytes/time remain retained, and no normal Upload is replayed.
- Source/protocol/HTTP/legacy boundaries passed 22 cases in 0.169 seconds,
  including original nonce recovery, malformed/foreign MIME, revoked/foreign
  authority, missing response writes, separate fixture retirement, and a real
  large PNG read in two chunks through private files below the frame ceiling.
- The final affected history positive plus those 22 boundaries passed in
  9.350 seconds. Historical file reads retain the actual `time.monotonic`
  callback and the existing five-second immutable-file deadline.

These tests model Qt, TLS and sockets explicitly while using the actual OAuth
and HTTP serializer logic, real PNG bytes, descriptors, weak lifetimes and
private original files. They start no listener, generate/install no certificate
and run no compiler or device. Private logs are
`.ios-host-tmp/snapshot-upload-backend-resume-20261027-{composed04,final09,source08,final10}.log`.

Fresh admission after a late original retains the first PID, instance and
account scope; a changed process or principal cannot be re-anchored.
Main/Actor/render evidence,
failed-upload then successful-upload composition, background return, backend
source/fixture retirement and paired main process/SDK closure remain open.
The actual Script also performs a concurrency-query GET on
`/api/v1/user_stories` to establish domain shareability before native Upload.
The [measured domain-policy preflight](SNAPSHOT_DOMAIN_PREFLIGHT.md) now supplies
an optional controlled-fixture concurrency projection from independently read
owned-domain identity/effective policy and actual account scope. Actual Script
and request-module cases distinguish an allowed share from ACL/foreign-domain/
revoked-account denial and stale-review callback exclusion. The owner's
explicit version-2 profile now retains and joins actual preflight query/reply/
policy originals through its existing nonce/WAL/frame machinery, with the
independent domain-reader public binding pinned from admission through pure
history. Default/literal version 1 remains unchanged. Backend write/leave
precedes the actual multipart request on the same backend clock; native jobs,
policy hosts and frontend consumption retain independent clock domains. Actual
frontend consumption and real external metaverse registration remain separate
obligations; requested IDs, an input ACK or a hardcoded nonempty result cannot
substitute for those sources.
