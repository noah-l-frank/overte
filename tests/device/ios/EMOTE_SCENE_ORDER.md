# Once-only Emote scene ordering

The scene3 protocol permits one committed Web-scene-quiet original per cleanup
ticket. Later real Actor cleanup cuts publish fresh ordinary facts and retain
the first scene reference. Repeated Primary cleanup therefore needs an explicit
historical ordering reader instead of treating that first scene timestamp as
a fresh current observation.

`IOSEmoteSceneOrder` is restricted to Emotes and the existing
`web-marker-scene-quiet` stage. Its metadata is the new closed
`iosEmoteSceneOrderVersion: 1` envelope, wrapping a literal shared reader3
historical journal. It uses the actual earlier Actor admission, candidate,
role/session/PID binding, phase instance, active cleanup ticket, original quiet
interval, committed receipt hash and once-per-ticket journal policy. The current
HTTP acquisition still has its original 1.5-second budget. The original scene
capture/receipt times are retained without alteration; their age is not a new
current-cleanup freshness claim.

The existing whole coordinator now exposes reader/final-qualification hooks.
Its default keeps Complete and its original 1.5-second summary freshness check.
The default reader factory explicitly maps the publisher's existing `None`
stage convention to `complete`; passing `None` directly to the stricter reader
constructor previously failed. A scene cannot satisfy that Complete reader.
An explicitly selected ordinary scene reader also retains its strict freshness.

Only rooted coordinator2 selects the new ordering owner and records
`primary-scene-ordered`. Its existing cleanup still captures real local quiet,
input, native, file and restored-pixel originals before and after the independent
scene read. This ordering result neither proves present Actor state nor retires
the retained native holders. A separately validated paired live window, exact
Actor observation/publication originals and per-role process/SDK end remain
mandatory before complete feature admission. The complete capability remains
closed and rooted finalization remains pending.

Nineteen no-build checks pass in 1.092 seconds: eight ordering/factory cases,
eight unchanged shared Web-scene policy cases and three once-only publication
cases. They exercise actual authenticated loopback HTTP and private journals;
native/candidate observations and acquisition clocks are declared models.
Counterexamples cover foreign binding even with a consistent receipt hash,
unknown delivery without resending, phase advance, cross-area reuse, legacy/
boolean/future tags, strict legacy freshness and slow current HTTP acquisition.
Eighteen earlier ordering/shared publisher checks pass in 0.905 seconds. The
initial factory regression exposed the default-stage constructor mismatch and
failed before the normalization fix; it is not counted as a pass.

The subsequent connected rooted case now passes repeated normal Primary
cleanup in 587.698 seconds. The independent Actor acquires another cleanup cut
after its original scene is older than the ordinary 1500-ms freshness lease.
Both role references advance while the actual HTTP retirement journal retains
exactly one scene entry, including its original captured and received epochs.
The Primary's normal input request count does not advance during the repeat.
The saved ordering owner retains both actual reads and the same original entry.
All 2694 captured source files remain unchanged during the run, and both owned
original roots survive fixture cleanup. The production terminal constructor
also reopens the actual Actor root/policy from that retained role metadata.

This uses the existing component-assembly fixture seam and declared native,
SDK, Qt, GPU and acquisition-clock models. It does not qualify actual operation
deadlines, whole current-WAL archival, process/SDK end or the full common
journey. Compilation and device qualification remain unexecuted.
