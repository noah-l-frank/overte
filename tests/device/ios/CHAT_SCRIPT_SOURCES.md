no-symlink and no direct-write-fallback boundaries include this fixed file.

The host `chat_script_sources` reader reuses `IOSPlacesModel` acquisition and

independently from repository Script bytes. Admission requires exactly one
live matching manager, its submitted main-code hash, its exact expected source

managers, extra relevant submissions, foreign process/artifact, old nonce,

## Explicit source-bound normal owner

`IOSChatDraftRuntime.draft_owner(..., source_bound=True)` uses the same existing
installed session, lock, normal input channel and `IOSChatDraftOwner` WAL. It
selects owner/observation version four. The default version-three profile and
literal one/two readers remain unchanged; neither live construction nor pure
archive adopts version four without the explicit flag. The existing original
frame envelope/namespace, history, operation, query and storage limits remain.

Each v4 observation durably retains its actual query before sending it. The
original configured Script root and submitted-code packet are acquired inside
the same original native/host clock bracket before UI/model reads. Their PID,
nonce, run, original native epochs and exact current manager/main-code binding
are rederived from those packets. The actual configured root, not a requested
path, selects the reviewed code. A different manager cannot re-anchor an
unfinished owner even if its Script bytes match. An absent/foreign source
therefore prevents normal input. Every later observation preserves the same
source identity, and reconstruction restores only the actual retained reader
clock/sequence state. No original is retimed.

Lost passive source returns remain in the existing interrupted observation
with their exact query. Later passive reads use distinct nonces. Lost Send
returns still resolve independent actual history without another Send. The
existing source-query intent hooks are restored on context exit, including
errors. Source queries outside a durably owned observation fail before HTTP.
Pure archive checks the original root/code files and native relations without
querying the app or writing metadata. This binding observes the pre-existing
product Script; it does not claim to create or retire that global manager.

Six normal-owner/error/archive cases pass in 4.453 s. Two canonical runtime
factory/candidate/context-exit cases pass in 0.079 s. A separate connected case
executes the unchanged production Chat Script in Node and passes normal
Send/close/reopen with the same v4 owner in 2.654 s. These are host logic
results with declared native/QML/SDK/clocks, not compiled iOS or remote Chat
acceptance. Thirty existing v1/v2/v3 draft/message/session/admission cases
pass in 41.764 s.

The final source-bound owner/production-Script/runtime selection passes all
nine cases in 6.901 s on the same final fixture. Owner and observation contracts
now register version four with literal readers one/two/three/four; live and

Three further production-Script restoration cases pass in 7.087 s with v4:
normal Erase/rebuild/close restores the original null history, lost Erase

## Receive continuity across reconstruction

The existing shared `IndependentChatReceiver` has an explicit
`retain_originals=True` version-two profile. Default version one stays literal;
neither profile adopts the other. Version two retains the exact latest primary
inspect and peer observe packets in the existing bounded private journal using
the existing packed-original codec. Native event limits, journal limits and
the 1.5-second acquisition deadline do not change. This journal is a continuity
floor, not an immutable archive or a current receipt after reopening.

`NativeChatObservation.restore` validates a historical packet on a pristine
reader without transport, clock sampling or writes. Candidate PID, iOS nonce
grammar, run, original source identity and complete event prefix are restored.
The next actual read requires a new nonce, greater sequence and unchanged
history. Reconstructed primary and peer readers therefore reject changed text,
sender, local-only flag or channel in an old event. Actual duplicate events
remain duplicated. An unexpected journal change blocks queries; a lost return
after a successful journal CAS requires reconstruction from the actual saved
packet rather than replaying an input. Retirement still fences only the owned
peer cache and leaves the primary owner responsible for its own scope.

The initial seven iOS-prefix/journal cases plus 31 existing shared receive/ownership
cases pass in 0.569 s. The final ten-case selection additionally retains both
full 128-event originals, rejects dropped history and literal-one adoption,
and preserves original mixer absence/replacement across reconstruction; it
passes in 0.272 s. Native receive state and SDK boundaries are explicit
models; private files, original codecs and the complete JavaScript probe run
on the host. The existing full-probe test now passes its source through Node
stdin because the expanded probe exceeds the operating system's per-argument
limit; its assertions and source are unchanged. The canonical iOS factory below
uses this profile. Association with a particular normal Send, immutable receipt
archives, UI rendering, outage/recovery effects and complete source/process/SDK
retirement remain open.

## Existing-candidate receive factory

The same `IOSChatDraftRuntime` now exposes the internal
`_chat_receive_components(primary_selector, peer_selector, run, primary_root,
peer_root, primary_lock, peer_lock)` factory. Both exact canonical lock objects
must already be held. It reuses `_sources` and `admit_existing_peer`, retaining
the actual original installed-code admission from the separately prepared
physical peer. Targets and sessions must differ, source/artifact must match,
and both current foreground processes must remain bound. Equal numeric PIDs
on different targets are valid. The factory creates or repairs no SDK session,
launch, install, transport or product configuration.

The private `iosChatPeerBindingVersion` one record (registry
`ios-chat-peer-binding`, current/read one) binds both actual caller-supplied
artifact roots by path, device and inode. Original admission clocks remain
unchanged. Reconstruction validates a fresh independent admission and current
candidate checks while retaining the first original record. A foreign root,
lost lock or changed admitted candidate prevents Chat queries. A lost return
after the binding CAS can adopt the actual existing record without creating a
cache. Binding metadata and both Chat scopes remain owned.

Construction sends no Chat command. The returned `primary_capture` must first
open its cache through the existing `OwnedChatCapture` admission and journal.
`IOSOwnedChatReceiver` extends the existing independent receiver with that
actual primary ownership: an unadmitted/inactive primary cannot authorize a
sample. Reconstructed pairs also validate both original source identities
against their retained active capture journals. Receiver reads retain the v2
original prefixes described above. `receiver.retire()` fences only the peer;
`primary_capture.retire()` separately fences the primary. Neither operation
releases the enclosing binding, artifact roots or session scopes, nor proves
global callback/process/SDK death.

`draft_owner(..., lock=primary_lock, source_bound=True)` explicitly shares that
same already held lock, allowing normal Chat ownership to compose without a
second lock acquisition domain. Unheld and foreign lock objects fail before
candidate queries. The default constructor still creates its own canonical
lock and keeps the literal earlier profiles.

The final twelve-case host selection passes in 0.814 s: eight actual
admission/scope/receive-prefix/CAS/owner counterexamples plus four canonical
source-bound runtime and lock cases. Private stores, original decoders and
locks execute; SDK/native receive producers are declared models. Construction
and reconstruction create no modeled Chat effects, and absent/foreign primary
ownership fails before receive queries. No native compilation or physical

## Immutable receive cuts

`IOSChatReceiveSources` is an internal observational child of those same
components. It owns no normal input and opens no extra session or transport.
The primary capture must already be admitted and active. Each cut uses both
original candidate-bound native clocks around a newly acquired independent
receive pair, retaining the complete raw DTO fields and all original native
epochs. Both clock brackets and their combined host window keep the existing
1.5-second bound; the existing twenty-second Chat checkpoint budget, 128-source
cut limit, 128-native-event bound and original-file size limits stay unchanged.
Fixture clocks in these host tests remain explicit models.

Before each actual native command, the child saves its role and exact command
in the bounded WAL. Every returned native-clock packet is durably retained too,
including nested clock reads made by Chat's existing reader. Complete cuts
require exact role/query order and retain the first/last clock packets as their
bracket endpoints. Both sender and reader hooks are restored on every exit. The
same `OriginalFrameStore` stores immutable typed actor frames with original
hash, byte length, device and inode; no new storage service is introduced.
Independent primary/peer PID, source instance, sequence, open-cache identity,
complete event-prefix and query-nonce relationships are rederived from the
stored packets. Duplicate messages remain duplicated. Foreign, corrupted,
unowned-prefix or missing originals prevent archive admission.

An interrupted passive read retains the exact query and observed native start
packets. Reconstructed readers restore the greatest actually observed native
cursor from both complete and interrupted originals, including every present
history. A changed interrupted PID or native source instance fails before a
new native query. The original host/native times are never refreshed. Lost
saved-original CAS returns adopt the actual complete opened/saved file after
its full typed/hash/inode checks, with no query or recapture. A subsequent
capture always takes a new cut; recovered storage is not returned as a fresh
measurement. Unresolved storage responsibility blocks archive admission.

Pure archive uses independently supplied bindings, run, artifact roots, original
peer-binding record and held locks. It reads the actual original files and
checks membership without live SDK/native calls or writes. It does not release
either cache, artifact root, binding or session scope. Four new contracts write
and read only one: `ios-chat-receive-sources`, `ios-chat-receive-observation`,
`ios-chat-receive-frame` and `ios-chat-receive-original`.

Eight host cases pass in 3.768 s, including normal capture/reconstruction/pure
archive, failed query WAL before send, changed current candidate, rewritten
receive history, physical original corruption/orphans, saved-original return
loss, interrupted clock-floor identity and missing nested clock originals.
Private files/codecs/locks execute;
all native, SDK and clocks are declared boundaries. The normal Send-to-peer
original join, source-bound UI/render outcomes, mixer control/recovery and
complete main-process/SDK cleanup remain open. This child enables no complete
Chat capability and does not qualify native compilation or a physical device.
