# Assets page and current-action components

These explicit host component profiles preserve canonical SDK/session roots
while keeping independently born episode output roots and locks. Page birth
runs the normal menu/open route before any local file is staged. Page-owner format
versions 1 and 2 retain its original source, binding, input ticket and page identity;
current action transports are reconstructed from independently observed phases.

New read jobs use their actual current action ticket. Inspect/retire preserves
the original job ticket required by the native reply protocol and separately
records current cleanup authorization through the existing Action/OriginalFrame
journals. Physical staged file manifests retain their birth ticket. A new mapping
or body read must use a parent read from its same current action. No input ACK
supplies native/file/model/server absence or image pixels.

The registry versions identify explicit codec profiles. Literal default owner
formats and native DTOs remain compatible. New formats require their independently
typed page, action, selected pair and episode contexts; default historical Session
readers refuse them until complete global integration is provided. Planned/opened
original prefixes, unknown namespaces, changed inodes or stale metadata stay owned.

The normal host models do not qualify an installed candidate or devices. They
also do not integrate the full 29-action journey. In particular, the existing
Model-removal Create/Home path closes the prior Assets root. Full dispatch must
retain that page generation and independently own normal re-entry and new view
owners instead of adopting a new root into an old source. The engine still needs
an explicitly bound optional consumed-step callback after all actual consumers,
and cleanup needs its distinct real cleanup-phase authorization.

Whole Assets/cancellation/public adapter capability gates remain closed. The
standalone cancellation-intent prototype is excluded from this publication.
Completed owned-prefix cleanup, generation handoff, typed Session/Scene/global
read membership, UI/current-action evidence, native/device acceptance and terminal
process/SDK retirement require separate qualification. Component or per-episode
end is never whole-feature end; this packet does not change the feature count.
