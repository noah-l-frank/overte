# Durable Assets baking and model-dialog input

`OwnedAssetsUsage` records intent before ordinary rendered checkbox, tree-row,
Add to world and model-dialog input. Its exact run/role/process/session,
file-owner token, page, model/tree/API/client/domain identities and chosen
`atp:/e2e-<run>/stand.fbx` path are joined to the existing immutable clock/UI
source carrier. The owner admits only the unchanged pinned FBX mapping from an
independent server read, bracketed by the actual current UI source. It does not
substitute cached UI permission text for current native effective rights.

Every emitted command is saved before delivery with its actual native token,
sequence and prior original frame. The transport request UUID and nested native
command UUID have separate roles. A receipt establishes only that command's
normal input delivery. Resolution requires a later original source with the
exact command sequence and actual expected checkbox/dialog state. The model
accept action preserves the original URL, default shape, dynamic value and
position; it neither edits model text nor invokes a product handler directly.

Lost toggle/acceptance returns recover by original reads without repeating the
input. Ignored inputs stay unresolved and cannot be reissued under a new
success claim. Deferred baking remains pending until its original callback
settles the UI. Fresh denied permissions, a changed URL or independent mapping,
and altered command tokens/admission/effects prevent delivery or replay.

This is a UI action owner, not bake or rendering evidence. UI checked state,
an independently reported mapping status and an entity-return value cannot
establish actual oven outputs, geometry, renderer texture consumption or peer
publication. A source carrier may be attached to a declared pre-existing
server asset without recording an upload result. The full feature will require
the ordinary upload owner and separate backend/model/resource originals.

The private runtime factory creates the closed owner but advertises no new
capability. Historical session inspection reads its existing original frames
without transports. Actual page/root/weak-client/quiet retirement can close
`usage-client`; any issued model acceptance keeps `usage-model-retirement`
blocking until separate actual entity/model/resource cleanup exists. Parent
upload and backend responsibilities retain their own existing rules. The old
picker remains `primary-chosen`; page death never rewrites it as retired.
