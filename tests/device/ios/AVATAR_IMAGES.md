# Original Avatar world pixels

`ios-avatar-image` and `ios-avatar-image-change` write/read version 1. Each
composition validates untouched Vulkan PNG bytes, actual GPU draw/fence/readback
times, full GPU and metadata retirement, original recorded view, the actual
Avatar marker entity and its fresh 128-bit phase challenge. Self and remote
subjects use actual Renderer4 mesh bounds and the optional original Avatar
World body collection. The complete actual collection also excludes another
rendered avatar overlapping the subject ROI, including the actor's own avatar.

Within a capture, actual world/renderer self geometry and scale agree, the
subject's physical root remains stationary, the actual recorded camera matches
the source frustum, and unowned tree and marker facts remain unchanged. A
remote avatar's advertised URL alone supplies no mesh or pixel geometry.

The missing-model journey permits actual unavailable geometry. That path
requires both original renderer snapshots to show no loaded geometry, no Rig
and no model in the scene. It also requires a retained earlier genuine PNG and
its actually rendered mesh box, with the same candidate, session, physical
root/orientation and scale. The ROI refers explicitly to the previously
rendered volume; current `actualAvatarBounds` remains null. A genuinely uniform
background is allowed only on this native-unavailable path, after decoding the
complete fresh world marker from the untouched original image. No image bytes,
hash, current geometry or foreground subject are filled or synthesized.

Changed-image proof compares the actual subject pixels separately from the
challenge. Actual Domain/AvatarMixer/session, scene, user-controlled camera
orbit, graphics options and unowned entity semantics remain stable. Avatar
scale/model changes may move the automatic camera; each image independently
joins its real recorded view and genuine projected subject geometry. Creation
ownership and model/scale effects are separate source proofs in the whole
decoder; this helper supplies no requested state or action verdict.

Five host tests use synthetic native/GPU boundaries and actual PNG decoding.
They exercise self and remote geometry, other-avatar overlap, unknown body or
mesh, moved roots, incomplete GPU retirement, absent geometry with an honest
uniform image, old pixels under new metadata, a changed marker without changed
subject, real changed subject pixels and a foreign Domain. Pure geometry math
reuses the committed Emote helpers without relabeling source DTOs. Native and
device execution remain unqualified; sample ownership, ordinary marker setup
and the complete feature cleanup owner still need integration.

The selected subject ROI must also be disjoint from the entire actually
projected marker Web quad. Excluding only the selected challenge crop would
allow other changing pixels from that same marker to masquerade as Avatar
pixels. The geometry predicate uses the original source entity dimensions and
native recorded view; a host counterexample keeps a valid challenge crop while
extending the actual marker quad into the otherwise valid Avatar body crop.
This tightens validation without changing the image1 DTO.
