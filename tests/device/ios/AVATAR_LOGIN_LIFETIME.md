# Avatar Login operands at process retirement

`AvatarLoginLifetime` is a passive Whole-only join. It decodes the unchanged
original role Login owner with its actual child account, provider origin and
candidate binding. The initial original preference receipt must contain a
complete independent Login-root source and no live unowned Login operand.
Actual Login input receipts supply the positive control-token-to-root
admissions. Unknown roots, missing components, changed source instances and
truncated histories fail closed.

The join consumes the existing typed Avatar Sources or PostLogoutTail original
bytes under their original native brackets. It performs no acquisition,
ordinary input, root mutation or clock rewrite. Each current root must extend
an original admitted identity and its immutable first-observed fields. Hidden
or detached live roots remain explicit `qt-root` holds. A genuine observed weak
expiry can end an individual hold. A Login reply, Logout return, restored
preferences or empty visible controls cannot establish that expiry.

The returned version-one lifetime proof describes retained responsibility. It
does not establish complete cleanup or process death. Whole Avatar must retain
these actual holds through its explicitly scoped marker-scene stage and its
opt-in terminal seal, then independently prove each actual process ended and
its SDK session disappeared. The existing Scene and Complete contracts keep
their original meanings.

Four focused host checks compose the unchanged Login owner, real loopback
HTTPS OAuth, private journals and explicitly modeled native/Qt boundaries.
Actual Python weak operands distinguish hidden retention from object expiry.
Counterexamples cover an unknown new root, incomplete inventory, source
rebirth, truncation, missing source, an unowned initial root and a foreign child
owner. Native compilation, device behavior and the complete paired Whole
terminal path remain unqualified.
