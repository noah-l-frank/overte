# Original rooted Emote terminal window

`IOSEmoteTerminalWindow` joins both actual rooted live journals to the existing
shared terminal description and three-pair window protocol. It derives the
cleanup ticket, process bindings and held resource aliases from the selected
original measurements. Both source locks must be held, with the Actor sharing
the actual Primary lock object. Run, fixture, phase, candidate and distinct
target/session identities must agree. Changed journal metadata, unresolved
live originals or a changed in-memory configuration prevent qualification.

Each Primary observation must exactly select an original live record. Each
independent Actor server entry selects its actual Actor sequence and committed
HTTP publication. The publisher reader reopens the original observation and
server receipt. The full original observation must also match the one retained
by that Actor cleanup graph. Requested fields and stored measurement hashes
cannot supply missing observations. The held resource identities must remain
the inspected identities throughout the common window. No input, query,
publication, timestamp renewal or cleanup occurs during this pure join.

The returned private version-one proof retains the exact live metadata,
selected immutable references, publisher metadata, description and samples.
Its common seal binds the original proof and exact window. A future terminal
controller must durably retain that proof through the existing original-file
ownership protocol before returning a seal. This helper alone does not persist
the proof, discharge current WAL responsibility, retire runtime metadata, stop
either process or delete either SDK session. It grants no complete capability.

The initial full three-pair host scenario passed in 1420.118 seconds, with all
2687 captured source files unchanged and 1439 original files retained across
both roles. It used real normal JS/W3C, source files, PNG decoders, independent
UDP peer bytes and loopback HTTP publications. The native, SDK, Qt, GPU and
acquisition clocks were models. A subsequent file-only replay of those actual
three pairs passed this helper in 104.287 seconds, rejecting a changed Actor
PID, missing Primary sequence and a one-millisecond HTTP receipt alteration.
The permanent scenario now uses the same helper and counterexamples; its new
integration is not covered by the earlier full-scenario result.

The permanent scenario's shared assertions subsequently passed file-only replay
in 104.370 seconds, including wrong lock-object and changed live-phase
counterexamples. All 1439 originals preserved their exact paths, device/inode,
length and SHA-256 against the post-scenario inventory. The five no-build
project suites, contract-version registry and whitespace checks passed.

These durations do not qualify the unchanged real operation deadlines. Whole
terminal inspect/seal/finish integration, current remaining-owner archival,
once-only Stop, independent OS absence for at least three seconds, SDK
DELETE/GET-404 and canonical/worker recovery remain required. Native compilation
and device tests remain unexecuted; Emotes is partial.
