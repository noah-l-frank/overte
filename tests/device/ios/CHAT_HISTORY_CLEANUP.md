# Ordinary Chat history restoration

Feature 10 remains partial. `IOSChatDraftOwner.restore_history` continues the
same durable normal-input owner with version-three owner/observation journals.
Literal versions one and two keep their exact grammars and cannot acquire the
new cleanup authority. Frame/original carriers stay version one.

The admitted original is an absent page/editor/keyboard and an actually empty
history whose independently read native value is `null`. Native view version
two supplies the SHA256 of the original QDataStream presence/value bytes and
the separate configuration digest. Neither a storage-kind label nor a requested
value proves equality. Other original representations refuse cleanup input;
their original journals and session responsibility remain owned. No native
setting setter, history injection or product behavior change is added.

One existing public cleanup phase authorizes separately durable internal steps:
normal reopen if necessary, Settings selection, ordinary Erase, close, reopen
a new actual page generation, and final close. Each primitive retains its own
original before/after cursor, normal control identity, query nonces and native
clock bracket. Only the actual owned Erase may remove earlier owned messages.
Rebuilding the page must independently show that the Script's internal history
cannot restore the removed rows. Empty Settings or hidden ListModels alone do
not pass. Final close keeps the existing three advancing cuts spanning three
seconds on all original host/native/UI clocks.

The entire method retains one unchanged twenty-second operation budget through
nested steps. No nested operation renews it. Ordinary version-three captures
reserve the final 32 slots of the existing 128-original bound for cleanup; no
storage limit is increased. Lost delivery resolves using fresh originals only;
ignored or unresolved delivery cannot send a second Erase. An earlier failed
action stays failed even after local restoration. Pure archival repetition uses
only the retained exact files under the original source lock and reports the
historical result, without querying or writing a current product state.

The result `historyRestored:true` covers this exact local original value,
unchanged configuration and observed closed page/editor/keyboard. It does not
retire the journals, session scope, Script/QML ownership, network/native
callbacks, process or SDK. No complete Chat capability is advertised. Native
instrumentation remains uncompiled and devices untested.

The dedicated host model cases execute actual private files, locks, WAL and
decoders. Qt/QVariant encoding, QML, message callbacks, native clocks and input
transport are explicitly modeled. Cases cover two channels, pure unchanged
archive repetition, lost/ignored Erase, different typed bytes behind the same
null kind, stale Script history after page rebuild, unsupported original
representation, already-empty cleanup and preservation of an earlier failure.

The explicit cleanup/message/legacy-draft selection passes 31 cases in 75.844
seconds. Two additional cases execute the real repository `armored_chat.js`
in one persistent test-owned Node process per case (13.604 seconds with
ResourceWarning treated as an error). The initial null value is seeded only
before that actual Script starts. Ordinary Erase reaches its original handler;
separate WAL-first reads obtain the actual stored null, clear-message emission
and empty rebuilt rows. Lost Erase recovery leaves the actual handler count at
one. The child performs Script.end, verifies subscription removal, exits and
closes its real streams. QML/transport/native clocks and QVariant encoding remain
explicit models; these results do not establish compiled Qt behavior. Earlier
fixture failures and their original diagnostics remain retained privately.

The 16-case settings/typed-value/budget compatibility selection passes in
0.103 seconds; the three existing production-Script cases pass again with the
extended producer in 14.230 seconds. All five approved no-build project suites
pass in 6.85 seconds. These are host logic checks, not device qualification.
