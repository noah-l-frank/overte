# Avatar marker quiet and retained Login/process resources

The opt-in `avatar-marker-scene-quiet` stage uses retirement wire version 4.
It is separate from original version-2 `avatar-scene-retired`, version-3 Web
marker quiet and version-1/2 Complete semantics. All original versions remain
readable. Default publishers still write version 2 and default readers still
require Complete. The new stage cannot be interpreted as Complete or an empty
resource inventory.

The closed `avatarMarkerSceneQuietVersion: 1` summary lists only marker entity,
file, GPU and pixels; Avatar/People Qt UI; marker Script listeners, VM and
timers; and the restored original World view. Account sessions, Login Qt roots
and native process resources explicitly remain owned. No claim of global Qt,
account, QSG, image or WK resource destruction is added by publication.

The same authenticated actor-only endpoint and earlier actual actor admission
apply. No server permission is expanded. A run/ticket can have at most one
scene stage, and only before any other retirement row for that ticket. This
invariant applies equally to live posts and fully rehashed historical journals.
Lost POST results resolve from genuine committed receipt reads, never another
send. Native cleanup still comes solely from the feature's complete original
decoder; this protocol supplies only bound ordering metadata.

The Whole Avatar consumer must separately qualify actual Login root admissions
and later originals, ordinary logout and preference restoration, provider
revocation, keyboard/IME, callbacks, image restoration and quiet before the
common process-end terminal seal. Actual held Login roots prevent emitting
Complete(resources=[]). The opt-in terminal end binds each original SDK's one
Stop, independent numeric OS absence and one SDK DELETE; it replaces the
lifetime absence assertion for those retained resources. The stage alone does
not enable the feature or prove that terminal path complete.

Eight protocol tests use actual authenticated loopback HTTP and private CAS
journals. Their native-cleanup decoder is explicitly modeled. They cover the
new stage, strict Complete defaults, original v1 files, unchanged v2 defaults,
lost POST delivery, cross-area/version/summary refusal and historical/live
single-scene ordering. Native/device qualification remains separate.
