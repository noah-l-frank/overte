# Snapshot Save and independent Photos original owner

`IOSSnapshotPhotosRuntime.photos_owner` supplies an internal Save/destination
flow over the already captured still PNG. It requires two existing separately
bound SDK sessions, the selected independently admitted Photos companion
archive, both actual source locks, the retained capture owner and the same
controlled Snapshot phase. It neither creates a session nor installs, launches
or rebinds an application. The complete Snapshot capability remains closed.

The owner reopens the captured private original, pins its exact capture result,
artifact journal and original file, and independently attests that both SDKs
address the same physical device. Only a digest of that private selector enters
its journal. App handoffs retain intent before the one ordinary activation
call. OS-only background guards preserve both process identities, original SDK
process sources, selected candidate and installed-code continuity; native/UI
reads continue to use the existing foreground guards.

Before the normal client Save input, fresh independent companion clock/Photos
originals must observe unchanged full ReadWrite authorization. This is passive
permission observation. No permission setter, callback acknowledgement or
limited-library absence grants access. The client keeps its AddOnly usage
description. Real permission and deletion-confirmation UI recipes remain a
requirement for the complete journey; an unavailable, ignored or pending system
action keeps responsibility unresolved.

The ordinary Save row must identify exactly the captured owned basename. A
new original native export operation, its actual Photos placeholder and
completed/expired native owners join that delivery to the destination. The
companion performs one resource read of the exact placeholder and original
basename, using PhotoKit original data without image conversion. The host
retains the actual AFC output and reads bounded 512 KiB original chunks. The
reconstructed bytes must equal the captured original exactly and decode as the
same still PNG. Native and host clocks remain independent original clocks.

Destination version 2 adds the actual completed original file's stat revision:
device, inode, mode, link count, uid, gid, size, modification time and change
time. Every native chunk validates this initial anchor before its first read,
checks its descriptor and named entry again afterward, and reports closed
readers. Replacing the file with identical bytes cannot qualify a new inode.
The literal version-1 reader remains available with its unchanged exact field
grammar; version 1 cannot authorize the new anchored chunk or retirement flow.

Cleanup sends Delete once for this owned Photos asset. Three fresh full-access
absence originals must span at least three seconds on both native and host
clocks after callbacks and weak owners have expired. The companion then
conditionally retires the anchored original bytes, exact native JSON journal
and original owned run directory. Its immutable receipt records actual ordered
unlink/rmdir steps, exact raw journal digest and reader closure. Three fresh
file/run absence observations span another native/host quiet interval. A failed
or partially executed retirement remains owned and cannot be replayed as a new
mutation. Cleanup finally returns to the original client and rechecks drained
native exports. Host originals remain available; the client capture file stays
owned for the later Share/upload stages and their final capture cleanup.

The parent journal, child query/input journals, app activations and companion
field/button slots persist responsibility before crossing a mutation boundary.
Lost returns recover actual original reception or immutable AFC bytes without
another Save, read, Delete or retirement call. An interruption after parent
input intent but before child reservation may reserve the still-unsent child
once. Partial immutable evidence remains frozen; no fresh source timestamp,
replacement inode or acknowledgement-only result is manufactured.

Photos Save uses separate `photos-save-*` owner, input-proof and native-source
namespaces. Its closed `photos-save-sources` segment profile accepts only raw
exports/inputs. The original capture/page owner names, exact input census,
schemas and default segment namespaces remain unchanged. Historical readers
reject substitution in either direction. The permission and native destination
codecs do not admit the entire feature.

Host coverage uses the actual Python owners, private CAS files, HTTP/AFC codecs,
original byte reads, filesystem identity, unlink/rmdir and weak host lifetimes.
Qt, PhotoKit, the OS process boundary and their clocks are explicitly declared
models. The production factory still uses the real existing main installed-code
and independently admitted companion contexts. These tests do not compile or
execute Objective-C, qualify an IPA signature/install, or demonstrate device
acceptance. The connected owner tests cover normal Save/read/delete/retirement,
lost returns, ignored Save, denied/limited permission, retained weak operations,
original-file replacement, immutable host evidence and interrupted reservation.
Source tests cover literal versions, the exact chunk boundary, journal bytes,
reader/deletion guards and closed namespace substitution.

The 2026-10-26 final targeted host selection passed 69 tests in 90.148 seconds:
Photos owner 8, Photos source 5, existing Snapshot input owner 8, destination 8,
companion admission/artifact 17, capture/recovery 10 and normal page owner 13.
A further 8 tests passed in 6.411 seconds: production Photos factory/context 3
and the final source/isolation selection 5. The factory tests use the actual
`InstalledCodeBinding` and verify that background permission is confined to
OS-only probes, changed original source/session scopes fail before Save, both
locks remain held and unowned AFC paths are rejected before a pull.

The outer journey still requires independent Actor/scene fidelity, Share and
upload destination originals, normal OS presentation/confirmation recipes,
full lifecycle restoration, final client capture and paired cleanup, and
device qualification in the authorized Proxmox Jenkins laboratory. An inner
saved or cleaned receipt explicitly retains these requirements.
