# Independent ordinary Avatar consent

`ios-avatar-consent` version 1 owns Accept and Decline on the actual independent
actor SDK. Its factory uses the existing candidate-qualified runtime, actual
actor source owner and actual HTTPS fixture origin. It creates no SDK session
and declares no feature capability.

Before each input, the original native account principal and endpoint hashes
must still match the allocated actor. The actual incoming Pal prompt must name
the owned primary avatar. Its original request UUID and immutable source
reference are saved before response delivery; the same invitation cannot be
reticketed and answered again. The actual remote primary must remain present.
The actual Accept/Decline event must still name that exact admitted invitation,
including during reconstruction. A new request from the same peer is refused.

Whole calls, UIKit tablet opening and each token-bound normal Qt event have
private durable ownership before delivery. The existing original input owner
retains command UUIDs, original immediate receipts and independent widget
readback. Unknown delivery remains issued after reconstruction. Neither a new
ticket nor an acknowledgement replays a whole consent recipe.

After the actual terminal success or decline appears, a separate ordinary
Close event dismisses the panel. Normal tab navigation opens Connections and
triggers the product's actual first-page fetch. Primary cancel and peer-terminal
recipes use the same navigation so subsequent observers can inspect completed
materialized tables. Re-entering Connections through Nearby also refreshes an
already open table using the existing real controls.

Every actor read preserves the original self model, scale, bookmark map and
complete unowned entity inventory from the first owned call. The consent
owner records delivery and original UI progression; independent reciprocal
POST, response-consumption and table proofs remain in `avatar_social.py`.

Host tests execute actual private owners, immutable source archives, original
HTTP/AFC normal-input parsing and command journals at explicitly synthetic
native/QML/SDK boundaries. They exercise accept, decline, terminal closure,
actual tab navigation, no-resend acknowledgement, lost delivery, foreign
account/peer refusal, a replaced invitation before delivery, a conflicting
retained input reference and an old invitation under a new phase. Whole feature
preparation, source recovery, GPU evidence and quiet cleanup remain separate.
