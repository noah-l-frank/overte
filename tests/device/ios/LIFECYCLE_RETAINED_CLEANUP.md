# Original retained touch cleanup

An optional retained-cleanup profile binds the existing inspect, release and
settle operations to the original pre-Down resource. The receiver retains its
actual operations object, resource, Source, loop, instance and original motion
receipt. Request identifiers select that retained birth; their JSON cannot
create a worker or supply ownership.

The existing Node bridge refuses a different owner before dispatch. The
original Python receiver checks its retained objects before any release or
settle effect, including every affected born lease. A newer receiver with the
same WDA session or copied identifiers cannot borrow the original resource.
Cleanup can release the original worker after current Source/RSD admission is
lost. Preparation without a born worker permits inspection and settle, without
claiming a native release.

The WebDriver sender retains the original URL, session and bound reply parser.
It copies the scoped selectors before use and accepts only exact strings for
the three existing cleanup operations. Later public client aliases cannot
redirect this sender. Ordinary WebDriver calls retain their existing parser,
transport guard, limits, errors and response-close behavior. Empty legacy
cleanup arguments keep their original version-2 response.

The source is in [the receiver](pymobiledevice3_wda_xctest.py),
[the Node bridge](appium_wda_host_ops.js) and
[the WebDriver transport](adapters/appium_adapter.py).
The optional response is touch version 3 with retained profile 1; all native
touch, motion and resource-retirement qualification flags remain false.
The normal held-input consumer is a subsequent integration step.

## Host verification and retained failures

Six receiver cases, six actual HTTP transport cases and three actual Node
route cases passed across the separate Root58, Root60, Root61 and Root62
selections. Their 93 original files remain retained. Actual task, thread,
descriptor, process and source-pin checks completed. The first two receiver
cases used bounded RAISE-only diagnostics; the last four had those diagnostics
enabled from their first execution. No two successful receiver cases were
repeated in the remaining selections.

Root55 failed before preparation because a function-local copy helper had not
yet been imported. The one-line Prepare import fixes that specific error.
Root56 and Root59 subsequently failed during Begin; their diagnostic
selections passed without another source change. Those failures and originals
remain preserved. Their cause is unresolved, and no stable timing claim is
made. The strict 1.5-second acquisition and 250-millisecond clock-join limits
were not changed.

This qualifies the host cleanup components. Canonical normal held-input
integration, authentication, native compilation, device execution and whole
Lifecycle acceptance remain open. Complete areas remain 5/14.
