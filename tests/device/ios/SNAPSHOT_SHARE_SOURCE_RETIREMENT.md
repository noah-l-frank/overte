# Snapshot Share conditional source retirement

Feature 11/14 now conditionally retires the six frozen Share source outputs
and its own final intent through normal Archive inputs and original evidence.
The complete Snapshot capability stays closed and the source-complete count
remains 5/14.

The Archive's original catalog takes one fresh nonce after its frozen six-file
inventory. It rechecks the original Documents parent, exact reserved-name
census and each original file's first revision and bytes. An exclusive final
intent precedes every unlink. The native result retains the actual initial
intent bytes and first file identity; it is never reconstructed from the
later completed record.

All original file readers close before deletion. Native code conditionally
unlinks exactly the six original global files and its own final intent, in
that order. Every step separately records actual unlink, synchronization and
parent-anchored `ENOENT` results. The parent descriptor's close result is also
explicit. Partial unlink, changed identity, unexpected source name or unknown
sync/close keeps an incomplete responsibility. No recursive deletion or input
resend occurs.

The result stays as immutable original bytes in the existing Archive process.
A readonly label exposes those bytes without another output file. Separate
normal nonce inputs inspect all seven fixed names and the source namespace,
with fresh native clocks, the original parent and exact retirement byte hash.
Only actual `ENOENT` establishes file absence. Unknown observations remain
unqualified.

The host coordinator requires completed original transfer, two-run retirement,
admission-reader seal and frozen source inventory. Before Delete it acquires
three independent original extension PID/bundle absence samples spanning real
Node and separately sampled host quiet windows. An unissued stale window is
preserved. A lost issued input resolves its actual original before new queries.
The Retire result stays historical; fresh post-deletion observations carry the
new independent absence evidence.

Pre-dispatch freshness checks read only the exact durable input envelope's
issued state. They cannot interpret an original frame's opened prefix as a
complete saved reply. Full first-file/length/SHA validation remains at original
retention and replay. Historical dispatch timestamps are also joined to their
original pre-input absence sample without assigning new clocks.

Three post-deletion rounds independently join original extension absence and
actual native file/namespace absence. Node/host and native-file/host windows
must each span at least three seconds. A late issued inspection retains its
original clocks and bytes before another passive nonce is admitted.

Archive controls are grouped by actual import and producer-fence lifetime.
This keeps the source controls visible after admission-reader closure and
restores that layout from the original catalog after controller recreation.
The UI accepts no requested phase or expected file/cleanup result.

Process and SDK retirement, capture/page restoration, upload/Actor evidence
and the complete outer Snapshot journey remain separate obligations. Native
source is uncompiled, and the repository process plugin remains uninstalled.
No compiler, build, device, installation, laboratory, service or remote
operation has been used for this work.
