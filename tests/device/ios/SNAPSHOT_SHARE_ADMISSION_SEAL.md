retirement. `IOSSnapshotShareOwner.admission_seal_owner()` requires its original
completed run cleanup, hands the existing Archive process to the foreground,
and creates `SnapshotShareAdmissionSealOwner`. Its ordinary nonce-only button
closes the original admission source's retained bundle reader. This remains a

## Actual native ownership

The Share compile-time branch retains its initial Documents parent identity.
Every successful identity/clock publication pins the actual newly published
file's inode revision, SHA-256, length and original parent. Publication checks
the previous owned version before overwriting it, or requires real absence for
the first version. It joins the actual exclusive temporary writer to the
published inode and verifies and closes its original reader. A foreign
pre-existing file, same-byte replacement or uncertain close/fsync cannot create
a new current-file anchor. Failed temporary files remain owned; this component
does not delete them.

The actual asynchronous bundle collection block retains a separate lease.
Only its weak expiry permits the normal Seal button to become enabled. The
source rechecks that weak reference, readiness, the original bundle census and
both current original output pins before attempting close. It then fences
future Share identity/clock observation and publication before calling
`close` on the original retained bundle descriptor. The numeric descriptor is
never retried after an uncertain close return.

The native source retains an immutable close record with the original source
instance, PID, birth/preparation clocks, bundle forest, initial bundle-root
revision, two output pins and actual close clocks/result. The normal Archive
screen exposes that record through a read-only accessibility value. It creates
no further output file. The source retains the first serialized bytes; a
recreated controller's label reads those same bytes and original clocks.
The button takes only a fresh nonce; it accepts no
path, expected identity, expected hash, desired close result or process state.
The Photos compile-time branch and its literal source readers are preserved.

## Durable host responsibility

The dedicated host owner admits only the existing Archive context, selected
IPA and original code admission. A closed subclass of the existing ordinary
Share UI action owns its nonce-field operations, one button dispatch and raw
read-only output. The legacy action's literal fields, envelope, frame keys,
file names and output selector remain its defaults. The new action uses its
own closed control, schema keys and original-file namespace.

The owner joins the seal to the exact last native admission sequence and
source identity, including the unchanged raw bytes of the last identity and
clock output. It retains original acquisition clocks and bytes before claiming
a qualified close. A lost button or output return reads the same immutable
record without another dispatch. An ignored input, source substitution,
partial/unknown close or an expired acquisition remains unqualified. It cannot
gain new clocks through recovery. Pure history reopens the original admission
and sealed output without SDK calls or writes.

This discharges only the admission bundle reader. Its two global output files,
the chunk and three retirement output files still require conditional source
retirement with exact first identities, original-byte joins and independent
absence windows. The Archive process, source SDK connection, capture/page
restoration, authenticated upload and independent Actor/scene journey are
also still separate obligations. Native companion source remains uncompiled;
the repository process plugin remains uninstalled. No device, compiler,
build, installation, laboratory, service or remote operation was used.
