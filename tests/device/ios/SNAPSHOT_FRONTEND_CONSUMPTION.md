only with `combined=True`. It emits owner/result3 in the same coordinator,

## Actual originals and operation

After the retained Upload baseline, Upload3 reserves and retains a Combined
HTTP original before ordinary input. It delivers the existing normal Upload
control exactly once, including original lost-return recovery, and retains a
second HTTP original before associating the independent native upload job.
Every passive query has its existing durable reservation and issued nonce
before dispatch. The original native/host bracket, raw UTF-8 bytes, full event
and V8 caller history, raw segment transitions and immutable frame identity
stay owned by the same Upload journal. An issued query recovers only its own
original, without another send. Incomplete raw/file prefixes stay unresolved.

`CombinedUploadHttpPacket` reuses `SnapshotFileWorkPacket` and its existing
segmented raw/write recovery. The new closed segment profile allows only
primary-role Upload, with the short `snapshot-http-upload-parts` namespace.
Its parent/body/frame/original1 and packet/frame/original1 have separate tags;
the existing Upload1 segment subject grammar is unchanged. The 32-character
namespace, 1 MiB frame, raw/source size, 128 child and global1024 frame limits,
one-use nonces, original file/inode guards and deadlines are unchanged.

Each HTTP source admits the independently observed Script root and all four
reviewed UTF-16 sources. Its actual manager membership, submitted main code
and complete evaluation originals must exactly equal the original settled
Capture2 worker. Native-main packet chronology uses the existing global native
source tail; no requested manager or code version enters the source command.

`backend_context(..., combined=True, frontend_http=True, domain_policy=...)`
reopens that exact Upload3 archive without a native/SDK query or input. The
same read-only Backend owner emits owner/query/result3. Versions1/2 retain
their own envelope, choices and flags. Backend3 still binds independent role,
authority, account, policy, original preflight request/reply and exact captured
PNG body before deriving the additional consumer fact.

The pure `snapshot_frontend_consumption.joined()` requires exactly one new XHR
since the retained baseline. It joins the actual protected response ID, full
query bytes, full response bytes/hash and owned HTTPS origin to a successful,
authorized responseText GET inside the actual retained request.js DONE
callback. The original Capture manager/code/root must agree. The normal input
received event precedes XHR creation; the actual response read precedes the
associated native upload birth. These comparisons use only the shared native
process epoch. HTTP, native-main and backend monotonic counters keep their
separate origins; backend request/write/departure ordering remains entirely
within its own original clock domain.

Actual reply destruction, callback release, timer destruction and XHR
destruction are mandatory for the consumer fact. Pure archive reopens the
retained files, hashes and inodes without GETs, source queries, input,
allocation, retiming or mutation. It does not retire source journals,
credentials, service processes, OS descriptors or SDK sessions.
