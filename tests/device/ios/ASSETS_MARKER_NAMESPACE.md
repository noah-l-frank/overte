# Explicit Assets child profile on the original marker owner

This prerequisite reuses `CreateMarkerScope`'s actual ordinary Script/picker
input, original API return, weak-holder, quiet-window and cleanup mechanisms.
It does not copy the owner or relabel Create image publication as Assets.
An Assets parent must explicitly own this marker child before using its
retained admission in a new Assets model/pixel sample. That enclosing sample,
Actor publication and whole Assets journey remain open; completion stays 5/14.

## Closed namespace and literal legacy behavior

Default Create still writes the original Scope2, Recovery1 and abandoned-read1
bytes. It reads old Scope1/2 and keeps all original filenames, schemas,
counters, command delivery, 1.5-second source brackets and three-second quiet
windows. No GUI, native collector, camera, permission or product behavior is
changed by this profile prerequisite.

Only explicit `namespace='assets'` selects Scope3 with mandatory
`scopeNamespace='assets'`. Its canonical state/files/script/recovery WALs are
`ios-assets-marker-scope-<role>{,-files,-script,-recovery}.json`. Their
Create counterparts remain `ios-create-<role>-marker{,-files,-script,-recovery}.json`.
The child uses disjoint `assets-marker` original/index filenames and
`assetsMarkerFrameVersion`, `assetsMarkerOriginalVersion` and
`assetsMarkerManifestVersion` wrappers, all1. Existing Create frame bodies
remain unchanged. Pending manifests validate their actual schema and stream
counter before archive or abandoned-read recovery.

The explicit child also has namespace-bound Recovery2 and abandoned-read2
records. Actual partial files, native prefixes, hashes and input delivery
responsibility are retained. Its abandoned reads have separate filenames;
an unknown input is never resent. No legacy metadata is rewritten to adopt
the new profile.

Archive callers must independently supply the expected namespace; the
untrusted envelope cannot select it. Default Create rejects Assets3 even
after a header-version relabel, and the Assets caller rejects old Create
schemas. The staged marker/companion code, `create-marker-v1` identity and
their pinned hashes remain the actual original marker implementation.

Separate streams do not authorize adopting or retiring another feature's
work. The same-root/run tests preserve retained Create metadata verbatim;
the future Assets parent still needs its own current admission and all
foreign/residual responsibility checks.
