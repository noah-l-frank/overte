# Durable ordinary Phone Graphics preferences v1

`PhoneGraphicsPreferences` composes the existing original-token Graphics surface,
passive native preference getter and owned scene/UI journal. It covers ordinary
open/close, resolution, Haze, Mirrors and measured original restoration for one
existing process. It does not implement background/restart or publish completed
GPU/image effects. Those lifecycle verbs are refused before input/reservation;
no full Graphics capability is advertised. Native instrumentation is uncompiled
and all devices remain untested.

## Original ownership and input

Construct with the active `PhoneGraphicsScene` and its held exact shared source
lock. `prepare()` acquires two original native packets, requires unchanged actual
preferences/lifecycle and closed owned UI, and freezes actual original preferences
before any setting input. The private CAS `phone-graphics-preferences.json` v1
pins the exact run, actual fixture URL and current candidate/session/process.
It preserves the original native packet and every latest accepted native cursor;
reconstruction restores original voice/account/animation source histories.
Replaced native birth, rolled-back cursor, changed scene owner or guard/lock loss
cannot reset into success. State is bounded to 128 action tickets and 128 original
input intents per action; storage/quota failure retains scope and fails closed.

`act()` accepts the existing closed v16 `feature.graphics.act` arguments for
`open`, `close`, `set-resolution`, `set-haze`, `set-mirrors`, `restore-original`.
It saves action and per-substep intent before any normal input. Every surface
input additionally saves original native and subject packets, optional original
Qt widget metadata and actual control identity. UI leases use the scene owner's
durable original journal. No Render setter or script/entity shortcut is an input.

The original resolution must lie on the actual visible control's original grid
before any preference mutation, including a toggle. Unsupported originals cannot
be changed and later rounded into a restoration. `restore-original` sends no
caller-selected original values: three separate resolution/Haze/Mirrors substeps
read the frozen actual native values. Each substep has its own issued/observed
record. An interrupted substep receives reads only on recovery; already delivered
ordinary scroll/value/toggle input is never replayed.

Each terminal substep reads the actual current Qt and native preference sources
independently. Open/close additionally verify actual SDK Tablet presence/absence
and original page profile. A successful widget readback cannot substitute for
native preference change. A scalar action must preserve all unrelated native
preferences; restoration requires the entire original native Graphics object.
The return remains exactly an input receipt, `{"performed":true}`. Actual render
scale, executed passes and image effects require subsequent independent complete
Graphics acquisitions; no requested setting is returned as a measured pass.

Repeated tickets require identical arguments and fresh original terminal proof.
Lost returns retain issued intent. If actual desired state was reached, a later
call may prove it without new input. An ignored input stays failed. Conflicting
ticket arguments, unrelated settings changes and foreign/replaced surfaces fail.
Each prepare/act/cleanup has a 30-second budget including source reads and durable
callbacks; existing nested input/source budgets still apply. Completed scene
setup has its own scoped deadline and cannot expire a later preference operation.

## Cleanup and final handoff

`cleanup()` uses a separate durable ordinary restoration plan. Unchanged original
preferences need only actual owned UI close/absence. Changed preferences require
normal owned Graphics open, each original scalar restoration and actual close.
Every cleanup substep preserves original input intent and its own observed proof.
An uncertain step receives reads only; completed substeps are not redelivered.
Lost close acknowledgments release leases only after fresh actual absence.

Final cleanup proves the entire original native Graphics object and empty owned
UI leases. Repeated cleanup reacquires original proof without new input. Foreign
replacement pages, ignored restoration or missing final absence keep the journal
red. `retire()` repeats cleanup, discards only the exact validated CAS record and
independently checks actual absence. General Phone cleanup refuses a retained
preference journal. This does not retire the scene or native GPU/file evidence;
the full feature must verify those separate owners and both independent roles.

Eighteen focused host cases use real private journals and explicit synthetic SDK,
Qt and native sources. They cover the ordinary sequence, a non-default 0.65
original, original-grid refusal, recreated source floors, ignored independent
native changes, lost scalar returns, partial restoration without replay,
unrelated preference mutation, callback deadline/storage failure, native birth/
cursor replacement, conflicting tickets, unsupported lifecycle input, idempotent
cleanup, retained ignored restoration and ignored journal removal. A separate
actual adapter-wrapper case covers whole-cleanup refusal. These checks establish
adapter/test logic only; lifecycle ownership and the full independent Graphics
coordinator remain to be composed.
