# Original Phone Graphics target-pixel comparisons v1

`overte_phone_graphics_effects.compare` supplies an internal pixel guard for the
future complete Graphics coordinator. It enables no adapter operation/capability.
Native instrumentation is uncompiled and all physical clients remain untested.
The fifteen host cases qualify this comparison logic with explicit synthetic
native facts and actual original host PNG files, not GPU rendering or devices.

## Inputs and original-source admission

Inputs are the run, feature `haze|mirror`, actual fixture root, installed/process/
session binding, role, two full original sample frames and their original PNG
bytes, the external image policy, original native clock callback and existing
scope guard. No desired setting, expected pixels, guessed camera or test verdict
is an input. Both originals are revalidated through the existing measurement
join, including current per-frame challenge decoding, seven actual native
subjects, actual recorded-view trace, original PNG/RGBA hashes and original
native memory/receipt absence proofs. Provider histories must preserve their
original append-only prefix and native/source/frame identities must advance.

The samples need different tickets and one process stage, provider, native birth,
GPU context, actual projection/view, target/viewport and controlled subject set.
Only the independently observed native preference for this feature may differ.
All other original preferences, lifecycle counters and scene/view data must
remain steady. The current native sample cannot predate the old sample; the
reference interval is at most the existing 45-second operation window. Both
observed preferences must agree with their independently executed batch facts.

## Projection and feature-specific pixel checks

The original recorded row-major projection matrix and camera quaternion/position
project all eight actual target-box corners. Off-axis projection is retained;
there is no FOV-derived replacement matrix. Clipped/behind-camera subjects fail.
The target is the actual run-owned distant white board for haze, or the actual
mirror surface for reflection. The comparison uses the middle half in each axis
to exclude silhouette edges. It excludes the entire projected world marker card
with a two-pixel rim and the external challenge decoder ROI. Changed challenge
bits therefore cannot substitute for a feature effect.

At least 64 target pixels and a 4-by-4 interior are required. Images retain their
original dimensions and pixels: no alignment, resizing, exposure correction or
generated replacement is used. At least 5% of usable target pixels must change
by more than 25 in an original RGB channel. Haze must change the board's measured
mean blue-minus-red by more than 10 in the direction of the actual observed
setting. Mirror enablement must increase the measured orange fraction by more
than 0.005, and disablement must decrease it. An orange pixel has original red
above 60 and red greater than both green and blue by more than 12. This matches
the controlled scene's behind-camera orange subject and blue haze, with the
other native settings held steady. A wrong hue or uniform exposure change fails.

The returned version-1 record contains actual image hashes, target UUID, projected
ROI/exclusions, sample count, original RGB means, blue dominance, orange fractions
and changed fraction. It does not turn the requested setting into a measurement.
The coordinator must retain it with the exact two original phase archives and
still satisfy the common feature state/image/publisher/cleanup contract.

## Deadlines and limits

The comparison uses a five-second total host budget, checked during pixel rows.
The current original sample must remain within 1,500 ms native freshness after
decoding, source joins and pixel work, including final native clock-query and
guard latency. An independent local elapsed-age floor also rejects a frozen native
clock during slow host decoding. Clock rollback, missing source/version/result, failed scope guard,
borrowed image/frame/owner, stale reference/current evidence or an incomparable
view/settings change fails closed. It performs no product input or cleanup.

These fixed version-1 thresholds describe the controlled fixture comparison;
they have not been qualified on native clients. Physical rendering, practical
fixture visibility, timing and normal scene/settings/restart orchestration remain
unverified. This component is not a completed Graphics adapter.
