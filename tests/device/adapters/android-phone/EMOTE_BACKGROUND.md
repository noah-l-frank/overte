# Phone ordinary Emote background and resume, version 2

`PhoneEmoteBackground` owns one ordinary Android Home/activation cycle for the
common Emote `background-resume` action. It uses the existing SDK session and
original Android OS/process observer. No native input setter, duration sleep,
synthetic restoration or Graphics-setting operation is introduced. The complete
Emote image/actor/quiet-resource/run-retirement coordinator remains missing;
this component enables no full capability or physical qualification.

## Ownership and exact journal

Construct with the adapter/selector, real Emote `PhaseFixtureReader`, already
held `phone-script-sources.lock`, existing private `artifact_root` and closed
`segment=0..15` (default zero). The chosen existing source/input journal namespace
is used throughout acquisition and reconstruction; the one background lease is
global to the run and cannot be adopted with another namespace. The
background owner can reconstruct while the process is genuinely backgrounded;
it never tries a foreground-only native/UI getter then.

`phone-emote-background.json` has exactly `emoteBackgroundVersion:2`, `runId`,
`fixtureUrl`, `artifactRoot`, `sourceSegment`, `payload`. Payload contains one exact record:
`binding`, `call`, `phase`, `beforeHeader`, `background`, `foreground`,
`afterHeader`, `cleanup`. Version 1 remains readable only in segment zero, with
`cleanup:null`, and upgrades to version 2 on the next real write. Binding is the actual candidate/artifact/PID-start/SDK session/
generation/target context. Call is the closed original `feature.emotes.act`
request with verb `background-resume`. Header fields retain the exact source v3
owner headers whose manifests address complete immutable original files.
Background/foreground are actual original Android status records, or null.

Phases are `background-issued`, `background-observed`, `foreground-issued`,
`observing`, `observed`. Durable intent precedes each possible ordinary input.
Only an actual observed background transition authorizes the one activation.
The actual current fixture phase, original provider birth and immutable input
history must match before new inputs. Foreign or retired phases do not activate
an old owned action. Existing unresolved ordinary Emote input/archive ownership
blocks the initial background action.

Before Home, fresh original native/UI/fixture sources must observe idle with no
active chooser selection. Background is not a hidden cancel or workaround for
an active Emote. After activation, a new source frame must have the same actual
process/native birth/Rig, advancing actual Rig evaluation, backgrounds and
activations each increased, unchanged launch count and unchanged native call
history. OS ACKs alone cannot satisfy these checks. Actual original foreground
and background OS/process records independently confirm the transition.

## Historical replay and recovery

`PhoneEmoteSources.archive` revalidates source v3 headers, immutable original
files, native/script/root/UI/phase histories and caller cursors. It creates no
live owner/runtime, dispatches no native request and returns no fresh facts.
The background owner brackets bounded local replay with actual Android binding/
process checks. Original native and host times remain separate and unchanged.

A lost Home return leaves `background-issued`. A reconstructed owner may observe
that actual same process in the background and send its one activation, without
another Home or any foreground-only source access. A lost activation return
leaves `foreground-issued`; actual OS foreground plus fresh native observations
can complete it without another launch. Ignored Home/activation remains red and
is never redelivered to manufacture success.

Once observing, completed source originals from a lost read return stay
historical. A new independent read is required for delivery. A source journal
still marked reading is unresolved and blocks completion. Failed host writes
latch the live object unavailable; reconstruction validates the last durable
phase and never reissues uncertain OS input. Missing/replaced source originals,
changed candidate/PID/session, missing OS evidence and changed source prefixes
remain failures with ownership preserved.

The full cycle has a 30-second monotonic budget. Background OS observation is
bounded to five seconds/51 reads at 100 ms. Ordinary source reads retain their
existing five-second and 1.5-second freshness limits. Actual OS/process status is
available without session repair or normal foreground-source construction.

## Retirement and remaining whole-feature obligations

`act` returns only `{performed:true}` after the original OS/native transition.
It supplies no public feature state, pixels, independent actor facts or global
resource-absence verdict. The complete owner must acquire fresh original Emote
state/image/actor evidence separately.

`retire(retain=None)` requires completed owned background state, a current complete
same-phase source history preserving the exact original completed prefix,
revalidated original native proof and actual current same-process
foreground. It removes only the exact background input journal; source originals
remain. The optional callback receives the exact header before deletion; callback
rejection, changed originals/context or a deadline overrun preserves the lease.
The full run owner must use this retention path.

New source/image observations after resume may extend the original history.
The last current source must still be idle in the same background input phase,
with the same native PID/birth/Rig, lifecycle, call/override cursors and original
events as the completed cycle. Missing/partial histories, a later fixture phase,
new override or unowned calls cannot authorize retirement. Retention IO must
not advance or replace that checked current header. This admits genuine later
observations without discarding the original lifecycle proof.

`completed_archive(header,source)` reopens a retained successful cycle after
its lease metadata retires. It returns original `(state,before_frames,after_frames)`
and preserves their original timestamps. The real source supplies actual run/
fixture/artifact/candidate binding and held lock. The readonly reconstruction
reuses the original decoder/source files and actual OS binding observer, with
a five-second bound including the initial guard. It accepts only completed
cycles without cleanup recovery. Its private view cannot act, recover, save,
retire or create a live source. It sends no native measurement request/input
and supplies no fresh feature facts. An independent actor may use the original
cycle as causal context but must acquire its own current source/image facts;
the historical primary frames cannot substitute for actor observations.

`recover_foreground(cleanup_call)` handles an interrupted cycle after the fixture
enters its actual `cleanup` phase. The public cleanup arguments contain only the
existing contract version/run ID; the original authenticated fixture supplies
the cleanup ticket and history. Its birth, exact prior activation prefix and
current cleanup ticket are rechecked before any input and throughout polling.
An unrelated phase, retired fixture, changed birth/PID/session or a replacement
cleanup ticket cannot borrow an old lease.

The original normal-action `phase`, `call`, source headers and observations remain
intact. The new `cleanup` field is exactly null or `{phase,provider,foreground}`:
`provider` is the original full cleanup phase packet; `phase` is
`foreground-issued` or `observed`; `foreground` is null or an independently read
same-process OS status. If already foregrounded, no input is sent. Otherwise the
cleanup intent is saved before one ordinary `app.launch`. A lost launch return
may be resolved by actual foreground observation. An ignored launch, or a lost
intent-write return before dispatch, is never resent and remains unresolved.
Foreground polling is bounded to five seconds/51 reads at 100 ms; the complete
recovery retains the 30-second bound. No foreground-only native/UI source is
constructed or queried during this recovery, including while backgrounded.

The return is private `{emoteForegroundRecoveryVersion:1,header}`. It proves only
recovery ownership and original OS observations. It does not complete the old
action, create native lifecycle/animation/image evidence, refresh timestamps or
allow normal `act`/`retire` to reuse a recovered failure.

`retire_recovery(retain)` requires actual current same-process foreground and the
same actual cleanup phase. Before deleting this lease it durably transfers the
exact packet `{emoteForegroundRetirementVersion:1,header,sourceHeader}` via the
required callback, then reopens the old and current source originals, metadata,
fixture history and OS state. `recovery_archive(packet)` revalidates this original
context without native getters or new feature facts. It uses the existing OS
binding observer and therefore is not an offline/device-disconnected acceptance
reader. The current source may still be an interrupted read; its journal and all
originals remain owned and unresolved. Changed or missing source data, callback
failure, a new background transition or a late retention prevents lease deletion.
Full source/input/scene/view/image/actor retirement and the independent final
native quiet window remain the enclosing feature owner's responsibility.
General Phone teardown attempts base cleanup but refuses success while this
background journal remains, regardless of process shutdown or SDK ACKs.

Registered device-free cases exercise actual Python ownership/replay and the
actual guarded Phone factory through synthetic SDK/OS/native boundaries. They
cover ignored/lost inputs, background reconstruction, native counter absence,
wrong source/fixture/process authority, corrupt originals, pending ordinary
input, failed writes, current phase changes and incomplete retirement. No device,
installation, compiler, build or Jenkins execution is performed.

Historical completed-cycle reads additionally bind the claimed primary namespace
to its actual retained source journal and unchanged original cycle prefix. A
later namespace must have the actual ready inactive predecessor, a genuinely
advancing first native/root/UI/fixture frame and unchanged native call cursor.
Copying a valid source header to another namespace path does not create that
ownership. Keep these original namespace journals until all background joins
and their enclosing retirement proofs have been verified. Missing/changed
journals are errors, not successful empty history. The bound process must still
be foreground; recovery while actually backgrounded uses the separate recovery
path above, without foreground-only native getters.
