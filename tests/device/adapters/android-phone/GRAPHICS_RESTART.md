# Normal explicit Phone Graphics restart v1

`PhoneGraphicsRestart` composes existing `RestartInputs`, ordinary app Stop/Launch,
original native/kernel proof, [version-2 scene/preference transfer](GRAPHICS_RESTART_SCOPE.md)
and fresh ordinary scene reentry. It is an internal input/ownership component,
not a complete `feature.graphics.*` triple. Independent old/new role archives,
fresh post-restart GPU/images, whole fixture/Web lifetime cleanup and the full
Graphics coordinator remain required. Native sources are uncompiled and all
devices remain untested. Host tests execute no application process or device.

## Configuration and durable phases

Construct with the existing adapter/selector, actual attached Graphics `Client`,
run and held exact `phone-script-sources.lock`. `act()` accepts only the closed
v16 `restart-app` arguments. It uses the existing SDK session/candidate input
admission throughout; no session repair, candidate install or alternate target is
available. The private `phone-graphics-restart.json` v1 pins actual fixture URL,
provider birth, exact arguments, full original old scene/preference journals,
original receipt/current source cursors, immutable complete replacement proposals
and recoverable final retirement archives. The separate
`phone-graphics-restart-inputs.json` is the existing original one-send v1 record.

Phases are `prepared`, `observed`, `proposed`, `applied`, `retiring`. Before Stop,
the original controlled scene must already be active, UI leases empty and
preferences ready/acknowledged without cleanup. Both role GPU-owner journals and
background input ownership must be retired. Fresh ordinary scene readiness is
rechecked without replaying earlier Go To input. Original native preference/
lifecycle proof and both complete ownership snapshots are durably saved before
any process input. An interrupted snapshot write can recover only an unchanged
`prepared` input plan; a missing snapshot cannot authorize a later Stop phase.

Stop and Launch each retain original one-send intent before delivery. A lost
return never causes either input to be sent twice. `_graphics_restart_stopped`
shares the reviewed source with Authentication: installed candidate, target,
exact existing session/generation, actual OS state and independent process state
must agree before launch. A stopped OS acknowledgment cannot hide a still-running
process. Unknown/bool status and changed target/install/session are refused.

After launch, new original native PID/birth/lifecycle and actual unchanged
Graphics preferences must satisfy the closed receipt contract. A separate
original native `ESRCH` result must prove the old PID absent. Permission/unknown
is not absence. New subject-v2 and complete new scene-load originals are acquired
and saved with their own retained cursor floors. Run UUIDs must initially be
absent and foreign new-process UI must be closed. Source failures preserve the
observed transaction and do not replay process input.

## Partial application and new process input

The complete exact scene and preference replacements are validated and durably
stored in `proposed` before either owner file changes. Applying a replacement
accepts only that exact old value or that exact proposal. Every write has separate
actual readback. If the second write fails, is ignored, or succeeds with a lost
return, reconstruction skips an already applied proposal and finishes only the
remaining exact CAS write. A foreign replacement is preserved and fails; it is
never overwritten as an owned old/proposed value.

`applied` is durable before normal new-process view input. New scene preparation
uses existing one-send normal Go To, measured eye offset and original native load
drainage. Camera recovery uses the ordinary View menu when needed. The fresh new
preference owner inherits the immutable old originals; it does not refreeze the
changed post-restart values. Repeat action calls independently recheck actual
new scope/readiness/preferences and cannot repeat Stop, Launch or Go To. The
return is exactly `{"performed":true}`, not GPU persistence or feature success.

Each operation has a 45-second whole budget. Existing per-source, input and
scene deadlines still apply; new scene/preference guards also enforce the outer
deadline before possible input. Backward clocks, storage/quota/guard/lock loss,
ambiguous originals and changed CAS scope remain errors. All diagnostics stay
in private ownership files; no target selectors or credentials are exported.

## Verified metadata retirement

After preference and user-scene cleanup, callers must preserve their exact final
v2 archives before retiring those journals. `retire(final_scene,final_preferences)`
requires actual absence of both journals and both GPU-owner journals. It validates
their restored/cleaned state, unchanged original archives and the identical
restart receipt. That retirement plan is durable before final source queries.

Fresh new native preferences must equal the original pre-test Graphics object.
New independent subject and scene-load reads must prove original user-scene/
feet/view/limited foreign inventory, run UUID absence and complete traced scene
load drainage. Accepted retirement source cursors are saved before continuing.
Another fresh native packet must preserve restored preferences and lifecycle.
Only then may the original input plan retire, with independently checked actual
absence, followed by the exact controller CAS record and separate actual absence.
Lost or ignored input/controller removal retains `retiring`; reconstruction may
repeat original proof and metadata removal without any process/UI input. Missing
final archives, foreign originals, rolled-back cursors or incomplete cleanup fail.
This retires component metadata only; the full feature must additionally verify
both observer roles, original PNG/receipt archives and fixture/Web cancellation.
General Phone cleanup refuses either surviving restart journal.

Sixteen focused host cases exercise the real one-send engine/coordinator against
synthetic SDK, OS and native IO with real private journals. They cover normal
restart/restoration, lost/ignored Stop and Launch, unknown kernel proof, lost
preferences, failed/ignored/lost-response partial CAS writes, foreign replacement,
repeated/conflicting tickets, pre-Stop storage failure, live GPU scope, missing new
subject and ignored final input/controller removal. Two actual wrapper cases
cover current stopped observation and changed session/install/unknown OS refusal;
a separate wrapper case prevents forgotten restart journals from green cleanup.
The combined 356-case selection also rechecks scene/preferences/background,
versioned scope transfer and Authentication input/feature regression. These are
adapter/test-logic checks, not physical restart or product qualification.
