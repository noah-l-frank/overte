# Phone owned ordinary Emote effects, version 2

`PhoneEmoteEffects` connects existing ordinary input ownership to original native
Rig measurements. It takes a real `PhoneEmoteInputs` backed by source journal v3;
it delivers no product input, retries no uncertain input, creates no new journal
and advertises no complete Emote capability. Whole image/background/actor and
resource-cleanup coordination remains incomplete. Phone still has
three complete source adapters, with uncompiled native code and no device runs.

Version 2 adds independently acquired actor effects and an explicit result role.
Version 1 results have no role and are not accepted as version 2 originals.
`PhoneEmoteEffects(primary_inputs, current_source=actor_sources)` reopens the
primary immutable input receipts only as stimulus and causal barriers. All current
Rig, VM, Qt and fixture facts come from the actor's own source journal, original
files and fresh acquisition. The constructor requires the same run, fixture root,
candidate/process and held source lock. Actor and primary revision indices are
independent; ordering uses original native and consumed-input times and cursors,
never revision comparisons across roles. An actor's prior playback reference is
reopened from its own originals when checking restoration. Primary effect results
or frame references cannot replace an actor observation. This helper does not
publish actor records or independently authenticate an observer transport.

## Original arguments and ownership

`reference()` returns the source owner's current exact `{revision,sha256}`.
`measure(reference,played=None)` accepts only that latest completed source frame,
a completed current input row and no interrupted source/archive responsibility.
The source and input headers must still match their durable originals. Original
input rows/history must agree with the owning memory state. A digest recomputed
from substituted in-memory facts is insufficient: current, pre-input and prior
play frames are independently reopened through their actual manifest and exact
original device/inode/length/digest/context checks.

The latest frame must belong to the exact run/role/candidate/process, current
input ticket, verb and closed input values on both original fixture reads.
Its native request starts after the original pre-input/consumption barrier.
The actual final Qt input cursor must match the completed input receipts; a
fresh envelope cannot reuse a sample collected before normal input consumption.

A prior play reference has exactly `{inputTicket,frame}`. The input ticket must
identify the latest owned play/Sit/override in the completed input history.
Its actual loaded playback is recomputed from immutable originals; no prior
assertion, name, pose, progress, Sit variant or restoration flag is accepted.
An older play cannot borrow a newer override or a foreign action/phase.

## Measured effects

For play/Sit/override, the original normal Qt button and the native loaded clip
must agree. A consumed Crying button followed by actual Waving fails, even when
the same real manager loaded and evaluated Waving. Actual names, Sit variant,
changed-joint fraction and current active/idle state come from Rig measurement
v2 and original VM caller provenance. Requested names only check causality;
they never supply returned measurements. A completed short clip remains idle.

For `wait-complete`, no product input exists in the original row. Actual selected
native restore and later evaluated idle pose must follow the latest owned play.
Cancellation additionally joins the original active pre-input barrier to a new
selected restore invocation and execution. Native range/rate/time determine the
250 ms early-restoration condition; a delayed automatic restore after an ignored
cancel reports false and cannot satisfy the final common early-cancel assertion.

An independently verified idle Sit-discovery reset has no new active-to-inactive
input. It returns kind `idle-reset`, actual idle state and no qualifying early
restoration. It cannot use a prior play reference to become the final abort.
Open/close without a previous play require actual current native idle. Later
open/close can preserve the original measured restore proof from the latest
play. A wait without an owned original play remains unavailable, even if idle.

Panel visibility comes separately from actual SDK tablet visibility and the
original current native ready Emote page. Open requires a present page; Close
requires both no page and actual closed tablet. Widget highlights never supply
animation or pose measurements.

## Exact result, freshness and failures

The private result has exactly `emoteEffectVersion:2`, actual `role`, `runId`, actual `binding`,
original `call`, current `frame` reference, `playbackReference` or null, `kind`,
measured `state`, and complete recomputed native `proof` or null. Kind is
`playback`, `restoration`, `idle-reset` or `idle`. State has the common six fields:
`animation`, `sit`, `override`, `poseProgress`, `restoredBeforeNominalEnd`, `panel`.
This internal record includes private origins and must not be published as a
public feature result; the complete owner must use the existing public aliases
and original image/actor contracts. No resource-absence claim is supplied.

Each measurement has a five-second overall monotonic bound. Original earliest
configured-root/native and fixture capture must remain within the existing
1.5-second freshness window at final delivery. Host/device clocks stay separate;
monotonic elapsed-age floors detect frozen external epochs, including delayed
provider reads, final guards, validation and returned-copy work. The actual
current fixture status is checked again after joining effects. Historical play
references are validated at their original times and never retimed as fresh.

Ignored or foreign effects, stale/previous-phase frames, missing acknowledgments,
wrong loaded names, unknown plays, corrupt/missing/replaced files, changed durable
ownership, lost guards and delayed delivery fail without another product input.
Originals and unresolved ownership remain intact for the future complete owner.
No cleanup, deletion, timer clearing or native restoration setter is introduced.

Host cases run actual Python input/source/effect logic against explicit synthetic
SDK/Qt/native boundaries, including all ten ordinary buttons. They verify test
logic only and establish no physical Emote success.

## Idle fixture-phase observations, version 1

`phase_recompute(reference)` and `phase_measure(reference)` observe the actual
fixture's `baseline` or `cleanup` phase without inventing a normal input row,
input receipt or acknowledgement. The baseline phase must be the fixture's first
activation; both original source-side phase packets must agree on its real
kind/ticket. An ordinary action cannot be relabelled as one of these phases.
The original selected Script/root/native history must actually observe an
enabled, loaded Rig with no active override. An unowned active override fails.
Panel visibility remains the original UI observation and can report an open
panel when the common test expects closed.

The exact private return is `{emotePhaseEffectVersion:1,role,runId,binding,phase,ticket,frame,state}`.
`frame` addresses this role's actual immutable source original; there is no
`call`, requested value, synthetic input row or ordinary playback proof. Idle,
no Sit and zero override progress are defined absent-override values admitted
only by the real native inactive observation. `restoredBeforeNominalEnd:false`
means this fixture-only phase has no qualified ordinary restoration action;
it does not erase old native restore events, replace previous measured action
proofs or claim that an old early cancel did not happen. Native and input
histories remain unchanged and owned. This is a phase projection, not a cleanup
or resource-absence verdict.

`phase_recompute` only reopens original bytes and derives historical facts;
`phase_measure` also requires the latest complete durable source context,
unchanged original source/input ownership, the actual same current fixture phase,
and the existing five-second/1.5-second native/host freshness bounds through
final copies/guards. Partial source owners, a changed phase/ticket, truncated
in-memory history, a stale reference, foreign/replaced original or frozen clocks
with slow replay cannot produce a current observation. No native observation
request, input or input journal is created by either method. The source owner
must have acquired its actual group first. Actor roles still use their own
source originals.

The existing observation owner now composes these methods with original
phase images using its frame/result version 2. Admission/readiness, whole-run
coordination, actor publication and final quiet/full resource retirement still
need integration before feature registration.

## Historical recomputation from originals

`recompute(reference,played=None,call=None)` reopens original input archives and
role-local source files, then derives the complete v2 effect state/proof again.
An explicit original `call` selects exactly one owned historical input and its
preceding history prefix. A later play cannot replace the original play being
restored. Current widget state, actual loaded file/pose/caller proof and original
cancel barriers remain independently checked. Stored derived state is not an
input to this calculation.

This method performs no target or fixture query and never asserts current
ownership or freshness. It keeps the actual source lock/candidate guard and
five-second monotonic replay bound; missing/replaced originals and late replay
fail. It does not retime evidence. `measure` uses the same calculation with its
existing live journal/provider checks and final 1.5-second delivery limits.
Phone image archive replay also recomputes and exactly compares the full saved
effect, including animation, Sit variant, progress, panel, restoration timing
and original native proof. Correct PNGs cannot legitimize invented stored facts.

Host counterexamples cover historical primary/actor cancellation after a future
play, foreign play references/calls, missing files, slow replay and changed
derived image/effect facts. Full Phone Emotes remains unregistered and native
instrumentation/device qualification remain pending.

## Current background restoration effects, version 1

`background_recompute(reference, previous=..., header=..., image_policy=...)`
reopens this role's complete original cancel observation archive and the actual
completed `PhoneEmoteBackground` header. The prior checkpoint must independently
prove a genuine early cancel with its original native play and cancel barriers.
Its cancel ticket must immediately precede the current background ticket in the
unchanged fixture history. An old cancel cannot be relabeled as a background
input; no new ordinary-input journal row or ACK is created.

Current native facts come from the given role's newly acquired original source
frame. The old cancel's original native frame must precede the actual cycle's
before-frame, and current native evaluation must advance beyond its after-frame.
Actual process/Rig/code/event provenance and the completed native lifecycle
counters remain bound. A new override, extra lifecycle transition, disabled or
unloaded graph, foreign role/history/namespace, changed input phase, missing
original or another actual OS background cannot qualify. Current panel state
comes from the new Qt source, never from the pre-background checkpoint.

The existing Rig restoration verifier recomputes actual idle state and early
restoration from the preserved real play/restore events and cancel barrier. It
does not copy the old checkpoint's state. The closed private output contains
exactly `emoteBackgroundEffectVersion:1`, `role`, `runId`, `binding`, `call`,
`frame`, `previousTicket`, `state`, `proof`. `call` is the original background
input; `previousTicket` is the actual preceding cancel. There are no desired
poses, timing expectations or success flags.

`measure(reference, background={previous,header,image_policy})` requires the
latest ready source, current durable ownership and actual fixture phase, then
enforces the existing independent native/host 1.5-second freshness limits and
five-second total bound. `played` must be absent. Historical recomputation alone
does not assert freshness or successful foreground restoration. Neither path
dispatches input or obtains native/UI measurements; the caller owns acquisition.
The background archive uses the actual bound OS observer and therefore is not
an offline/device-disconnected reader. Image-frame integration and full feature
registration remain pending.
