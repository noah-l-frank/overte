# Phone owned ordinary Emote effects, version 2

`PhoneEmoteEffects` connects existing ordinary input ownership to original native
Rig measurements. It takes a real `PhoneEmoteInputs` backed by source journal v3;
it delivers no product input, retries no uncertain input, creates no new journal
and advertises no complete Emote capability. Images, separate actor publication,
background/resume and whole-resource cleanup remain missing. Phone still has
three complete source adapters, with uncompiled native code and no device runs.

Version 2 adds independently acquired actor effects and an explicit result role.
Version 1 results have no role and are not accepted as version 2 originals.
`PhoneEmoteEffects(primary_inputs, current_source=actor_sources)` reopens the
primary immutable input receipts only as stimulus and causal barriers. All current
Rig, VM, Qt and fixture facts come from the actor's own source journal, original
files and fresh acquisition. The constructor requires the same run, fixture root,
candidate/process and held source lock. Actor and primary revision indices are
independent; ordering uses original native and consumed-input times and cursors,
never revision comparisons across roles. An actor's prior playback reference is
reopened from its own originals when checking restoration. Primary effect results
or frame references cannot replace an actor observation. This helper does not
publish actor records or independently authenticate an observer transport.

## Original arguments and ownership

`reference()` returns the source owner's current exact `{revision,sha256}`.
`measure(reference,played=None)` accepts only that latest completed source frame,
a completed current input row and no interrupted source/archive responsibility.
The source and input headers must still match their durable originals. Original
input rows/history must agree with the owning memory state. A digest recomputed
from substituted in-memory facts is insufficient: current, pre-input and prior
play frames are independently reopened through their actual manifest and exact
original device/inode/length/digest/context checks.

The latest frame must belong to the exact run/role/candidate/process, current
input ticket, verb and closed input values on both original fixture reads.
Its native request starts after the original pre-input/consumption barrier.
The actual final Qt input cursor must match the completed input receipts; a
fresh envelope cannot reuse a sample collected before normal input consumption.

A prior play reference has exactly `{inputTicket,frame}`. The input ticket must
identify the latest owned play/Sit/override in the completed input history.
Its actual loaded playback is recomputed from immutable originals; no prior
assertion, name, pose, progress, Sit variant or restoration flag is accepted.
An older play cannot borrow a newer override or a foreign action/phase.

## Measured effects

For play/Sit/override, the original normal Qt button and the native loaded clip
must agree. A consumed Crying button followed by actual Waving fails, even when
the same real manager loaded and evaluated Waving. Actual names, Sit variant,
changed-joint fraction and current active/idle state come from Rig measurement
v2 and original VM caller provenance. Requested names only check causality;
they never supply returned measurements. A completed short clip remains idle.

For `wait-complete`, no product input exists in the original row. Actual selected
native restore and later evaluated idle pose must follow the latest owned play.
Cancellation additionally joins the original active pre-input barrier to a new
selected restore invocation and execution. Native range/rate/time determine the
250 ms early-restoration condition; a delayed automatic restore after an ignored
cancel reports false and cannot satisfy the final common early-cancel assertion.

An independently verified idle Sit-discovery reset has no new active-to-inactive
input. It returns kind `idle-reset`, actual idle state and no qualifying early
restoration. It cannot use a prior play reference to become the final abort.
Open/close without a previous play require actual current native idle. Later
open/close can preserve the original measured restore proof from the latest
play. A wait without an owned original play remains unavailable, even if idle.

Panel visibility comes separately from actual SDK tablet visibility and the
original current native ready Emote page. Open requires a present page; Close
requires both no page and actual closed tablet. Widget highlights never supply
animation or pose measurements.

## Exact result, freshness and failures

The private result has exactly `emoteEffectVersion:2`, actual `role`, `runId`, actual `binding`,
original `call`, current `frame` reference, `playbackReference` or null, `kind`,
measured `state`, and complete recomputed native `proof` or null. Kind is
`playback`, `restoration`, `idle-reset` or `idle`. State has the common six fields:
`animation`, `sit`, `override`, `poseProgress`, `restoredBeforeNominalEnd`, `panel`.
This internal record includes private origins and must not be published as a
public feature result; the complete owner must use the existing public aliases
and original image/actor contracts. No resource-absence claim is supplied.

Each measurement has a five-second overall monotonic bound. Original earliest
configured-root/native and fixture capture must remain within the existing
1.5-second freshness window at final delivery. Host/device clocks stay separate;
monotonic elapsed-age floors detect frozen external epochs, including delayed
provider reads, final guards, validation and returned-copy work. The actual
current fixture status is checked again after joining effects. Historical play
references are validated at their original times and never retimed as fresh.

Ignored or foreign effects, stale/previous-phase frames, missing acknowledgments,
wrong loaded names, unknown plays, corrupt/missing/replaced files, changed durable
ownership, lost guards and delayed delivery fail without another product input.
Originals and unresolved ownership remain intact for the future complete owner.
No cleanup, deletion, timer clearing or native restoration setter is introduced.

Host cases run actual Python input/source/effect logic against explicit synthetic
SDK/Qt/native boundaries, including all ten ordinary buttons. They verify test
logic only and establish no physical Emote success.
