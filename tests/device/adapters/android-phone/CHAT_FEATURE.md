# Phone Chat public feature owner

The default-off `feature.chat.act|observe|cleanup` facade now composes all 25
normal Chat actions, the mandatory original `text-input` module and common v18
retirement. This is source implementation with host composition verification.
No Android product build, installation, device or physical delivery acceptance
is claimed.

## Inputs and independent originals

The existing catalog → `OverteSession` → Phone adapter → normal target input
path remains the runner. The owner uses original CHAT/Local/Domain/editor/Send/
BACK/Settings/Erase controls. It never inserts messages into a product model.
Original QML model rows, typed persisted history, native keyboard/touch state,
avatar position and lifecycle are acquired separately. The actual running Chat
engine, submitted source and V8 compilation must match the independently reviewed
[source manifest](../../feature_journeys/chat-source-manifest.v1.json).

An explicitly prepared, dedicated assignment client supplies a second original
native receive ledger. Its executable digest is an external reviewed input,
matched against an open kernel executable descriptor, PID/start/boot identity,
owned environment and actual source/result descriptors. Its native source and
fixed normal send operations share that actual peer identity. An E2E-only lease
pauses the fixture's existing trajectory, captures its stable original position,
performs bounded near/distant stimuli and restores the actual original position.
Outgoing ACKs, producer payloads, primary rows and peer heartbeats never become
remote receive events.

The original private domain controller stops/restarts only its owned mixer.
HTTP process state must converge with actual native node absence/presence in
both receivers and the peer control source. A restarted mixer requires a fresh
native identity. Offline Send is an actual local-only echo; reconnection sends
nothing. The common three-second quiet window rejects delayed replay. Explicit
retyping and normal Send produce the independently observed remote retry.

The separately credentialed observer reacquires every original source and its
own fresh screen PNG. It publishes only measured facts under the original phase
ticket. Original actor-journal GET entries resolve uncertain POST replies;
neither ACKs nor retimed old samples can prove publication. Both image paths
reuse the existing native-screen artifact owner and original after-capture view
check. The controlled assignment client is the independent delivery peer; these
PNG captures are two fresh acquisitions of the primary Phone view.

## Closed preparation

`OVERTE_PHONE_FEATURE_CHAT=1` requires the existing bound debug Phone candidate,
the separately credentialed adapter fixture reader, and a private configuration
file selected by `OVERTE_PHONE_CHAT_CONFIGURATION`:

```json
{
  "chatFeatureVersion": 1,
  "artifactRoot": "/private/existing/artifacts",
  "peer": {
    "chatPeerFixtureVersion": 1,
    "actorConfiguration": "/private/domain/chat-actor-config.json",
    "domainReady": "/private/domain/domain-ready.json",
    "actorArtifact": {
      "sourceRevision": "<independently reviewed 40-character revision>",
      "artifactSha256": "<independently reviewed 64-character AC digest>"
    }
  }
}
```

These placeholders are explanatory and fail actual validation. The existing
domain fixture's explicit `--feature-chat-receiver` option prepares the dedicated
actor. The facade attaches to that already owned process; it launches/discovers
no actor and changes no product behavior. Its artifact revision must equal the
primary candidate's independently verified revision. The controller URL is the
original private loopback domain receipt, with redirects disabled and bounded
reads/timeouts. Configuration and all ownership/artifact paths retain private
mode, symlink and inode checks.

Admit a private controlled profile with Tablet/editor/keyboard closed and an
actually empty original Chat history: absent, null, empty string, empty list or
empty string-list. A nonempty/foreign history is never overwritten. The native
history lease preserves original type and absence, plus unchanged Chat config;
its fixed-key typed atomic SettingManager restore retains ordinary signals.
Missing compiled-code, native keyboard, touch, pose, actor/kernel, mixer, image
or phase abilities keep the feature red.

Chat observer grammar is version **6**, with exactly
`featureObserverVersion`, `area`, `target`, `candidateArguments`, `fixtureUrl`,
`actorToken`, `durationSeconds`; `area` is `chat`. No expected message, desired
state or peer identity is supplied there. Historical v4/v5 cannot claim Chat.
Central integration owns the union with other observer areas and probe pins.

## Error recovery and full retirement

Private version-1 CAS journals retain candidate, phase and original source
ownership before mutation. Immutable digest-addressed blobs retain original
frames and bounded compressed journal headers. They are historical evidence,
never substitutes for fresh observations. A reconstructed reader pins original
source instance/counter/time and append-only receive history.

Lost Send replies are resolved from original native/storage/peer effects without
re-sending. A partially focused Type can resume an absolute editor replacement
under the same original phase. Cancelled partial acquisition keeps its journal
until required original sources recover, then retires the actual acquired leases.
Cleanup durably stages ordinary Erase/BACK, original typed history handback,
peer pose handback, actual online mixer, and both native cache retirements.
Uncertain post-restore journal replies cannot repeat Erase or retime handback.

Common v18 closes the actual fixture, waits for the separate actor's original
closure proof and calls cleanup again to select strict `finalize()`. Finalization
rechecks the original UI/history/receive sources, released touch, actual pose and
foreground process. It unlinks only pinned original command/result inodes after
native retirement, independently requires the actual native result descriptor
to be released, verifies original PNGs, archives immutable retirement evidence,
then removes live authority journals. Interrupted unlink resumes its original
closing intent; a replacement inode is preserved and fails. Repeated finalize
rechecks fresh primary sources and actual peer descriptor/name absence without
recreating IPC ownership. Private immutable JSON/PNG audit artifacts remain.

## Verified boundary

`test_chat_feature.py`: 20 host cases, including the full public facade/common
25-action replay, 27 checkpoints, fixture closure and repeated finalization;
ACK-only primary/peer sends, absent mixer effects, stale/replaced source,
missing keyboard/compiled code, lost replies, failed handback, held native FD,
modified PNG, late held touch and independently credentialed publication.
`test_chat_foundation.py`: three original text-module cases including ACK-only,
missing keyboard and actual synthetic probe drift. Eighteen private actor-file
cases include interrupted unlink and replacement-inode refusal; 94 native
reader/peer/process/receiver/UI/source-semantic host cases pass.

The host composition executes actual Python readers, normal input wrappers,
contracts, CAS files, retained file descriptors, loopback phase/actor journal
and original domain HTTP control handler. Native source/widget/network/kernel
qualification producers are explicitly synthetic. No real Agent, mixer, Appium
server or Phone runs in these tests.

Earlier source packets also compiled and executed the original QML/Qt6 normal
controls, native peer/cache/file helpers, and the actual SettingManager.cpp +
MOC with fixed history restore/signals; ChatView header syntax passed. Their
isolated build scripts require a unique `--build-dir` inside this checkout:
`phone-chat-native-test.py`, `phone-chat-peer-native-test.py`,
`phone-chat-history-native-test.py`. The peer/helper producers remain synthetic;
Agent.cpp, MessagesClient.cpp and TestScriptingInterface.cpp product translation
units, complete Android builds and every real-device behavior remain unverified.
