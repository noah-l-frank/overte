# Owned ordinary Phone Graphics scene v1

`PhoneGraphicsScene` owns normal scene entry, measured viewpoint alignment and
original scene restoration on one existing Phone process. It supplies no full
Graphics operation/capability or feature verdict. Native sources are uncompiled;
all devices remain untested. Explicit restart transfer, complete settings/action
ownership and the independent Graphics coordinator remain required.

## Scope and durable intent

Construct with the existing adapter/selector, an attached Graphics `Client`,
the run ID and the already-held exact `phone-script-sources.lock`. The private
`phone-graphics-scene.json` v1 CAS journal pins candidate/session/process binding,
actual fixture URL/provider birth, original subject-v2/scene-load packets,
all accepted source cursors, original restoration URL, immutable first scene
ticket, actual derived target feet, UI leases, action intents and final proof.
No session repair, fixture activation, direct camera/avatar/entity setter or
automatic restart is available. A changed process/source birth is refused.

`prepare()` accepts an initial serverless HTTP/HTTPS/file scene only when all
seven run UUIDs are absent, the camera is perspective `first person look at`,
actual body orientation is upright yaw and agrees with the camera, and no foreign
Tablet/Go To editor is visible. Two independent original subject reads establish
the restorable starting feet/orientation/scale/view and observed foreign entity
inventory. Initial native request and queued-delivery groups must all be drained
and the actual current scene-load generation must have committed that resource.
Unsupported starting state fails before ordinary input and remains untouched.

Each unique `enter`, `align`, `restore-close` and `restore` action is durably
issued before any UI mutation. Every ordinary surface input preserves its
original subject packet, optional original Qt metadata and control identity.
Tablet/address/menu ownership is saved and read back before input; fresh actual
absence precedes lease release. Original URLs retain all non-location encoded
query bytes. Allowlisted input URLs are derived exclusively from frozen original
or controlled scene/actual target feet. No arbitrary saved URL is adopted.

## Fresh original readiness

Entry uses normal Go To with zero feet and identity orientation. Readiness
requires all seven exact native controlled entities, actual scene URL, unchanged
original avatar model scale, no foreign entity in the explicitly limited subject
scan, and the independently observed committed/drained current native request.
Editor dismissal and HTTP delivery cannot establish these product facts.

The second ordinary Go To derives feet as `actualFeet + controlledCameraPosition
- actualCameraPosition`. This uses measured avatar/camera offset, never an
assumed eye height. Fresh subject and load observations must then establish the
actual controlled camera pose/projection, target feet and original model scale.
The independently read provider must additionally contain a completed original
successful scene response before the final native subject request. These setup
originals do not substitute for a subsequent fresh GPU/image Graphics sample.

Only reads retry: at most 101 readiness acquisitions and 20 seconds per wait,
within a 45-second whole prepare/restore budget. Existing per-source/input
timeouts remain in force. Backward clocks, changed identities, missing original
results, incomplete source inventories or CAS/guard/lock loss fail closed.
Successfully issued navigation is never redelivered after a timeout/lost return.
Recreating an owner restores its original cursor floors and issues only actions
whose durable intent does not already exist. A superseded live owner cannot
overwrite or retire a newer owner's originals.

## Restoration and retirement

`restore()` closes only owned UI, normally navigates once to the frozen original
scene/feet/orientation, and independently proves all seven run UUIDs absent,
original camera mode/position/rotation/FOV/aspect, original avatar feet/rotation/
scale and unchanged observed foreign entity UUID/digest inventory. All native
scene-load reference groups must be drained and the actual current generation
must have committed the original resource. Camera/feet tolerance is 1 cm,
orientation is 0.001 per component with quaternion sign equivalence, FOV/aspect
0.001 and model scale 0.0001. Foreign coverage is exactly the native 128 m,
1024-entity `graphics-spatial-v1` scan; it is not global world preservation.

Uncertain restoration preserves ownership and remains red. A later call may
prove the actual already-delivered restoration through new sources; it never
replays that Go input. An untouched reservation can retire without navigation.
An already restored owner reacquires independent original proof on each call.
`retire()` requires restored state and empty UI leases, repeats that proof, then
discards the exact private CAS record and independently verifies actual absence.
General Phone cleanup refuses any remaining scene journal; stopping a process
does not establish restored persistent/UI/world state.

Fourteen focused host cases exercise normal entry/alignment/restoration,
recreation without replay, ignored world input, pending native groups, lost
entry/restoration responses, preserved foreign UI/unsupported camera, changed
foreign spatial content, leaked run entities, replaced native birth, competing
owners, ignored journal removal and forged action URLs. They use synthetic
SDK/native boundaries and real private host journals, proving test/adapter logic
only. A separate actual adapter-wrapper case verifies the whole-cleanup refusal.
