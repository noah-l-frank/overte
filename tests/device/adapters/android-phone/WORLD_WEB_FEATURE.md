# Phone world Web feature adapter

The default-off `feature.world-web.act|observe|cleanup` facade composes all
nineteen current common v17 browser checkpoints with the existing Phone Appium
adapter. This packet implements the feature extension; the separately required
`world-web-video` foundation still needs `web.reference.*` input registration.
The complete catalog area must remain red until that foundation is implemented.
No device or physical acceptance is claimed.

Normal Running Scripts URL entry loads the unchanged owned `client.js`. The
script creates its original local Web entity and echo receiver. Native Android
pointer events activate the original controls. Text goes through a native
`InputConnection`; no DOM value assignment, handler invocation or JavaScript
click supplies an input. Read-only geometry determines where the original
control is, with bounded native keyboard scrolling and current view/creation/
grant/page guards. The served original fixture adds named ordinary Reference
and B links and a visible foreign-origin heading. It retains the original echo
protocol and deliberately has no cooperative origin filter.

The E2E-only native provider retains actual completion callbacks once per
native document identity, original script-facing requests, actual script
replies, and unchanged passive DOM histories across view reconstruction.
Original trusted Send attempts and matching page receives remain separate.
Its retained native histories are bounded and never evicted into an empty
success. The opaque response ID from the actual native current DOM joins the
independently read original HTTP response inventory. A server restoration does
not change the current document; only normal Reload can load its new 200 body.
No host GET, input receipt, requested state or expected counter is a measurement.

Each role acquires its own native, DOM, service, lifecycle and Java-fenced view
inventory. The publisher uses a separate actor credential and never invokes
primary observe or receives its normalized state. A shared original-source lock
serializes only the fixed transport files. Source-clock/phase/process/installed-
candidate checks surround acquisitions. Normal input intent is persisted before
one delivery; a lost return cannot authorize replay. PNG capture intent and
original inode/hash metadata are persisted in the private artifact directory.

Cleanup normally stops only the owned original script, verifies native and
Java authorities/queues are absent for three seconds, explicitly retires the
owned native history, and independently observes the restored empty baseline.
Double cleanup is supported. Finalization waits for the independently sampled
actor's own three-second window and original fixture retirement, then removes
active host journals through a durable retirement plan. A completed immutable
retirement artifact remains with original run evidence; repeated finalization
rechecks the native retired source. Unknown/replaced ownership remains red.

## Private configuration

Set `OVERTE_PHONE_FEATURE_WORLD_WEB=1` only for the existing candidate-bound
controlled debug Phone target. `OVERTE_PHONE_WORLD_WEB_CONFIGURATION` names a
mode-0600 file inside a private mode-0700 directory:

```json
{
  "worldWebConfigurationVersion": 1,
  "artifactRoot": "/private/current-module-artifacts",
  "foreignFixtureUrl": "http://controlled-second-listener:port/feature-fixture/v1"
}
```

`artifactRoot` must be the runner's actual current module artifact directory.
The primary origin uses the existing separate adapter-only fixture-access
configuration. The foreign origin must be a different resource-only listener
of the same controlled browser fixture. Reader and actor credentials remain
separate. The independent `script_observer.py` configuration version 3 accepts
`area:"world-web"`; it reconstructs the original private configuration from the
existing owner, never from a new environment override. No observer is started
by the adapter or host tests. Device execution belongs in the Proxmox Jenkins
laboratory under the existing policy.

## Checked scope and remaining qualification

Seventeen focused host cases cover the complete common journey, actual loopback
HTTP response IDs/404/restoration, source/history counterexamples, separate
credentials, one-send intent, default-off registration and original cleanup. Resumed retirement plans acquire another original three-second
native/Java/service absence window and verify the original saved PNG files,
inodes, sizes and hashes before active journals can be pruned.
Native events, pointer/IME boundaries and PNGs in those cases are explicitly
synthetic. Existing passive DOM and HTTP fixtures retain their own checks.

The actual `EmbeddedWebView.java` and all common Web helpers compile against
local Android API 34, AndroidX WebKit 1.12.1 and Core 1.1.0. The actual new C++
provider and grammar compile and run with Qt6Core against synthetic item/JNI
seams. The complete Android C++ translation unit and Test/probe integration
are not compiled; an Android build and real-device behavior remain unqualified.

Focused commands:

```sh
python3 -m unittest discover -s android/phone/tests/device -p 'test_world_web*.py'
python3 -m unittest discover -s tests/device/self_tests -p test_browser_resources.py
python3 -m unittest discover -s tests/device/self_tests -p test_native_web_dom.py
python3 android/phone/tests/world-web-source-contract-test.py --build-dir build/world-web-source-contract
```

The native contract check requires prepared Qt6Core, a C++ compiler and the
existing local JDK headers; it creates a new build directory. It is not an APK
build or a replacement for Android compilation. Do not promote any acceptance
or global complete count from host results. The parent integration must
recompute the source-bound Emote admission pins once after all concurrent probe
changes; this feature does not regenerate that catalog or learn expected values
from a target.
