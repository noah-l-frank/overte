# Phone Lifecycle/Input implementation

The default-off `feature.lifecycle-input.act|observe|cleanup` triple now
composes the complete common contract v18 journey, independent actor/image
joins, mandatory foundation capability gates and the fixture-closed finalizer.
Source/host composition is implemented. Android application compilation and
real phone acceptance remain unqualified.

## Original editor source v1

`Test.phoneLifecycleEditor` requires the default-off Phone E2E build,
`--testScript`, existing native lifecycle/private-results scope and real
OffscreenUi/Tablet providers. `phone-lifecycle-editor-{observe,input}` accepts
closed requests and writes original responses through the existing owner-only
atomic private file channel. Read-only command admission allows observe only.

`PhoneLifecycleEditor` walks the real rendered tree, binding the exact canonical
PathUtils-configured original Create, armored Chat and Running Scripts QML URLs
and their original `newText`, `textArea`, `filter` identities. A same-named field
from another QML source is unavailable. Weak page/context/field/window identities
receive non-reused opaque tokens only after real acquisition. History retains
creation/retirement times and current alive/attached/active facts. Temporary
background visibility loss preserves the same actual Chat identity; a destroyed
and recreated Scripts editor receives a new identity. Request order supplies
no generation. The public reducer joins these originals to its owned
workflow before exposing shared generation facts.

Current text/focus/frame and actual platform keyboard visibility are original
reads. Keyboard visibility comes from Tablet's validated Android runtime metrics,
not QML keyboard requests. Only empty or the corresponding closed per-run Create,
Chat or Scripts draft may leave the source. Unexpected private drafts, missing
roots, ambiguous current fields or invalid identities return unavailable.

Focus uses the ordinary Qt pointer route. Type uses the existing native IME
helper on the actually focused field. Neither directly invokes a QML handler,
sets text/focus properties nor submits a draft. Native input consumes its nonce
before a source/token lease can fail; an uncertain/rejected admitted command
cannot replay. The Python transport persists supplied intent before one send,
then requires fresh independently correlated originals. `performed` is an input
receipt; no text, keyboard, focus or complete feature result is inferred from it.
The existing five-second operation, 1.5-second freshness and bounded history
contracts remain. Missing/dropped/retimed source histories remain red.

Local component tests compile and run the actual new Test method, original
Create/Chat/Scripts QML pages, native pointer/IME helper, PendingFieldCommitOwner
and actual PreparedFieldCommit implementation with Qt6. A real held IME event
is rejected by its original context guard after destroying the old Scripts
page and creating a new unfocused empty page. Backend services, native test
lifecycle, PathUtils deployment roots and OS-IME metrics are explicit host seams.
Those tests do not attest Android IME, application rendering, a full Android
translation-unit build or device behavior. Separate reader/probe counterexamples
cover input ACKs without effects, closed grammar, missing original sources,
read-only mutation refusal and immutable weak identity history. Central admission
pins and global profile counts remain integration-owned.

## Original world input and motion sources v1

`phone-lifecycle-world-input` owns one normal hardware ArrowUp gesture through
the actual original primary render QWidget. The reviewed keyboardMouse mapping
routes Up to forward locomotion in the supported normal camera modes. No input
mapping, avatar property or drive key is assigned. Its original native event
object must actually reach Qt's event-filter dispatch before `pressObserved`
can appear. A focused QML editor may normally consume the key without changing
its draft; the separate actual effective-drive sample must then remain neutral.
`performed` does not supply a displacement, drive or dispatched-gesture count.

The Phone-E2E-only `KeyboardMouseDevice::e2eForwardKeyObservation` reads the
original device's actual Up channel and original current button map. The original
Application update samples this source, original feet, grounded state and both
effective/raw drive keys **after** the normal real user-input-to-drive transfer.
Each motion frame retains its own native instance/sequence/timestamp. Reading an
input response does not retime an old motion frame. Missing, stale or changed
original frame identity stays red. The full reducer joins current motion,
grounded baseline feet, phase/input histories and independent image/actor facts.

One original press lease lasts at most ten native monotonic seconds. There is
no keepalive or caller-selected extension. Explicit release, actual focus loss,
the original precise timer and owner destruction send only that original Up's
normal key release. Actual release/filter history and subsequent independent
button/effective-drive/position evidence remain necessary. Foreign preexisting
Up cannot be acquired, foreign release cannot release another run, and a late
unowned Up event makes the source unavailable. This is an exclusive test-input
scope; arbitrary concurrent physical writers are not an exclusive keyboard
identity guarantee. A missing original release never becomes cleanup.

The closed reader enforces candidate/PID/native-clock guards, independent motion
freshness, immutable native histories, single-send persisted control intent,
bounded timing and observe-only actor admission. Historical restore accepts only
original read observations, never relabels a mutating receipt as a current read.
These primitive sources alone do not advertise a complete area capability.

Component tests compile and execute the actual new Test method, real native
Qt keyboard dispatch/filter/timer, original KeyboardMouse press/release/channel
methods, original InputDevice button reader and the new passive source. They
also wait through the actual ten-second watchdog. Controller ABI/plugin setup,
application physics and original feet/drive producer values are explicit host
seams. The insertion in the complete Application update is source reviewed;
the full Application/Android translation unit is not compiled by that component
check. No hardware input, phone rendering, Android IME or device acceptance is
claimed. The source/host facade and mandatory foundation gates are described below.

The Phone-only weak field/window/QQmlContext identity registry is shared with
the existing PendingFieldCommitOwner. Its original held-event field token must
equal the real generation-3 editor's field token; the later actual current
Scripts token must equal the genuinely new generation-4 editor's token. No
Python association or copied source filename substitutes for that join. The
registry keeps dead weak references and never reuses their tokens. Existing
non-Phone pending-owner token behavior and wire schema remain unchanged. The
native Qt test compares both observers around a real original held IME event,
actual old-page destruction and a real new Scripts page before guard rejection.


## Public composition, independent actor and retirement

Enable only with a bound verified debug Phone candidate, the existing Phone E2E
and `--testScript` profile, `OVERTE_PHONE_FEATURE_LIFECYCLE_INPUT=1`,
`OVERTE_ANDROID_E2E_TEXT_INPUT=1`, `OVERTE_E2E_VOICE_TESTS=1` (the existing native
text-test compile/runtime prerequisite), an actual forward movement control and
the embedded controlled scene profile. Missing `text-input`,
`tablet-input-isolation` or `lifecycle-under-load` mandatory capabilities prevent
advertising the triple. Existing normal tablet controls are reused. These gates
do not qualify an absent native hook: unavailable source/IME/render/backend
observations remain red when acquired.

`OVERTE_PHONE_LIFECYCLE_INPUT_IMAGE_POLICY` names an owner-only private JSON file
with the existing exact `{imageExtent, markerRoi, imagePolicy}` world-render
contract. `OVERTE_DEVICE_ARTIFACT_DIR` remains a private resolved directory.
The existing separately scoped adapter fixture credential admits only original
phase metadata. The independent observer uses current `featureObserverVersion:4`,
`area:lifecycle-input`, its separately supplied actor token and its own original
source frames. It cannot issue editor/key/retained-event input. The narrow new
pending-owner read-only admission accepts only its existing closed `observe`
request. Primary observations and desired states are never actor observations.

Actual canonical QML page/context/field histories determine generation. Original
observed hardware-key deliveries determine world attempts. The retained original
IME event must join the original generation-3 field token, survive actual old
context retirement and reach the actual guard rejection against the distinct
new generation-4 field. Expiry, explicit release, a requested replacement or a
performed ACK cannot supply a stale attempt. Position delta and displacement
come from original native feet relative to the independently acquired grounded
baseline; the independent existing probe must corroborate actual feet, complete
fixture markers, serverless scene and renderer progress. Existing original
scene-load request/queued-delivery histories must independently show the actual
current scene committed with every traced lease closed.

All UI inputs use normal existing SDK tablet/app controls, native pointer/IME,
actual Android Back, ordinary Home/background and activation, and ordinary
controlled scene reload. The actual Chat field identity/draft survives background
with fresh OS/kernel/PID/lifecycle proof and actual focus/keyboard absence. A
held world forward key reaches real normal input mapping. The original controlled
wall contact must settle under the normal five-second input-effect deadline
while forward remains effective before acquiring a challenge marker; no view
lease, mapping override, drive setter or avatar setter is used. A source unable
to provide the required actual supported forward/contact behavior stays red.

Four image phases independently acquire original world-render-target PNG bytes,
recorded renderer frame/view, actual marker object, current original Browser/Java
inventory and current challenge. Original view leases are forbidden. Existing
strict PNG transport and inode/bytes/SHA validation are reused; internal PNG
filenames use the existing `navigation` evidence-engine vocabulary, while their
full candidate/session/run/role/stage bindings and the enclosing Lifecycle owner
remain exact. Every sample has new original acquisition identity and its own
public sequence/timestamp. Neither a fresh filename nor a marker-input receipt
proves rendering or movement.

Private CAS journals persist one-send input intent before every mutation. An
uncertain input is never replayed. Immutable original source frames and bounded
manifest indexes retain their actual inode/bytes/SHA under the existing 64 KiB
journal cap. Historical archive validation is local under the original OS lock;
it queries no SDK and supplies no fresh target observation. Interrupted original
writes resume only the exact owned byte prefix. Interrupted PNGs require exact
owned inode retirement intent and actual absence; unqualified foreign files
remain unresolved. Every source read keeps the existing candidate/process/native
clock guards, five-second operation and 1.5-second freshness. Native holds remain
ten seconds, with no keepalive. Normal facade scope is bounded at 45 seconds,
matching the existing Navigation scope; marker readiness/retirement windows are
bounded at ten seconds and do not enlarge individual source deadlines.

Cleanup releases only the owned original key/event, closes the owned tablet,
uses normal scene reload only when actually displaced, drains original marker,
Browser/Java/callback and GPU/binary receipt ownership and requires stable actual
neutral position, focus, keyboard and context state. Both roles independently
owe at least three actual observations over three seconds. The finalizer checks
that window against immutable original frames rather than trusting a journal
boolean. Contract v18 additionally requires original fixture closure and the
actor's newly acquired closed-phase original. Every finalization retry, including
a saved retirement plan or already pruned completed receipt, acquires a NEW
three-second absence window within five seconds. Native, pending-event, scene,
account and renderer histories must continue from the archived originals and
between every new quiet sample. Late input/context/scene/Browser/GPU work,
missing or replaced PNGs and incomplete primary/actor quiet ownership stay red.
A retained immutable completed receipt keeps strict repeated cleanup discoverable
without leaving active role/owner journals.

## Local evidence and limitations

The unchanged common full journey runs through registered public operations,
separate actor publications, actual private source/manifest files, byte-decoded
PNG challenges, release quiet and v18 dispatch/finalization on explicit synthetic
Android/kernel/physics/renderer producers. Counterexamples cover ignored input,
no-effect ACKs, field/context aliases, private drafts, foreign/unrecorded key
ownership, stale/retimed/dropped histories, missing scene closure, source resets,
late native work after an old plan, incomplete primary quiet/actor closure and
missing or same-bytes foreign-inode PNGs. The existing all-14 common composition
and ignored-effect checks, all-14 closed-phase dispatcher checks and existing
mock text/lifecycle/core tablet-isolation positive/negative modules also execute.
Those synthetic producers establish host composition only.

Actual local Qt6 component binaries compile and execute the original editor QML,
Test methods, pointer/IME helpers, shared field identity registry, original
retained event guard, original KeyboardMouse methods/InputDevice button reader
and actual native event filter/ten-second timer. Prepared build dependencies are
used only in this isolated worktree's new `build/lifecycle-*-native/qt-*`
directories. Application physics/controller ABI, deployment backend services,
Android IME/OS lifecycle and graphics remain explicit component seams. The full
Application/Android translation units and real device behavior are not qualified.
No device, installation, Jenkins run, remote network, push or GitHub write is part
of this work. Central integrated source/admission pins and global count profiles
remain parent-owned and must be regenerated centrally after source union.
