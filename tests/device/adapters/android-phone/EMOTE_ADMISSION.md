# Phone original Emote admission, version 1

`PhoneEmoteAdmission(source, policy)` owns read-only baseline admission through
the existing source lock, original Source/Input/fixture context and private
file engine. Run owner version 3 requires it before View/Scene setup. Source
version 4 additionally enforces executable/world approval on every current
primary/actor frame. This supplies no public feature triple, gesture/rendering
success, credentialed actor or whole-run retirement. Native instrumentation is
uncompiled and all device behavior remains untested.

## Explicit policy and fixed source catalog

The private policy has exactly `domainUrl`, `domainId`, `domainMarkers`,
`probeUrl`. Use the existing fixture environment's controlled domain URL, UUID
and sorted unique marker list. The URL is credential-free `hifi` with an explicit
port; the UUID is non-null canonical lowercase. Markers use the existing
`OVERTE_E2E_DOMAIN_[A-Z]+` grammar. The Phone debug launcher copies the unchanged
probe asset to its private files directory. Its explicit URL is one of:

- `file:///data/user/0/io.github.noah_be.overte.phone/files/overte-e2e/overte_e2e_probe.js`
- `file:///data/data/io.github.noah_be.overte.phone/files/overte-e2e/overte_e2e_probe.js`

The selected URL must match the actual assigned probe manager. No observed URL
or unknown target hash is learned as an approved expectation. Keep policy and
originals private under the existing evidence privacy rules; public facts must
use the existing normalized projection, not these private control headers.

The fixed `phone-emote-admission-pins.v1.json` contains version, source commit,
six allowed normal Phone manager paths, 440 allowed runtime dependency paths,
the copied probe pin and the exact native `(boundRequire)` helper pin. It pins
actual UTF-16LE code-unit length/digest from commit `6e886b2a35`; it is never
generated from a client response. Runtime `defaultScripts.js` uses the actual
Phone QFileSelector variant. The dependency catalog permits bundled executable
dependencies; top-level managers remain restricted to the six normal startup
paths plus the one pinned probe. Default and probe are mandatory; any other
actually present manager must be one of those approved normal children.

JSON dependencies identify the native compiler's actual
`module.exports = JSON.parse(__json)` shim at the known bundled path. This
establishes executable shim bytes, not runtime JSON input contents. Domain,
avatar, image, animation and other feature-resource content retain their own
mandatory independent checks. Compiled helper/dependency records are never
reported as gesture execution or UI effects.

Reproduce the fixed catalog locally without a compiler or target:

```bash
python3 tests/device/generate_phone_emote_admission_catalog.py
```

`--write` explicitly reproduces that fixed commit's catalog. Updating the source
commit/pins is an explicit reviewed source change, not an automatic compatibility
fallback. Host tests additionally compare current repository source bytes and
the actual native helper literal. All-known native membership must be complete
and match the actual engine inventory. Unassigned, foreign, duplicate or stopping
managers, unapproved compilations, missing top-level compilations and unapproved
require paths fail. A loaded require event must have its own actual compilation;
the `cached` field reports cache reuse, so a successful first instantiation with
`cached:false` remains valid.

## Actual read sequence and bounded readiness

For each record, the owner first journals reading responsibility, then acquires
one new role-local Source frame. It observes the existing passive animation
inventory and a new configured-root fence, independently reads the original
world probe through `probe.snapshot` in the already bound session, then obtains
the final fixture phase and clocks. Native queries receive only their existing
schema/nonce/action fields. There is no prefetch, resource repair, normal input,
setting change, timer deletion or expected-state argument.

Original configured roots bracket submitted/compiled sources and inventory.
PID, native birth, root sequence and timestamps remain coherent. The actual
assigned/compiled probe must match the fixed probe bytes. Its independently
acquired snapshot must be fresh, running/foreground, connected to the expected
domain UUID/host/port and actually observe the complete expected domain markers. Marker counts must
be coherent with the observed entity count.
Serverless, foreign, stale or unready worlds fail. Probe sequences cannot regress;
repeated sequences must retain identical actual snapshots.

Every one of the twelve source-derived animation URLs must have exactly one
actual passive-cache entry, loaded successfully with its original full FBX parser
model and fixed actual resource-byte pin. Valid missing/loading entries alone
may warm up. Duplicate entries, explicit failures, wrong loaded bytes or model
identity fail immediately, even while a different resource is still loading.
An absent result/hook or malformed packet is an error, not warmup.

Admission needs three independently advancing probe samples whose actual sample
epochs follow their own source fences, with ready caches and unchanged observed
entity count. Repeated samples do not add observations. The observation limit
is 32 records, each read has a five-second bound and original 1.5-second
native/host freshness, and the wait has a 30-second monotonic bound with 250 ms
gaps. Final file, phase and guard work stays inside freshness. A wait always
acquires a new original before returning, including after historical recovery.

## Original records and failure ownership

`phone-emote-<role>-admission.json` has exactly `emoteAdmissionVersion:1`,
`runId`, `fixtureUrl`, `role`, `binding`, `artifactRoot`, `policy`, `payload`.
The existing packed payload holds `{phase,records,pending,window}`. Phase is
ready/reading/admitted. Records are compact inode/hash-bound original references;
window is null or the three actual eligible record indices. It is recomputed
from originals on reconstruction, never trusted as a saved success flag.
Pending is `{index,original}` with the existing planned/opened/saved descriptor.

Each immutable `AdmissionOriginals(kind="admission")` file contains one record
with exactly `source`, `inventory`, `rootsAfter`, `probe`, `phaseAfter`, `epochMs`,
`hostEpochMs`, `monotonicMs`. Source references this role's actual original
revision/hash. The existing 1 MiB original and 64 KiB control limits are unchanged.
All original source/cache/probe epochs and identities remain unchanged.

Failed writes, missing originals, changed policy, ignored journal commits and
lost results retain responsibility. `recover_pending()` can finish only a real
complete opened/saved original by reopening its exact bytes/inode/context. It
does not query the target, replay an input or return fresh admission. `wait()`
then needs a new actual read. Partial/missing files or a pending acquisition
without an original cannot be silently replaced by a new query.

The owner removes no journal or original file. General Phone cleanup refuses
either role's remaining admission control. The enclosing complete adapter must
transfer and verify these originals as part of whole-run retirement, including
the failed-admission/no-setup case. That retirement, public observations and
credentialed actor publishing remain required before full capability registration.

Host counterexamples cover foreign/late code and worlds, stale/frozen probes,
missing/bad cached models, ignored commits, lost original returns, missing files,
false windows, policy changes, checked/unchecked role contexts and original image
archive replay. These simulations qualify test/adapter logic exclusively.


## Original context retirement, archive version 1

`retire(retain, retained=None)` transfers either admitted or failed admission
originals during the real cleanup activation, under the actual held source lock.
Interrupted readonly Source acquisition must be transferred first: admission
retirement requires a ready source with no pending read. It obtains fixture
input metadata only; no native/UI/cache/probe getter, gesture, new approval or
public cleanup result is produced. The existing five-second deadline includes
original reconstruction, retention, revalidation and metadata removal.

The exact packet is
`{emoteAdmissionArchiveVersion:1,header,sourceHeader,originalDiagnostic,cleanup}`.
Header is the unchanged v1 admission owner; sourceHeader freezes its exact
historical source context. OriginalDiagnostic uses the existing actual
partial-file descriptor for an opened original. An absent result, absent planned
file or verified saved file is represented by null according to the original
file engine; missing saved files never qualify as absence. Cleanup is the actual
original cleanup phase snapshot. Run birth and complete activation history must
still agree when reusing a retained packet.

`PhoneEmoteAdmission.archive(packet, source, expected_policy)` reconstructs the
closed historical source, inventory, world, Script and file contexts. It returns
the original admission state only, with the same phase, records, window and
pending responsibility. No usable live owner or fresh result is returned.
Reading failures remain reading failures. Missing, foreign, replaced, corrupt or
partially rewritten files cannot borrow a valid admitted header. Historical
replay preserves epochs and performs no target or fixture query; it also works
after source journals have advanced while their original files remain intact.

The real retainer must persist the exact packet before the admission journal is
removed. A rejected/lost callback, changed phase, slow validation, ignored discard
or changed original keeps ownership. The same retained packet can finish a lost
retirement return with no new source data or timestamps, including when the
actual admission journal was already removed. Current source admission, native
quietness, Scene/View restoration, actor lifecycle and whole-run retirement are
separate requirements. Failure-owner v2 now integrates this operation into Run
input cleanup after both roles' source failures have been retained. Successful
primary approval must match the parent's original pinned admission hash.

Host checks cover both roles, successful approval, absent cache results,
planned/opened/saved original interruptions, lost retirement returns, frozen
historical replay after new reads, foreign policy/context, changed derived
windows and failed admission before any View/Scene input. Native compilation
and device qualification remain unperformed.
