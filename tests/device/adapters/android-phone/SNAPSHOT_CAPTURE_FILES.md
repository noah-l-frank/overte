# Original capture-file ownership v1

This component implements source acquisition and retirement. It does not
advertise the complete Snapshot feature triple. The public facade still owns
normal input, pinned Script provenance, renderer/encoder/native-core quiet,
independent actor credentials and common v18 fixture-closed finalization.
The outer Snapshot observation remains v5. Central probe/code admission pins
must be regenerated by the integration owner after all source packets land.

`PhoneSnapshotCaptureFiles` extends the existing `AndroidSnapshotFiles`
private `run-as` binary transport. The adapter factory is
`_snapshot_capture_files(selector, artifact_root, owner_path, read_only=False)`.
The artifact directory and ownership-journal parent must already be private,
absolute, canonical directories. The caller serializes the shared probe channel;
the owner holds a separate bounded OS lock for its private journal.

- `plan(scope32, prefix)` persists a unique operation ID before native preflight.
  The independent original OS namespace and native preflight must be empty.
  Repeating an existing plan reads its original history and any later owned
  outputs; it never sends capture input. Prefixes have the normal UI's existing
  48-character bound. Foundation `parity-<16hex>-<kind>` prefixes use a separate
  explicit stable scope; extended `e2e-<32hex>[-suffix]` scopes are not adopted
  from foundation history. Multiple disjoint prefixes may share one scope.
- `acquire(original_path, captureId)` accepts only a completed original native
  capture and its actual opened/closed file. It returns `path`, `captureId`,
  `bytes`, `sha256`, `device`, `inode`, `artifact`, `capturedEpochMs`,
  `nativeClosedEpochMs`, `fileId` and `source=snapshot-capture-original`.
  The original path is a read selection, never delete authority. A fresh
  independent OS identity/digest, actual bounded binary read and second original
  OS/native read must agree. No caller digest, body or successful result is used.
  `capturedEpochMs` is sampled after this acquisition; historical native close
  time remains separate. An existing artifact is actually verified, and target
  bytes are reacquired rather than refreshing an old artifact's timestamp.
- `files(prefix)` retains the existing foundation `{files:[{basename,artifact}]}`
  shape. `inventory()` includes every actual owned output, including partial
  writes and failed/cancelled captures. Pending or unqualified files never
  disappear into a successful empty list.
- `binding()` exports the original candidate/process/session/scope and native
  instances/plans. A separately created read-only observer uses `attach(binding)`
  and independently reads original target bytes into its own private artifact
  directory/journal. It cannot plan, delete or seal target resources. Its
  `retire()` removes only its host copies, then requires actual primary target
  retirement. Observer credentials and role registration remain facade-owned.
- `retire()` persists file-ID/operation-ID intent before one native delete
  delivery. The native registry checks the original plan, capture, root,
  descriptor identity, closed original bytes/digest and actual absence. It
  retains original failed/open-failed/product-removed outputs too. Lost replies
  resume by newly reading the original intent/absence; an ignored delivery is
  never resent with a new operation. Each namespace is sealed only after all
  known captures/files close and original target files retire. Host files use
  durable planned/opened/saved/remove-intent records and original host inodes.
  An interrupted owned publication can resume only from its actual matching
  prefix and a newly acquired original body. Same-byte foreign inodes are never
  adopted. A planned-file collision or missing unretired saved copy remains red.
- `require_retired()` freshly checks all original native histories, actual OS
  namespaces, seals and host absence. Retired histories are never hidden when a
  later scope begins. Late target/host files, missing history, changed instances,
  roots, original identities, bytes or permission errors remain red. The receipt
  journal is retained; the public owner decides final phase archival.

`Test.phoneSnapshotCaptureFiles` and the closed
`phone-snapshot-files-{observe,control}` probe routes are available only for the
default-off Phone E2E build with `--testScript` and the existing lifecycle/test
root guard. The read-only command policy permits observe only. Native plan,
retire and seal commands accept closed IDs, not arbitrary caller paths. Native
and Python histories are bounded at 64 entries per category and preserve the
existing five-second request/1.5-second observation freshness contracts. The
binary transport retains its existing 256 MiB/90-second transfer ceiling.

The supported exclusion is an exclusive run-owned namespace and cooperating
normal capture producers. Descriptor callbacks do not alter normal QFile/
GifCreator opening flags, writes or normal failure cleanup. Observed identity
or body mutations are rejected. POSIX stat followed by unlink does **not**
provide atomic inode-conditional deletion against arbitrary external writers;
this is not claimed for either target or host files. Uncooperating same-UID
renames/writes are outside the exclusion boundary. Original directory identity
and a fresh namespace scan are still required; permission errors are not absence.

Local component checks compile the unchanged real Snapshot save functions,
the unchanged GIF worker against a prepared real GifCreator header, the actual
new Test method, and the new native registry with Qt6. They execute real PNG/GIF
encoding, original FILE/QFile closes, inode/digest reads and unlink, including
normal production/non-Phone guard profiles. DependencyManager, account/address,
UI, capture scheduling and lifecycle are explicit host seams. Fixed shell/binary
transport checks execute on real host files with a synthetic target source
producer; they are not Android shell/SELinux acceptance. No complete Android
translation-unit/application build, rendering, device test, installation or
hardware acceptance has been performed. Public foundation/feature integration
is handled in the parent Snapshot composition packet.
