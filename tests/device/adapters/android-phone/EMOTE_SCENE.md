# Owned Phone Emote domain scene, version 1

`PhoneEmoteScene` composes the normal prepared [view](EMOTE_VIEW.md), actual
[fixture input/inventory](../../native/PHONE_EMOTE_FIXTURE.md), original avatar
resource/render metadata, actual domain entity scan and native/Java Web runtime.
It owns these fixture resources and its diagnostic files. It provides no Emote
input/effect, current PNG, independent peer or whole-feature verdict and enables
no complete capability. Full Emotes remains incomplete; native code is uncompiled
and every device remains unqualified.

## Scope and normal preparation

Construct with the real `PhoneEmoteView`, its held source lock, private artifact
root, integral image extent and marker ROI. Those external construction inputs
use the existing strict fixture-input grammar. No device/session repair, install,
launch, domain navigation or camera/setting setter is added. The real normal
view owner has already selected Selfie/zoom; setup requires actual baseline.
Native factory guards pin the current original candidate/process/SDK through
local archives, inputs, file IO and final delivery.

A baseline separately acquires actual configuration/APK bytes, avatar/render,
world virtual-pad release, domain scan and native/Java Web inventory. The actual
view/pose/resource observations must agree. The world must still be `hifi`, have
all seven unrelated run-owned Graphics UUIDs absent and at most 256 scanned
entities. Both native snapshots and Java views/queued creations must have no
preexisting ownership of this run's Browser root. The enclosing session still
must prove the controlled domain UUID/host/markers and approved Script/content
membership. This component does not turn a URL or spatial scan into that proof.

The original projection predicts only fixture INPUT geometry. Every backdrop/
marker bounding sphere must lie within 120 meters of origin, inside the existing
explicit 128-meter spatial scan. Current normal view/loaded avatar identity and
actual pose must remain unchanged. Only then does the existing private fixture
helper persist the exact command/binding/current fixture phase BEFORE sending.
Current prepare ticket is checked again there. Lost returns reobserve the exact
original native lease; object add is never repeated. Missing/mismatched leases,
ignored creation or failed file ownership remain red and keep responsibility.

Fresh fixture originals must match the issued command and separately pass
actual UUID/object/geometry/view/property readiness. Original native/Java Browser
observations must independently agree on the actual marker document, handle,
creation, grant, page, source hash and loaded/authorized foreground state. Browser
loading may be polled, with a new original each time. Original foreign entity
IDs/property hashes must remain identical, excluding only the actual two owned
fixture IDs; scan count must change by exactly those present nodes. This is the
existing bounded `graphics-spatial-v1` property scope, not global world/history
preservation or live mesh/material immutability. No input ACK or requested shape
is returned as measured product success.

## Original records and phase fences

Private `phone-emote-scene.json` is exactly `emoteSceneVersion:1`, `runId`,
`fixtureUrl`, actual `binding`, `artifactRoot`, `imageExtent`, `markerRoi`,
`payload` (existing bounded packed codec). Decoded record is `phase`, `revision`,
`manifests`, `pending`, `prepare`, `release`, `window`. Phase is reserved/baseline/
preparing/active/releasing/released. A prepare/release record is exactly
`command`, `binding`, `fixturePhase`; release must match the actual original
fixture instance. Original fixture phase is fresh, active and appropriate to
baseline/cleanup. Old activation tickets never authorize new input/publication.
Wrong phase before acquisition emits no input and leaves the old journal usable.

Scene frames use the existing exclusive/private inode/digest/manifest file engine
through `SceneOriginals(kind="scene")`. Ordinary source/input readers retain their
original closed kind set; old inline/foreign files are never migrated. Each
record is exactly `emoteSceneFrameVersion:1`, `kind` (baseline prefix, then
fixture), `frame`. Frame is exactly `configuration`, `avatar`, `touch`, `world`,
`web`, `phaseBefore`, `phaseAfter`, `epochMs`, `hostEpochMs`,
`hostStartedMonotonicMs`, `hostObservedMonotonicMs`; fixture records additionally
contain the original `fixture` packet. Device and provider/host clocks stay
separate. Native main-observer births/PIDs, actual root poses/views, immutable
APK pins and each original counter/history must agree; Browser/Java independent
instances retain their own existing history contract.

A pending record is exactly `index`, `kind`, `original`, `manifest`, using the
existing planned/opened/saved descriptors and at most 1 MiB per immutable record,
128 records per manifest and 1,024 records per scene. Metadata remains at the
existing 64 KiB limit. Intent precedes native requests and file creation. Final
write/guard/copy cost belongs to delivery freshness. Historical reconstruction
reopens original actual inode/digest-bound files, never queries/retimes them or
trusts substituted memory. Partial/missing/foreign originals, failed writes and
lost metadata remain owned failures. Original evidence files are retained as
private diagnostics after successful resource retirement.

Every source group is bounded to five seconds and 1.5-second original native/
provider freshness, with monotonic age floors through final journal work. Whole
prepare/cleanup/retire methods have a 45-second deadline and bounded 32-read loops.
No expected animation duration or successfully acknowledged mutation supplies
an actual result. A slow final completed record remains historical and is not
returned as fresh setup.

## Independent cleanup and stable retirement

Only active cleanup authorizes release. The command uses the independently
observed original fixture instance, and its own durable one-send intent precedes
dispatch. Lost delete returns reobserve; they never repeat deletion. Unknown
scope or unresolved pending acquisition never becomes assumed-empty cleanup.

Each cleanup sample must independently prove actual node absence AND zero live
original node references, complete native/Java Browser drainage using existing
`released`, original domain/foreign property preservation and native touch
release. Node absence alone cannot hide a live Browser, queued creation or
callback. Browser absence alone cannot hide an original retained node.

The current contiguous suffix must contain at least three such samples and span
at least 3,000 ms in BOTH original native and host monotonic clocks. The last
native request must be at least three seconds after the first sample's final
native time; last host request must be at least three seconds after first host
observation. Any busy sample resets the suffix. Frozen clocks or adding separated
quiet periods cannot satisfy it. Window metadata is only `{start,complete}`;
historical replay reopens every original in that suffix and recomputes the proof.

`retire(retain)` obtains another original node/Browser/world/touch group and
extends that same proven suffix. The parent must durably retain the exact fresh
original proof before child journal removal; failed retention, changed candidate,
changed phase or late Browser reappearance leaves the child owned. Reobservation
also works after the separate view owner restores the original camera/preference;
actual root pose/model/domain/foreign state still must match. Parent Emote Script
work/UI/image/source/actor cleanup remains additional required work.

General Appium teardown refuses any remaining scene journal, including unknown
or partial data, even when base SDK teardown reports success. Nineteen registered
Phone host cases exercise actual normal UI composition, typed readers, real
private files and independent synthetic native boundaries. Counterexamples cover
ignored/lost input, wrong leases/world state, retained nodes/Browser callbacks,
late busy work, frozen clocks, stale final delivery, replaced/partial originals,
phase/candidate changes and failed parent retention. These qualify test logic
only, never target behavior or device acceptance.


## Closed provider ownership transfer, version 1

`retire_closed(retain, retained=None)` runs after actual fixture retirement and
the completed active cleanup drainage window. It obtains a new actual native
fixture/world/avatar/configuration/touch/Browser group between two inactive
provider packets. The original lease, cleanup ticket, provider birth, activation
history, native cursors, original avatar and unowned world must remain continuous.
Actual node references, Browser callbacks/creations and contacts must still be
released. It sends no prepare/delete input and never appends inactive packets to
the active-only `emoteSceneFrameVersion:1` originals or changes their manifests.

The exact parent-retained envelope is `{emoteSceneRetirementVersion:1, header,
frame}`. `header` is the original released scene control, including its immutable
manifest references and completed drainage suffix; `frame` is the new closed
native group. `retirement_archive` reopens every old inode/digest-bound original
and revalidates both the three-second suffix and the closed native group before
handoff. The mandatory retention callback runs before control removal. Rejected,
late or failed retention and ignored removal cannot report success.

A lost deletion return requires the caller's exact retained envelope, whether
the original control is still present or already absent. Historical retry checks
original files and actual retired-provider continuity, never emits new native
facts or changes epochs, and removes only the identical old control. Missing
metadata without that packet fails. The transfer is limited to five seconds;
new groups also retain the existing 1.5-second freshness through final deletion.
The actor, source/role streams, normal input and whole-feature journals still
require their own complete retirement. These host cases establish test logic
only; native code remains uncompiled and devices remain untested.
