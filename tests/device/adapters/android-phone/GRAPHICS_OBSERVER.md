# Independent Phone Graphics observations, version 1

`PhoneGraphicsObserver` composes the original GPU/native/UI/PNG sources for one
role. The complete feature coordinator is still missing; no full Graphics triple
is advertised. These host-tested Python sources qualify test logic only. Native
instrumentation is uncompiled and all physical clients remain untested.

## Scope and original acquisitions

The constructor requires the role's separately credentialed
`GraphicsFixtureReader`, role `primary|actor`, the already-held existing
`phone-script-sources.lock`, canonical private artifact directory and an external
`world-render-target` image policy. Normal existing-session factories bind the
actual installed candidate, PID/start, SDK session/generation and target identity.
The component never calls ordinary input, navigation, app launch/stop, fixture
register/activate, direct Entity/Render settings, or primary observe on behalf of
an actor. General Phone cleanup refuses either role's observer journal.

`read(after_sequence,stage)` accepts only a cursor already reached by this role
and process stage `0|1`. The future complete coordinator must authorize the
current fixture ticket/input completion and explicit restart stage before this
call, under the same lock. A stage is scope admission, never measured state.
Every read obtains the actual fresh fixture phase and read barrier, saves durable
`reading` intent, and acquires new originals through
[`PhoneGraphicsSamples` v3](GRAPHICS_SAMPLES.md) and the bounded
[original marker-readiness wrapper](GRAPHICS_READINESS.md).

The private `phone-graphics-<role>-observer.json` version-1 envelope binds run,
fixture/provider birth, role, artifact directory and image policy. Its compressed
hashed payload retains process binding, stage, public sequence, original source
clock floor, provider history, first baseline frame, last actual frame, actual
off-reference frames, original effect comparisons, process-transfer proof and
pending intent. Each underlying sample still has its separate complete durable
source/retirement/PNG ledger. Limits are 256 completed role observations and 64
original effect pairs. State bounds/quota failures remain red.

The first observation requires an actual baseline phase, closed Graphics page
and no shown owned Tablet resource. The six public baseline values come from
that original frame, including arithmetic measured viewport/target scale and
actual executed Haze/Mirror batches. Requested preferences never supply measured
scale or effect. `baseline()` returns this historical measured projection only;
no later frame is retimed as its original. Every public observation uses a new
original role-specific PNG, the actual ticket/clock, native lifecycle and actual
resource inventory. The existing v16 result validator checks the public shape.

## Actual target pixel effects

Actual native settings and executed passes identify each role's own most recent
off reference; caller inputs do not create one. At the actual Haze/Mirror action
phase, an observed on setting requires the role's original off/on PNG pair and
[`compare`](GRAPHICS_EFFECTS.md). It independently checks fixed recorded view,
source/native/fixture continuity, unchanged other settings and original target
ROI statistics. Haze must change the far-board blue dominance; Mirrors must
change the actual reflector's orange reflection. Valid setting/pass counters
without that target-pixel effect fail. Ignored input remains measured false and
cannot borrow the requested true result. Common journey expectations still
independently decide whether such actual false state satisfies the checkpoint.
Every completed comparison retains both complete original frames and measured
statistics. Historical decoding recomputes the comparisons from the exact
private original PNGs. There is no cached successful effect verdict.

## Separate explicit process transfer

A changed PID cannot be silently adopted at stage 0. A requested stage-1 transfer
requires this role's actual prior baseline/last frame and unchanged candidate,
SDK session/generation and target identity before new acquisition. This role
obtains its own new-process native/UI/GPU frame and separately issues an actual
kernel old-PID query. Original native births must differ, launch count advance
exactly once, activations/backgrounds retain the existing monotonic contract,
preferences persist, and GPU capture birth change. The exit packet must query
exactly this role's observed old PID, report actual ESRCH, and belong to the same
new Test birth as this role's fresh native frame. Unknown/EPERM or merely changed
PID is insufficient.

Both complete old/new frames and bindings plus the original independent exit
packet are retained. The old baseline and old effect originals keep their actual
process identities/timestamps. Old off references cannot cross a process boundary.
The actor never copies the primary restart receipt, old frame, new frame or exit
packet. The complete coordinator must additionally bind this admitted transfer
to its durable ordinary restart controller and the separately observed fixture/
Web lifetime histories; this component cannot authorize a restart itself.

## Phase races, failure and final retirement

A completed acquisition is retained under its original ticket before a changed
confirmation is reported as `GraphicsPhasePending`. A phase race inside final
confirmation also saves complete original facts without leaving an artificial
pending read. Neither path publishes old facts as current. An actor whose source
acquisition itself crossed a ticket may use only the same live sampler's exact
[`retire_changed_ticket()`](GRAPHICS_SAMPLES.md) proof, with measured native/file/
journal retirement and fresh changed-phase confirmation; its next read needs a
new GPU frame. Unknown captures, bad provenance or incomplete retirement cannot
use that recovery. Other interrupted `reading` states remain red on recreation.
The complete owner must explicitly resolve/retire them; a new CLI cannot silently
reset them or replay inputs.

The whole observation has a 30-second budget. The stricter 1,500 ms native/image/
fixture freshness bound still applies. Final phase I/O and source-guard latency
count, including a separate elapsed-age floor from actual acquisition so frozen
clocks cannot hide late confirmation. `publish` is actor-only and sends only the
role's fresh measured projection through its own credentialed Client. The shared
journal independently rejects a retired ticket, old clock or actor cursor.

`archive(...)` reads only original role packets and private PNGs, with no adapter,
SDK, repair, input or new facts. Missing/replaced PNGs, rewritten process/effect
history and wrong role/run/policy fail. Journals and original PNG diagnostics stay
retained. The future whole-run retirement plan must verify both roles, all stage
sample/fixture/Web proofs and final ordinary scene/settings restoration, save
exact archives, then discard each exact journal and independently verify absence.

## Host counterexamples

Twenty-four observer cases plus seventeen fixture-reader cases exercise actual
source readers, real private PNGs/CAS journals and explicit synthetic HTTP/native
boundaries. They cover both independent roles, actual haze/mirror target effects,
ignored input, counters without pixels, old/foreign source cursors/frames/files,
private write loss/ignored writes, each role's separate new-process/ESRCH proof,
changed candidate/session, native restart persistence, phase changes during
acquisition/final confirmation and frozen late clocks. The actual Phone cleanup
wrapper additionally rejects both retained role journals. These simulations are
not Android compilation, APK/device execution or physical acceptance.
