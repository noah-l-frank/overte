# Original Chat input dispatcher

`ChatDispatcher` version 2 composes the fixed common Chat inputs through
`ChatFlowInputs` v3 and the existing concrete input owners. It reads only each
recipe verb and its closed inputs; checkpoint states and witness facts never
drive an input. Baseline uses the separate original absent-cache sources. The
first normal Open owns both actual native v3 cache births through
`ChatCacheLifetime`, binding each original instance, self hash, PID, run and
exact source-lock object to that original baseline before any UI input.

Every step durably records its ticket and fixed route before child input.
Ordinary Open/type/channel/Send/Return/Close use `ChatNormalInput` v2; peer sends
use the original consumed `ChatPeerSend` input; the distant peer uses
`ChatPeerDistant`; background uses `ChatBackground` v2; the mixer uses
`ChatMixerOwner`; and recovery quiet uses `ChatNoReplay`. Factories are lazy and
must return those exact concrete classes with the exact parent role objects.
The distant sender is the same original peer owner. No callback can replace a
route with a Boolean success, receipt, requested state or expected effect.

The separate `ChatPhaseFence` obtains original fixture HTTP frames with its own
reader and nonce history. Every input marks its original phase/native-clock
anchor before its child CAS; the actual command publication checks the exact
same active ticket and full activation prefix after that CAS and the final
candidate/process guards. Each part of Type/Open has a separate fence. This
covers native cache creation, normal Pico QML commands, peer command-file
publication, mixer HTTP, background timer ownership and normal HOME/Resume.
Background phase reads use only HTTP and the original non-Qt epoch source.
Neither a new phase response nor a frozen host clock refreshes time spent in
the original CAS. Original phase frames are retained as immutable proof chunks.

The ordinary controller route reads its fresh phase before entering the
original input-session lock. Its original `stage(intent=...)` callback retains
the exact controller envelope in the parent journal before the native grant and
checks the original host elapsed-age bound after that write. This callback is
host-only: no ADB, guard, PhaseReader or session reentry. Version 1 journals are
retained without adoption.

After actual child closure, the dispatcher archives the exact original child
root packet and its canonical SHA-256 in the existing immutable private
`ChatSourceChunks`. Normal v2 roots carry the current original attempt and
completed-attempt chunk manifest; `rowIndex` identifies that original attempt.
They do not repeatedly embed the growing packed v1 history. The child journals,
their own immutable chunks and all original source transcripts remain owned.
The dispatcher then obtains two new original full source transactions through
`ChatFlowInputs.finish`, confirms the same original fixture ticket, and checks
native clocks and the 1.5-second wall-time bound after its final copy and writes.
These measured states are not synthesized from the archived child packets.
The separate credentialed `ChatWitness` still obtains its own new originals.

A lost child, input, archive or manifest response poisons the current session.
There is no warm failure overwrite, automatic resend, old-frame refresh,
adoption, truncation, reset or retirement API. Original `reading`/orphan writes
refuse reconstruction. Cold construction can audit historical root packets;
`history()` is historical data only, without current measured state or a whole
feature success claim. Cold owners cannot resume inputs, including after a
completed prefix, because not every lazy child yet has a passive reconstruction
contract. A new original run does not acquire an old unresolved run's journals.
Pico base teardown also refuses green if the dispatcher root or a reserved
immutable chunk name remains. A missing root never retires its children.

Focused host checks compose all 25 real child steps and the baseline using
explicit synthetic SDK/widget/native/network/process/time boundaries. Separate
fresh Witness transactions are compared with the unchanged shared checkpoints;
ordinary Send receipts cannot supply the independently observed peer history.
The test also exercises real private files/FD ownership for the synthetic peer
input producer. This is host composition, not actual device, service, OpenXR,
Agent, network or Overte executable execution. The dispatcher alone does not
close normal Erase/profile restoration, native input-file release, original
process/Qt retirement, final independent absence or public Pico feature wiring.
The complete Chat capability remains partial.
