# Original independent Chat publication reads

`ChatRemotePublication` version 2 passively joins actual independently received
fixture rows to an originally live independent host process and its actual
Actor3 publications. It constructs no live Actor, native reader, cursor or
publisher from private files. It sends no input, publication, Stop command,
source query or replay. Public Chat capability remains disabled.

The original typed Parent supplies its own `PhaseFixtureReader`, exact shared
source-lock instances, all twelve fixed source paths, original Actor instance,
run/fixture/bindings and the actual `LinuxChatObserverProcess` acquired while
that reviewed program was live. The Pico factory uses the Parent's original
peer clock and unchanged installed/native/peer guard. Constructor admission
does not discover a process or infer native AssignmentClient build provenance.
Its new private result root must be absent, including rootless chunks. Generic
application cleanup retains that root and every orphan child.

`acquire(after_sequence)` takes the last actually consumed **Actor** sequence;
it is neither a primary-observation count nor a phase offset. The reader takes
both original source locks and loads the actual initial/active/cleanup stage
prefix. It checks:

- Original private root bytes/stamps, complete chunk inventory and physical
  signatures captured before loading and compared after loading. An admitted
  immutable child can never be adopted with a new inode, even with equal bytes.
- Exact original Actor PID/instance/bindings and captured-pair grammar; the
  returned-publication certificate must match the actual publisher row, both
  original root values and both original physical stamps.
- The same pure complete source grammar used by the terminal historical graph:
  native Chat/peer/UI/keyboard/lifecycle, compiled V8 source transactions,
  original input authority, observation references, global cursor continuity
  and projected actual publication payloads. Full Script history additionally
  uses `original_history`, without creating a native reader or callback.
- The actual fresh independent phase and journal GET. Every received row must
  equal its original publication. An extra unreturned POST is refused, never
  truncated. A new phase without a returned current publication is an expected
  wait before foreground guard or result intent. Actual fixture retirement is
  terminal. An unchanged Actor sequence also waits without creating a result.

Only the actual initial cursor shape may omit `nextStage`: its original writer
adds that field at the first stage selection. Active/cleanup prefixes and the
terminal full graph keep the explicit `nextStage=None` requirement.

Every returned read persists a new immutable chunk with the original Actor
bytes/stamp, actual publication, independently received journal and literal
original bytes/stamps/digests of every source root used. Root transitions may
extend the same admitted chunk prefixes; they cannot replace old children or
change a source scope. The validated cache includes exact JSON types, root
paths, lock paths, original signatures, manifests and chunk byte accounting.

Actual primary and peer clocks qualify the original source epochs after the
fresh phase/journal read, final private CAS/fsync, copies and guard. The oldest
epoch belongs to the actual referenced observation frame, including its original
compiled transaction; a later unconsumed source frame cannot refresh it. The
original 1.5-second host/native bounds extend through actual outer lock exit
and final physical/cache checks. A ready-looking disk row after a lost/late
CAS or lock-exit failure cannot qualify the warm reader. The failed object
retains originals and refuses another read. A cold result root is not adopted.

This is a live observation component. Its source proofs and result history
still need the actual common cleanup-consumption callback, exact consumed
prefix/Stop2 intent and complete historical typed graph/process return join.
The reader has no method claiming common three-second cleanup, successful
shared execution, either-eye stereo, source retirement or whole-feature
closure. Its original process descriptors remain owned by the Parent; this
component neither closes them nor claims their final lifetime.

Version 2 additionally preserves the original read's host-monotonic start and
primary/peer/phase/journal epochs in each immutable record. Under the exact
Parent locks, `fresh_current()` verifies that same original record and current
phase, then checks those unchanged original clocks. `released_fresh_current()`
checks the same epochs after actual outer lock exit without a foreground guard.
Neither method acquires a newer native sample. A later unconsumed Actor frame
cannot make an older consumed frame fresh. `freeze(command)` binds the exact
version 2 Stop request to the last consumed record and blocks further
acquisition. It writes no Stop file and supplies no Stop-delivery ACK. Legacy
version 1 roots remain historical/retained; their missing clock anchors are
never invented or cold-adopted. The actual common consumption/one-write join is
documented in [the remote cleanup prefix](REMOTE_CLEANUP_PREFIX.md).

The source fixture uses a real separate owned Python stdin worker, actual
original Actor/publisher/cursor/source writers and real process/OFD admission.
The worker executes the actual initial sample, ordinary first Open, active
selection, cache retirement, cleanup selection and one extra fresh same-phase
publication. Native producers/clocks, Parent provenance, the remaining 24
input rows and HTTP transport are explicit seams: the Parent's model Client
requests the worker's actual independent `Journal.phase/snapshot` over stdin.
No product, AC, device, service or network server starts. Production HTTP and
the full Pico factory constructor with this source fixture remain unqualified.

The first two-case run was red at initial-prefix admission while the unchanged
terminal graph passed (11.569 seconds). The initial cursor field boundary was
then made exact. The next positive traversed all stages but failed a test-only
expectation that the real process guard returned `None`; it returns `True`
(14.274 seconds). A seven-case run passed the source positive and five counters
but its replacement test changed a child before asking the producer to publish;
the producer correctly refused first (22.754 seconds). Reordering that counter
to publish before the replacement tests the passive reader's own refusal.
That counter plus actual outer-lock failure, replacement during load and
same-canonical cache-type mutation passed 4/4 in 4.963 seconds.

The final serial selection passed 12/12 in 40.939 seconds: all eight new reader
cases, both unchanged terminal graph cases and the actual Pico unknown-process
refusal/rootless-retention checks. The complete stage-prefix positive uses
real separate host lifetimes and physical files with the explicit seams above;
it does not qualify a product HTTP or whole Chat execution.

## Pure warm prefix admission

The full common-executor diagnostic in
[the remote archive notes](../pico4/CHAT_REMOTE_ARCHIVE.md) reached its unchanged
120-second cap. At 60 publications the original complete historical grammar
cost 0.251174 seconds on one retained literal graph. The reader now uses
`ChatSourceGraphPrefix` only for pure grammar: old admitted frame hashes,
original expected context and fixed paths, completed flow-row hashes, cleanup
identity and stage prefix must match exactly. Strict JSON checks reject tuple,
dict-subclass, Boolean/number aliases and mutated cache values before hashing.
The current local reviewed Script pins and original file bytes are qualified
again on each call; a changed pin cannot reuse an old compilation admission.

Every new code/sample/observation/cursor/publication row still runs the original
full row grammar, including its full prior continuity. Complete Script native
history is replayed on every call. All root schema, revision, scope and
cardinality checks run on every call. The default terminal/historical graph
validator always performs the complete grammar and has no prefix by default.

The pending candidate is only a pure validation result. No caller-supplied or
copied candidate can commit, and an uncommitted candidate supplies no skipped
prefix. The live reader commits that exact candidate only after its original
outer lock exits and its original final cache/physical/native clock checks
pass. It then repeats the final checks, so a slow cache commit cannot move the
original deadline. A failure still latches the complete reader and retains its
originals; there is no source replay or cold cache restoration.

Physical behavior is unchanged: every acquisition still reads every complete
root and every child byte, validates the original chunk manifests and physical
signatures, compares every previously admitted child identity, performs full
directory inventories and final root-byte/stamp checks. The pure prefix is
never a file, source, process, release or freshness receipt. No wire, source
version, observation cadence, resource limit or 1.5-second bound changes.

Six pure admission/counter tests passed in 5.938 seconds. The real two-process
stage-prefix positive, final-CAS native jump and outer-lock failure passed
3/3 in 8.917 seconds. Four original physical/type/late-cache-commit counters
passed in 3.439 seconds, and retirement/unreturned-post/original-clock/freeze
checks passed 4/4 in 3.219 seconds. A pure historical repeat of the same
60-publication graph took 0.028861 seconds with the strict prefix, about 8.7
times faster for grammar only. No live owner or fresh sample was constructed
by that diagnostic; no new full execution or closure result follows from it.

The subsequent actual warm-source profile identified repeated complete
directory inventories as a larger cost than decoding: 143 Actor verifications
included 0.949 seconds in inventories under profiling. `ChatSourceChunks`
therefore still enumerates the entire actual directory on every verification,
using `os.scandir` entry names instead of constructing pathlib objects for
every unrelated file. Exact expected numbered names, unexpected-prefix/orphan
refusal, original child signatures, byte loads/hashes and all final checks are
unchanged. No directory contents or negative lookup is cached.

Eleven focused inventory/identity/lost-write/clock/limit/legacy checks passed
in disjoint selections of 5/0.294 seconds and 6/0.131 seconds. New counters
cover a matching directory appearing after a successful check and five
noncanonical/temporary/foreign frame names; no query or adoption follows.
A read-only inventory benchmark over the same retained directory (664 actual
entries, 61 original publisher children, 100 complete scans) took 0.239872
seconds with the fixed old implementation and 0.042356 seconds with the new
complete name scan. This comparison qualifies only inventory overhead; it is
not a fresh target sample or another successful whole journey.

The existing 355-frame/256-joint scaling case subsequently passed unchanged
in 10.646 seconds with the new complete name scan. It preserved all 355
originals across reconstruction without queries, retained the original flat
limit refusal and then acquired one genuinely new source frame. Together with
the disjoint checks above, all 12 chunk cases passed. The complete common
executor/application/archive/host diagnostic has not been rerun after this fix.

Two pure strict-type-walk prototypes were measured and not adopted. Over ten
passes through the same 61 retained records, unchanged recursive checking took
0.083093 seconds versus 0.108231 seconds for an iterative cycle-safe walk. A
minimal same-recursion/single-type-lookup variant measured 0.075832 seconds
against 0.083174 seconds for the original. These small historical measurements
do not justify a new cache/type mechanism; the original strict type walker is
unchanged. Profiler call costs alone are not treated as uninstrumented speed.

## Version 3 complete original bundles

New live writers use `chatRemotePublicationVersion=3` with the same complete
original record fields. [Source bundle parts](SOURCE_BUNDLES.md) change storage
only. The root adds ordered `bundles`, exact `logicalBytes` and `pendingBundle`.
Every actual physical part remains in the original `chunks` manifest and
counts against the existing 512-frame/16-MiB budgets. Uncompressed logical
original values additionally retain the original aggregate 16-MiB limit.

Before the first part, a durable `reading` root records the complete original
reference (part count/raw byte count/SHA). Each actual part commit advances
the same unresolved root. Only after every part has been reread under its
original scope/identity/index/manifest and the complete original reconstructed
byte-for-byte may the root become `ready`. A lost middle-part or ready-root
reply latches the original reader; complete-looking files are not adopted and
no publication/query/write is repeated. Native/phase/journal epochs, final
copies, source locks and final native/host age checks remain unchanged.

`original(index)` and pure `original_record(...)` reconstruct complete historical
logical values under the actual original part identities. They perform no
native query and grant no current/fresh observation or live owner. Explicit
v1/v2 historical roots retain their original single-chunk interpretation;
missing clock anchors or fragments are never manufactured. New constructors
still reject every existing root. The cleanup prefix accepts only actual warm
v2/v3 clock-bearing sources. The return join rereads every complete original
record through the same typed decoder, and the existing archive catalog
captures every root/part from its actual history; a logical record count cannot
omit physical fragments.

The real two-process four-record stage-prefix test now verifies six original
parts and exact reconstruction of every record (1/1, 6.106 seconds). Cold v3
storage reconstruction, historical v2 retention and original native-jump/
outer-exit refusal passed 3/3 in 3.314 seconds. Actual lost-middle-part and
lost-ready-root counters passed 2/2 in 5.860 seconds. The eight remaining
original phase/extra-post/physical-replacement/type/old-clock/freeze counters
passed in 6.439 seconds. A separate pure v1-storage test passed in 0.063
seconds; it restores no missing clocks or live source.

The passing Reader component entrypoint is
`remote_publication_component_tests()`. The separately named actual
oversize-publication diagnostic is excluded from that shorter selection.
It uses only genuine new Actor queries and stops
at an observed original packed-leaf overrun; no requested checkpoint/state is
injected. Full return/archive integration and that storage diagnostic must be
checked before another full common-executor attempt. Public Chat remains
disabled, and neither the 94-second refused run nor fragment tests imply a
successful whole journey.

The actual oversize-publication case subsequently passed 1/1 in 74.341 seconds
(74.593 outer elapsed). Its 56 complete original records used 111 actual
physical parts. The last original contained 93,305 canonical bytes and its
unchanged old `pack()` representation required 49,224 encoded bytes, actually
exceeding the unchanged 49,152-byte limit; old packing refused as expected.
The v3 value reconstructed byte-for-byte with SHA256
`363b13a3b492620b7ac0092013901da1bb2564ede6119cbaa13ca5ba729e2120`.
Logical originals totalled 3,964,722 bytes and physical fragment frames
2,160,188 bytes, each below its original 16-MiB budget. Every one of the 111
parts counted against the original 512-frame budget. Original files and the
storage summary remain retained; no input state or checkpoint was requested.

A separate read-only cold pass through those same retained files reconstructed
all 56 records/111 parts in 0.353769 seconds with the same last-original SHA.
It created no live owner, made no native query and granted no current sample.
Neither storage check qualifies the remaining true shared execution,
application/IPC, whole archive or final host lifetime.

Historical `original(index)` now checks its original warm JSON/type/digest and
fixed-path identities before and after literal reconstruction, together with
the original physical checks. These metadata/physical halves contain no live
process or foreground observation; normal live `control()` retains its original
metadata → actual process guard → physical-check order. Historical failures
latch the reader and cannot be retried after restoring a mutated cache.

Two actual counters first demonstrated the gap (both red, 1.646 seconds): a
same-canonical list→tuple alias or a source path change injected during the
literal read passed the old post-copy comparison. Both now refuse without
invoking a deliberately forbidden process guard. Those counters, repeated-read
refusal and the original cold-storage compatibility case passed 3/3 in 3.255
seconds. The short Reader selector now contains all 16 component cases exactly
once; the one actual oversize-storage diagnostic remains separate. No second
long oversize run was repeated to test these local fences.
