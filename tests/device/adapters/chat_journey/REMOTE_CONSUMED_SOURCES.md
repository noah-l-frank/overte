# Consumed Chat sources and actual independent return

`ChatRemoteConsumedSources` version 1 connects the actual shared cleanup prefix
to exactly its complete warm `ChatRemoteActorReturn`, then seals the original
primary global cursor. It supplies historical source closure only. Application
restart/profile comparison, final IPC, complete archival, Parent host lifetime,
successful full shared execution, native Actor build qualification and public
Chat capability are separate requirements.

Construction requires the original completed, nonfailed cleanup-prefix object,
the actual completed typed return using the same originally live process owner,
and a new primary source seal bound to that original primary cursor. No owner,
native reader, descriptor pair or completed result is reconstructed from files.
The result namespace must be empty, including orphan chunks. The Pico factory
binds the actual Parent/cache-release role and fixed prefix/return/seal paths;
its full positive construction remains unqualified. Premature admission and
ordinary-cleanup retention are checked separately.

The historical join checks every original read used by the live remote reader:

- Its unchanged warm cache, private result bytes/stamp and immutable own chunks.
- Every previously admitted source-child identity against the actual complete
  returned graph's original identities. Equal bytes in a replaced child do not
  create a new admitted original.
- Each preserved literal root's canonical bytes, digest and exact physical
  stamp types; actual Actor instance/run/bindings/host and original pair rows.
- Exact original chunk-manifest prefixes and source scopes, using slices of
  the already validated full graph. The shared pure stage-prefix grammar then
  validates the actual native/compiled/phase/observation/cursor/publication
  records again. It creates no live source object.
- Original flow/cleanup authority and publication-return certificates, plus
  every independently received literal publication payload.
- Exact original consumed cleanup bytes reconstructed from their actual header
  and sample rows, and the one physical Stop2 request's stamp/bytes/digest.
  Its requested payload belongs to the original consumed prefix; any additional
  same-ticket publications remain in the complete returned graph.

Only after that join does `run()` execute the original primary cursor seal.
It checks the same source/return relationship again and persists the actual
primary/Actor seal digests, typed-return digest, consumed/final Actor sequences,
original primary final sequence and unchanged `sequenceSucceeded` value.
Final copies precede original physical/cache checks. Historical `receipt()`
repeats those original checks without reentering a dead Actor's native guard.
Any failed join, seal, CAS or later receipt latches failure and retains all
originals; a complete-looking root is not cold-adopted.

The existing positive source test was extended instead of adding another full
catalog journey. In one actual Parent/Actor run it consumed the real shared
three-second baseline, wrote Stop2, preserved two later original publications,
consumed a fresh independent nonce, observed actual normal Actor host return
and original ESRCH, admitted all earlier literal source prefixes, sealed the
original primary cursor and checked the historical receipt. It passed 1/1 in
53.156 seconds. `sequenceSucceeded` remained the actual false value from direct
`wait/consumed_cleanup`; the native/widget/Parent/24-input and stdin-HTTP seams
described in [the prefix fixture](REMOTE_CLEANUP_PREFIX.md) remain unchanged.
This is not a controlled performance comparison with the earlier 67.363-second
partial path and not a device, full execute or full archival result.

Five focused cases passed in 16.563 seconds: canonical literal bytes reject
duplicate/escaped keys, tuple/bool physical stamps and changed digests; an
actual unconsumed Parent prefix cannot create a source-return join; the real
Pico factory refuses an unqualified prefix/return; rootless new result chunks
keep ordinary cleanup closed. No extra unchanged full positive was repeated.

The real warm-source profiling and retained-literal diagnostics later exposed
repeated full grammar in this historical receipt path. For all 61 original
record prefixes, full grammar per prefix took 6.130575 seconds versus 1.002624
seconds using one fresh strict `ChatSourceGraphPrefix` for the complete pass.
No live owner was constructed by that historical measurement.

`returned_prefix()` now creates exactly such an empty, local pure memo on each
invocation. It admits only previously validated identical JSON frame hashes,
original contexts, paths, flow prefixes, stages and current reviewed Script
pins. Each new row and complete Script native history still uses the original
grammar. The candidate commits only after that record's publication certificate
and every original received payload also match. Nothing survives between
receipt calls: cold/retry/receipt passes still reread and hash every original
literal, manifest, byte payload and physical stamp, with the existing complete
returned-graph and reader-history checks. No current sample or freshness is
derived from the memo, and no wire or source version changes.

Eight literal/memo cases passed in 4.631 seconds. The same existing actual
Parent/Actor/common-three-second/Stop2/extra-tail/nonce/kernel-return/seals/
remote-catalog case then passed in 36.427 seconds. Its source flag remained
false and every original was retained through catalog admission; no application,
archive retirement, host finalization or whole execution is claimed. This run
also includes the independently verified complete-directory name-scan change,
so its elapsed time is not attributed solely to the local grammar memo.
