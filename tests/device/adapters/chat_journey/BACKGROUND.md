# Original normal Chat background and return

`ChatBackground` owns the one HOME and ordinary activation at common Chat step
17. It accepts the two complete VR `ChatSamples` roles with their original exact
shared source-lock objects, current installed candidate, process identity and
separate original transcripts. The editor is already empty on Domain. The
owner does not focus it or enter a substitute draft.

Before HOME, the owner reads the real native keyboard inventory and arms the
existing bounded `NativeLifecycleBackground` source with a durable original
request. Both OS operations use the original `PicoGraphicsBinding` lifecycle
getters and ordinary input route. Candidate, target, original kernel PID/start
and actual foreground package are checked independently. A response or receipt
never supplies a foreground, background, keyboard or Chat fact. No foreground
Qt query is attempted while HOME has backgrounded the application.

The autonomous original Qt history must preserve the same original editor,
page, context, window and loader identities. At least one Hidden/Suspended timer
frame is 250 ms after the first Hidden/Suspended frame on both native epoch and
elapsed clocks, with gaps no larger than 500 ms. That entire interval must have
no editor/global focus and an actually created, enabled, unraised, invisible
keyboard with no pressed keys. The same native keyboard instance and real key
count are joined to both complete pre-HOME entity inventories. Return requires
an actual Qt Active signal and the same visible current empty editor. Merely
waiting on the host or observing an invisible keyboard after return is
insufficient.

Fresh complete Chat samples after return must retain both channel models,
receive histories, stored rows and the original Chat page generation. Both
independent original lifecycle sources must show background and activation,
without a process launch. Three seconds of advancing host and all eight native
source clocks prove quiet with gaps at most 1.5 seconds. Lifecycle counters stay
constant through the final post-release samples. The original timer release is
recorded once; its original ID, sequence, actual stopped timer and released
state are read back. Final result copying, persistence and guards remain inside
the original final source-clock freshness check.

The private `chat-background-owner` v1 journal preserves original raw native
packets, hashes, exact arm/release requests, OS packets and complete source
references. Reconstruction issues no input or query. Lost HOME can permit only
the distinct original Resume; an uncertain Resume is only observed. Cold
recovery acquires the same original Chat lock and uses only candidate/kernel/OS
sources until foreground is recovered, retaining every native journal. A lost
timer release is resolved with a new query and fresh complete Chat sources,
never a second release. Missing/replaced original processes are refused. Failed
qualification retains ownership and cannot repeat HOME, arm or Resume.

Pico's `_chat_background_source` directly binds this unchanged native source to
the original Chat parent lock. Lifecycle's separate Script-journey factory and
its path checks are unchanged. `_chat_background_recover` does not construct a
foreground-only source. Base teardown refuses green while the background
journal exists, including after OS process teardown.

Focused host tests run the actual owner, strict native reader and original Pico
OS getter/input methods with explicit synthetic device/native boundaries. They
cover normal closure, cold recovery without Qt, uncertain HOME/release,
missing/disabled/visible/focused keyboard, replaced context/page/process,
frozen native time and a new lifecycle activation after quiet. Actual Pico
native application compilation, device lifecycle, OpenXR and networking remain
unqualified. Timer release does not retire Qt objects or callbacks; final
process/resource release and the full 25-step independent witness remain open.
No complete Chat capability is advertised.
