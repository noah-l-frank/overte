# Original Chat cache and IPC release

`ChatCacheRelease` v2 adds the deferred IPC path described below. The unchanged
immediate component path still emits its original v1 journal. Both follow the completed original peer input close and normal
Erase/profile-restoration owner. It does not replace their journals. Admission
requires both original active `ChatCacheLifetime` owners, two new independent
`CompiledChatCacheAbsence` roles, the same exact two parent source-lock objects,
the original restored profile and the actual cleanup27 phase fence. Existing
roots/chunk orphans, incomplete histories or foreign bindings cannot be adopted.

The parent records each retirement intent before calling the once-only native
lifetime. It marks the actual current cleanup phase before its CAS and checks
that same original admission afterward. Each child separately persists its
original native retirement request and checks the current phase after its last
CAS/guard at the actual transport boundary. Primary and peer native3 sources
must report their exact original first-open and first-retirement IDs. Their
capture-owner v2 retirement records retain two original inspections; ACKs,
requested effects and empty fabricated inventories are not release evidence.
Unknown/lost writes retain the earlier journal and never cause a second input.

After both original retirements, each final role obtains its own new configured
root/Script/V8/root, primary cache, view/storage/VR keyboard, peer cache and
lifecycle observations. The packet must report the actual retired, absent,
empty native3 caches with unchanged source/session identities and exact original
mutation IDs. Chat/model/editor/keyboard and accepted storage must be empty.
The actual saved profile's config hash must still match. The two final roles
must agree on state, lifecycle and resources. Their histories are separate from
initial, active and post-Erase histories and share their role's original
compiled-code owner without resetting any cursor.

A full three-second quiet interval must advance both host time and every actual
native source clock, including all three code-source observations. Consecutive
native gaps must remain strictly positive and at most 500 ms. Every complete
pair, chunk write, returned copy, guard and clock remains inside the original
1.5-second source freshness bound. The phase is read independently before and
after each pair. No timer/clock reset, timeout extension or retry supplies a
missing interval. Reference chunks preserve exact source-frame hashes and
original query/epoch references; original source packets remain in their own
immutable histories.

Only after that interval does the new restricted peer transport close its
original observation command/result paths with `retain=True`. Its actual kernel
result-FD absence and own strict host OFD closure are required. The parent checks
original peer PID/source ownership and kernel FD absence again, after its final
manifest CAS and copy, before returning. Rootless release chunks prevent general
cleanup success. All original capture/lifetime/input/profile/model/IPC journals
remain retained; the enclosing fixture/source descriptor stays owned.

Pico parent v4 and later expose the immediate private component stage as `close_caches_and_ipc(after_epoch)`
after `close_input_and_restore_profile`. The new parent phases are
`cache-release-issued` and `caches-ipc-released`. Legacy v1/v2/v3 roots remain
readable for retention and cannot gain these v4 phases. The already compiled
v3 input/witness contract remains usable for its unchanged admission scope;
legacy v1/v2 cannot gain compiled-source claims.

The focused executable owner checks use actual private files/chunks/strict host
FDs and the existing original phase/ownership code. Native/V8/IME producers and
the 26 previous input metadata rows are explicit seams. They do not run the
previous 25 effects, a product Agent, network service or device. Countercases
cover phase changes after parent CAS, a lost second retirement intent, late
keyboard input, a native quiet gap under a frozen host clock and a native jump
after the final IPC CAS. Actual Pico checks cover premature-stage refusal,
rootless release retention and the existing lazy child/cache factory graph.

This stage does not establish Qt object/global memory destruction, old Android
PID/start finalization, post-restart independent physical/cache/worker original
profile equality, immutable final archival or hermetic Assignment Client build
provenance. These remain required whole-parent work. No public Chat capability
or full Chat acceptance is added.

V2's `defer_ipc=True` records `ipcDeferred:true` and returns `caches-quiet` after
the same two actual retirements and independent three-second source interval.
It does not unlink either observation IPC path, close the original result FD or
claim IPC release. The exact original peer transport remains available for NEW
passive native queries through the application restart. Input files are already
closed, so no peer input can be reopened. Its unchanged native3 tombstones remain
bound to the original first mutation IDs. The old source histories stay intact.

Pico parent v5 selects this path through `prepare_cache_release(after_epoch)` and
records `caches-retired`. The old immediate `close_caches_and_ipc` method remains
a component-only path and cannot establish a post-restart current peer proof.
A full parent must next prove the original application's death, new birth and
saved profile, acquire new independent post-restart originals while this peer
channel is still owned, then close IPC through the retained original transport.
That later process/IPC/archive owner is not implemented by this packet. No
closed IPC path is recreated and no old frame is relabelled as a new observation.
The deferred selector proves a NEW original Inspect after cache retirement with
the original kernel result FD still held, retaining both original histories.
