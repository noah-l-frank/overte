# Independent original Chat cleanup witness v1

`ChatCleanupWitness` continues the existing independent actor cursor after all
26 original `ChatWitness` publications. Its separate cleanup-stage
`ChatObservationOwner` acquires a new original source bundle for every sample
under the same actual Phase27 activation. The actor client, both source-lock
objects, original compiled-script source and primary/peer bindings must be the
exact original independent publisher's owners. Parent samples cannot replace
the independent actor source.

The final active witness bundle is read from its immutable physical chunk and
pinned by digest. New observations must retain actual source instances, PIDs,
advancing sequences, domain/connection identity and keyboard identity. Both
native cache sources must independently link their original open command to a
distinct actual retire command and prove retired scope absence. Historical
rows supply continuity only; all published state and timestamps come from the
new cleanup query. No source is reopened after IPC closure.

Each publication first records an acquiring intent, then the complete exact
payload under a publishing intent before its sole POST. The unchanged original
1.5-second native/host budget includes copies, final CAS, HTTP phase checks and
transport completion. An independent phase read immediately before POST cannot
retime native facts. A transport ACK is never feature success: the common
journey must separately consume the original received actor journal.

The private root contains `chatCleanupWitnessVersion`, `runId`, `fixtureUrl`,
`binding`, `peerBinding`, `originalWitness`, `originalWitnessSha256`,
`observation`, `phase`, `delivery`, `revision`, `chunks` and `pending`. Its
immutable rows contain `sequence`, `observationSequence`, `observationSha256`
and the original `payload`. Existing `ChatSourceChunks` limits apply unchanged;
the 26 original actor rows count against the common 512-row bound. Physical
chunks, the original publisher root, stored payloads and mutable cached rows
are compared before another publication.

Construction refuses every existing root and every rootless chunk. Lost POST,
CAS, stale source or retired phase leaves the exact intent and originals;
neither a warm retry nor a reconstructed owner can resend the publication.
There is no retirement/adoption operation, ordinary target input, native/Qt/
process release verdict, public capability or stereo evidence in this class.
The private Pico actor-source factory and actual finalization ordering remain
separate composition work, alongside the public cold-RPC boundary.

Seven focused host cases passed in 89.332 seconds. The positive uses the actual
common `Journey.wait` cleanup baseline for three seconds, new primary and
independent actor transactions on every iteration and actor sequence 27 onward.
Only baseline and first Open use ordinary controls in this fixture; the other
24 consumed input rows are metadata fixtures. Native/V8/widget producers and
clocks are explicit seams. The negative cases cover lost POST receipt,
retirement after the final publishing CAS, frozen-host native jumps during CAS
and wire copy, late successful POST and mutated historical cache originals.
No app, AC, network service, OpenXR runtime or device runs.
