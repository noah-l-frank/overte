# Independent original Chat witness

The primary input owner and its two component source roles keep their original
`chat-primary-samples-*` and `chat-actor-samples-*` v4 journals. The independent
publisher uses a third fixed `chat-witness-samples-*` journal, still schema role
`actor`, with its own four original native queries per accepted ticket. Native
receive caches and process/candidate bindings remain the originals. There is no
third actor, copied parent frame, replacement peer or reset source cursor.
The same exact source-lock instances are shared inside each parent; separate
processes serialize on the original OS lock inode. The existing independently
qualified fixture actor supplies the peer transport and kernel/executable guard.

`ChatFlowInputs` v3 records input metadata and original source references only.
It reads the existing common `PhaseFixtureReader` and admits baseline followed
by the 25 original common Chat inputs in order. It selects only `verb` and
`inputs` from the common inventory. It never consults checkpoint states or
evidence requirements. A ticket, interrupted admission, skipped input or
changed immutable fixture activation prefix cannot be replayed/adopted.
Baseline completion requires NEW full `ChatCacheAbsence` bundles from both
separate initial roles, with actual absent caches, closed Chat and zero scoped
resources. Other steps require NEW full active `ChatSamples` bundles. Six fixed
initial/active source paths and their distinct references stay in the owner
scope, and original query nonces cannot be reused across these stages. Both
paths require an unchanged original fixture phase. Parent references are retained for audit,
without becoming independent observations. This journal alone is neither a
product effect nor a completed Chat journey.

Run `ChatWitness` v3 only in the separate observer process with its own private
publisher `Client`. Pico's input-owner factory requires the restricted
`AdapterFixtureClient`; its witness factory refuses that client and requires
the fixed initial and active third journals. Baseline publication separately
rechecks its original cache absence; a cache that opened after the parent
capture fails rather than borrowing that earlier zero-resource sample. The existing coordinator independently restricts
publication to the separate actor credential. The publisher waits for the
current input metadata to complete, then independently queries primary native
reception, peer reception, actual VR keyboard/QML/storage and lifecycle. All
published fields are projected from those new originals. A changed actual draft
or model after the primary capture is therefore published as changed, even if
it disagrees with the requested checkpoint.

Original phase metadata brackets acquisition and publication. A full frame that
crosses a ticket change remains archived under its original ticket and is never
relabeled/published. All source copying, final guards and persistence stay
inside actual native/host freshness bounds, including frozen-host countercases.
The publisher makes one publication attempt per ticket. Its private intent is
durable before HTTP dispatch; an uncertain response remains unresolved and is
never resent, including after passive reconstruction. Already published tickets
cause no new native query. No input ACK, successful publication receipt, cached
parent state or requested effect supplies a witness fact.

Original source chunks, input metadata and publisher intents survive failure
and base process teardown. The normal source factory supports separate
post-Erase witness journals, preserving the real storage discontinuity. Full
resource retirement, post-Erase publication and actual OS process closure still
belong to the whole-journey owner. Old v1 input/publisher owners used active-cache baseline samples. V2 separated
initial/active stores but did not bind their original native lifetimes. Both
remain without adoption or replay; only v3 supplies the complete stage join.
No complete Chat capability is advertised.

Focused host tests use the actual original coordinator, phase protocol, strict
native Chat joins and original Pico factories, with explicit synthetic native,
QML and HTTP boundaries. They prove separate journals/credentials, input gating,
new actual-state publication, phase races, no replay after lost publication,
query-free reconstruction and final native clock checks. These component tests
run in one test process; no external credentialed observer, native Assignment
Client, networking product, application or device was started or qualified.

Pico's `_chat_admit_capture` writes the existing original capture admission only
after a fresh passive domain-aware native inspect proves no scope or prior retirement. It
does not send observe/retire. The explicit `pending_capture` source factory
requires that same original admitted binding; it creates unqueried active
readers without opening a cache. Ordinary default source admission continues to
require an actually active cache. Even a pending reader's first read refuses
absence, so it cannot manufacture active observations before the whole owner
performs its original once-only cache activation at the first normal Open.

The original positive Pico source experiment exposed repeated full candidate
verification exceeding the unchanged 1.5 s bound (93 verifications and 465 tool
subprocesses across setup and the failed read). The separate
[Pico host-input read seal](../pico4/CANDIDATE_READ_SEAL.md) now lets this actual
Pico factory/reader quartet complete with the real monotonic clock and unchanged
native freshness checks. This is synthetic-transport host evidence only; no
real SDK signing, live installed Android APK, network peer or device performance
is qualified by it.

V3 requires actual native Chat v3 already in the initial absent-cache frame.
The first active input and the independent observer each join their own initial
and active originals: actual source instance/PID/sequence, self identity, native
domain instance/revision/birth/UUID, view instance, physical-settings identity,
keyboard instance/sequence and lifecycle instance/counters must continue. Only
the explicitly admitted absent-to-active cache birth may change; its two actual
first-open IDs must be distinct. QML page generations remain measured across
the actual normal Open, rather than being required to stay absent or unchanged.
Later active frames preserve their original mutation IDs. The native v3 fence
prevents another first-open nonce replacing the same run/source lifetime.

The observer must acquire its own initial stage and cannot skip an activated
input ticket. Its private row sequence follows the original activation prefix.
A fresh replacement source inside the same PID/candidate cannot publish under
the earlier baseline's ownership, even when its apparent Chat state matches.
This is an original source-lifetime join; product facts still come solely from
new independent native observations. The whole dispatcher additionally owns
the actual cache request journal and normal input attempts.
