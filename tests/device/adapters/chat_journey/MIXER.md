# Owned original Chat mixer join

`ChatMixerOwner` joins two separate original-source `ChatSamples` roles with two
separate `FixtureMixerControl` readers of the existing private authenticated
fixture endpoint. The actor reader is read-only; both are guarded by the actual
fixture owner supplied by the enclosing run. They share only the original
endpoint identity. The Pico `_chat_mixer` factory additionally pins the actual
candidate/binding and separate original primary/actor transcript paths. It
starts no service, peer or device session and advertises no complete capability.

The controller's actual domain UUID must hash to both original native domain
sessions on each role. Native handler birth, revision, connected epoch and
connection birth stay unchanged. All eight original non-mixer fixture kernel
identities and original controller/stack stay unchanged. Both independently
queried native sources must lose the actual mixer, then agree on a usable fresh
mixer UUID. Recovery additionally requires an actual fresh fixture mixer kernel
identity and the original actuator generation advancing by exactly two. Requested
input, HTTP responses and process existence cannot supply native Chat state.

Every input is written to the private owner before transport as its complete
schema-2 command: original controller instance, run, unique nonce, freshly
observed actual generation and action. Offline and online may each be sent once.
There is no resend after uncertainty or reconstruction. The original controller
[online fence](../../fixture/CHAT_MIXER_SOURCE.md) refuses a delayed offline input
that arrives after recovery. A lost online response can be resolved only through
new passive sources, the actually admitted original online fence, fresh native
recovery and a new quiet window. The original intent is retained after success.

Transitions can propagate asynchronously through the independent native caches
and original QML models. ChatSamples journal version 3 explicitly records these
as historical transition frames. They contain original packets and emit no
shared state or resources. An internal boolean can qualify convergence, but a
checkpoint then requires four NEW original reads per role with the ordinary
strict full composition. No raw frame is promoted or retimed. Existing source
identity, immutable event history, accepted storage/configuration and domain
connection continuity remain strict. Old v1/v2 journals are retained and refused
rather than adopted under the new transition semantics.

Each source transaction, final guard and persistence must fit 1.5 seconds,
including monotonic age after the final clock read. Removal/restoration each have
a 20-second budget. Pending propagation is sampled every 500 ms. Offline and
online quiet each require three seconds on the actual host clock and all TEN
original native/controller source clocks. Each new capture advances, intervals
stay at most 1.5 seconds, all ten shared Chat fields/model/storage and the
original native reception lists stay unchanged. An empty old peer ledger or a
long unobserved sleep does not satisfy quiet.

A failed removal attempts the different online command once, even if native
observation is unavailable. This narrower process recovery persists two reserved
controller-only source frames and emits no Chat state/resources. It can prove
only the original owned mixer running, absent process intent, an admitted online
fence and no pending original controller callback. It cannot establish an
unobserved outage/native recovery or full feature completion. A genuinely full
bounded original transcript does not block this separate recovery admission;
the original transcript remains byte-for-byte unchanged. A lost journal write
still fails the original compare-and-swap guard and cannot authorize new input.

The focused host checks use explicit synthetic HTTP/native seams; the fixture
packet separately executes the original controller/HTTP bodies and real /proc
ownership against only its own synthetic stdin workers. They cover source/ACK
separation, original domain/process replacement, source freshness and ledger
continuity, read-only actor transport, once-only lost input recovery, actual
journal exhaustion and preserved original intent. No Overte executable, network
domain, service, headset or device is run. Full-app linking is not claimed.

This component does not type/send the offline fallback or explicit retry; the
whole normal Chat journey must still perform those inputs and inspect actual
native localOnly/remote arrival order. It also needs authentic independent
publication, background/resume and original profile/peer/cache/callback/file/
process release composition. Every original source and owner journal remains;
Pico base teardown refuses green while the mixer owner is retained, even if its
phase is online and the application has stopped.
