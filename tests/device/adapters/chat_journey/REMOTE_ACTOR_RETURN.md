# Original typed independent Chat return

`ChatRemoteActorReturn` version 1 joins the original historical
[Chat Actor graph](REMOTE_ACTOR_GRAPH.md) with the neutral
[byte/nonce/process transport](../OBSERVER_RETURN.md). Its scope is
`original-independent-chat-historical-return`. Component completion proves this
historical return boundary only. It does not qualify shared journey success,
stereo evidence, a native AssignmentClient build, restart, IPC release, complete
archival or public Chat capability.

The original Parent supplies its already acquired, still-live exact
`LinuxChatObserverProcess`, original expected instance/bindings/Stop command,
all fixed graph/return/consumption paths and a new private result path. Original
process methods must be the actual implementation. No process discovery,
launch, native source query or live Actor reconstruction is provided. Existing
result roots or rootless chunks refuse acquisition. The Pico private factory
binds these paths to the actual Parent/target and permits construction only
after its original deferred-IPC cache retirement. Premature construction cannot
write a result; ordinary generic cleanup retains the result and orphan chunks.

The consumer validates the immutable returned `host-closed` bytes and all nine
original graph roots before issuing a nonce. It first records private durable
`consumption-issued` intent, then invokes the neutral receiver's once-only
Parent consumption write. A lost response preserves the same issued nonce;
only passive `finish()` is possible afterward, with no second ACK write.

The actual Actor's current owner root may advance from the captured
`host-closed` root to exactly `parent-consumed`. Admission derives that entire
successor from the original payload and the independently read consumed
transport record: original return ID, consumed-root digest, Parent consumption
digest and actual Parent host identity. All old fields remain identical. This
single controlled transition pins the successor's literal bytes and physical
stamp. The original payload/stamp remains historical in the immutable return
chunks; it is never relabeled as the current physical Actor root.

Ready transport metadata, a not-yet-published successor, or an actually present
PID produce `ChatRemoteActorPending`. That exception asserts no completion and
allows only the same warm transaction to wait. A live or zombie PID cannot
supply ESRCH. Replaced graph/consumption/successor files, wrong scope, missing
originals and other uncertain outcomes quarantine the typed owner. No process
identity is forgiven and no old archive becomes a new observation.

Completion requires the exact independent consumed Parent nonce, frozen graph
and successor, two real ESRCH queries for the original PID and its actual
`/proc` absence. The private final record includes original graph/seal hashes,
original payload and current successor hashes/stamps, plus the original neutral
process-return packet. The same original absence clock bounds run after final
JSON copies, filesystem CAS/fsync, physical graph checks and record verification.
A lost final CAS or a late final check leaves a complete-looking disk row
unqualified: the actual warm owner stays failed/incomplete, cannot issue another
nonce, and cannot be reconstructed from that row.

The neutral receiver now exposes `consumed()` for original consumed metadata
without an absence verdict, and `historical_receipt()` for its exact already
returned frozen event. The latter verifies original packet bytes/digest,
consumed root/nonce/chunks and held original program descriptions; it does not
query a new PID or retime native facts. This adds no wire version or default
feature behavior. `ObserverProcessPresent` distinguishes the actual existing
PID from a returned absence sample; its condition is unchanged.

`receipt()` rechecks this same warm typed record and historical originals.
`close_host()` closes only the Parent's two original executable/entry descriptor
pairs. It does not retire a journal or claim parent-wide finalization. A complete
archive must capture these roots, original chunks and returned seals before
retirement and account for those program descriptions in its own host close.
The public operation/consumer, complete archive and enclosing resource join
remain separate work; existing local Consumer v1 still requires its original
live Actor object and is not fed these DTOs as a substitute.

The four host tests use an actual separate Python Actor fixture and Parent.
The fixture executes the existing actual Python source owners, ordinary first
Open, cache retirement, full source seal, real descriptor close and actual
Actor return sender. Native/Parent provenance and the remaining 24 input rows
are explicit seams. The Parent receives only original private bytes/DTOs,
records its own actual host nonce, waits for a real reaped kernel exit, and
closes its own original program pairs. No observer entrypoint, product App,
AssignmentClient, device or service is started. Fixture originals remain under
the Parent's private temporary directory until actual worker exit.

The positive and three counters passed 4/4 in 29.520 seconds: an identical
successor replacement, lost final typed CAS and a frozen monotonic clock with
a two-second epoch jump after the final fsync all refuse completion and retain
original records. The two actual Pico premature/retention checks plus the
unchanged return/process regressions passed 21/21 in 8.215 seconds. The complete
Pico factory constructor has not yet run with this new two-process source
fixture; its fixed-path/Parent guard is source-wired, while direct typed
constructor and actual kernel boundary are covered separately. No whole
feature or device result is inferred.
