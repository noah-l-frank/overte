# Consumed cleanup with original global Chat cursors

`ChatCursorCleanupConsumption` version 1 is a separate private source family.
It requires the exact primary `ChatObservationCursor`, independent
`ChatObservationPublisher`, current cleanup source owners and two original
`ChatCursorSourceSeal` objects. Their complete global histories began at initial
absence. A legacy private 26-publication witness cannot replace either cursor.

Register one `ChatCleanupFinalizationSlot.callback` when constructing the common
Journey and attach that exact Journey. Later, after original cleanup sources
and graph seals exist, bind exactly one consumer. The slot compares the actual
already-consumed primary and actor sequences with those original global query
histories. There is no caller offset, cursor assignment, callback replacement,
cold ownership or replay API. The slot is marked issued before calling its
consumer. Failures quarantine the exact bound source seals.

The consumer's observe route queries only its primary's new actual sources.
It does not publish actor facts or receive the actor's transport ACK. An
independently scheduled actor publishes its own new original observations.
The separate received journal must contain the exact actual cleanup payloads.
At final consumption, the actual common Journey must have consumed the actor's
latest publication. Extra unconsumed actor work cannot be silently adopted.

The callback accepts only that Journey's exact original immutable hook bytes.
It checks the current original cleanup activation and action barrier, every
consumed global primary row against its immutable local source reference,
every consumed witness against its exact independent publication/cursor row,
and the independently received original journal. The global values are used
as recorded; local source sequences remain unchanged. The complete receipt
header, SHA-256, received journal and source-edge hashes are stored with the
actually consumed rows. Only then are the actor and primary source graphs
sealed. Copies, physical writes and actual lock release remain inside the
existing final native-clock checks. There is no second baseline wait.

`sequenceSucceeded` retains the shared engine's actual value. A component
prefix followed by its cleanup-only common wait remains false, even when all
cleanup source seals succeed. Those source receipts are historical. They do
not restart the app, close native IPC, archive or retire any journal, close an
independent host process, or grant public capability.

Pico's private factory requires its exact warm caches-retired parent, original
final primary sample owner, fixed stage/cursor/publisher paths, current binding
and unchanged parent admission. Partial seal construction is quarantined.
The new fixed consumer root and rootless chunks keep generic cleanup closed.
Legacy baseline/archive code still refuses these unknown graph originals
until its explicit complete catalog join is implemented.

The source tests use actual initial/Open observe and independently received
witness calls to establish both original global cursors before cleanup. Their
remaining 24 input rows and native/V8/widget/network/clock producers are
explicit seams. Actor scheduling is an in-process fixture seam, not a claim
that the persistent independent observer-process stop/seal/host-close channel
exists. A full external 25-action execution, cold RPC lifetime, complete
archival/finalization, qualified peer binary and stereo evidence remain open.
