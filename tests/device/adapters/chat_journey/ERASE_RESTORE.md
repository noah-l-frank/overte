# Original normal Chat Erase and profile restoration v2

`ChatEraseRestore` composes normal Settings/Erase input, two independent original
source roles, original page destruction/reconstruction and native private profile
restoration. It is a retained component proof, not the complete Chat journey or
authority to remove any original ownership journal. Devices have not run.

The owner requires a previously captured original native profile and two existing
primary/actor source roles. It creates its own normal control owner and persists
every admitted input before the original Pico/OpenXR route. Erase authority joins
the captured original control to both independently acquired original ChatViews,
the exact whole-model native digest, all run-owned stored rows and saved original
configuration. Nonempty actual owned history is required. Neither row counts nor
a Send/Erase acknowledgement supply this authority. A changed digest refuses the
one input; an uncertain Erase is never sent again.

V2 first uses the original normal Open route when the complete journey's final
Close has destroyed the Chat page. An already open page produces no extra input.
If the tablet is closed, the normal token owner records its one controller-open
intent before the existing Pico/OpenXR route. `controller_intent(envelope)` is a
pure host-only CAS for the exact original tablet-open stream envelope; the
enclosing phase fence supplies the original native/host anchors and final grant
checks. No expected sequence/envelope is manufactured for transport. The stream
can be recorded once, and a lost gesture is never replayed. V1 journals remain
retained and cannot be reconstructed or upgraded by a new Erase owner.

Every pair's final freshness check also covers any attached original compiled
Chat sources and their independent current clocks. The complete source/model
transaction keeps its original 1.5-second bound.

Settings is an internal observation purpose in ChatSamples journal v2. It stores
the original native/UI/storage/lifecycle/peer frames and returns source metadata,
with no shared Chat state. The common journey permits Local/Domain for an open
Chat and therefore receives no invented channel or closed-page projection.
Previous v1 transcripts remain unresolved and are not adopted under the new
internal purpose. Ordinary source reads retain their existing canonical state.

History discontinuity is explicit. Before-Erase append-only transcripts remain
unchanged. Two separate post-Erase readers independently query the same bound
actual primary and peer caches, original view and lifecycle. They must match the
original native cache births, immutable events, identities, usable mixer and
lifecycle, while actually measuring null/empty accepted storage and empty Local,
Domain and visible models. No reset method grants a generic permission to shrink
an earlier source history.

Normal Close then requires three seconds of advancing host and all eight original
source clocks, no draft/focus/visible keyboard and stable native events/storage.
Normal CHAT reopening must create a different actual QML page generation,
select Local and reconstruct both empty histories. Clearing only QML/storage
while leaving the original Script array populated fails at this new page. A
second normal Close and another independently sampled three-second window
precede the one native restoration of the saved original history. Exact original
cache/worker/file fingerprints must match, followed by a third three-second
quiet window and a new native profile inspect with unchanged actual mutation
sequence. Settings setters and storage restore never populate model/peer facts.

Errors attempt original Close and saved-profile restoration only when those
specific inputs have not already become uncertain. Best-effort effects never
complete the component or remove its intent. The Pico factory checks original
candidate binding and distinct before/after journal paths; cleanup retains the
Erase journal, all four role transcripts and even a restored profile journal.

Focused host tests execute the actual normal token recipes and source/owner
composition with explicitly synthetic widgets, native caches, physical-profile
source and clocks. They cover new-page Script reconstruction, independent digest
refusal, lost Erase acknowledgement, late history after restore and retained
ownership. The separate real Qt5 checks qualify the native profile storage
component. Neither set executes a headset or establishes linked Android/native
application behavior. Complete Chat still needs ordinary Send/Return/lifecycle,
owned mixer removal/recovery, authenticated independent publication and verified
whole-run actor/callback/file/world-input retirement.

Two focused v2 component methods passed in 21.204 seconds: normal reopen after
the final closed Chat, and the closed-tablet original stream intent plus lost
gesture/no-resend path. Native/V8/widgets/controller effects in these tests are
explicit synthetic seams; the original owner/token/source/CAS code executes.
These checks do not claim actual headset input or whole-feature cleanup.

The native storage proof selects the actual original worker's QSettings format.
It supports INI and the product's registered JSON format without guessing from
file suffixes. JSON admission requires the original writer's exact Qt-indented
object bytes, rejects duplicate/escaped/normalized fixed-key aliases, and hashes
the original literal fixed-row tokens. Empty JSON history is absent, null, an
empty string/list, or the exact empty QStringList encoding generated by the
original JSON writer. File-supplied serialized variants are never deserialized
by this ownership decision. Compact, noncanonical or malformed legacy files fail
closed; this observer neither rewrites them nor changes product permissions.

Both formats retain the original private descriptor, inode/timestamps, immediate
parent and private ancestor through final parsing. Before its one conditional
restore, the native Manager performs another bounded original worker/file read;
a stale cache alone cannot authorize writing over externally changed settings.
Real Qt5 tests compile the whole Manager, its original QObject metadata, and the
complete original SettingHelpers.cpp and SharedLogging.cpp. They exercise both
actual formats, original read/write type semantics and an externally changed JSON
file with unchanged Manager cache. This remains a component proof: no device or
complete native application has run.
