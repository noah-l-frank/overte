# Private Pico Chat composition v4

`PicoBoundAdapter._chat_composition(target, phase_source, peer_config, domain_ready)`
constructs `PicoChatComposition` from the existing original candidate/process
binding, an adapter-only `PhaseFixtureReader`, the original private actor config
and the original private domain-ready file. It neither discovers nor starts a
fixture. No public `feature.chat.*` capability or operation is added. Whole Chat
remains partial until original Android process/QML
retirement and dedicated final evidence/journal closure are joined and verified.

Before acquiring the peer, the parent journals admission. The real
`OwnedChatPeer` independently qualifies its actual Linux PID/start/boot,
executable digest, inherited fixture owner/config, assigned script digest,
native source birth and original held source descriptor. Its configured source
revision comes only from native ActorSource2. This is clean-configured compiled
metadata, not a hermetic Assignment Client build receipt or exact dependency
graph/toolchain qualification. The APK revision is never copied into the peer. The parent explicitly records
`peerOriginBasis: "native-configured-metadata-only"`; this does not qualify a
missing hermetic receipt or grant complete actor/feature acceptance.

The peer's host state lives in a separate private `chat-peer-state-<target>`
directory and owns its original `script-sources.lock`. Primary sources use the
existing primary source lock. Every parent/child role shares these exact two
lock objects; independent processes use the same original OS lock paths. A new
parent refuses retained peer files or source chunks even if its own root is
missing. Generic cleanup detects the parent and every retained nested peer
file, including rootless input-close chunks. Only a private regular zero-byte
single-link lock file may remain as an otherwise empty baseline directory.
Symlink/foreign/nonprivate lock paths cannot make cleanup green.

`OwnedChatMixer` pins the original ready file's inode/full stamp and closed
schema. Both original files are independently private and pinned. The existing fixture
CLI may place its ready file outside the actor-config output directory; a parent
path match is not invented as a producer invariant. Both newly constructed `FixtureMixerControl` readers
use the original same-port loopback URL/token and that exact actual actor guard;
one can issue the owned mixer command and one is read-only. Even the first
independent GET must name the original ready domain UUID. The ready file itself
provides credentials/config authority, never process readiness, a current mixer
state or a native domain observation. Existing original mixer GETs/native joins
still provide those observations.

The ready schema also accepts the optional original
`createPermissionsControlUrl`, only at the same controller origin and exact
`/v1/create-permissions` path. This permits the existing Create owner to share
the fixture without authorizing another service or weakening either file stamp
guard. Two focused actual-factory tests cover this extension, foreign ports and
paths, and replacement of the original ready inode.

`prepare()` first acquires the actual original profile through its existing
durable native owner, then admits both genuinely absent native caches. It builds
two initial absence roles and two separate active roles, using the existing
shared `ChatFlowInputs`, `ChatDispatcher` v2 and their original phase fences.
V2 and later select the closed compiled-source model and absence readers described in
[the source/model join](../chat_journey/COMPILED_CHAT_SOURCE.md). Initial, active
and Erase readers share each role's exact original code-source owner and lock;
the independent witness owns separate readers and its own source journal.
Every actual model read obtains fresh configured-root/Script/V8/root originals
before the four existing native sources, with one unchanged 1.5-second bound.
Legacy v1/v2 parent manifests remain retained and cannot qualify compiled-source
v3/v4 witness admission. V3 remains readable for its unchanged compiled input
scope, but cannot acquire v4 cache-release phases.
Active roles cannot read before original cache activation. Cache creation stays
lazy until the first Open. All six child kinds use the existing actual Pico
factories: ordinary Chat UI/keyboard, original peer Send/distance, passive native
background timer plus once-only OS inputs, original owned mixer control and
no-replay quiet. Final QML/controller/grant publication hooks remain bound to
the same original dispatcher fence. No source is reconstructed from an ACK.

`step()` durably admits each parent attempt before the actual dispatcher.
Already issued, unknown or failed inputs cannot be resumed/replayed. The parent
CAS, returned copies and final source guards stay within the original source
freshness checks. Cold construction retains an existing root and refuses input
reconstruction. A lost parent receipt does not overwrite the earlier issued
intent, reacquire a native profile or replay a child.

After all original 26 baseline/action records complete, `admit_cleanup(after_epoch)`
qualifies the actual unchanged Dispatcher chunk/root proofs and uses
[original cleanup admission](../chat_journey/CLEANUP_ADMISSION.md) to admit only
the independently observed current cleanup ticket27. The original activation
epoch must precede the caller's barrier. Its dedicated original journal and
current phase fence remain separate from the completed action fence. A lost
admission or incomplete action sequence authorizes no cleanup input.

`close_input_and_restore_profile(after_epoch)` first admits this actual cleanup
phase when not already admitted, then joins the original held-peer
restore/motion proof to the dedicated input close owner. It then creates two new
post-Erase source histories and runs the existing normal Settings/Erase,
reconstruction, exact original profile restoration and quiet owner. Those old
and new histories remain separate and retained. Each ordinary Erase input marks
the original cleanup ticket before its own durable intent and uses that same
final QML publication fence. Closed-tablet Open stores its actual original
controller envelope through the Erase owner's host-only CAS, with the existing
original final grant checks. Each input-file unlink also marks before its issued
CAS and rechecks the actual cleanup phase immediately before removal. The saved
profile's one Restore marks before its durable request and the actual bound
native writer checks the same cleanup fence after its final native guard.
Original run, binding and exact lock must match the profile owner. A changed or
retired cleanup ticket fails closed. This method does not yet claim native cache,
observation IPC, process, QML-context or full-feature resource release.

`close_caches_and_ipc(after_epoch)` then joins the two original cache lifetimes
and two new compiled final-absence roles through
[the original cache/IPC release owner](../chat_journey/CACHE_RELEASE.md).
Its retained chunks and rootless cleanup guard preserve every original source.
The new peer transport has its own strict original host descriptor and cleanup
fence; the old action writer is unchanged. Only actual original native3
retirement IDs, a full independent three-second source quiet interval and actual
kernel observation-FD absence permit `caches-ipc-released`. The final parent
CAS/copy is followed by original guards/clocks and another kernel FD check.
No journal is retired and no Qt/process or complete feature release is inferred.

`_chat_witness_composition(target, independent_phase_source, peer_config)`
constructs a separate `PicoChatWitness` with its own publisher Client/credential,
new primary/peer/view/lifecycle readers and its own original source histories.
An adapter-only client is refused. It passively reacquires the same actual
owned actor and same OS lock paths, without profile/cache mutation. Existing
`ChatWitness` v3 reads current fixture phase and parent admission metadata,
then independently obtains every target fact. Parent result values are never
published as witness facts. The witness must attach before baseline/first Open;
a late observer cannot reconstruct missing original absence evidence.
