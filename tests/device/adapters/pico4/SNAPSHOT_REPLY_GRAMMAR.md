# Pure old Snapshot cancellation-reply grammar

The retained new-run Snapshot composition reached the unchanged 120-second
limit before normal Close. Measured original archive times place most cost in
Cancel/Still, Save and Upload. This component addresses only repeatedly parsed
immutable old cancellation replies. It supplies no source, effect, capture,
status, freshness, physical-file, cleanup or whole-feature receipt.

`SnapshotReplyGrammar` binds its exact JSON scope to the actual run, complete
candidate/process/target binding, PID, parsed current Snapshot Script pins and
SHA-256 of their actual file bytes. The pin reader uses a bounded original
descriptor and compares complete relevant file signatures before and after
reading. A changed current pin cannot reuse a prior admission.

Every validation hashes all complete original saved-reply DTOs, including the
literal raw reply string, SHA, request and host/native anchor. The already
admitted prefix must remain byte-identical, with exact JSON types: tuple/list,
dict subclasses, integer/string keys and Boolean/number aliases cannot share
a key. Mutable cache/candidate values are sealed separately. Truncation,
altered old bytes, foreign scope or a changed pin refuses admission. New rows
always run the unchanged complete original reply validator. The original
current request-table membership/equality checks still run for every row.

The main frame loop, full native/Script/file continuity, VM/code joins,
current UI and status acquisitions, actual namespace/file reads and complete
physical checks remain outside this grammar cache. All original clocks,
negative/quiet windows, cadence, 500-ms maximum gaps and resource caps remain.
The default complete validator is still used on cold construction; no memo is
persisted or reconstructed from a journal or a ready label.

## Candidate and actual exit

Validation proposes a pending candidate and never uses it as a warm prefix.
Repeated validation before a real commit revalidates every new row. The actual
owner's final original fence records that exact candidate only after matching
the current memory scope and reply bytes. All candidate/hash work is before
the original final native/fixture/monotonic age checks.

The public operation wrapper waits for the actual outer Script source-lock
exit. Nested calls or a caller still holding that lock discard the proposal;
they cannot claim a completed exit. An exception on the actual exit cannot
commit. After the real exit the owner requalifies current pin bytes, root
bytes and full original physical inventories. It commits only the exact
pending object, repeats the pin/root/inventory checks, and checks final native,
fixture and monotonic ages including all commit work. A slow commit or a clock
jump aborts and clears the memo. Original journals and uncertain inputs remain
retained. A cold owner replays the complete original grammar and may observe
the original effect; it never resends the command to repair this cache.

No locked controller publication callback reads a Script pin file, fixture,
SDK or native source. That callback uses only the already prepared memory
scope and pure reply grammar, plus its original private CAS and host age
validator. Final memo admission occurs after that entire operation returns
and its actual source lock has exited.

passed in 0.059 s, total 21.94 s. Seven pure counters use the actual original

new-row validation, mutable/copy aliases, Boolean/foreign scope, old-reply and
pin changes, actual outer lock exit/failure, slow hash work and late commit
under frozen/native/fixture clocks.

controls, original controller Session, local cancellation source and physical

decoder call; a new reply does. Cold load has no admission. Mutating an actual

consumed-input journals; cold reconcile observes without another input. The
existing new-run baseline/Open and frozen host-only controller-CAS counters
also passed separately, 2/2 in 5.815 s.
