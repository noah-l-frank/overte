# Original pre-input baseline, normal position restore and process continuation

This source prototype joins the existing Lifecycle owners. It remains partial and
does not advertise a public capability or a complete feature result.

`PicoLifecycleRestore.begin()` runs before the first Create/world input. It
uses the existing original `PicoLifecycleProcessRetirement.begin()` and freezes
the actual initial World/native/domain packets. An existing late pose is never
renamed into this baseline. The existing Create/X/Chat/background/Scripts/
pending/replacement/close/second-world/release owners then run unchanged.

The restore owner derives one literal location-only path from those original
feet and quaternion values. The original `AddressManager` branch for a leading
slash calls `handlePath(..., wasPathOnly=true)` without `setDomainInfo`; the
original scene URL therefore remains under the existing exact equality check.
A complete URL with a new `location` query would replace `_domainURL` and
cannot satisfy that check. No avatar setter is used.

`PicoLifecycleRestoreSurface` is a private subclass of the existing normal
Graphics/Go To surface. Its authority admits only this owner's frozen literal
path. The general Graphics URL policy is unchanged. Tablet/Home/GOTO/field/
normal replacement/submit remain the ordinary input route. Original subject
and widget observations, actual commands and controller envelopes are durable
before transport. A surprising Home-ray requirement is refused before sending
an alternate trigger stream. An uncertain navigation attempt is never repeated;
only actual restored pose and hidden UI can complete its read-only continuation.

Every restore input fence uses the same authoritative `World.current()`, and
the existing `Process.prepare()` supplies the complete original three-second
restored/stationary window. The World128/16-MiB/48-KiB/file/freshness/cadence
limits remain unchanged. The actual executed join must report its final count;
no forecast is a successful budget result. The immediate restart callback may
use that exact just-produced prepare proof only through the unchanged
`require_stop_ready` guard. It never labels a required fresh query a duplicate
or refreshes an old source fact. A stale proof is refused before Stop.

New process owners use version 2. They admit actual NativeChat version 2 or 3
disconnected packets with their genuinely empty connection birth and zero
connection epoch. Connected packets still require the original active mixer,
domain identity and genuinely new connection birth after restart. Existing v1
owners retain their original version/writer and strict version-2 connected
admission. No connection, PID/start, handler UUID or kernel absence is inferred
from ACK, caller input, first-seen time or another source's identity.

The prepared single host test intercepts the existing editor fixture before its
first input, runs its existing nested pending/close prefix, uses the original
normal navigation/token/session classes, then continues the existing process
restart owner. Native Qt/physics/domain/OS effects remain explicitly modeled
boundaries: the model applies the path actually submitted through the normal
field, rather than inserting a requested final pose into an input receipt.
No device/native-client run, independent peer/image closure, complete common
engine execution, final file retirement or public cold/RPC completion is proven.
