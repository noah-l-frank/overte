# Normal Pico Snapshot Capture/Cancel parent

`PicoSnapshotCancelOwner` composes the first normal v16 Snapshot steps with the
existing Pico controls and original source/file owners. It advertises no
`feature.snapshots` triple. `partial-ready` means the original pre-render Cancel
job has stopped and retired after a real no-output quiet window. The SNAP page,
original preferences, native file plan and all journals remain owned for the
following still capture, Save, Share, upload and background/resume operations.

The parent uses the original Pico SNAP entry, controller-open transport and
normal field/combo controls. It selects the run-owned animated name and PNG
through those ordinary inputs. Before Capture it persists the native file plan
and independently scans the actual empty namespace with
[the file owner](SNAPSHOT_CAPTURE_OWNER.md). The existing
[FastCancel](SNAPSHOT_FAST_CANCEL.md) then consumes the actual original Capture
token and sends normal Cancel locally inside the unchanged pre-render window.
No script handler, direct capture/cancel method or replacement timer is added.

Every child action has durable parent intent. Every final QML, file-plan and
FastCancel writer has a parent delivery CAS after its original SDK/candidate
guard. Actual UI token, generation and sequence are joined to the independently
read parent frame. The last exact independent fixture-phase read follows the
last CAS and native guards. Native and host clocks cover the final copies and
fsync. The existing OpenXR intent callback performs only private host CAS; its
publication validator uses the original stored envelope/host age without phase,
SDK/native queries or session reentry. Original session nonce and sequence stay
bound across cold construction. A phase advance, retired fixture or slow final
CAS cannot authorize input from an earlier ticket.

All readers reuse the exact parent ScriptSourceLock instance. The file owner
retains its existing subordinate journal lock. The parent retains bounded
compressed original raw native, Script, file-source and FastCancel packets and
their hashes, complete UI DTOs, independent OS inventory, fixture originals and
original delivery commands. Histories cannot be truncated to make space.
Native, Script and file prefixes are validated again on cold load; malformed
non-null originals are rejected rather than replaced by older convenient data.

The VM join independently reads the actual configured Script root and native
manager/code/compilation inventory. The selected Snapshot compilation must
match the reviewed UTF-16 code-unit pin. Every original pending/cancelled caller
must belong to that exact manager, submitted code and compilation. A matching
basename, echoed command or input receipt cannot supply this provenance. The
root source is the unchanged reviewed root dependency from fixed
`71faaacaa4`; that local dependency is already owned by the integrating branch.

The bounded local job must report actual `pending` then `cancelled` for the same
original Script context, with the actual 350-ms/60-s timers first registered
and then absent. Parent observations retain the initial empty Script history
and native request inventory. A new unrelated context or native allocation
cannot count as this pre-render cancellation. Three seconds must then elapse on
seven original clocks: host monotonic, native requests, Script history, native
UI, native file observer, Script-work outer capture and manager-thread work
capture. Each adjacent sample is at most 500 ms apart on
every clock; a larger gap resets the window. The independently scanned files,
native descriptors and accepted native captures stay empty, the exact Script
history is unchanged, and native projection/request/upload work stays idle.
A fresh unchanged original ScriptWork v2 inventory selects that actual compiled
Snapshot function on every post-cancel probe. Owned/unknown timers, evaluation
or active callbacks prevent quiet, even when the historical cancelled caller
reported no timers. Invocation/registration counters must stay unchanged during
the entire quiet window, so completed work between samples cannot disappear.
Only afterward does the one original local job receive its retirement request.
Native Qt-object or whole feature retirement is not inferred from that flag.

Interrupted arm/open return paths only query their original state. An uncertain
Capture start is never resent: recovery sends a new observation nonce for the
same original job. A missing original job remains unavailable and retains its
intent. A child preference read cannot fabricate an original mode or format
that was never saved. Standalone original file/parent journals block public
legacy input and base-cleanup success even if a base process stop has occurred.
No restart is introduced as a cleanup substitute.

The fixed additional Phone comparison
`c5da60717a36a462715d414da5f71adaa6cbe2bf` was reviewed for actor transition,
partial-source floors and immutable history checks. In particular, malformed

partial prefixes remain floors (`6626edea3d`). The new parent keeps its original
locked prefixes and exact cold readers. The separate single-use unlocked host
history pass from `60d5e290e0`/`fe7c149557` is a candidate for the later heavy
actor/PNG cleanup replay; it is not copied as a second current-source system or
claimed as an implemented independent actor here.

The focused host tests use the actual Pico private factories, normal input
publisher, original OpenXR session, private CAS/fsync, fixed shell scan and
binary transport. Their Qt/VM/local FastCancel target producer is an explicit
synthetic boundary. Actual original QML/NativeFieldInput/timer/VM caller/native
FD checks remain in their existing separate native owning groups. Lost replies,
undelivered starts, late files, changed compiled bytes, frozen target clocks,
slow final CAS, last-guard phase changes, original controller publication and
cold arm/open recovery are covered. No devices or external systems are used.

cases are registered without loss in four smaller groups with the unchanged
120-second limit: `snapshot-normal-cancel-owner`, `snapshot-cancel-quiet`,
`snapshot-cancel-recovery` and `snapshot-cancel-fences`; later narrow recovery
and pure guard cases are included there too. The subsequent live ScriptWork
join is also covered there; its
actual native queue/compiled-function implementation is the existing reviewed
ScriptWork2 source, not a new timer observer. The final selection passed all
four groups (15 cases) in 229.45 s: 53.511, 50.927, 48.865 and 76.148 s.
Registry, coverage, documentation, source layout and whitespace checks passed.
This is a test composition result, not an APK/device run.
