# Independent native Model peer originals and cleanup return

Feature 4/14 remains **partial**. This packet joins the existing normal Create
Parent to a distinct host worker and a distinct observed domain client. It does
not implement the complete common Create Actor or advertise `feature.create.*`.
The existing v4 permission/denial/retry owners, normal controls, resource checks
and complete Parent cleanup window remain unchanged.

## Actual ownership scope, independent effects

After ordinary NEW has produced a measured Model, the existing private Parent's
`issue_peer_scope()` reconstructs its original Model owner, reacquires its native
entity/resource sources and pins the actual owned UUID, actual domain creation
timestamp, original create ticket, native source/client identities, candidate
binding and original fixture provider/birth/activation prefix. Its private
`create-feature-peer-<target-key>-<run>.json` companion persists before handing
off the scope. A requested resource, field value or command receipt cannot
create that scope. The scope gives no entity creation/edit/delete authority.

`PicoCreatePeerSource` must run in another actual host PID/start/boot identity.
It accepts existing `NativeCreateEntities` and `NativeCreateModelResources`
readers for an already bound independent client, the existing
`PhaseFixtureReader` and its own existing `ScriptSourceLock`. Actual query
responses must show both a different native application instance and a
different domain session UUID from Primary, while observing the same original
domain. A second host querying the same client refuses the peer path.

Both clients must expose the existing v4-or-later entity source with actual
`createdEpochUs`. UUID equality alone cannot join an independently observed
recreated entity. Legacy v3 originals remain readable by the ordinary Parent;
they cannot invent a domain birth or opt into this stronger scope.

The worker independently reads the actual entity type, domain host, creation
timestamp, client-local entity lifetime, actual Model URL and loaded Geometry
source hash. The material verdict joins the worker's actual entity assignment
to its independently loaded NetworkTexture/material slot. Actual entity
absence, loading, ignored material propagation and wrong type remain observable
failures or false measurements. Primary supplies UUID ownership scope; Primary
samples and requested URLs never supply worker effect facts. The worker pins
its own Model/Geometry and entity lifetime; later replacement cannot silently
reuse the same domain UUID.

## Existing source and return ownership

The worker owns `create-peer-originals.json` and existing immutable
`ChatSourceChunks` children in a separate private directory. Each original
native command is retained before dispatch; each full response string and
SHA-256 are retained before the native reader parses or rejects it. Commands,
correlations, original timestamps, native sequences, all source fields and
partial acquisitions remain retained. Original fixture metadata is also
retained before a foreign-provider refusal. Failed acquisition is sticky and
cannot issue another query through that worker. Constructor reopening cannot
adopt an old worker's directory or its uncertain queries.

Read admission includes original host/native anchors, final physical checks and
actual outer source-lock release. It never changes an original packet clock.
The source remains bounded by existing query, private-file and immutable-child
budgets, with at most 64 accepted records; no size limit or 120-second journey
budget is increased.

The worker's cleanup observation must first have independently observed the
owned original while present. It then needs actual absence and death of every
observed entity, Model, Geometry, material and texture original. Both native
capture clocks and host time must advance for three seconds, with gaps no
greater than 500 milliseconds. Retained cache objects or an ignored remote
Delete prevent that result. This is observed-original closure, not a complete
allocation history or process-wide resource inventory.

The source reuses the unchanged `ObserverReturnSender`/`ObserverReturnReceiver`
transport and `LinuxChatObserverProcess`: immutable source bytes and full
physical stamps, a new independently consumed Parent nonce, original executable
and program ownership, and actual original worker absence. Consuming a nonce
while the producer is still alive cannot retire the Parent companion. Typed
return admission reloads the original children, reconstructs native continuity,
creation identity, query correlations, material facts, original fixture scope
and the complete independent quiet window. An ACK or a JSON `retired` flag is
not the proof.

The Parent continues ordinary owned deletion/cancellation while its companion
is issued. Final retirement remains blocked until `accept_peer_return()` admits
the original consumed return, observes actual worker absence and verifies
closure of the original process descriptors. A cancelled worker with no return
leaves this companion and original Parent owned. The Parent's existing full
three-second multi-source quiet window still follows this join. Ordinary input
is not replayed during read-only recovery. Original worker/return files remain
retained evidence; this packet does not add their final global archive owner.

## Executable host boundary and remaining integration

The focused `CreatePeerSourceTests` use the real normal Parent/factories,
Open/NEW/Apply/Delete transports, private CAS/source histories, a separate real
stdin process, original process/file owners, opaque return, consumed nonce and
actual exit. Native/Qt/SDK, replicated domain properties, renderer/cache
objects, fixture provider and time are explicit independently faultable models.
The worker constructs its own renderer/resource observations; it receives no
Primary public facts or expected success state. The v4 domain-birth producer
seam is explicit test data, not a migration of historical native originals.
The evidence runner retains only its own temporary fixture directories; actual
worker, source-lock and process-descriptor cleanup still execute.

Counters cover ignored replica creation/material, cache retention, same-client
queries, stale and foreign original responses, original provider substitution,
