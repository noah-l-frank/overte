# Explicit original Pico operation host: transport prerequisite A

Feature4/14 remains partial. This packet supplies one bounded original CLI
process over several operations; it does not enable a Create journey, add
capabilities, compose the independent Actor or qualify final product cleanup.
The existing catalog, common Journey and Pico binding are unchanged.

An explicit `OverteSession.operation_host(private_empty_directory)` context
uses the existing `adapter_client.invoke` seam, including calls made through
`module_support.operation`. It lazily starts one child on the first operation.
Outside this context the original one-process-per-operation path is unchanged,
including Phone/iOS use and its60/120/240-second timeouts. A nested context or
changed manifest/target is refused instead of starting a replacement host.

The actual Android CLI accepts `operation-host` only for an explicit Pico
native binding and target. It constructs the normal source-owned adapter once.
It reads operation DTOs separately; it does not rewrite `vars(args)`, environment
or cwd for each request. The original candidate factory may set its existing
`require_identity` flag once. No other factory argument mutation is admitted;
subsequent exact argument values/types, environment and cwd remain fixed.
Every original adapter/native/candidate guard still runs on normal dispatch.

## Original process and policy boundary

The client pins original manifest, interpreter and CLI entry bytes, complete
physical signatures and actual original OFDs. Only the reviewed Android Pico
native-binding command prefix is eligible. It acquires the actual child
PID/start/boot, direct Parent, executable and exact command line while live.
Both sides check their original identities. Pipes retain independent kernel
aliases; a recycled number, even for the same inode, cannot become its old OFD.

The existing six policy/reader/control environment keys are stripped before
Popen. No policy document, requested verdict or `expectedFacts` is sent.
Request DTOs admit only a version, unique ID, existing operation and arguments,
and original deadline. Existing argument/result contracts remain in use.
Strict JSON types, key uniqueness, depth and exact encoded-size preflight reject
coercions and oversized escaping before codec allocation or process/pipe input.
The live context also refuses changes to its original fixed scope.

The first operation timer starts before manifest pinning, spawn and factory.
All later checks, writes, dispatch, response acquisition, original archive,
decoding and return consume that same operation's unchanged60/120/240 seconds.
Monotonic regressions refuse. The host is local stdio only, sequential and bounded
by1560 seconds and the existing file/byte limits; no socket, discovery, network
listener, daemon, repair or device-test service is introduced.

Successful closure sends an explicit versioned Close frame, drains the original
stdio, obtains actual direct-child `waitpid` status0 and two kernel absence
checks, then releases only qualified original host handles. Bare EOF, a JSON
closed marker, stale PID or a new process cannot replace these facts. Closure
never invokes `adapter.cleanup` or supplies product-resource retirement.
Failure may terminate only the proven original child; lost ownership keeps its
handles uncertain. Host exit alone never proves app/Qt/native cleanup.

## Retained raw originals and uncertainty

The caller supplies a new canonical private empty directory. Its mutable root
uses existing `LifecycleProcessFile` original OFD/CAS handling. Immutable raw
pieces use existing `OriginalDescriptor` and `ClosedOriginalFile` checks. Scope,
actual program/source pins, original request bytes, full original reply bytes,
physical identities, hashes and receipt CAS are retained. There is no cold
adoption, truncation, slot reuse or retry from an earlier namespace.

Before sending, the client reserves one entire4MiB reply,64KiB stderr,64KiB
request, receipt and root/CAS overlap against the unchanged512-file/16MiB bill.
Every binary piece is at most64KiB. Bounded namespace scans and complete original
byte/physical checks remain mandatory. This private transport adds a4MiB wire
window; it does not raise a native/source limit or admit a full Common flow.

Each acquired chunk is kept before its storage attempt and is fsynced before
the next pipe read. Complete replies receive an immutable receipt and verified
CAS before parsing. Malformed, wrong-ID, partial and exact-cap replies remain
available after refusal. Stderr drains nonblockingly under its own bound.
Unsolicited output is retained before any next adapter dispatch. If storage
itself fails, acquired bytes remain in the warm owner and any partial original
remains retained; full durable storage is not falsely claimed in that failure.
No decoder or later acquisition may proceed from it.

Any uncertain delivery, source/FD/program mutation, file/CAS failure, output
limit, parser refusal or timeout permanently poisons that owner. No fallback,
second host, input replay or automatic product cleanup follows. `abort()` cannot
replace the original public failure with a later original-FD guard error or
close a recycled foreign descriptor.

## Next required composition

A warmer adapter alone does not preserve the Create Parent: the current
`_create_journey` factory constructs another object on each call. The next
reviewed packet must cache the actual factory-created Parent, its original
readers/lock, original direct worker and its own `waitpid` responsibility.
It must enter the actual `peer_input_boundary` before the existing common
`client.activate`, hold it through normal input and preserve final original
retirement. The common runner retains all policy/provider control.

There is no Begin/Activate/Act/End protocol in packet A. Such a later bracket
must allocate one original act deadline before Begin and retain that exact
anchor through provider activation, normal dispatch, End and return; separate
calls with refreshed operation timers cannot supply it. Full Create remains
closed until that Parent/input/Actor/effect/final-retirement composition exists.

## Root integration: preserve original prefixes across append windows

Root review reproduced two actual open-original counterexamples: changing the
shared cursor through the exact original OFD could overwrite prior bytes, and
a changed physical timestamp was accepted before the next append. Both failed
against the previous implementation. Appends now use explicit `pwrite` offsets
from the already verified prefix length, independent of the shared cursor. Each
open fragment pins its last observed complete physical signature; every guard,
append and seal checks exact prior bytes and that signature before writing.
Only a successful owned append advances its signature. Partial/unknown writes
keep original responsibility and do not decode, replay or adopt another owner.
