# Original Pico Create modal delivery and Qt resources v1

Feature 4/14 remains partial. This packet supplies an original native join for
ordinary Create Import/Save: actual file-browser root, Qt listener, original QML
context, Window response delivery and normal UI token binding. It does not
advertise the complete Create triple or establish imported domain entities,
product export bytes, model/texture rendering, voxels or domain authority.

Only the dedicated `OVERTE_E2E_FEATURE_TESTS` Pico build with `--testScript`
contains this source. The actual `OffscreenUi::fileDialogAsync` creation thread
records a weak original listener, root, context and window, their random native
identities, exact resolved original component URL and native times. It checks
the original caption, JSON filter, single-file/save mode and actual
`NativeFileBrowser_QMLTYPE_N` base type. Both original direct browsers and the
real `TabletFileDialog.qml` subclass are admitted. The latter has its own actual
resolved URL and no root QML name; neither is rewritten or invented.

The original file listener carries a plain native delivery ticket back through
the existing call. Window may have been invoked from a Script thread, so no
GUI pointer reads, new GUI wait or QML evaluation are added there. The actual
Window response lambda holds the ticket. A native lease starts when that real
callback enters and ends only after its original response signal emission
returns. Root/listener destruction cannot release an unconsumed ticket. Actual
QObject/QML-context lifetime is independently read through weak pointers;
missing views never imply context retirement, and no internal Qt context is
destroyed by this instrumentation.

The source retains at most 32 original dialogs and 128 object generations. An
object shared between records keeps its actual identity; Qt address reuse gets
a new identity. Original roles, identities and event times never change. Dead
objects cannot resurrect. Profile mutation, foreign thread, unexpected duplicate
registration or exhausted bounds makes acquisition unavailable. No private
selected path, callback argument or generated import/export result is recorded.

Pico NavigationUi publishes `createDialogBindingsVersion: 1` and a separate
`createDialogBindings` packet. On the actual GUI thread it joins each original
weak UI root pointer to its actual OffscreenUi-owned delivery record. The
binding includes both source instances, original UI inventory sequence and the
dialog/root/listener/context/window identities. It is not a matching basename,
caption, request nonce or expected effect. A live Create picker without that
original binding makes ordinary input unavailable. The existing private file
IO can read those original bindings for the future durable owner.

The separate read-only `feature-create-dialogs-observe` probe command accepts
only schema, action and a nonce. Its TSI getter requires the private launch and
lifecycle boundary, refuses stopped foreign threads and missing OffscreenUi
dependencies, and records actual native process/acquisition clocks. A bounded
512-result cache preserves original packets/times on replay and never evicts.
The probe saves only the original native packet to private
`feature-create-dialogs.json`. `_create_dialog_observer` reuses the existing
candidate/PID/start/private transport guards and original raw-byte/SHA retention.
Its parser rejects rewritten/lost records, weak resurrection, invalid delivery
phases and foreign UI/native source bindings.

Six selected Python/Node counterexamples are registered in `normal-create`.
The selected `create-dialog-native` Qt5 harness exercises the original
TabletRoot fileDialog function, unchanged TabletFileDialog/NativeFileBrowser QML,
original OffscreenUi factory and ModalDialogListener methods, original Window
browse/save response lambdas and original TSI getter. Ordinary pointer/IME input
produces actual Cancel/Import/Save signals. Original native packets and direct
UI-root bindings pass through the real Python validators. It independently
observes pending/active delivery while the actual Window callback executes,
actual listener/root destruction, retained original context flags, native
replay and missing-dependency refusal. Selecting a Save URL does not create any
export bytes in this test.

The isolated harness stubs tablet routing ownership, reticle presentation and
preference storage, plus the existing host keyboard presentation boundary. It
does not compile the complete application or V8 signal proxy, run OpenXR or
qualify a physical Pico. Actual retained Qt contexts remain resources. Compose
these sources with the separately observed Script callbacks, durable file/input
owner and independent entity/domain effects before claiming full cleanup.

The scalar delivery lease also follows a real Window receiver on its original
foreign Script thread. Only enabled, mutex-protected scalar history changes
there; weak QObject/QML inspection remains GUI-only. The vertical Qt5 harness
moves an actual Window receiver to a running QThread, opens through the original
blocking UI factory, clicks the real Cancel button and independently samples the
GUI source while the original foreign-thread signal callback is still running.
It requires one live dispatch inside that callback and original return/listener
retirement afterward, without a fabricated response or a GUI-thread handoff of
the product callback.
