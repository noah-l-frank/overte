# Pico normal Model resource-binding owner v1

Feature 4/14 remains **partial**. The existing private `_create_models(target,
run)` factory now composes its v2 normal Model/property owner with the passive
[original native resource source](CREATE_MODEL_RESOURCES.md). NEW glTF/OBJ,
normal name/unit dimensions, Properties filter/TextArea/ApplyTyped and distinct
normal Select/Delete keep the original input routes and durable once-only
intents. No full Create operation/capability is advertised.

## Actual effects and durable originals

Before the first normal input belonging to a Model or texture attempt, a
private companion journal pins the exact native resource JSON and SHA-256,
original domain connection generation, process/launch identity and capture
time. It accepts at most four anchors (two Model steps, each with one texture
attempt), bound to the original candidate/session and run. It does not alter
v1/v2 property-owner originals or the v1 original script-work transcript.
The latest original native resource packet has a separate existing-style
private source journal. All native packet/history and private file limits
remain enforced; failure to persist a baseline prevents its associated input.

The first observed actual Model association is durably pinned to the actual
owned Entity UUID, independently of the requested Model URL. It must be a new
native Model original after the pre-input baseline. Once the actual loaded HFM
source URL hash matches, that loaded Geometry identity is also pinned. A later
Model/Geometry replacement for the same Entity cannot silently pass. Actual
resource, entity, script-work and UI capture clocks must all advance at least
three seconds while the measured source/property/work predicates remain
stable. Matching field text and a consumed button receipt cannot supply them.

Before normal texture input, the actual original `checker.png` material slot
must refer to the original run/Model-ticket glTF texture URL, loaded and not
failed. The texture ticket stays distinct in the original property owner.
After the once-only normal ApplyTyped, the actual Entity `textures` property
and original edit time must agree, and the same pinned Model/Geometry and
unchanged material/channel/slot identities must actually refer to loaded,
nonfailed NetworkTexture objects at the distinct texture-ticket URL. Other
channels must retain their actual bindings. A declared independently faultable
renderer actor verifies that an applied Entity property with an unchanged
material binding stays unresolved.

Lost Apply responses reconcile from original observations alone. Partial
filter/text/Apply failures never repeat uncertain input; only the distinct
normal Delete of the actual owned Model may mutate cleanup state. Pinned raw
baselines and native lifetime histories survive reconstruction. A later
same-UUID domain reconnect cannot qualify an orphan after other source
journals have already retired: its preserved resource anchors still require
the original connection generation and original native histories.

## Retirement and remaining boundaries

Normal Delete establishes the actual Entity/object effect separately. The
whole private owner and resource journals retire only after fresh observations
also prove death of all **observed** Model, Geometry, material and texture
originals. Tree absence or shared-pointer expiry cannot supply QObject death.
Cache-held NetworkTexture QObjects and other retained originals keep the owner
open without additional input or eviction. Partial host retirement retains
remaining source/anchor journals; a fresh joint quiet proof can retire those
orphans without resending input.

An older property owner lacking pre-input resource anchors may still use its
original read-only reconciliation/distinct normal Delete routes. It cannot
retroactively claim a complete resource baseline or resource retirement. Those
originals remain retained for a later independently proved whole-lifetime
closure; a requested empty state is never substituted.

This source inventories actually observed objects, rather than every
intermediate allocation/assignment between samples. Original encoded/decoded
image bytes, complete allocation history, actual GPU texture binding, both
completed draw eyes and submitted capture, current visible pixels and peer
replication are still separate required joins. The internal property outcome
remains `texture-property-applied`; this component does not set the full
common Create `textured` checkpoint. Model-to-export composition, PolyVox
world interaction, permission/denied-authority restoration and whole GUI/
script/resource closure remain part of full Create work.

## Host validation

`test_create_model_resource_join.py` uses actual owner/readers/private durable
stores and normal TokenCreateUI envelopes with a declared substituted
Entity/Model/renderer/cache actor. The actor's material/resource state is
independently faultable from the Entity property and receipt; it is not a
physical-client/native-renderer claim. Cases cover actual loaded resource
binding, lost response/read-only recovery, unchanged renderer after a real
property effect, actual native Model replacement, retained model/cache
resources, failed baseline write before input, corrupted original bytes,
partial host retirement/orphan recovery, same-UUID reconnect after partial
retirement and missing legacy pre-input anchors. The original native source
and original QML/normal field routes have separate Qt5/Qt6 source tests.

Registry adds only `pico-create-model-resource-join` v1. The additive
`create-model-resource-join` selector maps to `tablet-and-create-ui`; parent
integration adds one to its actual current catalog count. Full Interface,
domain, peer, Pico, OpenXR and GPU execution remain unrun here.
