# Original Pico Emote cleanup work

`PicoEmoteLifetime` v1 joins actual closed/idle [Pico original sources](EMOTE_SOURCES.md)
to the [original manager-thread work inventory](../../native/SCRIPT_WORK_OBSERVATION.md).
It is an owned private observation component. It neither dispatches an ordinary
input nor retires resources/journals, and advertises no whole Emote capability.

The [fixed Phone selection](PHONE_SHARED_EMOTE_LIFETIME_20261022.json) preserves
the existing original-storage, phase/work joins and bounded quiet architecture.
Only methods through work reading/waiting are selected. Phone finalizers,
background policy and application assumptions are excluded. The actual Pico
raw-widget projection, target-bound private factory and source lock remain in
use. The two role journals and orphaned lifetime journals block base cleanup.

Before constructing a reader or querying native work, the owner durably saves
its reading responsibility. Each record reopens the exact immutable original
source file and validates the real separate Pico Emote manager, compilation,
code, complete all-known membership and native process/feature birth against
the separately acquired work inventory. Advancing global/worker cursors and
original source/phase times remain required. Missing or lost work cannot be
retried after reconstruction; the pending journal remains owned.

A quiet record requires the actual Rig override inactive, tablet closed, no
remaining UI controls, no selected or unknown timer entries (even inactive), no
active selected/unknown callback and no engine evaluation. Original cumulative
callback invocations and timer registrations, Rig calls, lifecycle and Qt input
cursor must remain stable across the window. Work that starts and finishes
between samples resets it. No foreign timer is cleared to produce quiet.

At least three records and three seconds on every actual host monotonic,
device epoch, provider epoch, worker capture, native Rig and UI elapsed clock
are required. Any inter-sample gap over 1.5 seconds resets the window. Individual
reads preserve the existing 1.5-second source freshness and five-second bound,
including final guards and original clocks. The returned window is retained
historical diagnostic evidence; final cleanup must acquire current sources and
prove its other obligations independently.

Nine device-free counterexample cases use actual Pico source/work owners with
explicit synthetic Qt/OpenXR/Rig/VM boundaries. They cover retained/inactive/
unknown timers, active callbacks/evaluation, frozen clocks, missed callback
activity, a new native override, observation gaps, foreign code/membership,
reused cursors, changed phase and lost replies. No actual playback/GPU/device
qualification follows from these simulations. Focused native component compiler
checks retain their separate documented boundaries.

Whole Emote completion still requires all three normal Sit variants, actual
Pico background/recovery, current two-eye avatar images, independent actor
publication and final original Qt/callback/native/file ownership transfer and
journal retirement. This quiet component alone cannot satisfy those obligations.
