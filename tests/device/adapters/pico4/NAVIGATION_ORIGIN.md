# Original directory selection and restoration on Pico

This is an internal source/host component of the unfinished Navigation adapter.
Native sources are uncompiled and actual Qt/VR/device execution remains untested.
Three complete source/host areas remain Scripts, Authentication and Graphics.

## Original sources and permitted baseline

The actual directory URL comes from `MetaverseAPI::getCurrentMetaverseServerURL`:
it reads `private/selectedMetaverseURL`, defaults to the original production URL
with its `/server` path, and can be overridden by HIFI_METAVERSE_URL. The actual
LinkAccountBody directory field writes that setting on normal Enter/Return and
updates the AccountServices auth URL. It also clears the password and can log
out an existing account. A requested fixture URL or UI field alone cannot prove
which endpoint the product uses.

`NavigationEnvironmentObservation.h` is enabled only under both dedicated Pico
E2E flags and --testScript. It reads the actual selected setting and presence,
actual effective MetaverseAPI URL, override presence and the existing passive
AccountManager observation on its actual GUI owner thread. It does not call
isLoggedIn, refresh credentials, create UI, change settings, log out, update auth
or alter TLS. An unowned principal and all original token/refresh/pending state
remain observable through the existing account contract without exporting them.

The existing NavigationUi supplies its actual original frame and weak original
login-page/server-field objects. The source reads only the actual field digest,
active focus and whether the actual original password is empty; no credential
text is copied. It requires the same reviewed generic login control/root. An
incomplete/old frame, unavailable account or missing actual field is unavailable.
Three original unrelated preference values and their presence are privately
hashed together: pinned metaverses, fetched metaverses and maturity filter.
No raw unowned server list, username or password is exported.

Native `navigationEnvironmentVersion:1` is queried only by the closed nonce/run
action `feature-navigation-environment`, using existing lifecycle/private-file
and candidate guards. The original probe writes the fixed private file
`feature-navigation-environment.json`. The source bounds unique requests at 4096
and poisons a wall-clock regression. The shared reader requires exact schema,
HTTPS endpoints without credentials/query/fragment, the actual PID/source birth,
monotone native/UI/account histories and a frame at most 1500 ms old. An original
restoration URL may retain its path. One request has a five-second/51-read bound.

Before any input, the owner requires an explicitly present original selection,
matching effective/auth URL, no environment override, empty original principal,
no token/refresh/pending request, an empty password and a field draft matching
the actual selection. It refuses unowned work rather than clearing it.
An ordinary directory field cannot restore absence of the setting; a candidate
with an implicit default is therefore refused before any input. This is a
concrete source limitation, not permission to seed a setting through a setter.
The selected owned fixture remains a separately supplied strict HTTPS origin;
existing native TLS trust is required. No TLS bypass is added.

## Normal input and durable continuation

`native-navigation-origin-controls` v1 is an optional marker on the existing
Pico NavigationUi. It admits normal Return only for the original login.server
field in addition to the pre-existing password submission. The existing
focused-field key route executes the original QML handler. There is no private
handler invocation, signal emission or new product control. Other platforms and
old snapshots retain their existing operation set.

The private Pico `NavigationOrigin` factory uses the existing bound normal VR
input router and the independent native reader. The parent must already own the
tablet/source/input lock and open the ordinary generic login page. Four normal
steps focus the directory field, replace it, submit it, and use Home to close.
Every exact control/token/process/bridge/generation/input-sequence/elapsed intent
is durably recorded before one input. PicoNavigation's optional expected scope
rejects intervening input before delivery and supplies the same original scope
to native admission. The private input file is cleared after replacement.

Actual field/focus observations resolve the first two steps; matching selected,
effective and passive auth endpoints resolve submission; actual page absence
resolves Home. An ACK cannot replace any effect. All four applied lost replies
can resume from the pending intent without resending. Ignored effects retain
that intent and a replacement parent ticket cannot adopt them. Each call has a
twenty-second ceiling and at most 81 bounded effect reads per stage.

Completion requires a fresh three-second quiet window of advancing native/UI
clocks, unchanged input/page generation and account event/generation counters,
closed original login page and unchanged unrelated preference digest. Gaps above
1500 ms, altered federation/maturity, another input, account work or another
endpoint prevent completion. A distinct parent ticket can restore the exact
captured original selected URL, retaining its path, through the same normal
steps. The parent opens the page again before restoration. No native history is
reset and no credential is reconstructed.

`navigation-origin-operations` v1 preserves at most 256 unique query IDs, the
original baseline, current original packets, pending input and quiet groups.
`navigation-environment-archive` v1 stores each complete original packet in a
private immutable file named from its run and SHA-256. The existing bounded
private-file reader and CAS journal store are reused; missing/changed/escaping
originals fail recreation. The live journal contains digest references so a
full 64-event account history remains within the unchanged 64 KiB limit. Raw
packets keep their original timestamps and account history. All evidence files
remain for the unfinished whole-area finalizer; no global metadata/resource
retirement or actual app-restart transfer is claimed here.

real durable private journals/archives, original probe JavaScript and the actual
LinkAccountBody directory key handler under Node. Qt, native Settings/account,
package/OS and VR boundaries remain simulated. Counterexamples cover all four
lost replies and ignored effects, foreign credentials/drafts/passwords/override,
absent original setting, stale clocks/cursors, source replacement, changed
settings/account/input during quiet, archive/query tampering and full original
64-event history. These tests never compile or run native code.

The [directory owner](NAVIGATION_DIRECTORY.md) now joins current original
HTTP consumption and original Places records/models with normal search. Next
