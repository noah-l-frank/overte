# Original bookmark handoff after a Pico restart

`navigation-bookmark-operations` v2 reads v1 unchanged. Ordinary operations
still use `NavigationBookmarks`, `TokenPlacesUI`, `PicoPlacesIO` and the existing
native control/LocationBookmarks sources. A new optional compressed handoff
retains the complete predecessor journal with its original PID, native birth,
UI root, input tokens, timestamps and three-second storage/UI histories. There
is no metadata rewrite pretending that an old UI belongs to the new process.

The predecessor must have completed normal Add and Rename, have no pending
input, and own exactly the run's renamed bookmark. After actual one-send
`RestartInputs` Stop/Launch, the proof requires both original full native
lifecycle packets, the same candidate/target, a different PID-start and Qt
bridge, the actual new native birth/counters, and the original new-process
kernel `ESRCH` receipt for the old PID. Unknown/permission errors never prove
death. The new LocationBookmarks packet must have a new source birth and match
the original complete map, unowned hash, owned address and physical file
revision/bytes/hash exactly. No adapter writes bookmark storage.

The new ordinary Places page is acquired independently. Its original root must
be new, its submitted QML source unchanged, and its actual owned and unowned UI
rows must join the native map. The transferred owner permits only normal
Delete; Add/Rename and a second nested adoption remain unavailable. Delete
keeps its existing original-effect checks, three-second native/UI quiet,
uncertain-input reconciliation and one-send behavior. Restoring the logical
map does not assert removal of an originally absent backing file.

The private `_navigation_bookmark_adopt` factory uses the actual retained
`RestartInputs` owner, original Pico runtime, native lifecycle/bookmark/process
readers and the parent's existing `ScriptSourceLock`. A fresh original fixture
`open` or `bookmark-delete` activation gates admission before and after the
actual destination CAS. Combined host/native age includes validation and the
CAS; a frozen host clock cannot hide a native jump. Late/changed admission
retains ownership and sends no input. Reacquisition can observe an existing
handoff without repeating Stop, Launch or Delete. The predecessor, restart input
journal and evidence remain until a future whole Navigation finalizer verifies
their independent retirement.

`5527d540e99cc6dba4204a5e904a854e6e1cd2b4`, inspected read-only following the
user's renewed reuse instruction. Its complete Navigation owner was introduced
by `b9a827a8de88ab056eb79c4b3eeb596fbd093e9d`. Its restart sequence supplied the
reuse model: durable ordinary Stop/Launch, full native birth/counters, actual
old-PID absence and unchanged persisted bookmark storage. Pico reuses the
existing shared `RestartInputs`, `validate_native_restart`, native process
presence and already integrated Pico bridge-change validator. Phone's stable
Qt bridge assumption, touch keyboard metrics, private mono marker/image source,
new v17/v18 contract and Phone normal UI are not Pico evidence or a reason to
replace the existing v16 coordinator.

The owning `navigation-bookmark-restart` host selector runs ten unchanged
bookmark cases and nine restart/transfer cases, including the actual private
factory, original private file readers, normal Pico control transport, lost
Stop/Launch/Delete results, old/foreign roots, candidate/storage changes,
unknown process status, final-guard phase changes and both host/native CAS age
counterexamples. OS/process/Qt boundaries remain explicitly synthetic. It does
not build or qualify an APK, launch a product process or access a device.

The whole Navigation parent still must compose normal tablet reopening, both
roles' restart and world/marker/stereo acquisitions, maturity/origin restoration,
independent publication and complete original Script/XHR/Web/resource/journal
retirement. This packet advertises no complete Navigation capability.
