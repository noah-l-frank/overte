## Same original target and independent worker

The new fixture creates the synthetic candidate and its files once in Parent.
It constructs the normal editor through the actual canonical factory before
input. The worker receives only sealed candidate CLI/configuration paths,
expected binding and raw-source connection metadata. It independently creates
the canonical adapter, re-verifies those same candidate files, reads the same
original host session and constructs the existing Actor source. It never
receives a live Parent owner or a measured Parent result, and cannot create a
Default Script manager or emit normal input.

All six native/Qt source producers remain in Parent. The Python factories,
normal transport and durable pre-input intents execute; the native/Qt/SDK/input
effects and physics remain explicitly declared host models. Candidate tools,
APK/receipt contents and OS target metadata are synthetic fixtures, not a
compiled installation or device qualification. Normal Create text still uses
the existing token/Qt-IME operation. Stock VR keyboard Unicode is unproved.

Normal Parent input and Actor acquisition use different ScriptSourceLock
objects in different real Linux processes over the same canonical path. The
positive compares actual held file descriptors' device/inode values and worker

flock acquisition: while Parent holds its original lock, Actor cannot acquire
it, create its source root or issue a native query. Releasing that exact lock
allows the same pending acquisition to proceed; no query or input is retried.

The positive publishes its own baseline, Create and typed-field records after
normal tablet/open/focus/type. Its full binding equals the normal editor's;
its source root equals the canonical normal-owner namespace. The same original
field, durable intent and consumed cursors remain retained. Actual worker exit
and kernel absence are verified. No second mutating World owner is created.
