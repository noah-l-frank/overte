# Durable Pico Create JSON picker composition v1

Feature 4/14 remains partial. `_create_picker(target, run)` now composes the
existing normal Create controls, original JSON staging, actual file-browser
controls, native dialog delivery/context source, actual Script callbacks and
an independent read-only domain-entity source. It provides private `open`,
`cancel`, `import`, `delete`, `reconcile` and `release` operations for a complete
Create owner to call after entering the original Create page. It does not add a
parallel public journey or advertise the incomplete common `feature.create`
capability trio. The existing catalog/OverteSession normal Cube/URL foundation
retains its separate contract.

The owner requires the existing Create/Script opt-ins and candidate/process
binding. It shares the existing Create source lock, refuses another normal
Create or regular Script reservation and records all state in private target/run
files. Four original tickets can coexist in one run. A completed Cancel or
Delete can precede another ticket while its actual original Qt context remains
retained. Each ticket keeps its own original input bytes, file token and path;
there is no transfer to the next resource ticket or invented export file.

Before normal Domain/import-tab/Browse input, the owner captures the original
Create editor inventory, empty selection, actual domain/session/permissions,
original domain scan, full original callback/compile history and native dialog
history. It persists each operation attempt and original control reference
before input. An interrupted operation cannot be replayed after reconstruction.
A distinct normal Cancel can recover an uncertain Open/Import only while its
actual original picker/callback remains observable. A lost Cancel, Select or
Delete is reconciled by original observations alone. Missing or delayed effects
keep ownership; there is no fallback resend.

Opening joins the actual UI-root pointer binding to the native dialog's original
listener/root/context/window identities. Exactly one new native dialog and one
new original Window browse callback must appear. The latter must belong to the
actual assigned manager's compilation of the original `system/create/edit.js`,
including its measured UTF-16 code units and digest. A matching filename alone
is insufficient. Acquired raw native callback/dialog/entity bytes and their
SHA-256 survive adapter reconstruction; restored readers enforce the original
append-only source histories before another observation is accepted.

Cancel uses the actual Cancel button. Accept focuses the actual filename field,
commits only the original owned JSON path through normal IME and clicks Select.
The existing file-control owner independently proves destroyed picker roots
and three seconds of fresh original UI inventory and native/host clock progress.
The composed owner also requires the original native delivery to return, its
listener/root to die, the original Script callback to disconnect and its
original dispatch count to reach zero. Cancel requires the actual original
`Import cancelled.` status, unchanged empty selection and no matching domain
entities. Import requires actual `Imported 1 entities.` status, the real selected
UUID, one independently read Domain Model with the staged name/model URL/unit
dimensions and a native edit time after the original baseline. A consumed input,
selection UUID or status text alone cannot establish the import effect.

The separate `feature-create-entities-observe` hook accepts only schema, fresh
nonce, action and run. Under the existing E2E/Pico/testScript/private lifecycle
boundaries, it reads actual EntityScriptingInterface properties, actual NodeList
domain/session and effective rez permissions. It never creates or edits entities.
It scans Domain entities within 128 metres of the actual avatar, retaining every
original UUID whose actual name uses the run namespace. Those UUIDs are then
queried directly even if moved, renamed or changed to another host. Deleted
UUIDs remain in the original absent-ID inventory; their disappearance from the
radius never proves deletion. The independent property scope is explicitly
`create-domain-v1`, with actual position/dimensions/rotation/name/type/host/model
URL/textures/parent/visibility/lock fields. Unowned scanned entities retain
original property digests and the owner's baseline must remain unchanged.
This is local entity-tree evidence, not independent server/peer/render evidence.

The native source retains 32 owned UUIDs for each of four run namespaces and 512
immutable original nonce results per observer birth. Private JSON records retain the existing
64 KiB finite state limit; an oversized complete original fails closed before
subsequent input rather than truncating history. It refuses missing native
dependencies without instantiating them, stopped foreign threads, exhausted
history, changed commands under an old nonce and unavailable entity reads.
Original PID and acquisition times remain native. Python rejects malformed or
nonfinite rows, changed source/domain/session, lost tracked UUIDs, stale packets
or candidate/process replacement. The normal probe only saves this original
result to its separate private `feature-create-entities.json` file.

Normal Delete uses only the independently observed imported UUID. Actual domain
absence, original unchanged scene, empty selection, returned delivery and quiet
callbacks must persist for three seconds on host and original native clocks.
The final release additionally requires a fresh joint quiet interval, actual
complete picker absence, no active original native dialog/listener/context or
Script callback/dispatch and no owned entities. Native dialog elapsed time,
entity capture time and UI elapsed time must independently advance. A surviving
original QQmlContext is explicitly retained and prevents file/owner retirement;
there is no destruction of Qt internals or inference from page absence.
Original files are released only afterward. Per-ticket release progress is
persisted before subsequent tickets are retired. Base cleanup reports unresolved
picker/source/file journals and retains them even when application teardown
runs. A read-only acquisition failure before the main/file reservation can
retire its observation journals only after a fresh joint three-second native/UI
quiet proof; a missing owner alone never establishes that proof. The existing
normal Cube foundation refuses concurrent picker ownership.

The selected `create-picker-owner` host group exercises normal token controls,
original metadata parsers, actual owned host file bytes, durable reconstruction,
Cancel → second-ticket Import → normal Delete, wrong URL/ACK-only refusal,
uncertain input/reconcile and retained-context release refusal. The separate
`create-entities-native` Qt5/QtCore harness compiles the original TSI getter
against substituted dependency/tree boundaries, runs its native gates,
immutable nonce/budget logic and original moved/renamed/deleted-ID reads, then
validates its original packets with the real Python source parser. The original
Import/Save QML/listener/Window vertical Qt5 harness remains a separate check.
The complete application/entity APIs have not been compiled by this isolated
harness. No device, domain server, peer or renderer has run.

The full Create feature still needs normal model creation and resolved texture
render/peer effects, actual product export, PolyVox input/settled original data,
controlled authority permission denial/restoration, independent full actor and
artifact publication, normal page/settings restoration and the complete common
21-checkpoint driver. These are not replaced by this partial private composition.
