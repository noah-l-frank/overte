## Interfaces that cannot be copied as a whole

The current `PhoneSnapshotsFeature` imports `PhoneCreateFeature`,
`native_phone_touch_state`, Phone marker/world-render ownership, Phone lock and
v18 finalization. Its complete actor/public facade therefore cannot be renamed
as Pico. Pico must retain its actual normal navigation/3D TabletRoot and
OpenXR ownership, independent two-eye render source and current common contract.
Phone's actual mono marker/pixel acquisition does not prove Pico stereo. Pico's
ordinary still getter itself reads half the HMD composite width; a PNG callback
cannot be relabeled as two-eye evidence. Panorama/cubemap retain their own
secondary-camera path and evidence obligations.

The Phone native headers additionally compile only for
`ANDROID_APP_PHONE_INTERFACE`. Any selected neutral component needs explicit
Pico/default/non-Pico build and runtime proofs, actual `--testScript`, private
started lifecycle and original owner/lifetime checks. A macro rename alone is
not qualification. No functional product fix or broader native permission is
part of this selection.

The shared legacy `AndroidSnapshotFiles` at the fixed Phone reference still has
`OVT_SNAPSHOT_FILES_V1` with three columns. Pico's richer original-stat/full-path
source uses explicit V2 and accepts V2 only; producer and parser must move
together. The Phone `CaptureFileTransport.scan()` has a separate unchanged
`OVT_CAPTURE_SCAN_V1` grammar, with its own original root/device/inode/UID/file
metadata and native FD history. It calls the base binary transport, not the
legacy `_list`, and must not be relabeled as the new richer V2 listing.

No source here permits a force-stop ACK, hidden restart, requested deletion or
callback-only export to establish full cleanup. Final original Script work,
Qt/observer scope, private/OS/receiver/server resources, settings, independent
actor and native allocation boundaries must actually close before a complete
Pico capability is advertised.
