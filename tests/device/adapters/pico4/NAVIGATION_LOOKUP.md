# Normal Pico Go To lookup and original modal presentation

This is an internal source/host component, not a complete Navigation capability.
Native additions are uncompiled; Qt, OpenXR and device boundaries in host tests
are synthetic. Physical runs remain zero.

`_navigation_missing` composes the existing TokenScriptUI/PicoScriptIO manager,
actual arrival/Home/bookmark/reply/modal readers, owned provider and the shared
source lock. It starts from independently measured B, a closed Home tablet,
unchanged original bookmark map/file and no retained Navigation/modal owners.
`navigation-missing-lookup` v1 persists each input intent before normal delivery.

The owner opens the tablet with ordinary OpenXR input. It observes the original
Home root/current page and searches at most 32 actual pages for the original
GOTO button. Page changes, GOTO, focus, replacement and Return use the existing
candidate/process-bound pointer and IME paths, fresh tokens and original
bridge/generation/input counters. `pico-navigation-lookup-controls` v1 requires
[native panel v2](../../native/NAVIGATION_PANELS.md) and original address metadata.
An acknowledgment establishes delivery only. The address authority admits only
this run's exact owned `hifi://hidden-<run>` URL while its persisted replace or
submit intent is active; arbitrary URLs or public scopes are not adopted.

Normal Return must produce a new original lookup generation, the owned HTTP
provider's completed 404 response and the same original native captured reply,
queued callback, critical modal root and live listener. Their response identity,
origin, message hash, lookup ticket and original submit barrier are joined.
World B and the original bookmark file/map must remain unchanged throughout.
The original source groups and successful before/input/after history are
retained; they cannot be replaced with requested values or delivery receipts.

On actual Android sources `PlatformInfo.isStandalone()` returns false. The
original `TabletAddressDialog.onAccepted` therefore follows `loadAddress` and
`DialogsManager.hideAddressBar`, which goes Home and closes the HMD tablet.
`OffscreenUi` creates its real message box and emits a notification without a
guaranteed reopen. After observing that original hidden 404 modal, this owner
issues one ordinary tablet open and independently requires physical presentation
of that same root/listener. An already presented original modal needs no reopen.
No Settings override, synthetic error or direct handler invocation is used.

Each action has a 20-second budget, at most 81 observations per pending input,
1024 original query identities and 40 successful input records. Joined source
groups span at most 1500 ms. Lost open/page/GOTO/focus/replace/submit/reopen
results preserve the original pending intent. Recovery observes its effect and
never resends it. Ignored input, foreign callbacks, stale or replaced sources,
extra Qt inputs, changed world/storage, altered histories and ambiguous delivery
remain unresolved. The shared source lock is required during actual actions.

The successful owner retains the original lookup ticket and submit barrier for
[native error dismissal v2](NAVIGATION_ERROR.md), which uses a later challenge.
This component deliberately leaves the visible original modal owned: normal OK,
whole-tablet close and complete resource retirement belong to the enclosing
flow. Navigation state/actor/public composition, maturity/scene restoration,
process/bookmark transfer and complete Script/XHR/Web/timer/callback retirement
remain unfinished. No complete feature triple is advertised.


## Joined normal lookup and later dismissal verification

The recovery self-test executes both existing owners over the same original
PicoNavigation/PicoScriptIO input manager and native source identities. It
activates the later dismissal challenge without retagging the earlier lookup,
then uses original modal OK and proves seven native retirement samples spanning
three seconds. Fresh arrival and original bookmark storage remain at B/baseline.
Lost submit and lost OK results preserve their own intents without another
lookup or click; ignored OK, retained roots/listeners and wrong ticket/barrier
fail. One case performs the missing lookup against the actual owned loopback
HTTP server during normal submit and retains the original 404 header, body
bytes/digest and original response ticket through dismissal. Other provider body
completions and every native/Qt/OpenXR boundary remain simulations. This joined
host test does not supply the missing public feature/actor/finalizer composition.
