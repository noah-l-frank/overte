# Original remote Emote component capture

`PicoEmoteRemoteCapture` is private Capture2 with `mode: remote-avatar`.
The existing local `PicoEmoteCapture` remains Capture1 with its existing default
factories and historical meaning. The two modes do not relabel each other's
headers, image directories, Native sources or local scene/marker evidence.

The component takes an existing `PicoEmoteNativeCycle` Parent and two original
Source3 owners. The primary source runs on the Parent's actual Pico client and
observes the viewer. The viewer source runs on the other actual client and
observes the Parent's actual session UUID. Actual session, target binding,
Native instance, Domain and renderer facts come from their original sources.
The generic binding's `sessionId` remains its QML bridge identity. Avatar
session UUIDs come only from the viewer's independently retained original
primary Native packet; unrelated UI/Avatar UUIDs are never interchanged.
Matching process numbers across devices are allowed; borrowing another Native
instance or renderer birth is not. No requested model, name or input ACK supplies
the viewer's pose, geometry, draw or image facts.

Use `emote_remote_capture.held(parent, primary, viewer)` outside normal actions
to acquire the two distinct existing target source locks in deterministic path
order. `create(adapter, viewer_target, parent, primary, viewer)` then uses the
existing Emote WorldRender factory's explicit Source3 actor branch and original
Pico model-draw reader. That branch checks the actual canonical source pathname
and Script lock, separately from the incompatible Graphics lock namespace.
It preserves existing foreign-owner exclusions, storage and receipt wiring.
Failed sources can retire their same original issued ownership, while both new
intent and actual acquisition send require a live ready source. No device
service, Domain or independent worker is created. Both Source3 owners must
already have their original responsibility;
their histories, cursors and intervals are never reset for a capture.

## One complete bounded normal component cycle

Run the unchanged NativeCycle baseline, normal Open and one normal Play using
its canonical input owner. Create Capture2 against that completed original
Play and call `read(play_ticket)` under the two original locks. It retains
responsibility before the first original remote request or GPU command. One
primary and two viewer Source3 acquisitions bracket the actual submitted stereo
frame. Source originals and their original provider bookends are reopened and
validated from their immutable files. Their actual phase must be the same
original Play ticket and provider instance.

The existing `remote_draws` validator joins the actual remote Avatar/Model/Rig,
loaded geometry/source and viewer recording frustum to both executed submitted
eye camera slots. The viewer renderer birth must match its capture and draw
stream. The original PNG is written by `GraphicsOriginals` with its actual
exclusive file/inode/hash ownership; no re-encoding, copied eye or manufactured
challenge is used. It is submitted draw/PNG provenance, not proof that those
pixels visibly depict an Emote or contain an independently owned marker.

Before returning, the existing capture release engine requires actual drained
image memory and zero callbacks, then the complete original issued receipt
inventory and a separate file-absence observation. The retirement instance
must equal the original viewer renderer before the WorldRender owner is
discarded. An ACK or equal PID cannot qualify that retirement.

Continue with the unchanged normal Cancel and Close. Activate the original
cleanup ticket and let NativeCycle measure its actual final neutral and full
three-second Rig/manager/work quiet interval. `finish_cycle()` finally joins
the same original baseline/Play prefix and actual closed/quiet Parent header to
the completed Capture2 and retirement originals. It reports this bounded
component closed while leaving whole-feature, independent Actor and pixel
qualification false. All source, normal-input, image and quiet journals remain
retained; no product state or journal is silently discarded.

## Failure and original ownership

The capture journal lives below the existing Parent `.child-` prefix. Rootless
children and actual pending writes already prevent generic Pico teardown.
Capture2 itself pins its actual original journal/directory OFDs through the
existing `LifecycleProcessFile` CAS writer. A pending original write or an
uncertain/recycled descriptor cannot be adopted, force-closed or hidden by
constructor failure. The unresolved owner stays strongly retained until actual
host finalization.

Malformed, unavailable, foreign or lost source responses stay with their Source3
request/raw intent. The capture cannot retry a Native or GPU acquisition, and
a failed or late final validation is durably `failed`, including after a
completed metadata save. Host failure recording uses only the exact original
journal owner and performs no product operation. Lost or partial captures can
recover only their same original resource retirement; they cannot acquire a
fresh image or return an old result as a successful observation. A partial PNG
retains its actual planned/opened file responsibility.
The PNG is saved before the later model query or remote bookend can fail.
The exact model request is journaled before dispatch, and its original guard,
send and reply getter remain inside the unchanged Parent/capture interval.
Malformed model-draw reply bytes are not separately archived by this component;
the retained request, PNG and resource owner do not qualify such a reply.

Retirement may inspect a logically failed or acquisition-expired Source3 only
through its same original file/directory OFDs, complete immutable transcript,
unchanged current header and original candidate guard. This cleanup path does
not call the Source3 acquisition guard, query again, renew its clock or make
historical data fresh. The unchanged Parent's 120-second deadline still bounds
the component; expired Parent ownership remains unresolved rather than being
discarded as successful cleanup.

The Parent's original host monotonic, Native and provider anchors remain under
120 seconds throughout remote queries, GPU/storage/inventory dispatch, PNG
writing, final validation and native quiet. Source3 keeps its own original
32-observation, 512-fragment and 16 MiB transcript bounds. Capture2 uses one
primary plus two viewer queries and does not rotate namespaces or create a new
interval. The final delivery includes all decoding, copies, persistence and
guards in the original 1.5-second freshness calculation.

## Qualification limits

Host tests use actual Python/file/OFD owners and the existing normal-input,
phase, renderer, storage and receipt validators. Native Avatar/Qt/GPU/OS facts
remain explicit models. No compiler, actual renderer, device or remote lab run
is performed. A real physical effect, remote clip/caller/Sit recognition,
independent worker/publication, full viewer work quiet and final Actor resource
retirement are not supplied here.

The unchanged Common16 Emotes flow has 28 checkpoints and ordinary random-Sit
collection. Capturing all changed checkpoints with two viewer brackets exceeds
one Source3 owner's 32-query limit. That full flow still needs an original
global cursor/namespace lease and independent role composition which preserve
the same overall 120-second budget; starting a new Source3 to renew it is not
an allowed substitute. Pose changes and newly observed committed sections
remain correlation, never a manufactured remote Emote name or caller proof.

## Selected owning groups

Capture2 and component-cycle1 are private, explicitly selected formats. The
local/default Capture1 factory and reader retain their original version and
meaning; package compatibility includes both explicit modes, without converting
a local scene or self-avatar into a remote observation.

The final canonical three-case route plus twelve legacy Capture1 cases pass
24.845s with274 sources/inputs unchanged. A manual14-case remote aggregate
passes141.584s across independent fixture lifetimes; it is not one bounded
journey or a default120s selection. Root therefore registers disjoint wrappers:
13 remote cases pass77.028s with159 loaded sources unchanged, the original
remaining32-slot counter passes1/3.364s with159 sources unchanged, and a
separate three-case canonical wrapper uses the already qualified actual route.
The old stereo wrapper now selects exactly the unchanged local class, so no
new remote case is duplicated into that existing group. An AST coverage check
requires all17 new cases exactly once. No deadline or counter is raised.

These cases cover actual Script-vs-Graphics lock admission, separately retained
Native Avatar UUIDs versus unrelated QML bridge IDs, wrong client/renderer/eye,
original source capacity, lost acquisition/model/journal results, preserved PNG,
late model dispatch, original OFD/process boundaries, final CAS, callbacks and
Parent timers. Qt/SDK/GPU producer values remain explicit models. Malformed
model reply raw retention, whole28, independent publisher/viewer quiet, clip
causation, challenge pixels and final global retirement remain open.
