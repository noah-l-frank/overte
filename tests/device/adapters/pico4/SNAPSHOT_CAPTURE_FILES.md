# Original Pico capture-file plan, descriptor and retirement source

This E2E-only source selects the actual file-owner algorithm and observer hooks
from fixed Phone `5527d540e99cc6dba4204a5e904a854e6e1cd2b4`, originally introduced
by `7cf33d5dd32d1413d351ca9c29c59dcf4fe2b798`. It changes the platform admission,
class/protocol names and transport to the existing Pico architecture. Braces
and precedence parentheses preserve the selected algorithm under the existing
strict compiler warnings. Observer fingerprint reads additionally use nonblocking
open and reject changed full metadata across FD/path reads, including mode,
UID/GID, links, size, mtime and ctime. A substituted FIFO stays unavailable
without blocking a native worker; normal product opening flags are untouched. It does not adopt the Phone facade, v18 recipe,
touch input, mono render proof or Phone's blocking cross-thread getter.

The normal product's QFile/FILE opening flags, writes, close calls, render and
GIF timing, and failure removal remain unchanged. Dedicated
`OVERTE_E2E_FEATURE_TESTS` plus `ANDROID_APP_PICO_INTERFACE` compile the observer;
actual `--testScript` enables its registry. Original accepted capture begin and
terminal notifications, the Application still-save/complete360/GIF capture
scopes and original QFile/FILE callbacks supply ownership. A file row records
its original capture, preexisting status, directory device/inode, opened file
descriptor and device/inode, actual close, byte count and independently read
SHA256. Pending, failed, cancelled and normally removed files remain visible.

Before normal Capture, a persisted operation ID must plan an empty exclusive
run-owned prefix. A native original namespace scan must be empty. A preexisting
file or capture that began before that plan cannot be retroactively adopted.
The existing `parity-<16hex>-<kind>` names remain valid; separate `e2e-<32hex>`
scopes are distinct original plans. Matching prefixes cannot overlap. Native
histories have 64-entry bounds and retain earlier scopes and original failures.

`Test.featurePicoSnapshotCaptureFiles` uses the existing bounded weak Snapshot
queue. It requires the actual private FeatureLifecycle, testScript, HMD mode,
settled queue and already available Snapshot dependency, without initializing
it. Private commands are closed and nonce-consumed before plan/retire/seal.
The existing Probe forwards unchanged actual DTOs to the private
`feature-pico-snapshot-files.json` writer. Original sources remain distinct from
`accepted`: that flag is never proof of a plan, file, successful write or close.

`_snapshot_capture_file_source` binds the exact parent ScriptSourceLock.
Read-only sources cannot issue controls. A control source requires its parent's
exact final `before_send` callback. `PicoSnapshotCaptureFileIO` reuses the
original NativeNavigationIO writer and callback after its last candidate/
process guard, targeting only the existing Android control-command channel.
The temporary status correlation envelope supplies no state facts; the strict
source independently acquires the original complete native packet. A fresh
nonce is required for every observation. Historical restore is a prefix only;
new reads cannot retime an old packet. Final result copies and native guards
are followed by both native-clock and monotonic source-age checks. Both private
Snapshot source IO classes also recheck the actual installed candidate on each
source guard; their final freshness guard cannot rely only on unchanged PID.

Retirement accepts an original file ID and persisted operation ID, never a
caller path, digest, expected body or success value. All known captures must
be terminal and original descriptors closed. Actual inode/bytes/digest and
original directory identity must still agree before one unlink. The same
operation subsequently reads original absence and never repeats deletion.
Normal product removal and open failures remain separate retained originals.
A namespace seals only after original closure and actual absence. Late files,
changed identities/bytes, unknown history and permission errors stay red.
The supported exclusion is an exclusive owned prefix and cooperating normal
producers. POSIX stat/unlink is not an atomic inode-conditional operation
against arbitrary concurrent same-UID writers; that guarantee is not claimed.

The `snapshot-file-originals` host selector compiles original Snapshot PNG save,
complete360 and the new whole TSI getter against actual Qt and files. The old
native request/weak-lifetime compiler also compiles the new hooks. A second
check compiles the unchanged actual GIF worker with the already reviewed real
GifCreator fixture, pinned by SHA256. Real PNG/GIF bytes, original descriptors,
close, inode replacement, changed bytes, partial failures, cancellation,
preexisting files, unexplained absence, late output and one-send retirement
are exercised. Production/non-Pico and missing-testScript profiles preserve
ordinary encoding without an owner. Account/address/UI, renderer/scheduling,
VM and target transport remain explicit host seams. Application still-render
callback scope placement is source-reviewed; the full Application translation
unit and physical renderer are not compiled or run by this check.

This remains a private component, not the whole Snapshot triple. The next
composition must durably bind the native plan and independent OS empty scan
before the actual normal [FastCancel](SNAPSHOT_FAST_CANCEL.md) input, then join
original VM/code, descriptor/file inventories and three-second quiet. The fixed
Phone host file owner and separate `OVT_CAPTURE_SCAN_V1` binary scan are reuse
candidates; neither is implemented by relabeling Pico's richer existing shared
LIST V2. Still-file and actor ownership, all v16 export/permission/OS steps,
settings/Qt/directory/native-resource finalization and device evidence remain
open. Native plan/file histories stay retained; no restart or common cleanup
contract change is introduced.
