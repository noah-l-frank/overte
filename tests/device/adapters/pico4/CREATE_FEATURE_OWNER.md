## Original ownership and normal input

normal Pico control transport and source lock. Its adapter-only fixture client
can read original phase metadata; it has no runner/actor publishing or authority
mutation credential. Metadata is input history, never an effect source. Every
root call and actual normal input original is durably written before granting
input. The child then persists its own original intent. Failure at either write
prevents that input. All private histories remain candidate, process/launch,
run, source, domain connection generation and real script compilation bound.
Every parent intent freshly rereads the original fixture phase after UI/native
acquisition, before granting child/Qt dispatch. The current ticket and exact
activation prefix must still equal the original pending call, or the recorded
cleanup activation. Advancing or retired phases retain the original pending
owner without dispatch or replay. Act/reconciliation completion and final
retirement freshly check the phase again, then all acquired source/UI capture
ages, before changing completion or removing originals. A combined sample
anchor retains original native epoch plus host monotonic start before source
acquisition. Admission uses the maximum of actual native now and the initial
epoch plus rounded-up elapsed host milliseconds, including final phase reads,
retained copies, Root CAS and candidate guards. Frozen native time cannot hide
a slow host. Original packet clocks are never changed.

The bounded `pico-create-feature-completion` v1 companion retains the exact
original call through the pending-clear CAS and its subsequent checks. A
failed post-write check restores pending; if that restoration itself fails or
the process stops mid-transition, the companion blocks later input and
restores the original ticket before read-only reconciliation. It grants no
effect, retry or fixture mutation. Retirement retains it until original joint
proof; no marker is interpreted as a successful input receipt.

Stored calls must exist with their exact typed stimulus and order in the
original fixture phase history. No requested state is accepted.

## Lost replies and joint cleanup

A lost reply leaves the root's exact original call pending. Read-only
reconciliation can qualify independently measured effects; it cannot resume
unattempted configuration or repeat an uncertain normal input. A Model created
before a lost NEW response can instead receive a distinct ordinary Delete.
An original file dialog may receive a distinct normal Cancel while still
actually pending. A consumed choice that already returned is read, not cancelled
again. Child attempt journals prevent retrying these uncertain cleanup inputs.

Cleanup requires an actual coordinator cleanup activation and keeps the
original pending call. The root owns all source histories until fresh joint
observations prove all actual known Entity, Model, Geometry, material, texture,
callback/listener and Qt context retirement, quiet actual script work, original
setting/file restoration through their existing owners, and restoration of the
original tablet state. Host time alone is insufficient: entity/resource/work
capture clocks, native dialog elapsed time, UI elapsed time and lifecycle capture time must also advance
at least three seconds during the final common quiet interval. The root never
restarts the process, evicts caches, deletes product objects or pumps Qt events
to manufacture retirement. Partial child retirement leaves the root originals
and remaining files owned for fresh read-only recovery.

Actual cached resource QObjects and original QQmlContexts can remain alive.
They keep cleanup open. The existing original LastBrowseLocation writer can
also fail to restore some original typed values physically; that boundary stays
retained. A completed root cleanup has no remaining component journals; another
cleanup call returns only a performed receipt, with no state/effect assertion.
Actual target baseline observation remains a separate required source.
