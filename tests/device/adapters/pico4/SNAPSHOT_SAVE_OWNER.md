# Normal Pico Snapshot Save component

`PicoSnapshotSaveOwner` continues the existing normal Cancel/Still owner at
`still-ready`. This is the unchanged v16 MediaStore branch: the original SDK
profile must select `media-store`; Photos permission rows and Documents picker
rows are selected only by their original supported backend. A Documents source
is refused before new input until its exact provider/name proof exists. No
Pico filename, product button, common recipe or backend operation is changed.

## One original parent and one ordinary Save

The factory reuses the exact parent's ScriptSourceLock and normal PicoNavigation
publisher. The Cancel owner admits one typed Save continuation at still-ready;
it does not replace the final transport callback or add another input system.
The parent journal/immutable originals and original capture host inode remain
pinned. New full original frames use the existing ChatSourceChunks mechanism
under a separate `snapshot-save` scope; orphans block public input/base cleanup.

Prepare binds the actual current NativeSnapshotAdapter handle and original
captured path. Before the ordinary existing Save button, the parent persists
`input-issued`, observes again, then persists the exact completed QML command.
The callback checks its original path hash, token, generation, next sequence,
UI source and unchanged export baseline. All native guards precede the last
exact fixture-phase read. Final native and host clocks cover journal fsync,
copying and guards. A late phase/clock change leaves the intent unresolved and
prevents the original writer. Cold code never sends Save again.
An interrupted `prepare-issued` can finish with read-only observations. Any
previously stored handle/export baseline remains authoritative; recovery cannot
replace it with an intervening export or issue another preparation/input.

## Save effect and independent PNG

A new original Java request must match that actual native handle/path, follow
its ordinary QML intent and contain created/copied/published/delivered-success
original events. Success callbacks alone are insufficient. The existing OS
owner must have independently qualified the actual new MediaStore URI with
its original provider UID, Pico owner package, exact display name, device/inode
and reopened/closed original stream. Its provider UID differs from the original
capture's actual app UID; its file identity differs from the original capture.
The actual original byte count and digest must match the independent captured
PNG. No requested digest, URI, filename or successful result enters a command.

The owner next persists one exact readback command/resource ID. Only an actual
completed native job can qualify its private copy. Native source version,
instance, query sequence, full histories and immutable terminal identities stay
bound. A lost response is recovered by new read-only observations of that job;
an absent/failed/unknown job cannot cause a replacement read command.

The existing private binary transport independently reads that real copy. Host
publication reuses the unchanged exclusive planned/opened/saved writer and
inode-bound partial recovery from PicoSnapshotCaptureFiles. The resulting
bytes must decode as PNG and equal the original captured PNG bytes. Native
completion and current acquisition epochs remain separate. Host publication
failure retains its planned/opened original; no existing file is adopted.

## Current original quiet

OS-destinations V3 is explicit. The original existing private inspection now
reopens/closes the provider stream and rechecks identity/hash before recording
`verifiedEpochMs`. V1/V2 cached publish/absence views cannot qualify current
Save quiet. Each inspection has its own durable original envelope before its
one publication. Recovery must resolve that exact original check before any
later check can be sent; no unknown inspection is retired or resent.

Each qualified checkpoint also rereads actual private-copy full stat/hash
metadata, current native capture/file observations, original Script work,
normal Review state and original native export lease. Fifteen clocks must
advance three seconds with gaps at most 500 ms. Provider content/identity,
private-copy complete provenance, original histories and invocation counts
stay unchanged. All interleaved pre-inspection/pending frames remain archived;
the quiet window explicitly cites only its successful original checkpoints.
Cold validation checks the same timestamps, signatures and original check IDs.
It cannot replace those frames with cached publish facts or acknowledgment.

The provider source exposes device/inode and reopened bytes; it does not claim
unexported provider mtime/ctime. The private copy includes full mtime/ctime.
`pendingIo=[]` proves task quiet; `workersTerminated` describes only E2E readback
workers. Neither proves the product OverteSnapshotExport pool destroyed.

## Retained obligations

The result is `PICO_NORMAL_SNAPSHOT_SAVE_COMPONENT_ONLY`, with whole Snapshot
and device acceptance false. Source images, MediaStore destination, private
copy, host copies, native service maps, UI/context, settings and all original
journals remain owned. This component never deletes them or claims complete
resource retirement. The report is historical; fresh reconciliation/phase
admission is still required for any later operation.

Normal Share/chooser/independent recipient, upload failure/success/independent
backend, HOME/Resume, original restore, concrete worker/Qt/process retirement,
scene/image semantics and full common-engine evidence remain separate required
work. Existing explicitly versioned restart handoffs may later be reviewed for
an authorized cleanup transition; this component introduces no restart,
force-stop, product executor shutdown or common-contract exception.

The host flow's JNI/renderer/Android provider are named seams. It creates and
hashes separate real files and executes actual Pico transport/factory/file
scripts; native QML/JNI and original Java owner checks are separately owned.
No host result is an Android OS, Pico stereo or SDK26 qualification.
