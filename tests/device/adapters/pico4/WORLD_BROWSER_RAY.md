# Pico world Web: original geometry and normal trigger

This is a private, partial World Web component. It adds no complete feature
capability. The enclosing 19-checkpoint world journey, trusted DOM effects,
text/keyboard, independent actor/stereo evidence and complete retirement remain
required. An OpenXR transport acknowledgement is only an input receipt.

The fixed Phone browser owner reuse is recorded in [the original browser
handoff](BROWSER_ORIGINALS.md). The world input path uses the existing calibrated
Pico controller/session. It does not inherit Phone touch coordinates. No Phone,
iOS or reference worktree is changed.

`pico-browser-originals` v3 adds only `measure-ray` for `pico-world-web`.
Ordinary commands retain their existing v2 wire form; historical v1/v2 archives
remain readable. Tablet/reference actions cannot request a world ray. The
command contains the original native handle/creation/grant/page and a closed
fixture control. Host coordinates, arbitrary selectors, text and desired
outcomes are not fields of this passive operation.

The actual selected NativeWebViewItem requests the unchanged owned Java DOM
geometry. Its original asynchronous callback validates document/grant/page,
image, visibility, presentation and world surface before invoking the passive
`PicoWorldWebRayProvider`. Ordinary tablet pointer/IME/wheel operations retain
their original Tablet-only guard. The observer neither focuses nor delivers
input. It preserves the original geometry string and native document identity.

The default-off E2E/Pico scene provider resolves the actual sourceIdentity and
its actual QQmlContext to the same Web entity. It accepts only the owned local,
visible, pickable `OVERTE_PARITY_WEB_REFERENCE`, with matching source URL,
positive dimensions, supported DPI, unit rotation, central registration and no
parent. The original NormalControlUi hit test rejects actual overlays, clipped
points and disabled controls before returning geometry. It reads actual item-to-scene corners, window size, entity pose, tracking
matrix and HMD position. Parent-scaled/noncentral geometry is unavailable.
The Python consumer separately checks the complete closed V1 ray, actual DOM
center through that item quad, DPI/window cap and the world point.

Projection follows the original `RayPick::projectOntoXYPlane` and
`WebEntityRenderer` methods. Window dimensions are capped at 4096 and truncated
by the real QSize conversion. Pointer conversion still multiplies by the raw
39.3701 * DPI; treating the capped window as a normalized full entity would aim
at the wrong point. Actual item corners also retain the keyboard-shrunk or
translated QML surface rather than assuming a full-window item.

`PicoWorldRayClick` measures once and uses the existing `observed_grip_pose`
tracking conversion and right-hand OpenXR calibration. `_world_browser_click`
binds the existing launcher identity, exact Script source lock and existing
input session. Before input the enclosing owner must persist the complete
original intent. Its separate stream callback durably binds the actual original
64-hex session nonce, sequence and `input.primary` envelope. Final publication
callbacks are host-only and match that exact envelope; they do not query the
native clock, guard, HTTP or locked SDK. The original host/native clock anchors
cover measurement, durable writes, publication and the original reply within
1500 ms. A late or lost reply consumes the one-shot object and retains unresolved
parent ownership; there is no resend or cold adoption.

This component returns the original session receipt. The enclosing parent must
independently acquire actual trusted DOM/script/server effects and neutralization
before advancing its phase. Callbacks are not a complete phase/cleanup owner,
and this component does not remove journals or declare a resource absent.

The `world-web-ray` owning group contains eight input/source counterexamples,
one actual private-factory case and one fresh Qt5 compilation of the unchanged
provider, RayPick and renderer method bodies. Its entity/avatar/HMD getters and
Android DOM/transport are explicit host boundaries. Three literal native output
rays (including DPI cap, rotation and translated/shrunk item) pass the production
Python consumer; malformed/foreign geometry and stale, slow, lost or changed
input envelopes are refused. The complete selected NativeWebViewItem translation
unit also compiles and passes the existing original tablet pointer/IME regression.
The combined 23 cases pass in 11.403 s. Literal native outputs, extracted original
bodies and source hashes are retained privately. Two earlier harness-only failures
(missing host library search path and missing SourceLock constructor argument)
preceded that result. These checks qualify selected host components; the full
application/APK, Android WebView scheduling and devices remain unverified.

## World text continuation (2026-10-24)

`pico-browser-originals` v4 adds the world-only `commit-text` response; ordinary
commands remain v2 and passive rays remain v3. `pico-world-web-text` v1 keeps the
complete original focused geometry string, native editor text/cursor/anchor,
kind/sensitivity/enabled/focus metadata, original IME attempt epoch and native
view identity. It is limited to the closed `text`/`foreign` controls. Historical
v1/v2/v3 forms keep their meanings. The separate `delivered` Boolean describes
only the actual IME attempt. A false attempt retains these same originals.

The native callback invokes no pointer or focus operation. It requires a fresh
original focused DOM field, exact independently received native editor metadata,
current world document/grant/page/image and matching original editor kind. The
original world scene/hit-test provider must admit the actual item/point before
one ordinary QInputMethodEvent goes through the actual QQuickWindow. Hidden or
sensitive editors, unsupported selection/absolute-position ranges, private key
codes, malformed UTF-16 and unbound/foreign sources are refused. The native view
identity and editor metadata are copied before event dispatch, so synchronous
item retirement cannot cause a post-event dereference. The actual native nonce
is consumed before dispatch. There is no second IME attempt for that nonce.

`PicoWorldTextInput` composes the existing one-shot normal controller ray, fresh
independent focused geometry, a separate durable IME intent, one commit and a
fresh independent geometry readback of the actual text. All stages share one
five-second host/native budget, with the existing per-source and native callback
limits retained. An ignored ray never acquires focus; a successful IME receipt
without an actual editor change cannot complete the sequence. Any failure latches
uncertain ownership, and the caller retains all phase, gesture and IME journals.
The private `_world_browser_text` factory uses the same existing source lock and
launcher/session. This is still a component of the enclosing world journey;
fixture-phase ownership and whole cleanup are not replaced by these callbacks.

Thirty selected cases pass in12.537s, including the seven new text cases and the
unchanged browser regressions. The original text provider and complete selected
NativeWebViewItem/JNI world callback are freshly compiled. An actual world-item
host case verifies native focus refusal, one real Qt/Java IME delivery, unchanged
actual native text at the substituted Android consumer, no pointer attempt,
negative delivery behind an overlay, same-nonce replay without another event, and native source
retirement. Entity/HMD resolution and the delivered normal-focus callback are
explicit boundaries in that backend case; the original scene provider is compiled
separately against real Qt transforms. Literal native outputs and extracted
provider bodies are retained privately. Seven Python flow/counter cases use an
explicit input-consumer model, with ignored-ray and ignored-IME variants. Neither
model is Android WebView, OpenXR device or full application qualification.
