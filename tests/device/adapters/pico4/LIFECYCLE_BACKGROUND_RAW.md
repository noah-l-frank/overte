# Lifecycle Background3 raw storage

The explicit `raw_layout=True` option on the existing private Background
factory selects one warm `LifecycleBackgroundRaw3` on the same original
`ScriptSourceLock`, target, run, binding, native process and normal owner graph.
The default factory and existing Background1 archives keep their old layout.
This storage option does not enable a public Lifecycle capability or complete
the sixteen-action journey, required image checks, native execution or device
acceptance.

Background3 stores each actual getter return in the existing `AudioRawArchive`
range journal. That includes empty returns, repeated getters, rejected replies
and acquired replies whose candidate dies before archival. A durable reservation
precedes the actual send/getter. Literal bytes and their original command,
receipt ordinal, physical identities and host clocks survive before parsing or
the next query. An uncertain send, append, receipt or root CAS is terminal;
there is no resend, replacement owner or cold writer adoption.

The actual five readers are Lifecycle UI, Gesture, Drive, native Background and
native Feature. The existing `capture`/`read`/`exchange` bodies supply their
original `started` and requested native clock through an optional `before_io`
callback. Its default is `None`. After storage work, the transport wrapper
rechecks the same original five-second acquisition bound. It also preserves the
existing World and enclosing Background 1.5-second acquisition bounds and the
original mutating arm/release input fence. Acquired raw retention has no native
query or business-clock gate. The Chat observation preceding Background runtime
admission remains outside these five hooked reader instances.

The owner projection references the earliest exact retained receipt for a raw
SHA. A later getter still has its own durable receipt and original clock. It
cannot renew the projection's receipt. No extra long-lived raw string or
canonical DTO cache is retained. One fresh host-only batch checks the complete
current part/index bytes, original OFDs, physical stamps, range extents, UTF8 and
hashes. Encoding and decoding compare against temporary bytes from that batch.

The closed namespace bill inventories all existing files and their complete
physical sizes before JSON parsing. It then reserves all declared outer packed
decoders, source bundles, nested history, expanded owner copies and three full
owner/CAS copies before the first decompression. Additional decoder peaks are
preflighted before allocation. Disk bytes, read-pass bytes, decoded DTOs,
temporary raw batches, metadata and the incoming literal reservation are
additive under the unchanged 512-part, 16 MiB and 64 KiB bounds. Unknown, malformed,
oversized or pending foreign files prevent the next query. No mutable decoded
or cost cache supplies budget authority.

A pure verification pass can reuse only the same original capacity admission:
the complete namespace name/stat lease remains pinned under the original lock,
and raw growth is bounded by a genuinely issued durable reservation. Foreign
growth or a replaced lease fails before batch reads. A full bill is required
before queries and materializing encode/decode. The full bill itself checks
the existing lease before reading or decoding; it cannot adopt changed known
roots, plausible additional chunks or a replaced same-byte inode. Actual local
Background owner CAS and exact warm Operations writer receipts are accounted
explicitly. Other writers require their own original typed receipt; receiving a
new full bill alone never authorizes a changed file. This grants no fresh source
or input authority.

The opt-in warm `LifecycleWriteGate` is installed on the same actual Chat,
World and Source3 writer objects. Its one-use permit reserves the complete
encoding, child, root-CAS, metadata and temporary-copy window before the
existing codec runs. An open permit blocks external namespace reentry and a
second writer. World1/2, Chat1 and Source3 root/Chunk1 grammars remain unchanged;
default `None` writers retain their existing path. Original source/phase clocks
and acquisition anchors are compared without renewal.

A root transition pins the existing prepublication OFD and full original bytes
before the existing writer's actual CAS. Completion requires its actual
readback/new eight-field stamp, unchanged other old pins and the original old
OFD's exact unlinked bytes. Source3 reserves before `source_bundles.prepare`;
its opt-in child sink reuses the unchanged canonical/pack/digest codec while
holding the actual O_EXCL creation descriptor and independent kernel alias
through chmod 0600, positional writes, fsync and exact readback. Only this proven
child and its actual root CAS can extend the existing lease. This is distinct
from a post-hoc reader opened after a file was created. Unknown writes, changed
OFDs, failed close or preflight failure retain the exact writer, permit and
already-acquired value strongly, including a failure before a permit returns.
No deletion, retry, cold adoption or additional Native acquisition is granted.
Actor/peer writer composition remains outside this packet.
