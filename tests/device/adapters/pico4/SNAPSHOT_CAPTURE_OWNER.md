# Durable original Pico Snapshot file ownership

`PicoSnapshotCaptureFiles` selects the existing fixed Phone5527 host file owner
from `7cf33d5dd32d1413d351ca9c29c59dcf4fe2b798`. Its real independent shell scan,
binary reads, native file-ID ownership, private host publication and one-send
retirement are reused. It is not a second capture/input implementation and
does not advertise the Snapshot feature triple.

The private Pico factory binds the original current normal UI bridge, candidate,
process and parent context before constructing the owner. It acquires the exact
parent ScriptSourceLock before the separate file-journal lock; all nested
source readers reuse that same instance. The private canonical artifact and
journal roots remain owned. Controls require the parent's exact final callback;
read-only observers cannot plan, delete or seal target resources.

The Pico owner version 1 adds an explicit closed `controls` journal to the
selected algorithm. It persists each actual final native control command after
its last SDK/candidate guard, matching the already durable plan/file/operation
ID. This is intent, never an observed effect. CAS compares the original loaded
revision and verifies readback instead of overwriting an intervening revision.
The outer parent applies its phase fence after that final CAS. The source then
checks its original host admission deadline before the original writer, with
no SDK/source read in that final callback. A slow CAS remains unresolved and
cannot silently issue or cold-resend the native plan. Existing Phone journals
without this Pico ledger are not silently migrated or adopted.

`plan(scope, prefix)` persists its operation ID before native preflight and
independently scans the real OS namespace. Native plan and OS directory/file
identities must agree. Existing unplanned files cannot become owned results.
Repeating a persisted plan only reconciles its native history and later owned
outputs. The method never sends ordinary Capture input.

The separate fixed `OVT_CAPTURE_SCAN_V1` protocol uses the existing private
AndroidSnapshotFiles binary transport. It observes directory identity and each
actual file's device/inode/size/UID/link-count/digest. It neither substitutes for
nor changes the richer shared Snapshot LIST V2 provenance format. Missing or
incomplete success framing, wrong ownership, symlink/hardlink, extra output,
changed bytes/inodes or permission errors remain unavailable.

Acquisition requires an original completed capture and closed native file,
independent before/after OS reads and actual bounded binary bytes. Historical
native close time remains separate from acquisition completion time. Host
publication is exclusive and records planned/opened/saved state plus its actual
inode before fsync. Reacquisition reads the target again. Same-byte foreign
host inodes and incomplete unowned collisions cannot refresh an old artifact.
Full FD/path metadata is checked across host reads. Archived native boolean/
counter types remain strict and cannot be repaired into observations.

Retirement journals each original file/operation intent before one native
control delivery. Lost responses reconcile native IDs/absence rather than
resending deletion. Partial, failed, cancelled and normally removed files stay
obligations. Native plans seal only after closure and actual namespace absence.
Host removal records durable intent and requires its original owned inode;
interrupted owned publications resume from their exact actual byte prefix.
Late files, dropped native histories, changed roots and missing unretired host
copies stay red. All receipts and histories remain retained.

A separately created read-only owner can attach an original binding and read
its own target bytes into its own private artifact root. It removes only those
host copies and requires the primary's actual target retirement. Credential
registration and the complete independent feature observer remain outer-owner
work; this component does not claim an independent physical/feature actor.

The `snapshot-capture-file-owner` host group selects 28 owner/scan/recovery
cases and one actual private Pico factory case. Fixed shell scripts, host
files/inodes/bytes and private CAS/fsync are real. The native target producer
is an explicit synthetic transport boundary; actual native PNG/GIF/descriptor
and ordinary QML input checks remain in their separate owning groups. Tests
cover response loss without resend, ignored control, incomplete writes, same-
byte foreign inodes, mutation, retained failures, read-only roles, late output,
strict cold archives, foreign journal revisions, distinct scan framing and a
final two-second CAS delay with a frozen native clock. No device is used.
