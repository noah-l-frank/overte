# Original retained-page World resume source boundary

Feature 6 remains partial. The continuous private normal prefix reaches thirteen
of the unchanged nineteen common v16 steps. This host-native counterexample
establishes a concrete source boundary before adding background/resume; it does
not change any native producer, foreground/grant behavior, observer protocol,
normal input or public capability.

## Actual existing path

`EmbeddedWebView.setForeground` calls `nativeForeground`, updates each original
Java document grant and, for a retained document, resumes/authorizes the same
WebView without reloading it. `NativeWebViewItem::acceptForeground` advances the
original session generation. The existing native world DOM source requires the
original `_featureWebFinishedGrant/Page/Document` to equal the current tuple
before making its Java DOM query. That finished tuple changes only at the real
`acceptFeatureWebFinished` event. The original Pico world ray measurement has
the same finished-tuple guard; a normal calibrated Reload cannot borrow geometry
qualified under the previous grant.

When the actual provider has reliable per-document mute, suspension can retain
its document. When mute is unavailable, the original `WebAudioLifecycle` can
close the document instead. The counter below isolates the first actual native
path; it does not pretend that either provider was measured on a Pico device.
The old synthetic Tablet target's unconditional `app.launch` → new source load
is deliberately not used as product evidence for World resume.

## Original-body host counter

`test_world_web_resume_native.py` uses the existing original Pico/JNI test
assembly and complete unmodified `NativeWebViewItem.cpp`. Its test translation
unit includes that original implementation so it can passively inspect the
already-existing E2E `worldWebScopes.documents` inventory; no product accessor,
private/public macro, generated replacement method or new source is added.
Original provider/pointer functions are extracted by the existing helper.
Android WebView callbacks and Java inventory scheduling remain explicit JNI
recorders; the Java runtime acknowledgement is not a full runtime DTO. The
native before/after inventory is produced by the actual native implementation.

The test delivers exactly one initial native page/finished event, obtains its
actual ready World source and writes it privately before doing anything else.
It calls the actual JNI `nativeForeground(false)` and `nativeForeground(true)`,
then independently obtains the current native runtime inventory. It neither
loads a new URL nor sends another finished event. The initial finished identity
is creation3/grant4/page1 in the successful fixture. After return, the current
native identity is still creation3/page1 with active created session, not
loading, and grant6. The live original finish inventory still contains exactly
the old grant4 record and its original timestamp.

A new actual World source request stays pending and dispatches no new Java DOM
query. There is one Java query total, from the original initial observation.
A repeated pending read advances the original pending packet's sequence/time;
it is not an immutable completed reply. The existing source prunes older ready
Observe replies from its bounded native cache. The old nonce correctly becomes
unavailable there; the original finished packet is retained in the private
file archive instead. No old reply is reconstructed from the new state.
A current-grant world Reload measurement is also refused before any Java
geometry query. Finish-event count remains one and delivered reload count zero.

Every initial-finish, grant, runtime, pending, old-cache and measurement original
is written separately before the next assertion. Actual JNI argument strings,
compiler commands, source hashes, binary, diagnostics and first failures remain
in private0700 stages. The compiler/link share the unchanged 90 s bound and the
owning selector retains the unchanged 120 s bound; no device or external service
is used. The retained original implementation's behavior is the expected result
of this diagnostic, not a green whole World journey.

The final exact native case passes in 6.639 s. Two earlier preserved runs fail
only at concrete harness assumptions: same-byte repeated pending packets and
permanent retention of an old completed reply in the native cache. Both were
corrected against the actual original implementation, never by changing the
producer. The first failed stage predates immediate inner-record checkpointing;
its complete source/build/logs are retained, but it has no completed original
packet archive. The second stage retains all originals through its failing
assertion. The final stage retains all successful original records. No old
packet, clock or failed stage is retimed or overwritten.

## Proposed observation extension, not implemented

Any future Pico-World-only version must keep current-grant association separate
from the actual old finished-event identity. An `originalFinish` record would
retain its true handle/creation/grant/page/document/finishedEpoch; a current
record would retain fresh allowed current grant, DOM nonce/epoch and native /
runtime identity. Association requires the same original handle, creation,
page and document plus actual active authorization. It must not mark the new
grant finished, count the old event as another document load, or change the old
Tablet/World getters and their version history.

A corresponding passive geometry form must retain that same association and
may only support ordinary input already authorized by its actual frozen phase.
It cannot insert a manual Reload into `background-resume` to force a replacement
document. The unchanged v16 step explicitly requires a new actual blank
reference document from lifecycle loss; usable retained DOM or a manually
reloaded document cannot substitute for that required lifecycle result.

The isolated original-body counter does not execute the full normal OS HOME /
Activity / Qt / native return chain. That chain still needs an original audit
and meaningful execution before concluding whether lifecycle-driven recreation
occurs elsewhere. Without such proof, step15 is unavailable under unchanged
v16. An additive source can honestly expose retained facts, but cannot change
the original finished-event or document-load inventory to qualify that step.
The observation extension requires separate schema/body/cold/geometry review
before implementation. Normal owned Close/ScriptStop and original resource
retirement remain executable separately from this unresolved phase.

Registration-only coverage passes in 0.094 s (1/245 local catalog groups).
Four repository suites pass in 2.66 s; registry and whitespace checks pass.
The native case is not repeated merely for registration/documentation changes.

## Normal Pico lifecycle source audit

The ordinary once-only route in `pico4/lifecycle_input.py` admits the original
process/candidate and sends exactly `KEYCODE_HOME` or the controlled Activity
start. It does not restart the process or force-stop it. `PicoInterfaceActivity`
`onPause`/`onResume` call `PicoEmbeddedWebHost.foreground`, which calls the actual
shared `EmbeddedWebView.setForeground` and native grant path tested above.
The Activity's separate legacy OffscreenWebView path is not the selected common
NativeWebViewItem backend. The manifest keeps PicoInterfaceActivity singleTask;
Qt delegates a new intent and activity lifecycle, rather than a source URL
change in the World QML loader. The default debug launcher prepares its owned
assets and starts that Activity; this is not a proved new World document.

The Qt application state path in `Application_Events.cpp` publishes visibility
and network/auth gates; its active-state branches do not reload World URLs.
The Pico World QML loader reloads on URL/source changes. OffscreenSurface's
pause/resume toggles rendering without replacing its root. WebEntityRenderer
has a 30 s nonrender timeout method, but the inspected implementation only
configures/connects its private timer and does not start it. No additional
wait is inserted to force that unrelated timeout, and no normal lifecycle
recreation guarantee is inferred from it.

This audit finds no guaranteed immediate lifecycle-driven new World document
in the reviewed normal source path. It is not a device execution or universal
negative proof about every Qt/provider/context-loss path. Without actual
original lifecycle-driven replacement, step 15 remains unavailable under the
unchanged v16 requirement. The separately executable normal Script Stop does
not convert this unresolved background result into a completed recipe.
