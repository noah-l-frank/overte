# Create original voxel source join

Feature 4 remains partial. The existing `create-voxel-source-native` selector
now passes one continuous normal Add/Preset 1, original CPU texture and voxel
edit, settings restoration and normal Delete flow. It reuses the original
`featureCreateEntities` version 6 body, `featureCreateVoxels`,
`CreateEntityLifetimes`, `CreatePolyvoxResources` and the existing production
Python validation, continuity and retirement predicates. No new product getter
or device capability is introduced.

The initially empty original entity source arms the local-insertion observer.
Actual NativeCreate detail controls, Pico/offscreen pointer bodies and field
input open the original NewPolyVoxDialog through complete original `fromQml`
and Tablet callback bodies. Normal inputs select 8³, Preset 1 and the original
initial cube/style. The complete original `createNewEntity` defaults/function,
dialog handler, local-copy/EntityTree insertion, factory, constructor,
initialize and creation-time bodies create the actual object and original
local-insertion event. Its original cuboid handler fills 64 values. No
prepopulated volume, prefixed name alone, adopted object or synthetic insertion
record substitutes for this normal Add.

Octree placement, property application, node/domain/avatar/lifecycle,
controller SDK/pose, entity-list transport, simulation and scene removal remain
named host endpoints. In particular, moving/scaling/naming the dialog-created
object to the canonical stroke position remains a direct declared property
endpoint. The live production Parent and its transport/controller are not
qualified by this native process. Normal QML/NativeCreate bridge/EditModes and
the complete original EditVoxels module handle TOOLS configuration, the actual
registered mapping callback, remove stroke and restoration of all seven
settings. Controller delivery is not an OpenXR/device observation.

The original PathUtils canonicalizes its scripts directory without a trailing
slash. The testgated Extra and Voxel control guards now share one directory-URL
normalization before their existing exact context resolution. PathUtils, QML,
actual product URLs, parent/instance/token checks and input ownership remain
unchanged. The same native selection checks the actual original directory,
its slash equivalent, qrc scheme separation and complete original QML under
foreign file/qrc contexts. Foreign TOOLS pages receive a genuine settings
reply and valid TOOLS tab before rejection, so missing settings/tab cannot
mask the context check.

The original factory runs synchronously on the actual render caller while
its NetworkTexture already has GUI affinity. It moves the new Request to its
own manager thread. A passive observer records this unchanged route; it does
not move product calls or QObject affinities. Request bytes/result/SHA are
read on the actual Request finished thread, then sent as an immutable receipt
to the GUI observer. Weak observations are copied under a mutex. Factory
owner argument and actual QObject parent are separate observations: these
Requests have no QObject parent. Their original factory connects the supplied
NetworkTexture's destroyed signal to Request deleteLater. The original
Resource finished handler also schedules Request deletion after reading it.
Both Request QObjects are already dead at the decoded baseline, while their
factory-owner NetworkTextures still live.

Each fresh mode has newly private data/config/cache roots. Original cold-cache
version initialization happens before the empty baseline. There is no cache

cleanup used as a release action or retirement proof.
