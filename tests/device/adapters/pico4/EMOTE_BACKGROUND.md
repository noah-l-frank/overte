# Owned original Pico Emote background cycle

`PicoEmoteBackground` v1 uses the existing `PicoGraphicsBinding` OS/process and
ordinary lifecycle methods. It reuses the [fixed committed Phone ownership
architecture](PHONE_SHARED_EMOTE_BACKGROUND_20261022.json), while retaining
Pico package, candidate, process/VR identity, input session and source factories.
No new lifecycle input system, Phone SDK or image path is introduced.

The actual Pico Activity `onPause`/`onResume` paths publish existing visibility,
audio and web lifecycle transitions. The owner first retains fresh idle native
Rig and chooser originals under the actual background fixture ticket. Its
existing durable ordinary Emote input history must be acknowledged and have no
pending archive. The before-source and input headers are preserved with the
new owner before any lifecycle input.

Background and activation each have a distinct persisted issued state before
calling the existing ordinary Pico operation. Original kernel process identity
and foreground-package observations independently prove the OS edges. After
activation, new original sources must retain the same process/native birth,
manager/code membership, Rig and immutable animation event/call history, while
native background/activation counts and actual Rig evaluation advance without
another process launch. An OS acknowledgement cannot supply those native facts.

The factory can reopen private responsibility without constructing native UI
or repairing the application. Archive decoding uses original private bytes and
actual OS admission; foreground native factories run only after foreground is
observed. Lost input replies never resend the original operation. A lost
post-activation source leaves its own incomplete acquisition and the background
journal intact; reconstruction cannot query through it again.

If the original action has been retired, a separately activated cleanup phase
may issue one independently journalled normal activation. Lost cleanup replies
also cannot replay. This returns original foreground-recovery context and does
not complete the retired action, prove current feature state or retire journals.
Base cleanup refuses even an orphaned background journal.

Six host cases exercise actual Pico host source/input/phase owners with explicit
synthetic OS/Qt/OpenXR/VM/Rig seams: normal cycle, ignored background, both lost
input replies, missing native activation, lost source and separate lost cleanup
activation. The owning `normal-emote` group also checks the actual private
factory without foreground-native construction. No device or actual background
playback qualification is established.

Whole Emote integration still needs independent process publication, current
original stereo avatar evidence, normal all-three-Sit
coverage, actor publication and final native/Qt/file/input ownership retirement.
An input `performed` result is only the owned lifecycle action result. Its
historical native cycle proof must not be retimed into a current feature sample.

without OS/native reads or input authority. Current measurement separately
