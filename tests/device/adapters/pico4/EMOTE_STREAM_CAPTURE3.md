# Passive Source4 originals and Capture3 composition

This private component reuses the existing normal Emote native-cycle Parent,
its four actual Open/Play/Cancel/Close actions and original three-second quiet
window. It does not complete the Emote Common journey. Native Source4, Qt,
kernel alias support, GPU/OpenXR execution and an independent deployed Actor
remain unqualified. Every returned completion flag stays false.

`PicoEmoteStreamArchive` reads only actual Role4 journals and their existing
range originals. It grants no input, source acquisition or live authority.
An actual completed role CAS with a lost response can expose an explicitly
unconfirmed original tail; that tail cannot become an accepted sample.
Current root/index/part bytes and original physical identities are rechecked.
The historical reader never opens a new source or renews a clock.

`PicoEmoteStreamCapture` is Capture3, accepting only the exact current
`PicoEmoteStreamCycle` after its original Open and Play. `acquire(ticket)`
collects the original primary/viewer samples, actual existing render/PNG
storage result and model-draw observation. It returns an awaiting-after state.
The caller releases both locks while the autonomous native producer advances.
`complete()` obtains a genuinely later sample ID, validates its brackets around
the original draw/frame, and uses the existing storage release, complete native
receipt inventory, original receipt deletion and independent absence proof.
Both methods retain the same durable component start and original five-second
window. The enclosing original Parent policy still includes all source work
within its original 120 seconds. No frame request or Source3 request ID is
manufactured.

`PicoEmoteStreamModelRaw` and `PicoEmoteStreamWorldRaw` use the same existing
native model/world/inventory files and closed storage-receipt names. Actual
binary SDK stdout is durably retained in the same range archive before
framing, UTF-8, JSON, schema or business-clock rejection. Capacity is reserved
before each actual getter/send; partial timeout bytes remain originals.
Fresh root/file stat framing and the original Source4 native-root node remain
required. The existing native query and storage/retirement algorithms are
reused. There is no second raw quota. Current callbacks, factory objects,
component clocks and admitted state graphs are pinned; successful CAS/readback
is the only admission of a new Capture3 state.

The actual capture object enters a strong owner pool before its file owner
can acquire descriptors. Failed/uncertain captures remain strongly reachable;
host finalization closes only the actual original descriptor owner. Neither
traceback disposal nor a later equal-byte object replacement grants authority.

The proposed canonical Binding factory is not installed yet. Current
Capture3 construction requires the exact Policy2/Originals2 capacity owner
and same archive; Policy1 without native-file capacity refuses before GPU. Its initial
retirement boundary will use unchanged strict Role4.guard: failed/unknown role
CAS cannot authorize retirement, and such captures remain owned. This does
not claim complete failure recovery. Existing Capture2 and Source3 defaults
are unchanged.

## Explicit compound-capacity integration

The new Policy2/Budget2/Originals2 opt-in and bounded Native publisher implement
the persistent native-file allowance in the same original512/16MiB domain.
Actual encoded PNG size is reserved before first chunk; native GPU memory
keeps its existing32MiB bound. The Native file bound is an enforced pre-write
policy, never an inference from reader limits. Detailed semantics, refusal
history and separate actual integration proofs are in
[the capacity source document](EMOTE_CAPTURE_CAPACITY2.md). The C++ publisher
is not compiled/device-qualified; the canonical factory/public route and
whole Common completion remain open.

Eleven explicit wrappers select49 distinct cases: capture1/6/3/3, passive
reader4, capacity9, PNG5, publisher6, routing4, actual baseline/constructor3
and actual integration fences5. Each owning selection keeps its original
120-second bound; combining these selections is not a whole journey. The
capture wrappers now use the actual Policy2/Originals2 capacity composition.
Their earlier no-capacity results remain historical and capacity-unqualified.
The separate capacity-cycle positive overlaps the capture component and is
not registered a second time. Python and Pillow are required by the existing
PNG owners; no compiler, build, device or Domain is used. The fixture executes
real host file/framing/CAS/descriptor operations with declared render/native
models. Its two eye rows and CPU PNG are not GPU/stereo qualification.
