# Original Navigation arrival and normal Places transit

This is an internal source/host component, not a complete Navigation capability.
Only Scripts, Authentication and Graphics have complete Pico feature triples.
Native sources remain uncompiled and all devices are untested. These additions
reuse the existing probe, original native Graphics subject, world-render owner,
private files, normal Places controls and Pico candidate/process/OpenXR route.
No native instrumentation or product behavior changes in this packet.

## Inputs and independent observations

`_navigation_arrival` reads the actual periodic probe after its previous sample
sequence and the original native subject through separate nonce-only reads.
`navigation-pose` v1 requires the actual native-motion PID/time, original scene
URL, grounded low-velocity feet, five fixture markers and fresh renderer. The
original GUI avatar feet must agree within 5 cm. Actual HMD/world pose remains
separate from avatar feet; no camera or requested destination supplies location.
The measured result is A, B, C or unavailable, derived from original sources.

`_navigation_transit` composes `navigation-transit-operations` v1. The parent
provides the already open idle original Places page and holds the existing
`script-sources.lock` for the entire action. The private Pico factory checks
that same lock before every operation; its child capture uses the same object.
Directory transit starts at measured A, bookmark transit at measured B, so an
ignored click cannot borrow a preexisting destination. Normal tab/scroll/owned
row clicks use the existing token/reference/pointer route. Directory selection
requires the current completed `NavigationDirectory.observe_current(ticket)`
join to the original refresh response, manager/code, outgoing message, actual
root records and current model. This read uses the new parent ticket and the
original refresh receipt; it does not refresh or type again. Bookmark selection
joins the actual renamed owned bookmark and independently persisted native map
and file. Both row addresses must match the actual controlled viewpoint URL.

Every input records its exact control, original token/scope and pre-input UI
before delivery. A missing acknowledgment leaves that intent pending. A later
call with the same ticket resolves only the original counter/effect; it never
resends the input. Unknown delivery, foreign input, changed original root/model,
maturity, dialog, unrelated bookmark file, process or source
identity fail with ownership retained. Scrolling is bounded to 64 consumed
steps, and each pending effect to 81 observations within the 20-second action
limit. Parent setup, maturity preparation, page reopening and final cleanup
remain explicit responsibilities of the unfinished whole feature.

## Stereo source and lifetime

`navigation-stereo-source` v1 joins original pose reads before/after one actual
world-render acquisition. Both must describe the same measured destination.
The existing Pico role owner requires capture v4, two original eye descriptors,
actual executing GPU camera matrices and successful same-frame OpenXR submission.
The capture interval must lie between the original pose observations. Original
recorded head and actual forward camera midpoints must agree with actual HMD
pose; no fixed mono eye is substituted. The exact original RGBA PNG is retained
through the existing private image-only writer and file identity checks.

`navigation-stereo-owner` v2 (reading v1/v2) records acquisition intent before the existing
native role owner. It verifies actual image-buffer release, retained callback
absence and complete issuer receipt-file removal plus separate absence reads
before discarding that native owner. A lost acquisition, partial image or
uncertain mutation receipt remains owned. Known successful removal can resume
with a fresh read-only inventory; release/remove are not silently repeated.
A saved complete record is historical source evidence. Reopening it revalidates
the exact original PNG and retirement headers; it is never a new screenshot.
The reused generic role storage retains its existing Graphics namespace and
foreign-owner exclusion; this does not enable a Graphics or Navigation feature.

After normal selection and independent native arrival, normal Home must remove
the Places page and the passive original weak root inventory must independently
show its destruction. The component then acquires/retires the stereo source and
requires three seconds of measured destination, absent old page/root, unchanged
bookmark storage, stable input/generation and advancing native/UI/elapsed clocks.
Complete original before/current/quiet packets and unique query IDs use the
existing bounded compressed history envelope in the private 64 KiB CAS journal.
The parent retains this journal and image for independent publication/finalizing.

## Verification and remaining work

The arrival and transit self-tests execute original Python adapters/readers,
normal Pico input parsing, private image files and native receipt-file protocol.
Widget/Qt, native avatar/HMD/probe/GPU/OpenXR and Android boundaries are synthetic.
Counterexamples cover ignored/lost input, scrolling, stale/missing/foreign
sources, distant recorded head or actual GPU cameras, changed arrival, retained
old root, unowned storage changes, bad original PNG and incomplete release.

This source join does **not** verify a fresh Navigation challenge in both eyes
or changed-world raster pixels. It does not establish original Script/XHR/timer
retirement. Whole-area maturity/origin composition, remaining Go To closure,
restart/bookmark transfer, independent actor publication and final resource/
metadata retirement remain unfinished. No full Navigation capability is added.

The later [stereo evidence extension](NAVIGATION_STEREO.md) adds independently
verified hidden-UI/lifecycle v2 source intervals, exact original-journal metadata,
two-eye current challenge/world change and an explicit owned scene profile. This
transit component retains its v1 historical-source behavior. The enclosing
feature must normally close the whole tablet and acquire fresh v2 samples after
quiet; it cannot republish this earlier capture with a new timestamp.
