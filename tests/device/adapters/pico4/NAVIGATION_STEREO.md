# Original Pico Navigation stereo image evidence

This packet connects the existing Navigation source owner, private original files
and common Journey to an explicit two-eye image policy. It also supplies an
optional owned Navigation scene stimulus through the existing fixture server.
It does not register the complete Navigation feature triple. Complete source/
host areas remain Scripts, Authentication and Graphics; native sources are
uncompiled and all devices are untested.

## Source and original artifacts

`navigation-stereo-source` v2 adds actual original native feature/lifecycle and
passive generic VR UI observations before and after acquisition. The existing
probe/native avatar/HMD join, original capture v4, executed GPU cameras and
successful same-frame OpenXR submission still establish original stereo source.
The full ordering is native-before, pose-before, UI-before, capture, UI-after,
pose-after, native-after. Native source births, original counters, lifecycle and
Graphics configuration must agree across this interval. Actual tablet visibility,
3D keyboard and editor focus must be false. Visible initial UI is refused before
world acquisition. Later UI/source changes retain the original unresolved owner.
The sampler never hides UI or sets pose, camera, scene, preferences or state.

`navigation-stereo-owner` v2 retains all v1 source/resumption behavior and adds
an optional independently allocated `journalId`. This identity names one source
acquisition; it is separate from the current action ticket and native request
nonce. Multiple advancing frames under one action therefore retain distinct
original journals and PNGs. The parent must persist its allocation before using
the private `_navigation_stereo(..., journal_id=...)` factory, retain any pending
owner and never allocate a replacement after uncertain delivery.

The source journal resides in the existing private artifact root as
`navigation-<run>-<role>-<journalId>.native.json`. The exact saved CAS journal is
the metadata artifact. There is no derived substitute or separate metadata
writer. `artifacts(sequence)` requires a complete v2 source, the original path,
unchanged journal and original PNG identity. Its native buffer/callback/complete
issuer-file retirement headers are revalidated independently. The existing
image-only writer keeps its Graphics implementation namespace; no Graphics
feature state or image verdict is reused. V1 owners/sources remain readable,
and a completed legacy owner is not reacquired or silently converted into fresh
v2 image evidence.

## Independent two-eye verification

`stereo-navigation-evidence` v1 is selected only by the trusted external screen
policy profile `pico-stereo-navigation-v1`. Its closed fields are `source`,
`profile`, `sceneUrl` and `eyes`; each `left`/`right` eye has an original-pixel
`marker` and `subject` rectangle. This policy belongs to the independent runner,
not adapter arguments. It must match the original provider's controlled scene.
No host-test rectangle is a qualified headset preset.

The verifier reopens the unchanged original PNG and bounded 64 KiB compressed
source journal. It reconstructs the original source/pose/UI/lifecycle/capture and
retirement joins. Each policy rectangle must fit inside its actual native eye
viewport. Marker and subject regions must be disjoint. The existing generic
128-bit challenge decoder and nonblank-subject measurement run independently
for both eyes. A `changed` checkpoint requires at least five percent changed
subject pixels in each eye, a different independently measured A/B/C location,
a different action ticket and advancing original sources within 45 seconds.
Changing only the challenge or one eye cannot establish world change.

The common Journey requires the original completed scene write before the native
image interval and the exact installed-source revision. The sample must retain
the oldest original probe/motion/render/native epoch, measured location, original
lifecycle counters and exact image/metadata artifact identities. Advancing sample
numbers cannot republish a native request, render-frame ID or GPU frame/execution
pair. Context, native/subject/UI/query cursors and bounded histories are pinned.
The existing 1.5-second sample age, five-second analysis and 20-second/81-read
checkpoint limits remain. A retained completed record remains historical;
the three-second transit quiet window cannot make its earlier capture current.

## Explicit Navigation fixture stimulus

`navigation-scene-stimulus` v1 uses the existing server and original controlled
scene. Set private fixture configuration `navigationSceneProfile` to
`pico-navigation-scene-v1` alongside `navigationProvider`. The provider's actual
`sceneUrl` must point at this server's configured scene path and authority.
Without this opt-in, the provider keeps its original v1 responses and serves no
new scene alias. With it, provider v2 additionally reports `sceneProfile` and
bounded `stereo-scene` completed-write receipts. Readers accept v1/v2 and reject
profile changes; this is an explicit fixture input, not a product endpoint hook.

GET of that exact scene path accepts only the existing A/B/C viewpoint queries,
current owned run, correct HTTP/TLS authority and active challenge. The original
floor, collision wall, fixture markers, interactable geometry and spawn remain.
Its original entity script bytes use a run-owned resource URL on the same server.
Three owned Web challenge carriers and differently colored checker cues provide
world stimulus at the existing A/B/C positions. The original interaction script
is unchanged. Marker HTML reuses the existing current-ticket polling and PNG
challenge resource. The same source lock covers the bounded actual response
write and retirement; missing, partial, foreign or duplicate write confirmation
poisons readiness and creates no successful receipt.

## Verification limits and enclosing work

Host tests run actual Python samplers, Pico private factories, original-file and
receipt protocols, per-eye byte analysis, common engine and owned short-lived
HTTP fixtures. Qt, native lifecycle/avatar/HMD/UI/GPU/OpenXR and Android boundaries
remain synthetic. The authored scene geometry is input, not observed rendering;
its physical visibility, actual original-pixel rectangles and headset latency
remain unqualified. No builds, compilers, devices or device services are run.

The enclosing Navigation feature still needs a durable fresh-image publisher
and separately acquired actor, normal page opening/Home/tablet close, remaining
Go To closure, maturity/origin setup and restoration, process restart/bookmark
transfer and full Script/XHR/Web/timer/callback/metadata retirement. Reuse the
existing normal VR tablet close input; the source refuses visible UI and cannot
close it. Preserve the original scene and prove removal of the owned stimulus
and original entity-script/Web lifetimes during final restoration. Retire active
ownership indexes while retaining the complete original PNG/native-journal
artifacts for independent review. The existing
transit component's v1 historical image is not a replacement for fresh v2 samples.
Missing full capabilities continue to prevent an overall green run.

The later [normal-close/fresh-frame owner](NAVIGATION_PRESENTATION.md) now journals
one normal global tablet close and fresh original source allocation. Both source
roles retain independent captures, original timestamps and exact metadata/PNG
identities. The common two-eye policy remains external to that publisher.
Full feature state/actor/public/finalizer composition remains incomplete.
