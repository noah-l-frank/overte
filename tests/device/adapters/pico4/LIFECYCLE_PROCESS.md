# Original process retirement and restored new baseline

`pico-lifecycle-process-owner:1` extends the existing partial Lifecycle owner.
It does not advertise `feature.lifecycle-input.*`, delete journals, or return a
complete cleanup verdict. No hardware execution is established by host checks.

The private `_lifecycle_process_begin(target, run)` factory must run before the
Create editor and first world gesture. It freezes the existing original world
baseline, native graphics/audio/account state and read-only native Chat inspect
source. Chat v2 uses the actual DomainHandler UUID/connection history and actual
MessagesMixer active socket. It never opens a Chat cache or subscribes.
An unowned active audio recording is rejected. Settings coverage is explicitly
limited to the original graphics packet, audio recording/muted, login state,
and avatar movement motor settings; this is not a whole-preferences backup.

`_lifecycle_process_prepare` requires both independently consumed world attempts,
the original X/Back join and its preserved weak Qt flags, a closed tablet,
released actual keyboard and controller, and three seconds of restored original
3D feet/body pose and normal grounded quiet. The scene URL, scale, orientation,
sensor transform and movement motor settings must match the original baseline.
The actual original domain source must remain unchanged, including its revision
and native connection birth. Position/domain restoration must already have been
performed through normal controls. This component never teleports, assigns an
avatar pose, writes settings, deletes a QQmlContext, or claims an input receipt
restored anything. A missing normal restoration route remains unavailable.

`_lifecycle_process_restart` uses the existing `RestartInputs` owner and ordinary
`app.stop` / `app.launch` adapter inputs. Exactly the original World, Back and X
journals are bound to that input owner. Before stop it repeats actual restored
quiet and checks the original acquisition's final monotonic age, including a
frozen device clock. Issued stop/launch intents are never replayed. Recovery
reuses `_script_restart_recover_binding` with the original input owner and
process journal: it can establish a host binding only after original native
birth/counters plus actual ESRCH of the old PID, and sends no input itself.
Prelaunch process absence uses the existing application-UID OS process query.
An uncertain stop may only advance after a separate stopped observation; an
uncertain launch may only read/reconcile the already issued launch.

The new binding reads the original normal navigation bridge without reopening
the old process's still-owned Script manager. Final observation requires a
different real PID/start identity, a later OS birth, the pinned candidate and
target, a different native launch instance with persisted lifecycle counters,
and actual old-PID ESRCH from the new owning native process. Unknown/EPERM or a
still-present/reused old PID never proves retirement. Fresh original
UI/Keyboard, Pico gesture and Avatar observation instances must differ. The
new gesture history must contain no world gesture. Three seconds of actual
neutral restored new-process pose, settings and domain are observed with both
native and monotonic time. A new actual DomainHandler/connection birth is
required while domain UUID hash and mixer identity match the original; native
reconnection revisions cannot change during the quiet baseline.

Only original process-owned scopes are then reported retired. Historical Qt
flags remain byte-for-byte in the original Back source: a retained context is
never relabeled dead. Pure historical World/X/Back validation does not construct
old live readers after the OS owner has gone. All original raw observation
bytes and hashes remain in a single bounded compressed process transcript;
embedded owner transcripts are decoded before that outer compression to avoid
compressing duplicate opaque compressed blobs. The original three journals,
process journal and restart input journal all remain intact.

Device-free tests execute actual readers, shared locks, World/X/Back/session,
restart input owner, historical validators and Pico factories over explicitly
declared native, OS, input and physics boundaries. The positive fixture's pose
restore and process/domain births are boundary data, not client-run evidence.
The complete editor/Unicode/keyboard composition, background/pending-stale
journey, independent peer displacement and image evidence, normal restore
inputs and complete source/file/lease cleanup still require full closure.
Existing cleanup continues to reject the retained World journal.
