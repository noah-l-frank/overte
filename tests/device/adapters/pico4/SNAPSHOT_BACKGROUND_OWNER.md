# Normal Pico Snapshot background and return component

`_snapshot_background_owner` extends the completed original Upload parent with
normal once-only HOME and controlled ordinary Activity activation, original OS
process/foreground observations, independent native lifecycle transitions and
three seconds of unchanged Snapshot/VM/file/account/backend observations. It is
private and partial. No public Snapshot capability or whole-recipe result is
introduced.

The lifecycle join comes from the executed `background()` implementation at
`b62e012f1328e30b80604bb447a60db0d8a748df`,
`tests/device/adapters/android-phone/overte_phone_snapshots_feature.py:699-730`:
original native instance/process, unchanged launch count and strictly increased
background/activation counters after genuine OS background/foreground. This is
an immutable Git-object reference. The Phone facade, v18 migration, Phone touch
and its foreground authority are not copied. The existing Pico
`PicoGraphicsBinding._graphics_lifecycle_status` and
`PicoBoundAdapter._pico_lifecycle_input_once` remain the OS transport. Existing
Chat-only `LifecycleBackgroundHistory` is not repurposed as Snapshot history.

The parent and every Cancel/Save/failure-Upload ancestor remain linked to their
original private headers, immutable component manifests and physical chunk
identities. Cold admission reopens the parent's actual successful native/TLS
join, exact phase, contiguous original quiet window and unchanged mutation
scope. No ready label supplies those facts. The background owner uses the exact
existing `ScriptSourceLock` instance. A cold background constructor opens only
host originals. It does not construct a Qt/native reader or repair foreground.
Its live Save/Upload readers are acquired only after OS foreground is proven.
Strict JSON types and immutable digests bind in-memory parent authority too.

Each normal OS action has a durable issued intent before the existing SDK
transport. Its final callback runs after actual candidate/process/foreground
checks and immediately before the single original SDK write. The final native
and parent guards precede the exact independent phase read. Only validation,
clocks and private host checks follow it. Monotonic elapsed time includes the
intent CAS and rejects stale input even with a frozen fixture clock. A changed
phase refuses the write while retaining the issued journal. Neither HOME nor
Resume is resent after an uncertain response. Cold recovery observes the actual
OS and, after return, original native lifecycle and Snapshot sources.

At least 250 ms of consecutive background OS samples are retained, with at most
500 ms between them. No Qt query occurs there. Return requires the original
process and native instance, unchanged launches and increased backgrounds and
activations. Original capture/VM histories, settings context, Review generation,
file rows, native Upload jobs/events, account identity and exact backend request
scope remain unchanged. Original Upload QObjects/replies are retired and scoped
Script work is idle. Three seconds of consecutive unchanged sources use every
independent clock and gaps at most 500 ms; cold validation keeps that same rule.

`partial-ready` does not mean complete retirement. Review, the native Capture,
Save copies, backend story, global Export executor and every original journal
remain owned. The current component explicitly reports
`independentAfterReturnPng: false`: file inventory/hash preservation is not a
fresh independently acquired return image. Normal foreign chooser/receiver,
scene/stereo/panorama fidelity, final Close/settings restoration and complete
resource retirement remain separate open obligations. No hidden restart,
product button, product backend function or cleanup exception is added.

## Host verification and fixture provenance

The disjoint `snapshot-background-owner` and `snapshot-background-fences`
selectors cover normal HOME/return/quiet, uncertain HOME/Resume, ACK without OS
consumption, foreground without native lifecycle transitions, late phase
changes, slow intent CAS with a frozen clock, cold chunk/parent substitution,
missing OS checkpoints and skipped quiet observations. Actual bound Pico
factory tests preserve the identical lock and prove that cold construction does
not acquire live Qt sources. Existing once-only transport tests separately own
the actual original SDK routing and candidate/process guards.

`self_tests/pico-snapshot-background-fixture.v1.json.gz` is the complete decoded
Cancel/Save/failure-Upload/success-Upload host-model lineage from the separately
passed normal Upload case at `0166738f3191da44dac21ceb4865375651c690e3`.
Its compressed SHA-256 is
`342ebb8ad0d383692458f703c0afa51e139882beabae7e46ba1938c30290ef9d`.
The bounded fixture reader checks those bytes and the explicit synthetic
qualification. The test reconstructs actual private original containers and
rebinds only header hashes for their new test-store representation. Complete
original frame contents are preserved. Virtual current observations and OS,
native/JS/Android/HTTP producers are explicit seams. Historical TLS metadata
never supplies a current server, device identity or permission. No credentials
or real device selectors are present. The fixture avoids replaying the 115.6 s
normal prefix inside each background counterexample; it does not replace that
separate proof or relax any source/container/time bound.

The original pure base-frame parser was moved unchanged to
`snapshot_base_frame.py` for cold OS reconstruction. Its existing warm cache and
all actual reads/guards remain in `PicoSnapshotCancelOwner`; the new background
parser does not construct that live owner. Every retained parent base frame is
replayed through the extracted parser. No timer or input system is duplicated.

--test snapshot-background-fences --test coverage-matrix --junit <owned-private-report>`.
