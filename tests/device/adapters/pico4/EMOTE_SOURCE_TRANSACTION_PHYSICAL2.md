# Private Source transaction physical protocol 2

This opt-in source packet composes the existing Raw reply owner, its existing
append/OFD writer and the same original Parent/Cycle. No public capability,
source-complete claim, device campaign or whole Common result is enabled.

The fixed one-SDK command publishes a bounded request through the existing
private control channel, then returns actual process/file bookends, the actual
native receipt and all six lexical originals in one stdout. Exact stdout and
timeout/nonzero prefixes precede every physical/UTF8/JSON parser. Native body,
receipt and framing together retain the existing one-MiB maximum. Extents are
absolute offsets into that same original SDK literal; no full body slice is
made. The existing lexical Wire1 defaults and original format remain separate.

The SDK collector waits for both the actual matching receipt nonce and the
absence of the publisher's pending marker, including dangling symlinks. Receipt
bytes become visible before the writer finishes marker close/unlink and directory
fsync; reading at that point can correctly fail the later directory stamp fence.
The wait uses the same command, bounded 50 retries, 50 ms pacing and original
five-second acquisition window. It does not republish, retry an issued SDK read
or renew a clock. All original process, file, directory, control and final marker
checks remain in place. Host counters use actual owned files and the fixed shell:
no stdout while the matching receipt is visible with a marker, success after
actual unlink/fsync, and bounded refusal for retained or dangling-link markers.
Exact stdout is retained by the existing Raw writer before framing or assertions;
completion and custody assertions run outside lock exception normalization.
These are transport tests with declared packets, not native execution or a
current Emote effect or whole-feature qualification.

The Native assembler calls the original roots-before, script, inventory,
native, roots-after and the SAME `NavigationUi` observer. Each builder retains
its actual request ID, sequence and source time. Native pending keeps the first
request and the existing bounded Probe scheduler; there is no added sampler,
ARM or renewed clock. The Native publisher reuses `PicoEmoteCaptureFile`'s
original paired descriptors, pending marker, current-byte/readback/fsync and
close guards. Its actual readback proof binds the wire's original node/stamp/
hash. The receipt also carries its own original node admitted before in-place
publication, rejecting identical first-get inode replacement of either file.

The actual wire buffer is singular. After successful original wire readback,
the existing strong file/expected-byte holder retains the wire and the
assembler clears its duplicate before publishing `builderSettled`. A failed
builder, serializer or publication remains strongly held and uncertain.

`SourceProfile1` is selected before Bootstrap/ARM and is included in the
existing actual `other_bill`, alongside both roles' existing Source4/capture
files and all existing Host originals. Each enabled transaction role reserves
its OWN permanent transient slot, even after Raw retain or failure. Primary
transaction + Actor Source4 is the current bounded configuration; it is not a
whole-budget result. Two enabled transaction roles currently fail the pure
existing-budget minimum before any cold runtime/SDK construction.

The per-role reserved slot is 4,222,976 bytes, within the existing 4,224,088
side limit. It covers the conditional allowed-packet Native build/readback
and the later Host decoder peaks. Native persistent copies, fixed wire,
receipt, command/unknown temporary and existing files are charged separately.
Envelope/receipt parsing finishes before Native Header/Extent/source parsing;
only a small physical proof remains beside the existing lexical metadata.
The actual Native first-builder oversized-QVariant peak is still unqualified:
the new conservative prepass prevents a second complete JSON allocation, but
does not prebook the allocation already performed by an original builder.
No complete Native capacity proof follows from the file bound or Host tests.
