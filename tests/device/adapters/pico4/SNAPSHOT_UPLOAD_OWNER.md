# Normal Pico Upload component

`PicoSnapshotUploadOwner` composes the existing normal Cancel/Still/Save owners,
existing normal path-bound Review Upload control, original native upload reader,
original VM capture context and independently authenticated TLS receipt/PNG
readers. It is private and partial. It advertises no Snapshot capability.

The failure and success owners have separate durable journals and immutable
original component stores. Each pins the exact completed Save parent, original
Capture file/PNG, run, candidate, process and identical source-lock object. Success
also pins the original completed failure owner. It accepts the shared v16 input
order, including the original intervening Share input transcript; those metadata
entries **do not qualify Share**, its foreign chooser or its independent receiver.

Normal Upload admission records its parent intent before the existing QML input.
The existing final `NativeNavigationIO.before_send` callback reads originals,
records the actual completed command exactly once, and checks the exact current
fixture phase after the final durable CAS and native guard. Source clocks and
actual host elapsed time include final reads and CAS work. Unknown input remains
issued and may only reconcile by reading original sources. No second ordinary
Upload is allowed, including after cold reconstruction.

Original evidence joins retain:

- Actual pending-VM manager birth/domain/href and current original Still path.
- Native job birth after the issued phase and pre-input sample, original QFile
  device/inode/UID/link identity, bytes and consumption digest, native requests,
  replies and weak object retirement.
- Actual fixture login principal/endpoint/token observation. The component does
  not log in, set an endpoint or replace an Auth owner.
- Actual independent domain permission GET, multipart bytes, request/reply IDs,
  JSON body, image/story IDs and complete private physical file metadata.
- A separate authenticated backend PNG acquisition, original binary headers,
  decoded image, exclusive recoverable host publication and original Capture PNG
  equality. This does not read the native capture as its independent source.
- Three seconds of unchanged original native/VM/UI/work/backend/account samples,
  with at most 500 ms between every consecutive clock and fresh final fences.

Failure requires an actual recorded offline reply (`status == 0`), not an ACK or
an arbitrary HTTP error. Success retains the actual backend story. Post-upload
quiet requires all observed native upload QObjects/replies retired and no active
Script upload. It does not destroy the global product Export executor, delete
the story, close Review or retire Capture/Save/source journals.

Cold validation binds every backend frame to the exact complete phase history,
rejects an effect attached to unresolved input and rejects skipped intermediate
quiet frames. Post-proof mutations must be exactly the original native job's
joined requests, so a deleted/replaced story cannot hide behind an unchanged
aggregate count. No current source or ordinary input is replaced by an archive.

`snapshot-upload-owner` is a normal factory/transport composition with actual
private host PNGs, actual loopback TLS, independent physical wire files, a genuine
connection-close failure, real image/story API recovery, original quiet and cold
read-only reconstruction. Native QML/JS/VM/Settings/account adoption, Android/JNI,
OpenXR consumption and rendering are explicit host seams. The native original
bodies are covered by their separate existing owning compiler tests. No combined
native-client TLS, Android device, physical VR or whole Snapshot result follows.
The test models private PNG creation from the outset and does not repair file
metadata after original Capture admission. `snapshot-upload-fences` keeps narrow
phase, stale-clock, context-substitution, uncertain-input and original-container
counterexamples separate from that long normal prefix.

Actual Share/receiver, Resume/Close, complete settings/baseline restoration,
global executor/host retirement and Stereo/Panorama/scene fidelity remain open.
No restart, product button, backend product function, contract migration or
cleanup exception is introduced.
