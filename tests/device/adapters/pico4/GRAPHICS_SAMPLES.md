# Durable role/process stereo Graphics samples

`graphics-journey-samples` v4 adapts the frozen sample transaction architecture
to actual Pico passive UI, native subject v3 and stereo camera/render v4. Its
original source hash is in [`FROZEN_REFERENCE.json`](../graphics_journey/FROZEN_REFERENCE.json).
Phone v3 remains separate; there is no implicit journal migration. The sampler
performs source reads and evidence ownership only, with no ordinary input or
fixture activation and no complete public feature operation.

Each process/role/stage journal pins candidate/PID/session binding and original
native, subject, Graphics UI, tablet, GPU, storage, receipt-inventory and provider
cursors. Recreating an owner restores actual GPU frame, execution, submission,
trace and camera-batch floors. It does not rely on the unused `capture.frames`
attribute in the frozen reference. Source reads use the same explicit held lock
as role-scoped capture/retirement and preserve weak UI/QML inventory histories.

Before acquisition it persists `reading` and the original ticket/barrier, then
saves every accepted source cursor and the exact original capture intent. The
current authored scene/HTTP delivery, actual tracked HMD and both-eye challenge
must independently agree. The original tablet packet must be bracketed by the
native interval, have a complete inventory with no foreign managers/pickers and
agree with the independently observed physical tablet state. Hidden retained
Graphics roots remain actual resources.

The sampler writes the [original PNG/native JSON pair](GRAPHICS_ORIGINALS.md)
with immutable transition checks under its journal compare-and-swap. Every
completed frame references both saved file identities. It then proves native
buffer/callback absence and actual complete issuer-file removal/fresh absence
before removing capture ownership. Only after actual final guard/clock and
1500 ms age checks may the new facts return. The entire operation is bounded to
20 seconds; source/file helpers retain their shorter bounds.

`graphics-journey-measurements` v1 composes original historical facts without a
caller-supplied current clock. The live sampler separately checks currentness;
archive validation never retimes a packet or creates a new product observation.
The returned pair is also accepted by the external common stereo verifier.

A pending transaction cannot be adopted as ready. Stale-marker frames retain
both original files, retire their actual native capture, and may be journaled
as rejected history before a new acquisition. Changed-ticket retirement can
finish a fully written but uncommitted metadata record from original byte/inode
proof; it never republishes the interrupted sample. Partial/unknown files,
unknown acquisition results, lost candidate or incomplete receipt cleanup keep
unresolved ownership. New control nonces cannot hide replayed camera cursors.
Primary/actor file and process histories remain separate.

Histories stop at 256 samples/frames, 512 original files, 64 rejected-marker
entries and 32 changed-ticket retirements. The existing bounded packed-state
limits also apply; no source floor is evicted to admit more work.

The full observer, ordinary background/restart, independently credentialed actor
and UI/QML/XHR/reply/Web-renderer/capture three-second retirement coordinator
remain required. Restart must preserve the original old-PID death proof and pin
newly observed framework registrations for the new process; IDs from a dead
process cannot be compared as if they still owned new UI entities. No full
Graphics capability is advertised. Native compilation, real timing and all
physical devices remain unverified.
