# Original Pico Snapshot export observations

This private component observes existing Save, System share and Upload controls.
It does not qualify the whole Snapshot journey, SDK26, stereo or any device.
The next owner must compose these originals with the retained normal Cancel/
Still journals, exact phase admission, an independent PNG and real cleanup.

## Existing product path

`NativeSnapshotReview.qml` already implements `exportImage` and the Save to
device/System share/Upload buttons. Normal QQuickWindow pointer events reach
those original handlers; no product button or backend operation is added.
`NativeSnapshotAdapter::request` owns the original process-wide monotone handle
and request ticket. Its new plain C++ observation returns those identities on
its actual GUI thread under both the dedicated test build and `--testScript`.
It is not a QML setter or new export entry point.

The Pico native bridge registers the real additional `nativeFeatureEnabled`
symbol. Ordinary launches return false; existing Java export behavior remains
on its original branch. The actual JVM/class-loader contract tests the complete
registration against a different application loader.

`TabletScriptingInterface::featureExistingTablet` is passive: it reads only an
already existing proxy on the GUI owner thread. The ordinary `getTablet` would
create a proxy when absent and cannot be used as an independent observation.

## Fixed source reuse and ownership

The Java export recorder, private readback files/worker, original destination
owner, MediaStore/Documents inventory and share-grant inventory are selected
from fixed Phone commit `5527d540e99cc6dba4204a5e904a854e6e1cd2b4`.
The three portable original Java host contracts are selected byte for byte from
that same object into `tests/device/contracts/snapshot/java/`. Android resolver,
chooser and UID access are explicitly fixtures in those host tests. The actual
production Java classes also compile against the prepared Android34/AndroidX
Core artifacts; that is an API compiler check, not an Android OS run.

Pico adapts only its authority/private roots, existing native admission and
normal VR control metadata. The closed command accepts original request and
resource IDs; it accepts no caller URI/path, expected bytes/digest or desired
Save result. Java `accepted`, callback success and chooser selection remain
original events, never destination/recipient proof. Complete original JNI JSON
strings are preserved in the outer version1 packet.

The bounded existing Snapshot source queue executes the actual GUI observation.
The getter checks the same original proxy, surface, root, window and native
lease before and after both Java reads. It retains the actual Tablet service
owner and consumes command nonces before uncertain operations. Missing
services, blocked owner queues, absent current pages or uninitialized Java stay
unavailable. A detached original page can remain alive; absence is not death.

All Python readers use the parent's exact ScriptSourceLock. Mutable readback,
delete or revoke operations require an explicit parent callback before the
original command writer and a pure host deadline after the last SDK guard.
Freshness includes final guards and copying under both native and host clocks;
archived history is only a prefix floor for a new observation.

## Independent saved original

`PicoSnapshotSavedFiles` selects only an actual completed native readback ID.
It transfers the original closed stream copy through the existing app-private
binary transport. Its private `OVT_PICO_SNAPSHOT_SAVED_META_V1` framing includes
full device/inode/mode/UID/GID/link/size/mtime/ctime provenance before and after
hashing. Legacy three-line metadata cannot qualify it. The public Snapshot file
DTO and original binary framing are unchanged.

A changed inode, symlink, permissions, hash, native job/copy association or
source identity fails closed. Host publication is supplied by a durable owner;
this reader never adopts or overwrites an existing host file. Actual native
completion time remains separate from a fresh historical acquisition epoch.
Late publication/final guards cannot refresh old sources under a frozen clock.

## Explicit remaining boundaries

The normal Pico basename is `parity-<run16>-still-png-...png`. The fixed Phone
Documents owner conservatively requires its original `e2e-<fullrun>-...png`
provider naming proof. That validator is retained. SDK26 Documents ownership
is unavailable until the actual provider run/UID/document ID is independently
bound to the original Pico source file. Renaming the product or weakening that
proof is outside this component.

`SnapshotAdapter` creates its product `OverteSnapshotExport` daemon pool on the
first submitted export and has no normal executor shutdown in initialize,
detach, cancel or terminal delivery. `pendingIo=[]` proves task quiet only.
`workersTerminated` belongs to the separate E2E readback worker/watchdog; it
cannot prove the product pool dead. No hidden restart, executor shutdown,
forced Qt destruction or process-identity transition is introduced.

Save/Share/Upload/Resume parent composition, independent recipient/backend
roles, OS picker/chooser control, settings restore and complete original
resource retirement remain obligations. All existing Snapshot journals and
originals remain retained.

## Device-free checks

The `snapshot-export-originals` selector owns strict packet/normal-control
validation, the actual private factory and probe body, real private filesystem
transfer counterexamples, the whole original native JNI/lease TU, actual QML
Save/Share/Upload pointer handlers and bounded getter bodies, plus the fixed
portable Java contracts. Qt5 and Qt6 compile the four runtime/build profiles.
Qt6 keeps the unchanged Qt5 UTF16 overload's deprecation warning and preincludes
QChar/QBitArray for GCC16/Qt6 header completeness; no product code is changed for that
host compatibility. Native JNI is deliberately unavailable in the pointer test,
so it proves the actual normal error path, never a saved image.
