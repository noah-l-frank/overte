# Durable original Emote stereo acquisitions

Feature 5/14 remains partial. PicoEmoteCapture v1 owns exactly one acquisition
for an indexed primary/actor source checkpoint. It uses the parent's exact
ScriptSourceLock, original PicoEmoteSources archive, candidate/PID/run binding
and actual fixture phase before and after the acquisition. The input ticket is
metadata only. Both original phase packets must continue the original parent
phase; they cannot supply avatar, model, camera or pixel facts.

The original NativeAvatarRender query before acquisition must match the original
parent native instance and Rig. The existing native stereo WorldRenderCapture
then supplies the original submitted image and actual camera buffers. A separate
PicoWorldModelDraws query binds the loaded model's own executed eye cameras to
that same capture. A second original avatar query bounds model/geometry/Rig,
root pose and central recorded view. The existing per-eye original PNG challenge
and projected body validator checks the complete join. No normal Emote input,
animation verdict or actor publication is provided by this component.

The acquisition command is retained in the private image journal before the
downstream WorldRenderOwner intent and before dispatch. Only the first live
call can acquire. Reconstructed or uncertain journals cannot acquire again.
Native storage receipt intents are retained before each storage operation.
Cleanup requires the original native memory release plus independent zero-buffer,
zero-callback inspection, and complete original issuer/file inventory remove and
absence packets. The existing common retirement validator binds every receipt
to its original owner. Only then is the downstream world owner discarded.

Original image bytes use the existing GraphicsOriginals byte/storage engine in
an exclusive private indexed Emote directory. Its internal stage0 is local to
that directory and makes no Graphics feature assertion. Planned/opened/saved
file intent retains exact inode/device, length and hash. Replaced, linked,
foreign or partly written files cannot become complete original evidence.
The owner retains the original PNG, model/avatar/phase packets and retirement
proof; it does not delete originals or claim whole-feature resource retirement.

Recovery is cleanup only. A lost acquire/query/release result is never resent
as a new acquisition. A retained cleanup proof can be replayed as historical
cleanup after a later pixel/phase failure. It cannot satisfy a new live image.
Unknown journal writes stop warm and cold dispatch; ownership remains unresolved.
The original completed archive can be read after the parent source advances,
or after its exact header is retained by a parent and the child journal is
retired. It uses only the retained original source prefix and original file
identity, without requesting, repairing or retiming any target observation.

Pico binding reuses actual org.overte.pico native/private transports and the
existing owned storage/inventory engines. Separate Emote world-owner namespaces
exclude the other Emote role and both Graphics/generic owners in both directions.
Orphan image/world journals prevent successful base cleanup even if the parent
source journal is absent. No public complete Emote capability is advertised.

Fresh delivery includes original phase/native clocks, all final guards, copies
and repeated PNG validation within five seconds and original 1500ms native age.
Ten owner counterexamples cover success, exact originals, passive reconstruction,
historical parent advancement, lost acquire/model/release/journal replies,
partial image writes, changed bytes/inodes/links, ignored release, foreign Rig/
phase, wrong challenge and final native/host clock changes. Two actual Pico
factory/teardown cases cover exact parent lock, candidate and foreign ownership.
The rendering/native/HTTP/time boundaries are explicit synthetic producers;
these tests qualify host ownership logic, not an application build or device.

The ownership shape was compared against the fixed committed Phone capture
owner at abb7f6b60d97daf17752aadf94e2b5df099bb7ba. No Phone WIP, mono view,
touch input or platform class was copied. Existing shared original-file,
retirement and source-lock engines are reused unchanged.
