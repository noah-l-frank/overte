# Remote consumed Chat sources in the existing finalization path

The optional version 1 `pico-chat-remote-archive-extension` connects the actual
[remote consumed-source join](../chat_journey/REMOTE_CONSUMED_SOURCES.md) to
`PicoChatComposition.restart_and_close_application(remote_sources=...)` and the
existing `PicoChatArchivePlan`. The legacy local-cursor/baseline paths remain
separate; no missing remote evidence is manufactured for older archives.

Parent admission requires its actual completed 26-input flow/cache-release
owner, the original shared hook/slot/Journey, exact run/bindings/source locks
and the same fully returned Actor/primary seal. All three sequence-success
checks must be true: actual `Journey._cleanup_sequence_succeeded`, original
consumed header and returned source receipt. The direct-wait false diagnostics
cannot authorize application restart or whole finalization. A rejected bind
latches the Parent and retains its journals. The remote and legacy consumption
families cannot both be bound.

The existing application owner still performs the once-only controlled restart,
original new PID/birth/profile comparison, actual old-process absence, original
postrestart quiet observations, deferred IPC release and final independent
absence. No input/ACK or native lifecycle counter is invented by this extension.

The remote archive catalog includes the actual source-join/prefix/reader and
typed-return roots/chunks, primary seal and all its original owners, complete
returned Actor graph and its immutable source chunks, generic literal return
transport and the independently consumed Parent nonce. The current Actor root
is its actually admitted `parent-consumed` successor. The old `host-closed`
payload retains its historical bytes in the original transport children; it is
never assigned the successor's current physical stamp. Source/nonce/root/child
stamps are compared with the original warm receipts around catalog acquisition.

The archive metadata records the explicit remote family/version, consumed-source
and typed-return hashes, distinct original primary/Actor seal hashes and actual
sequence-success flag. Generic cleanup accepts this optional profile only when
all fields are complete, correctly typed and true. It rejects partial fields,
false success, tuple/duplicate seals and mixed legacy/local/remote metadata.
The existing immutable archive-byte verifier remains mandatory.

Final host ownership capture additionally includes the original Parent-side
independent observer executable and entry open-file-description pairs. The
existing host closer closes those actual captured owners, then detaches wrappers;
the extra descriptors cannot disappear behind a successful close ACK. General
`detach()` remains best-effort host cleanup and grants no resource/feature result.

Scope of checks so far: the actual Pico optional-metadata parser and early
Parent admission cases passed 2/2 in 4.056 seconds. These deliberately model the
sealed archive bytes; an empty test directory is not a completed archive. Four
existing real immutable-catalog cases and the existing real original-host-close
positive passed 5/5 in 0.178 seconds. The single existing Parent/Actor positive
was then extended with actual remote catalog acquisition and passed 1/1 in
55.876 seconds. It acquired all actual graph/reader/prefix/return/seal/nonce
roots and original chunks, verified the actual current `parent-consumed` root,
and retained the old `host-closed` payload in the original transport. Its actual
sequence flag remained false and every original file remained present; no
retirement was claimed. This is not a controlled performance comparison with
earlier host runs. Full successful shared execution, actual application/restart,
complete remote archival and the new final remote-host closure branch have not
been qualified by this packet. Public Chat capability remains disabled.
