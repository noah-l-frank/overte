# Internal complete-run Graphics coordinator v1

[`GraphicsFeature`](../graphics_journey/feature.py) joins normal Pico scene,
preference, background and restart inputs with separate original stereo
observers, active Web ownership and final quiet lifetime owners. Its internal
API is `prepare`, `act`, `observe`, actor-only `publish`, `cleanup` and primary
`finalize`. The public adapter/actor dispatcher and common `Journey` runner
integration are still pending; no complete Graphics capability is registered.

The parent saves current provider phase and input intent before delegating to
the existing one-send owners. A different ticket cannot replace an unresolved
action. Repeating a completed action also requires the actual current binding;
its ACK remains separate from fresh original effect observation. Lost Home
recovery loads archives before constructing any foreground-only scene owner.
Restart adopts only the original qualified Pico Qt bridge/process transfer.

Primary and actor acquire their own immutable PNG/native metadata pairs. Their
separate role/stage journals preserve original source cursors, both-eye cue
effects, old-process frames and original old-PID ESRCH. Each process stage must
also establish original ownership for all three world Web/renderer sources.

Cleanup first restores actual preferences and measures a fresh three-second
stereo baseline. Finalization restores the original world/avatar/framework and
retires input owners before either role can claim its original resource quiet
window. The actor must finish its own window. The parent then validates both
roles, every stage and original file before metadata retirement. Actual absence
of acquisition owners and fresh complete native issuer/receipt inspections
remain mandatory.

Final verification continues exact original lifetime floors in the separate
`graphics-final-runtime.json` journal. The continuation requires actual current
foreground/native binding and new original source reads; it cannot recreate an
ordinary role/acquisition owner or treat archives as current facts. Every retry
starts a whole new window. Complete original final headers and group files are
retained with immutable canonical SHA256 references before their live journals
are removed. Component archives precede parent/retirement journal removal.

Host verification currently covers all fifteen shared phase definitions through
the real coordinator, normal controls and independent original stereo readers,
including background/restart. A composed finalization case verifies restoration,
separate actor quiet evidence and absence of every live component/parent/final
runtime journal. Counterexamples cover foreign phase, ignored setting, lost
Home/launch replies, process replacement, actor input refusal, independent
ignored-renderer scale and continuation admission. The full common `Journey`
engine, `OverteSession` operation binding and actor configuration remain the
next integration boundary and do not count as passed from these direct cases.

Run the analytical stereo cases explicitly with `python3 -m unittest
self_tests.test_pico_graphics_feature_stereo` from `tests/device`. They repeatedly
validate original rasters and archives and are slower than the enrolled source
unit cases. They use synthetic SDK/native boundaries and private receipt files,
including an already-created normal native tablet screen as an explicit initial
condition. Native compilation, real VR input/rendering/timing and every device
remain unverified. No product behavior, dependency, service or device is changed.
