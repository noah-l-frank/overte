# Pico original navigation error replies

`_navigation_replies(target)` reuses the original candidate APK/install digest,
controlled PID/start/OpenXR session and actual foreground guards on every I/O.
It reads only `files/overte-e2e/feature-navigation-replies.json`, with the existing
one-attempt private run-as transport and independent native clock. The factory
requires no Scripts UI or input. Missing E2E input-layer/candidate/process sources
remain unavailable; no environment flag supplies original native observations.

The [shared source/receipt contract](../../native/NAVIGATION_REPLIES.md) requires
the actual typed current RequestTicket, native generation/activity, actual HTTP
error and response header, immutable native history and the matching separately
bound original fixture receipt. A newer native lookup cannot lend current
status to an old callback. The component returns raw original receipts only;
it cannot establish the actual modal, B position, loaded Places model or feature
success. Those native/independent UI/arrival/bookmark/image/recovery/cleanup joins
remain missing. No complete `feature.world-navigation.*` capability is advertised.

All 53 normal-Scripts component host cases pass. The three new source integration
cases cover actual read/join semantics, ignored source/superseded scope/foreign
PID and changed candidate before a new command. Source/SDK/UI boundaries are
synthetic. Native source is uncompiled and devices are untested; no OpenXR or
device service was started.
