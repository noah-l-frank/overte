# Normal Pico pre-render Capture/Cancel component

This private component drives the existing normal Pico Capture and Cancel
controls. It is one bounded vertical step toward the common v16 Snapshot
recipe; it does not advertise a complete Snapshot capability or delete any
journal, file, native allocation or Qt context.

`PicoSnapshotFastCancel.h` selects the original bounded algorithm from fixed
Phone `5527d540e99cc6dba4204a5e904a854e6e1cd2b4` (original packets
`b1b6c408ef9cdca4e33c325e277536ee62fe1f6e` and
`c1fe91014457c2740e53cb9186cb603de620f6ed`). The existing product Script keeps
its actual 350-ms pre-render and 60-second timeout timers. The selected test
recipe samples their original work inventory with a 2-ms precise Qt timer,
refuses to deliver Cancel after 300 ms, and stops its own timer on success or
failure. It neither delays rendering nor calls a QML handler or native cancel
method directly. Existing normal NavigationUi observe/apply, actual tokens,
sequences and original surface pointer delivery remain the sole input path.

Before Capture, fresh original Review v2 must show loaded capture settings,
animated mode, PNG format and the actual name
`parity-<first 16 run hex digits>-animated`. A requested name or field-input
receipt cannot supply this fact. The actual accepted native request history
must remain unchanged, with no native request, projection resource, upload-map
entry or pending original Script work left active. Completion requires exactly
one new original pending event with the actual active 350/60000-ms single-shot
timers, followed by the original cancelled event for the same request and an
empty actual timer inventory. Capture/Cancel input receipts remain separate.

The E2E-only `Test.featurePicoSnapshotCancel` getter requires the original
private FeatureLifecycle, actual `--testScript`, HMD mode and bounded settled
owner queue. The private native TabletBridge supplies only its real current
TabletRoot, original window and surface, and additionally requires an active
Qt application. Missing dependencies remain unavailable. Commands are closed,
nonce-bound and consumed before uncertain input. A job is retained before any
input and is never evicted. A timed-out queued query cannot later start work.
The provider holds its original bridge weakly; there is no independent input
manager, handler registry, renderer or service initialization.

The fixed private channel is `files/overte-e2e/snapshot-cancel-ui-command.json`
and `snapshot-cancel-ui-status.json`. Its original QSaveFile writer uses mode
0600 and atomic commit. `PicoSnapshotCancelIO` reuses the existing immutable
NativeNavigationIO final `before_send` callback after candidate/process guards.
Its private factory requires the caller's callback and the exact parent
ScriptSourceLock instance. The eventual owner must durably retain its exact
intent and fresh phase before this publication. There is no public facade or
claim that merely binding an arbitrary callback satisfies that owner contract.

The strict version-1 envelope retains unchanged original native Capture v2,
Script v2 and Review v2 frames, original input commands/receipts and all job
summaries. Original history prefixes, distinct source queries and immutable
terminal/retirement samples are checked. Source reads do not substitute desired
values. An original completed ScriptWork v2 packet can be selected for a hidden
or closed Review only by its actual cached request nonce and exact native
manager/code/compilation ownership. Empty UI absence alone cannot prove idle.

`reconcile()` only reads the existing original status; it never reissues a
command after response loss or cold restoration. Consumed query IDs also
prevent an explicit second publication of that same command on a live reader;
restoring an archived packet consumes its original query ID. Final copies, original guards
and a native clock recheck occur before acceptance, with a monotonic lower
bound on source age even if either clock freezes. The raw original receipt retains its first actual host/native age anchors;
rereading the same status cannot replace them, and cold restoration requires
those unchanged anchors. A historical packet remains historical when restored. The native `retired` flag means this bounded recipe's
timer is stopped and its first original idle sample is retained. It does not
mean final three-second quiet, file/FD retirement, Qt deletion or whole cleanup.

The owning `snapshot-fast-cancel` host selector compiles the complete unchanged
normal NavigationUi translation unit (default configuration) and whole original
NativeFieldInput.cpp. A separate feature translation unit compiles the selected
recipe, whole original new TSI getter, actual bridge root/provider/request/tick
bodies and private writer. Their object layouts do not cross macro boundaries.
It loads the complete production NativeSnapshotReview.qml in a real host
QQuickWindow and types the owned name through original pointer/IME input.
Explicit synthetic VM/VR/tablet/render services bound this host check: actual
Qt timers, original caller/work/recorder bodies and unchanged QML are real,
but V8, a headset/OpenXR runtime, real rendering and Android files are not run.
The default NavigationUi unit uses `-Wall -Werror`; its unrelated unused
feature-only pointer parameter prevents `-Wextra` in that unit. The feature
unit and original field input use `-Wall -Wextra -Werror`.

The test exercises normal cancellation plus acknowledged-only capture,
changed UI generation, native capture starting, retained upload, stale input,
unowned name and wrong mode. It checks disabled runtime admission, duplicate
commands, blocked original dispatch with late callback, strict complete DTO
readback, changed archived originals, response loss, cold read-only recovery
and frozen-clock final guards. A separate actual private factory case rejects
publication after its parent callback or candidate binding becomes invalid.
