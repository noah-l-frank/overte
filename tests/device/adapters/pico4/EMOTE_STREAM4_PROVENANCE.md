Source4 reuses the current Pico normal Emote Parent, inputs, effect and quiet
owners unchanged. The private range journal, SourceLock alias, original closed
files and current descriptor owner come from the integrated Audio raw package.
Binary fixed-file framing follows the integrated `PicoProbeOriginals` and
`AndroidSnapshotFiles` pattern. The actual transport is the existing SDK
`AdbTransport.execute_bytes`; no device service is introduced.

The existing Source3 native/Host code supplied the actual remote Avatar,
geometry, camera, Domain/client and committed interpolation leaves. The new
timer producer gathers these actual native leaves directly and has no legacy
request ID or generated observed state. The existing default Source3 query
body remains unchanged except its explicit opt-in mixed-arena refusal; its
32-observation history cap is unchanged. The new sample/frame allowance is a
separately declared bounded producer policy within the same compound limits.

The small new native descriptor pair intentionally follows the existing
`PicoAssetsOriginalDescriptor` pattern rather than extracting/changing the
Assets owner. Current source inspected for that pattern is
`tests/device/native/PicoAssetsBakeOriginals.h`. Its headers omit no runtime
requirement here: Source4 still needs an actual successful kernel alias query.

`F_LINUX_SPECIFIC_BASE+3`; the base is1024. NDK header omission supplies no
proof about Android kernel support. The native implementation is uncompiled.

`5e8ff8aa19571f5718b982dc47a165b8f22e0dc0`. No Phone/iOS file, monoscopic UI,
