# Pico Create normal voxel edit and render-copy ownership

Feature 4/14 remains **partial**. The private Create parent v3 composes the
original v16 `voxel-edit(mode=remove, brushMeters=0.5)` after its independently
identified canonical PolyVox creation. This extends the existing first-twelve
and [PolyVox creation](CREATE_POLYVOX_PARENT.md) flows without advertising the
full `feature.create.*` capability trio.

The parent enters the original TOOLS tab through normal input. The new
`pico-create-voxel-controls` v1 surface binds original NativeCreate QML URL,
real QML context/root identity, native control types, actual window, finite
scene geometry and actual control metadata. Normal pointer, combo key and
NativeFieldInput operations configure the original cube/remove/click/laser
settings and a 0.5 meter brush. The original backend settings echoed into the
actual QML root are distinct from uncommitted control drafts. All seven original
settings are captured before configuration and restored through that same normal
route, with observed original mode restored last. Unsupported numeric text,
negative zero, nonfinite values and unrepresentable original settings refuse.

The normal transport uses the existing immutable
`NativeNavigationIO.bind_before_send` owner. Original phase advancement in its
last native guard produces no QML command publication. Generic paging retains
its existing explicit admission; voxel controls require their real inputReady.
No entity/voxel API, product JS callback, QML property or requested geometry is
written directly by the adapter.

An actual owned PicoOpenXrAdapterSession sends three distinct normal streams:
Tablet close, one calibrated primary stroke aimed at the independently measured
original entity position, then Tablet open. Actual native Home entity identities,
tracking transform and head position derive the grip pose. The exact envelope is
persisted by the original Session intent under its native session lock. The fixed
[before_publish API](../../openxr_input/BEFORE_PUBLISH.md) checks only the
previous durable envelope and original native/host sample anchors under that
lock. It performs no guard, new source, HTTP, ADB or Session call. Frozen native
time cannot conceal host time spent in final SDK admission or writer preparation.
No second intent, resend or sequence adoption is introduced. Every exact stream
must independently reach original neutral, followed by a fresh native Home
packet showing its actual resulting tablet state.

Completion requires independent actual compressed voxel bytes and all 512
values. Only original 255-to-0 removals qualify, with some of the central cuboid
remaining. Original UUID, creation time, host, parent, name, position, rotation
and dimensions remain bound to the created subject and original domain
connection generation. The source must prove actual Ready/mesh state and counts,
actual original included EditModes/EditVoxels compilation hashes, completed
original voxel timer registration/invocation, quiet callbacks and three seconds
of advancing host, entity, script-work and UI clocks. The original raw
entity/callback/work packets, hashes and original UI frames survive later Delete.
A final fresh parent sample must equal the stored actual effect.

## Original mesh and renderer copies

`pico-create-entities` v5 adds `pico-create-polyvox-resources` v1. The existing
atomic volume getter records its actual shared mesh under the same original
read lock as the voxel/mesh snapshot. The unchanged original asynchronous
PolyVox renderer update sends a test-gated passive notification after its normal
mesh, material and texture update. The observer reads renderer-owned fields on
that original render thread. A mutex protects only bounded weak histories; the
GUI does not race those renderer fields, load resources, query GPU textures,
look up caches or evict anything.

The source distinguishes entity mesh, renderer mesh copy, renderer QObject and
three actual NetworkTexture copies. Original control-block identities and actual
QObject guards survive allocation-address reuse and deferred deletion. No strong
mesh/renderer/resource reference is retained by the observer. Actual matching
entity/renderer mesh identities must join before a stroke can complete. Mesh,
renderer and resource histories remain append-only and bounded; overflow refuses.
The independent acquisition sequence must advance but is not an effect change
in the three-second quiet comparison. Actual resource identities, render-update
counts and liveness remain part of that stable comparison.

Deleting a Tree object does not qualify retirement of the renderer's retained
mesh or texture. The existing shared Create entity-retired predicate now also
requires every known v5 PolyVox mesh, renderer QObject and texture QObject to
be dead. Original v1-v4 entity packets remain readable; v4 primitive creation
remains supported, while the new stroke requires v5 before its first tool input.
A candidate-guarded parent upgrade reads original v1/v2 journals and adds the
empty v3 edit owner without rewriting old source IDs or times.

## Recovery and validation boundaries

A lost final settings response can reconcile read-only when the exact actual
settings, stream neutralization, native effect and quiet work already exist.
An ACK, requested brush settings or unchanged actual voxel bytes cannot complete
the call. Cleanup may perform one distinct normal settings restoration and
observe its exact result before original Delete/retirement. Unknown or partially
completed controller sequences remain owned; cleanup never replays them or
retires their original envelope. Original Qt contexts, cached NetworkTextures,
physical browse-setting restoration and unresolved children retain their
existing refusal behavior. The parent retains raw effect proofs after Delete.

`create-polyvox-native-ui` additionally runs actual NativeCreate TOOLS controls,
whole original Pico/Offscreen pointer bodies and NativeFieldInput under Qt5.
The unchanged original nativeCreateBridge/EditModes/EditVoxels JS is executed by
a declared QQmlEngine JS/runtime/controller/raycast/volume/timer actor. The actual
emitted UI messages cause one original cube-removal stroke (64 to 16 occupied
actor voxels) and exact normal settings restoration. Real Qt moved geometry,
disabled controls, a higher foreign overlay and clipping refuse the held token
without reaching the pointer sender. This is not a V8, device, physical controller,
domain or GPU-effect qualification.

`create-entities-native` compiles the complete original atomic volume and local
insertion bodies, the actual native getter, and the whole original asynchronous
renderer update. Declared mesh/GPU/cache/storage boundaries surround that update;
its separate real host render thread notifies the real weak collector. The test
observes old/new mesh identities, retained renderer mesh, actual deferred QObject
death, and retained/dead texture guards. Its cache actor follows original
ResourceCache::getResource by moving newly created resource QObjects to the GUI
thread. No product affinity or lifetime is changed.

[`create-voxel-source-native`](CREATE_VOXEL_SOURCE_JOIN.md) joins that existing
normal TOOLS fixture to complete original native VoxelVolume, meshing,
compression and shape preparation, actual timers, the existing atomic getter
and weak resource collectors, then normal settings restoration and Delete.
Its native/host quiet clocks and explicit tree/scene/SDK endpoints are documented
separately. It does not replace the production parent or qualify device/GPU
retirement.

`create-voxel-owner` and `create-voxel-guards` partition `test_create_voxel_owner.py`: production parent,
Session, private CAS, phase/source histories and token owners with explicitly
declared native/controller/UI/domain actors. Tight cases cover normal edit and
joint cleanup, cold lost-restore reconciliation without replay, ACK without
actual volume effect, retained mesh after Tree deletion, and frozen native time
plus a two-second final admission delay with zero stream publication. Actual
PicoNavigation/NativeNavigationIO voxel DTO publication and a final-guard phase
race are checked separately in `create-feature-owner`. The two new bounded selectors retain all
five cases with no overlap or omission, leaving the existing nine primitive
cases separate. The local catalog changes from 68 to 70; integration adds two
to the parent's actual current count. Timeouts and assertions are unchanged.

Remaining full Create work includes original denied/rez authority and exact
restoration, independent peer/current state, completed actual stereo draws,
texture/pixel/artifact qualification, GPU/backend allocation retirement and
complete v16 final-state/resource closure. Mesh-copy lifetime and render-update
identity alone do not prove any of those effects. There have been no physical
Pico/OpenXR runs or complete Interface builds for this packet.

The passive `e2eSettingsReceived` provenance follows fixed Phone commit
`203d6b65f06f46d03e47bf8ca9314dcb149ffdf8` (read-only source pinned at

This counterexample exposed a host-listener error: the old harness attached its
signal spy after `Component.onCompleted`, losing the original `nativeCreate.ready`
request and admitting unchanged QML defaults. The harness now uses normal
QQmlComponent beginCreate/completeCreate lifecycle to attach before completion,
asserts the actual ready message, and delivers its original bridge reply only
after the no-baseline counterexample. Its explicit entity-list transport actor
implements the original ready branch's refresh; no product lifecycle is altered.
