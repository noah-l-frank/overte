# Digital PC originals bound to the normal Audio cycle

The existing normal Pico recipe now has a private
`join_completed_preview(PicoAudioPeer(...))` operation. It consumes the actual
completed cycle3 after its normal Start, automatic completion and retained
originals. It creates no second normal owner or journey. Full Audio,
independent whole-Actor and physical acoustic qualification remain false.

## Narrow frozen reuse

The [selection manifest](AUDIO_PEER_REUSE_20261102.json) pins Phone
`a7be274da152b9d0b77e2fe5bb9874c5b1e18a31`. The original selection copied the shared `Peer.preview` method verbatim,
plus additive runtime state/status/dispatch and CLI forwarding. The later
opt-in original-recorder source extends that method while preserving the
default preview API; its current ownership is documented in the PC Start join. The existing voice receive APIs keep their behavior.
`OVERTE_E2E_RECORDED_PREVIEW_TESTS=1` explicitly gates the new provider.
Nothing in this source packet starts a PC client, audio server, microphone,
capture process, Domain or service. Authorized future laboratory execution
must use the Proxmox environment and existing permanent Raspberry Pi Domain.

The provider reuses the actual owned PC receive-monitor capture path. It retains
a separate `preview-<start-ticket>.wav/json` pair, refuses reused capture IDs,
limits retained files and known captures, validates format/size and requires a
new query to inspect absence after an owned release. Its source stays
`private-pc-playout-monitor`, with `physicalAudioHardwareTested=false`.
The PC monitor may observe network microphone traffic. It cannot independently
prove that Pico's physical speaker played the local preview.

The Pico reader reuses the frozen PC session, candidate/runner hash, readiness,
domain, request and original-file checks. It pins the actual private session
hash at construction and adds complete file signatures, exact JSON sidecar
bytes, and actual WAV header/payload-to-metadata validation. Those additional
checks were needed because frozen Phone performs part of its WAV validation
in a separate file owner, which Pico does not import. No Phone touch/UI,
monoscopic rendering or public Audio coordinator is copied.

## Same Parent, actual original bytes

The normal recipe's private journal is version2, reading1/2. Old version1
roots keep their schema and normal behavior, with no implicit migration into
the new join. The version2 Parent records an issued digital-evidence intent
before querying the independent source. It binds the exact immutable
`capture3.retain` child root, native cycle/history, and normal recording-start
ticket. The later `await-completion` ticket is never substituted.

The operation rereads all original native input and accepted-sink PCM through
their saved complete physical signatures and hashes. Wrapping that actual PCM
in a WAV header preserves its bytes; it generates no requested waveform.
The existing shared recorded-preview analyzer processes the full input, sink
and independently retained PC WAV using that original Start ticket.
The PC capture must cover the real native cycle's recording/sink times.
Its full original packet, WAV reference/signature and exact JSON sidecar bytes
and signature remain attached to the same durable Parent. Original consumer
metadata cannot borrow the correct signal bytes while claiming a different
sample rate or frame count.

Malformed/missing/foreign/wrong-challenge evidence leaves its actual observed
source replies under issued ownership and prevents later normal input. A later
call can read only that same capture; it cannot arm or replay receive, Start,
HOME, mute or X. A lost joined-Parent return similarly recovers through reads.
Successful historical joins do not replace later current target observations.
The original phase/Host budget includes copies, writes, final file/process
guards and the actual outer source-lock exit. Joined journals and all original
PCM, WAV and JSON files remain owned. No release or whole-cleanup claim is made.
