# Passive remote Emote Source4 component

This opt-in private component adds an independently clocked native producer
without increasing Source3's 32-observation allowance. Source3, Capture2 and
the original normal Emote input/effect/lifetime owners keep their defaults.
Source4 is not a complete Emotes adapter, native build qualification, hardware
result, independent Actor qualification or visible-animation/pixel verdict.

`PicoEmoteStreamCycle` attaches to the exact existing `PicoEmoteNativeCycle`
before its first baseline. It delegates that Parent's normal Open, Play,
Cancel, Close and original three-second quiet algorithm. The first baseline
read hook runs only after the original Parent has durably issued its original
host/native/provider anchors. It retains that exact Parent baseline and seals
one immutable policy for both resolved roles before their first stream IO.
It creates no second recipe, input Session, owner deadline or Source namespace.

Each role uses its actual SDK/native process and clock binding. The later
Actor anchor receives only the remaining original host window. This is
execution policy, not a fabricated native clock attestation. Native ARM checks
the original epoch is not future and its fixed deadline is no later than
that epoch+120000ms. Neither ARM nor a different run can renew it. Host guards
retain the same original Parent 120s and existing 1.5s control / 5s acquisition
windows, including reservation, framing, parser and final-guard work.

## Native producer and physical ownership

The new API is gated by E2E, Pico and Linux. ARM/STOP/DRAIN use at most 32 unique
controls. Native GUI timers independently sample every 500ms, without a wanted
pose, Host query ID, requested Emote or synthetic legacy envelope. Each role
issues at most 256 native frames; the compound allowance is 512. Timer samples
have native stream IDs, native sequences and original actual native times.
The original deadline timer and every sample/write fence stop further work
when the owner expires. Stop disconnects both actual timer objects; Drain
requires their actual deferred destruction, no in-flight tick, the original
queue quiet and verified writer/OFD closure. Unknown work remains owned.

The publisher uses only its fixed files in the existing TestResultsLocation.
It requires the actual private original directory, paired original descriptors,
fresh named/held full physical stamps and complete current bytes. Each write
first durably creates a fixed uncertainty marker. Partial writes, unexpected
bytes/stamps, changed directories, lost/unverified descriptors and unknown
unlink/fsync outcomes are sticky; no retry, truncation/adoption recovery or
namespace rotation is supplied. A positive ARM original comes only after the
actual first write/readback. Its original root/sample node, sample fullstamp,
bytes/hash and actual sample ID are retained in `armOriginal`; Stop/Drain
preserve this historical proof. The Host pins those nodes before its first
sample getter. Fresh read framing checks both root and sample complete
before/after metadata; initial same-ID bytes/fullstamp must still match ARM.

`F_DUPFD_QUERY` must actually prove alias equality at runtime. The Pico/Linux
owner uses Linux UAPI 1027 when the NDK header omits the declaration. Unsupported
or error results leave capability unavailable; inode, offsets and flags are
never substitutes. No target-kernel support or C++ compilation was established.

## Original returns and compound accounting

The fixed bounded sample/control scripts use binary `execute_bytes`. Their
complete obtained wire bytes, including malformed, NUL, overrun prefixes,
partial timeouts and late returns, enter the existing `AudioRawArchive` BEFORE
framing, UTF8 or JSON parsing. That reused journal is explicitly an Emote raw
literal container; it supplies no Audio fact. A native command reserves both
its future ACK and its actual send-return receipt before dispatch. New work
requires the current business Parent; already-issued return archival uses
only the original host/scope/lock/OFD authority. A lost Parent cannot consume
or discard the earlier guarantee. Unknown CAS/append remains pending and
prevents replay or cold continuation.

Both roles share one raw archive and the original 512-part / 16MiB aggregate.
Fresh full inventories include both source roots, all existing Parent/source
and input copies, budget/baseline files, expanded packed histories and images.
Raw metadata/ranges and both native current/control/intent worst cases are
charged too. No second quota, reset or exemption exists. Literal parts retain
the existing 64KiB maximum. Accepted role history stores references to these
originals rather than independently persisting a second decoded sample.

Existing `emote-remote-owner-` source names reject prior/mixed/rootless history
before either role arms. New coordinator/budget/raw children use the original
Parent's already guarded `.child-` family. No new Binding cleanup exception is
needed. An accepted in-memory sample graph is sealed only after successful
original role CAS/readback; substitution or mutation refuses before new IO.
