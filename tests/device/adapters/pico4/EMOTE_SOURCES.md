# Original Pico Emote sources

`PicoEmoteSources` v2 acquires original configured Script roots, actual compiled
Emote code, passive animation-cache resources, evaluated native Rig history and
the original Pico VR navigation/chooser snapshot. The existing phase reader
brackets each acquisition. The existing `script-sources.lock` serializes these
queries with the Script journey; there is no new transport or test service.

The private `_emote_sources` factory pins the installed candidate, process and
existing VR bridge. Both primary and actor roles have separate journals and
original files. Role names alone do not prove independence; the unfinished
whole-feature coordinator must join independently acquired sources and process
ownership. These sources do not send a feature input or produce an effect verdict.

Version 2 follows the original Pico `NavigationUi::observe` generation change
when tablet visibility changes. Such an edge is retained as a source transition;
the [one-send input owner](EMOTE_INPUTS.md) separately binds it to an original
controller intent. Live-root replacement without a visibility edge and reuse of
a retired generation fail. Version 1 archives retain their fixed-generation
rule; changing a header cannot authorize an unsupported historical transition.

The original store is a reviewed platform-independent extraction from fixed
Phone commit `abb7f6b60d97daf17752aadf94e2b5df099bb7ba`, documented in
[the selection manifest](PHONE_SHARED_EMOTE_ORIGINALS_20261022.json). It preserves
canonical private bytes, original timestamps, inode/device identity and bounded
immutable manifest indexes. Phone UI, SDK transport, mono rendering and the
Phone-specific whole-source owner are not selected.

## Acquisition and interruption

Responsibility is written before constructing source readers or issuing an
observation request. Each successful read joins all original sources, checks
source births, compiled identities, all twelve loaded raw-FBX model pins and
original evaluation/caller histories. Original VR widget tokens, advancing
native UI cursors and the binding's actual bridge are retained without input.

Both target and host clocks plus monotonic elapsed time enforce the existing
1.5-second delivery window, including archival I/O and final guards. The entire
operation is bounded by five seconds. A slow final archival commit may leave a
valid historical frame; it cannot return that frame as fresh. A crossed input
phase is retained before `EmotePhaseChanged` and yields no current facts.

Reconstruction reads complete original files and replays original Script,
animation, inventory/model and UI cursor histories without native queries.
The next successful read must acquire new originals. An interrupted read
remains `reading`; reconstructing the owner cannot resend its missing query.
`recover_complete` can finish an exact already complete owned original and its
manifest without a native query or fresh return. Missing, partial, replaced or
foreign originals remain unresolved. It never retires the source journal.

General Pico teardown still reaches the original process stop, then refuses
success while either role's source journal remains. Process stop is not original
source retirement. No full Emote capability is advertised.

## Verification and remaining work

`emote-original-sources` runs the common storage and original-source owner checks
without a device or compiler. `normal-emote` additionally exercises the real
private Pico factory, exact shared lock and retained-journal teardown. Boundaries
for product Qt/Rig/OpenXR and clocks in these tests are explicitly synthetic.

The normal ten-button input path, one-send owner and focused native UI/cache
helpers have separate verification records. A complete Emote area still requires
independent playback/cancellation/replacement joins,
current original two-eye images, independent actor publication, interruption
composition, actual callback/timer/resource ownership and full retirement.
No native application or headset/device qualification is established here.
