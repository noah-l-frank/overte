# Original Scripts and pending-input continuation

This private `pico-lifecycle-pending-owner` component continues the existing
Create/X/Chat/HOME-return owners. It advertises no complete Lifecycle operation.
New owners write version2; admitted version1 owners retain their original
layout, writer and operations without migration. Version2 adds the actual
mutation replies described in the [continuous operations packet](LIFECYCLE_OPERATIONS_PENDING.md).
The existing shared sixteen-step scenario remains unchanged. Independent peer
and image evidence, later world movement, normal position restoration and final
process/context/file retirement remain separate unfinished requirements.

`_lifecycle_pending_owner(target, run, source_lock=..., world=..., background=...)`
requires the original candidate/process, exact World/source-lock instance and
released original background owner. Its complete private archive hash stays
bound throughout this continuation. Fresh original Chat/keyboard facts must
still match the returned Reply context before the first new input. Historical
Chat text is never queried as current after leaving that page.

The same original OpenXR session stages physical left X using the existing
button envelope, durable intent and final host publication fence. Its owned
neutral receipt is followed by independent actual Home, field/page retirement
and VR keyboard observations. The Create-only Back journal remains unchanged.
The existing normal `TokenScriptUI.open_manager` route opens Scripts; the final
normal QML command is privately persisted through `bind_before_send` after
original candidate/token/sequence admission. No URL dialog, script load, direct
QML handler or property setter is exposed.

Original empty Scripts field/page/context identities must differ from Chat's
before assigning generation 3. Existing native pending-owner focus/type inputs
must independently agree with actual Scripts/VR keyboard sources. The owned
Retry draft is retained as one original native Unicode commit. Its complete
capture command/event/source/hash/time receipt survives the second ordinary X
and genuinely new empty, unfocused Scripts field/page/context. Only then does
generation 4 name that actual replacement. Tokens from the pending owner and
Lifecycle source retain their separate original namespaces; neither is copied
as another source's object identity.

The original held event is attempted once through its original native guard.
Only its unchanged `rejected/context-retired` terminal history, empty actual
replacement editor and released keyboard permit progress. Expiry, release
without attempt, sent input, an ACK or an arbitrary rejected event cannot pass.
The native ten-second hold ceiling is unchanged. The additional host bound
uses acquisition start minus original native elapsed hold time; response
delivery cannot create a later birth. It is never refreshed by context
replacement. Original release and inventory reads
precede three seconds of complete current UI/keyboard/gesture/three-dimensional
feet quiet at the existing 250-ms cadence. Gesture history cannot change inside
that window. Original world/stale attempt counters remain measured histories.

Every issued phase reconciles only its exact original native command, bridge
cursor or controller envelope. Lost replies never authorize repeated focus,
typing, hold, X, entry, attempt or release. An uncertain grant, missing original
intent, ignored effect or incomplete replacement stays unresolved. This owner
does not erase any journal or claim surviving Qt contexts have died.

`release_owned()` separately handles a captured original event after partial
failure. It needs no current UI query: exact original pending-source identity,
capture command, event and intent cursor remain mandatory. Its one release is
durably recorded before delivery; an uncertain release only reads that original
cursor and terminal inventory. Successful failure cleanup returns only actual
pending-event absence, leaves all journals retained and prevents resuming the
interrupted scenario as a stale-attempt success. It supplies neither a stale
attempt nor Qt/process/whole cleanup. A persistence failure cannot authorize an
unrecorded release.

`lifecycle-pending-owner.json` retains complete input intents and lossless
references to `pico-lifecycle-pending-originals:1` in
`lifecycle-pending-originals.json`. The existing immutable source-chunk container
preserves each original raw packet and SHA under the separate Lifecycle-pending
run/binding scope. Bounds remain 512 children, 16 MiB and 64 KiB per private
file. The original manifest's full physical stamp is recorded in its parent
owner and verified through the existing private original-FD reader. Complete
inventory/signature reads remain mandatory. Admitted raw inspection memory
uses the existing immutable bytes/hash/scope pins; inspection copies cannot
rewrite sources. Cold reads fully decode the original files. Lost child/root/
parent publication, changed bytes or identities and orphan files fail closed.
General cleanup also retains responsibility for any owner/root/orphan child.

Both native readers build their result copies before the final candidate guard
and native clock. The pending owner retains original response bytes/request
for this join. Its optional final-send callback checks the already persisted
original command after the last transport guard, without another intent or
source query. Native and monotonic age remain at most 1500 ms, including a
frozen native clock; existing five-second exchange ceilings remain unchanged.
The controller's locked callbacks remain host-only.

Nested continuation actions share the same twenty-second host call budget;
they cannot refresh it when one child returns. The independent native held
event keeps its original ten-second ceiling across recovery. Result construction
precedes the final source clock, including the Back branch, and a further final
candidate/native/monotonic age check runs after the actual source-lock context
exits. It performs no new query, mutation, adoption or replay. An outer lock
failure or late exit cannot return a successful current result; original
journals remain retained for read-only reconciliation.

post-transport receipt time minus native elapsed time. The unchanged original

capture was 12.852 s, but a byte-identical still-fresh packet delivered 600 ms
later produced `holdHost=13.452`. The failed originals remain retained. This
was not a native TTL extension, but the added host barrier was too late.
