## Exact early retention and transfer

The same canonical Actor and six original readers now select private source
version2. Before each next native query, the already acquired original request
and literal response are durably retained in bounded staging parts through the
existing `source_bundles` and `ChatSourceChunks` codecs. Original phase endpoint
DTOs are retained before the shared phase reader validates them. The fixture
client exposes decoded phase DTOs, not original HTTP wire bytes.

The staging root is `lifecycle-actor-in-progress.json`. Its original root OFD,
directory OFD and each original child OFD remain independently pinned. Atomic
root CAS uses `LifecycleProcessFile`, which pins the prepared candidate OFD
before rename. Physical signatures retain the original device, inode, mode,
UID, link count, length and nanosecond modification/change clocks. Immutable
copies do not replace these stamps with their own physical identities.

Each completed six-source group copies the complete original staged root,
every exact staged child file byte and stamp, and the actual publication DTO
into one immutable main source bundle. All copied source bytes are decoded
and compared before a durable verified-transfer receipt exists. Every child
then has a durable unlink-issued intent, another exact immutable destination
read, original-clock check and original OFD/path/directory check before unlink.
Unlink, directory fsync, observed link count zero, actual original OFD close and
path absence precede the durable observed retirement receipt.

The complete final staging ledger is copied into the before-publication bundle.
Only its verified copy and the main root's durable unlink-issued intent allow
the staging root itself to be removed and its original file/directory OFDs
closed. The transport-reply bundle includes that observed root-retirement
receipt. The actual reply is retained before current-candidate validation can
reject it. Such retention grants no successful sample or replay permission.

There are three main bundles per successful group: native originals,
publication phase with final staging ledger, and actual reply with root
retirement receipt. Each bundle still splits through the existing bounded
codec when necessary; three bundles do not imply three parts for arbitrary
large inputs. Fixed staging slots can be reused only after actual retirement
and delivered publication. Failed or uncertain scopes cannot retry or reopen.

## Storage ownership and live source authority

Fact-free archival operations check the same original warm host, scope and
binding bytes, source lock for mutations, namespace, original OFDs, complete
root CAS and file identities. They do not query the target merely to preserve
a literal already received. Full six-reader/current-candidate guards run at
actual source queries and admission, publication, and actual outer lock exits.
The original source capture/request/known-frame clocks retain their unchanged
freshness limits throughout transfer. Storage success supplies no native
cleanup or new source/input authority.

The candidate-loss counter retires the existing declared target model after
the actual UI original getter returns and before its archival callback. All
three already acquired source literals survive; no pending/native/subject query
or publication follows. This is explicitly model candidate-loss evidence,
not actual native-process or device-exit proof.

## Unchanged bounds and historical reading

The512 active immutable-part and16MiB limits cover main and live staging parts
together. Main container bytes, nested decoded staging container/source bytes,
logical original bytes and actual stored bytes are accounted separately and
bounded. Three complete64KiB metadata reservations cover both roots and an
in-flight atomic write. Each individual root/child retains its64KiB ceiling.
Bounded capacity is reserved before another literal can be queried. The
diagnostic highwater records actual live counts and bytes, including the
overlap while a verified immutable copy and its staging originals coexist.

`ActorOriginals` reads historical source versions1 and2 without opening a live
source, checking a live product PID, adopting ownership, issuing a query, or
renewing freshness. V1 data stays V1. The portable V1 compatibility case is an
explicit synthetic codec fixture; it is not new native or process evidence.
Missing roots, orphans, unknown CAS, copied-file/root replacement, real OFD
recycling, uncertain unlink and uncertain close remain terminal. Remaining
originals and uncertain handles are retained for actual host finalization.

The storage fault tests exercise real private files, kernel OFDs and unlink
operations. The81-group capacity case uses one actual independent Linux
Actor and the same canonical candidate/session/lock as the original normal
editor. Native, Qt, SDK and physics producers remain the existing declared
fixtures. Its complete measured bill and retained run are recorded below;
an early passing subset is insufficient.
