# Pico normal domain Model owner

Feature 4/14 remains **partial**. The private `_create_models(target, run)`
composition supplies normal NEW glTF/OBJ creation, independently observed local
entity effects, one-shot normal property input, normal Delete and measured
original Script/entity retirement. It does not advertise `feature.create.*` or
replace the existing catalog → OverteSession → normal Create foundation. The
full feature driver must still compose its actual texture/export/JSON/PolyVox,
independent authority/peer, original stereo drawing/image and artifact evidence.

## Normal input and recovery

The existing Create and Script opt-ins, private input directory and installed
candidate/process/session guards apply. After the caller enters the original
Create page, `invoke('create', ticket=..., fixture_url=..., resource=...)` admits
only the existing v16 `model-create` inputs `gltf-bundle/main.gltf` and
`obj-bundle/main.obj`. It uses the existing `TokenCreateUI` and Pico normal
navigation transport: NEW tab, actual Domain combo choice, normal resource URL
field/IME and original Model button. The adapter never calls an entity mutator,
a QML function, a signal or the Script timer API to deliver input.

The actual original assigned Script manager and compilation of
`system/create/edit.js` must be unique across the complete callback source. Its
original resolved local/qrc URL, native V8 Script ID, UTF-16 code-unit count and
source digest are joined to the shared original ScriptWork v2 source. Selecting
a name or manager URL alone is insufficient. The actual local domain connection
birth/revision, session UUID, both effective rez flags, original avatar-centred
scan and unowned property digests must stay unchanged.

Before input, the owner stores actual source frames and pins its original work
baseline. Each normal input's original token/scope is persisted before delivery;
the Model-button attempt is durably marked before sending it. The entity is
adopted only from an independently acquired native entity frame: one new actual
Domain Model, its exact ticket URL, no parent/lock, original edit time after the
baseline, actual selected UUID and original weak object identity. Initial
unnamed/invisible Models are tracked by their closed run/ticket resource URL,
so the original asynchronous load interval does not hide an unresolved entity.

Creation first waits for actual `Entities.isLoaded`/native visual readiness,
actual visible state, positive renderer vertex count and retired original
`edit.js` work. It then uses the original name, dimension fields and Apply
button to set the existing run namespace and unit dimensions. The complete
actual entity properties, original timer registration/invocation counters and
original UI state must settle again before creation finishes. Unit dimensions
are observed from the entity source; field text or an input receipt cannot
establish the edit.

`reconcile` acquires fresh original sources and **never sends input**. A lost
final Apply can finish only when the original properties actually changed.
A lost Model/name/partial-property input cannot restart creation or repeat the
edit sequence. A distinct normal Delete is allowed only after independently
adopting the actual owned Model; it targets that UUID through the normal list,
selection and Delete controls. A lost Delete uses observations alone. Failed
intent writes, unknown/missing effects, candidate/source/domain replacement and
foreign entity changes retain ownership. A later step cannot overwrite an
unresolved earlier attempt. Two resource tickets are admitted per owner.

## Original work and object lifetime

The shared ScriptWork v2 source records real native timer registrations,
invocations, function Script IDs, active callback depths, evaluation and the
original timer inventory, including inactive retained timers. The owner waits
for its actual `edit.js` timers and active callbacks to retire. Completed
ordinary background signal invocations may continue. Known foreign compiled
script timers remain present and are never cleared by the test. Unknown timer
or callback origins, including retained completed unknown activity, refuse
qualification. Shared-manager script IDs identify original compiled source;
this does not invent a separate native identity for every JavaScript closure.

Each settle window requires three seconds of host, original entity capture,
original queued Script-work capture and original UI elapsed-clock progress.
The native UI process/session and command generation/sequence must remain
stable during that window. Polling is finite (103 observations, 20 seconds per
settle window); initial acquisition allows three seconds and read-only orphan
retirement thirteen seconds. The original script itself can schedule its
100 ms load checks for ten seconds and its 200 ms dimension checks for another
two seconds. A visibility change at its load timeout is insufficient without
actual native readiness and geometry.

The native entity source is now v3, with passive v1/v2 readers retained. It adds
actual `visuallyReady`, `naturalDimensions`, original texture slot URLs and
renderer counts, plus append-only `entityLifetimes`. The lifetime helper holds
only `std::weak_ptr` references to the actual original objects looked up under
the original EntityTree read lock. It records original first-observation time
and a native identity; these are not fabricated creation times. Tree absence
with another actual strong holder remains `alive=true`. A replacement pointer
under the same UUID cannot become the original. Original object death cannot
be reversed after reconstruction.

Normal Delete and final release require both actual tree absence and original
weak-object death, empty selection, unchanged domain/scene and quiet original
callbacks/timers. The existing original EntityRenderer holds its EntityItem
strongly, so a live original renderer prevents this weak-object retirement.
Independent mesh/material/GPU payloads can outlive that object; this source does
not claim their retirement, a submitted draw, either eye's pixels or peer/server
absence. Those must join the existing independent render/peer owners later.
The picker owner now requires v3 weak death too; a v1/v2 source can be read
passively but cannot authorize new picker input or complete retirement.

## Durable original evidence and ownership

Separate private 0600 journals retain candidate binding, the two ticket steps,
original input attempt and original callback/entity bytes with their SHA-256.
The work journal retains exact raw native baselines, original frames around
membership transitions and the latest original frame in the existing bounded
canonical compressed transcript format. Redundant intermediate polls are
replaced only after native continuity validation. Real retired-manager IDs,
append-only compiled sources and monotonic activity counters are reconstructed
from original frames; no current packet is retimed or treated as an old input.
There are at most 64 work checkpoints, 48 KiB compressed, 16 MiB expanded and
64 KiB per private state file. Exhaustion retains the originals and fails before
further input rather than truncating provenance.

The existing shared Create source lock serializes the composition. Another
Model run, a picker owner, the existing Create-management owner or a regular
Script reservation prevents acquisition. Picker/management owners likewise
refuse a retained Model owner. Target cleanup inventories all Model journals,
including read-only orphans, and cannot erase them through application teardown.
After observed final cleanup, main and source records retire. An interruption
between those host deletions leaves source journals visible; read-only recovery
requires a new joint original quiet proof before discarding them. No unresolved
resource is inferred retired because a journal is missing or the app stopped.
Native source limits stay four run namespaces, 32 original UUIDs per run and
512 immutable nonce results per observer birth.

This owner does not own or restore the full Create editor, VR keyboard or
original Qt context. The separate Lifecycle/picker owner must still prove their
retirement; the already documented retained original QQmlContext and original
Cancel/typed Browse writer boundary remain unresolved when observed.

## Selected host validation and integration

`create-model-owner` exercises glTF → actual properties → Delete → OBJ → Delete
with substituted native/UI boundaries, lost input and read-only recovery,
inactive/unknown original work, retained entity holders, frozen clocks,
membership replay, original raw-frame tampering, candidate/scene replacement,
failed durable writes and partial host-journal retirement. Its Node case loads
the original `nativeCreateBridge.js`, unchanged `createNewEntity` body and
original defaults from `edit.js`, with declared entity/clock/native-dispatch
boundaries. Actual load, two-second dimensions, ten-second load-timeout and
denied-host routes execute; no V8/client/domain behavior is claimed by Node.

`create-model-native-ui` compiles the original `NormalControlUi` and complete
original `NativeFieldInput.cpp`, loads the unchanged `NativeCreate.qml` from its
real resolved URL and uses actual Qt pointer/IME delivery. It independently
reads the exact original Domain/Model/URL `sendToScript` payload, consumed and
stale token refusal and the original missing-URL error. PathUtils configuration
and a visible Qt host window are explicit boundaries. No QML handler is invoked
by the test, and a button receipt is not an entity-effect verdict.

`create-entities-native` compiles the real production getter with substituted
entity/tree/domain APIs and real original shared/weak objects. A removed entity
held outside the tree remains alive; releasing that real holder produces weak
death, and same-UUID replacement refuses. Actual initial unnamed/invisible model
admission, loaded render fields and forbidden URL query/fragment cases execute.
The complete Interface/native translation units, real V8/entity renderer,
physical Pico, domain server, peer, OpenXR and GPU remain unrun here.

The registry adds `pico-create-model-owner` v1 and
`pico-create-model-work-originals` v1 and advances `pico-create-entities` to v3
with readers [1,2,3]. Two additive Pico host selectors map to
`tablet-and-create-ui`. Parent integration must add **two** to its current
catalog count, preserving all other feature mappings. Aggregate coverage stays
partial with no full Create operation claim. The reviewed shared ScriptWork v2
API is a dependency; the primary branch already contains it and should preserve
its newer shared files instead of replacing them with this branch's dependency
backport.
