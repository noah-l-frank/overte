# Normal Script file-bundle ownership, version 1

The existing `NormalScriptManager` has an internal `script-file-bundle` scope.
It composes the existing original-byte `OwnedScriptFiles`, normal token-bound
`TokenScriptFilePicker`, service-row observer and ordinary manager/row inputs.
It is an input/cleanup ownership component, not a second runner, functional
execution verdict or complete feature capability. Internal factories now exist
on the three separate local platform branches; full Script/restart/peer joins
remain to be implemented.

Construction requires the actual file owner and picker objects, already staged
persistent file intent and exactly matching process/session/candidate or explicit
component-only contexts. This scope uses the existing private manager journal
envelope at `schemaVersion:3`, `sourceKind:'script-file-bundle'`, plus exactly
`fileOwnershipVersion:1`, `fileOwner`, `pickerOwned`. Existing URL/create scopes
remain schema 2. There is no automatic mode or process-binding migration.

`fileOwner` starts null. Before the normal From File click, a separate fresh
native original-byte read establishes the actual directory and four controlled
file bytes. The journal freezes exactly `runId`, `ownerToken`, `hashes` and that
actual `directory`, and records `pickerOwned:true` before delivering input.
A guessed or changed directory/token/run/hash or replaced native-file intent
cannot be adopted. A preexisting picker is rejected before ownership is written.
Native process/source/token guards remain the platform's responsibility.

`file_picker_choose(resource)` accepts only `script.js` or
`script-bundle/main.js`, rechecks current original bytes and rejects an existing
same-basename service row, including case variants. It records the exact source
URL and `loadAttempted:true` before any selection. The existing picker verifies
actual selected rows, companion, review manifest and primary item before one
ordinary Use Files click. A missing/ignored/uncertain selection retains intent
and is never automatically replayed. Success of these inputs does not prove a
running engine, loaded companion, advancing effect or peer observation.

`file_picker_cancel()` and manager cleanup use original current picker reads.
An ignored Open can be retired only after independently observing stable picker
absence; a still-visible owned picker uses its normal Cancel/Back route. An
ignored Cancel leaves a valid recoverable journal. Manager cleanup does not
close the tablet while any journaled URL dialog or file picker remains open.
This also fixes the existing URL scope's failed-cancel path, which previously
could write `managerOwned:false` while retaining `dialogOwned:true` and thereby
make its own journal impossible to reopen safely.

Normal `stop_source()` retains existing original row/order/token checks and
waits for source disappearance. Its result is still narrower than independent
effect/engine cleanup. The next controlled primary can be selected only after
the preceding load intent has been retired. Manager cleanup cannot discard an
active/uncertain load intent; file intent and original files remain separately
owned until `OwnedScriptFiles.release()` obtains an independent absence read.
The complete coordinator must perform both stages and establish stable peer
cleanup; closing a panel or a native deletion ACK is insufficient.

The public `scripts.*` foundation retains its exact existing HTTP URL grammar.
The file scope refuses those dispatch operations and URL-dialog loading; its
only primary selection path is the normal file-bundle picker. Guessed file URLs
cannot broaden a registered public operation.

The nine new host cases use real private journals and temporary fixture bytes,
with explicit synthetic native UI/service/storage boundaries. They cover both
primary paths, cancellation, ignored input/stop/release, changed originals,
foreign rows/pickers/owners, invalid resource paths, retained ownership and
recovery after failed Cancel. The source-correct synthetic picker recreates its
empty selection on each new dialog, matching `NativeFileBrowser.qml`'s default
`chosen:[]` and destruction on completion. One additional existing URL-manager
counterexample checks recoverable failed Cancel. No C++ is compiled and no
device behavior is qualified by these tests.

A real app restart uses an explicit separately verified ownership handoff:
same independently verified installed artifact/target and original file token,
observed old process death, actual new process/source identity, current owned
script absence/byte observations and durable adoption before cleanup input.
The v16 mobile recipe expects no automatic user-script execution: normal reopen
and reimport are separate subsequent actions; see [the current Script flow](../feature_journeys/SCRIPTS_SOURCE.md). The native
`.owner.v1.json` already survives process death; host context equality must not
be weakened to bypass the handoff. The [version 1 transaction](SCRIPT_RESTART_HANDOFF.md)
now implements original observations and recoverable private file/manager binding
transfer. One-send normal lifecycle orchestration and full independent feature
evidence/cleanup remain required; no complete feature capability is enabled.

Phone `_script_file_manager(selector)` uses original staged bytes plus normal
Phone manager/file controls and rechecks installed identity on UI/service I/O.
Pico `_script_file_manager(target)` and iOS `_script_file_manager(selector)`
reuse the original UI runtime independently of the manager journal's URL/file
mode, so reconstructing a file owner cannot accidentally construct/adopt a URL
manager journal. The iOS factories keep separate original native clocks; the
physical runtime/storage paths retain candidate/source guards and legacy/unbound
entrypoints explicitly refuse these new factories before I/O. These are internal
input/ownership components. General cleanup still rejects unresolved file
intent, and no complete feature capability is enabled.

Platform source checks pass on synthetic native/OS boundaries: Phone 107,
Pico 55 normal-Scripts plus 21 native-feature cases, iOS 395 no-build cases plus
ten binding checks. They preserve the selected actual primary path, require
separate original file absence and retain both intents on process/candidate
loss. These counts do not qualify product behavior or any device.
