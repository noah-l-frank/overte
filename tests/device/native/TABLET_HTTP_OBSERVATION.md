# Original Pico tablet HTTP ownership

`native-tablet-http` v1 observes the existing `RootHttpRequest.qml` → system
`request-service.js` → `scripts/modules/request.js` → native
`XMLHttpRequestClass` path. It is a source prerequisite for ordinary Go To and
Graphics cleanup, without a whole feature capability or navigation verdict.
Native code is uncompiled; host simulations do not qualify Qt, networking or VR.

The native provider is installed only in `OVERTE_E2E_FEATURE_TESTS` plus
`ANDROID_APP_PICO_INTERFACE`, with the existing explicit test-script/results
launch arguments. The actual system-tablet root and normal Pico UI observation
share one GUI-owned bounded ledger. It recognizes the original QML helper type,
its actual parent/context and callback map, retaining weak root/helper pointers
across hiding, detachment and replacement. It never filters pending callbacks
because the page is invisible. A dedicated native-only enable flag observes
actual QML callback execution; the default QML flag is false on every platform.
Exceptions keep their original behavior; they are never swallowed or repaired.

At the existing native `fromQml` forwarding point, a unique actual callable QML
request ID acquires a native lease. Only the internal message envelope gains
that private ID. Original options, URL, headers, body, response and scheduling
remain intact. The service passes it through the request module's existing
optional callback parameter. Only the dedicated native binder can bind the
original newly constructed, unused XHR on its original script thread. A missing
binding remains an unresolved request even when the QML parent is gone.

Native events retain primitive actual state and weak pointers, queued onto the
GUI ledger. They cover original handler assignments, ready-state transitions,
whole native/JS callback entry and return, active timer state, destructor entry,
actual QObject destruction and every original network reply, including earlier
redirect replies. No strong product object, callback, response body or plaintext
URL is retained. Original parameters, context URLs and reply URLs become hashes.
Reply destruction is acknowledged independently of its weak pointer clearing;
no queued destruction event can silently disappear behind an empty callback map.
The original timeout timer is neither stopped nor repaired by observation.

The closed probe command accepts only schema version, a fresh 32-hex command ID,
a 32-hex run ID and `feature-tablet-http-observe`. The probe preserves the native
object at `feature-tablet-http.json`, using the existing atomic owner-only save
path. Missing native hooks publish unavailable data. The owning Pico factory
uses the original candidate/OpenXR/process-start guard, native clock, private
transport and one-send request behavior. No helper performs input or launches
an app, service or request.

The Python reader validates original append-only roots, request identity,
callback IDs, exact event histories and state/depth transitions, global event
cursors and each reply's provenance and actual retirement. It rejects stale or
foreign samples, reused/nonadvancing acquisition identities, vanished history,
callback/object revival, malformed/incomplete sources and final guard/time loss.
Read acquisition has a five-second host budget and 1,500 ms original-age limit.

`released()` requires every original QML root/helper to be actually gone,
every observed callback depth to be zero and every original reply to be destroyed.
The XHR itself must either be actually destroyed or remain inert at DONE with no
handlers or active timer. HTTP success, an absent XHR, hidden UI and an empty map
alone are insufficient. The whole feature owner must additionally join ordinary
Home/page closure, scene/Web lifetimes, independent actor observations and a
three-second quiet window before deleting journals or owned evidence.

The ledger bounds are 128 roots, 512 requests, 8 replies per request, 128 events
per request, 8,192 total events, 4,096 non-recapturable observation nonces, a
4,096-node/128-depth QObject walk and 262,144 serialized bytes. Exhaustion becomes
unavailable/incomplete; old history is never evicted to manufacture release.
Only observation resources are retained, with no cancellation, retry, forced GC,
request ID repair or product functional changes.

No Phone/iOS producer was promoted to this Pico-only source. The shared JS/QML
additions remain inert without the dedicated native binder/enable flag. Later
integration must preserve those gates and prove the same actual producer before
requiring this contract on another platform. Native compilation and device
qualification remain separate, unperformed work under this session's boundary.
