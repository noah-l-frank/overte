# Focused first-failure preservation

These opt-in host runtime helpers keep the first failed focused device test in an explicit debug hold. Normal `run.py` and sequential supervisor behavior remain unchanged. A reviewed private configuration and exact hashes are required; the helpers do not discover devices, install software, repair sessions, restart fixtures, or bypass admission checks.

`debug_harness_bootstrap.py` installs narrow hooks around the original runner. Module stdout/stderr is retained completely in private mode-0600 files. A nonzero result blocks before automatic screenshots, the next module, or adapter cleanup. At the original module deadline, only a freshly proven owned process group may receive SIGSTOP; the failure verdict is retained. The hold-aware isolated executor waits instead of converting that hold into an outer timeout and cleanup. An independent Jenkins resource lock must remain held throughout.

The original source inventory, installed-candidate checks, setup barriers and module limits remain authoritative. The exact original native verifier must pass before any launch and again before every configured domain-dependent module. Container Running/ExitCode metadata explains a failure but never replaces that verification. Native controller failure preservation is a separate opt-in controller contract; historical runtimes that already cleaned up are not retroactively preserved.

Existing private adapter spans are projected into closed phase, timing, observation and source-frame records. Request completion is not an input effect. The adapter bootstrap changes only request category labels, preserving its original one-JSON response protocol and every original input. Root's separately pinned `diagnostic_logs.py` publishes complete sanitized text chunks; raw logs stay private. Native memory publication omits cgroup paths, argv and credentials and records actual numeric samples only. Live log snapshots explicitly identify their observed prefix, time and body hash.

The public generation consists of summary, JUnit, safe events, the complete artifact index, and a last-written `debug-state.json` receipt. Readers must validate the independently pinned publication policy and every indexed body before archiving an explicit allowlist. Log-publication failure remains a visible error with a safe core receipt; it never grants cleanup or PASS. Files are immutable after the receipt.

A generic cancellation does not authorize cleanup while held. Only an owner-private, exact-context request `{"schemaVersion":1,"action":"cleanup","contextSha256":"…","nonce":"…"}` permits leaving the hold. The nonce must never enter public logs. Existing owned cleanup and native-controller release must then be verified separately; a release request is not a cleanup-success claim.

The host tests use actual owned subprocesses, the original harness/supervisor and generated private fixtures. They perform no SDK, network, container or device actions. Run the selected tests with standard unittest discovery in this directory; no alternate test framework is introduced. Actual laboratory execution remains exclusively through the official Proxmox Jenkins CLI. Deployment configurations, secrets, measured receipts and source/build identities belong outside the repository.
